# P4c：口語表的改壞讓語意校正來補（探索；2026-10-20 登記）

P4b（`experiments/p4b-colloquial/README.md`）照登記不出貨：口語表（T2、μ 0.5、γ 0.25）在 discordtune 對出貨最後選字是 128／92，改壞太多，而且 92 列裡至少 64 列是 s 第一名把 n-gram 原本對的字改錯。維護者看完結果與兩位研究顧問的建議後決定（2026-10-20）：口語表造成的改壞讓語意校正（小模型重排的融合）來補，再找調整空間；出貨標準同日放寬（`docs/methodology.md` 同日一節，從這一片起適用）。這一頁在跑任何 P4c 的數字之前 commit。

兩位研究顧問都建議停掉這條線，估計縮小 μ 之後淨值只剩 +5～+15，而且「只在 n-gram 分差小時才套表」是唯一可能的變體。這一片照維護者的方向做，不包含閘門變體。

探索片：只用調參層（chatclause、cvtune-clean）與開發層（discordtune）、回歸層集合，不碰判讀集與保留集；不改核心與 App，不出貨。

## 做法

- 口語表固定用 P4 的 T2（`2984eeb5…`），γ 固定 0.25；CLI 的 `--colloquial`（P4b，PR #239）。
- **格點**（事先固定，24 格）：μ ∈ {0.1, 0.2, 0.3, 0.5} × 融合的 α ∈ {0.3, 0.5, 0.7} × δ ∈ {0, 0.25}，τ 固定 2。α 越大、δ 越小，小模型越容易推翻 s 的第一名，也就是語意校正越能把口語表改錯的字改回來。μ 0.5、α 0.3、δ 0.25 就是 P4b 那一格。
- **算法**：每個 μ 用 CLI 跑一次（`--colloquial … --tinylm … --tinylm-scores`），得到依 s 排序的前 8 名的 s、`ll` 與每個候選對不對；不同的 α、δ 離線用 `experiments/s7a-tinylm/fusegrid.py` 的 `pick` 重算最後選字（P4b 的 verifier 已驗證離線重算與 CLI 逐列相同）。**錨點**：每個 μ 在 α 0.3、δ 0.25 的離線選字要逐列等於 CLI 的 rowstats，不等就停。
- 基準一律是**現行出貨設定的最後選字**（不帶 `--colloquial`，α 0.3、τ 2、δ 0.25）。

## 選格（只在 chatclause，n 5,761）

- 合格的格：照新出貨標準第 1 條在 chatclause 上算：不顯著變差（精確 McNemar p ≥ 0.05，或淨值 ≥ 0），而且改壞 ≤ 30（26 按列數換算到 chatclause：26 × 5,761 ÷ 4,958）或改壞÷改對 ≤ 0.5。
- 在合格的格裡取淨值最大的一格；同分取 μ 小的，再取 α 接近 0.3 的，再取 δ 0.25。
- **沒有任何一格合格** → 照登記結案（口語表這條線停），discordtune 不跑。

## 預算、資料、停止條件、範圍外

- **程式**：`experiments/p4c-colloquial/p4c.py`（讀 CLI 的 `--tinylm-scores` 與基準 rowstats，離線算格點、選格與判讀表，只輸出數字）＋單元測試，走 `/code-review`（探索片，不送 verifier）。
- **雲端 VM** ≤ 2 小時：chatclause 先跑（4 個 μ），選格之後才跑 discordtune 與公開集合的那一個 μ。私人集合的傾印只在 VM 上、跑完刪掉；帶回來的只有數字。
- **停止條件**：錨點不符；私人句子被帶回 Mac；要用到判讀集或保留集。
- **範圍外**：n-gram 分差閘門、重建或修正口語計數、重新選 γ、改 τ、書面設定、核心與 App。

## 結果（2026-10-20，雲端 VM，`p4c.py` `eebf7590` 與 main `62e67938` 之後的 CLI；所有臂同一台機器；私人集合的傾印只在 VM 上、跑完刪掉）

- **錨點與雜湊**：`p4c.py` 在 α 0.3、δ 0.25 的離線選字和 CLI 選的候選或 rowstats 不同時會印 `STOP` 並以 1 結束，VM 腳本在 T2、私人列、cvtune-clean 任一雜湊不符時也會停。這次 `--select` 正常選出格子、五個判讀步驟都是 rc 0、腳本跑到結束（VM 執行紀錄），所以錨點與雜湊都通過；紀錄裡沒有逐項印出「通過」的行。

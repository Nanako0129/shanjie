# 常談與讀音通道項在保守／積極也生效（探索；2026-10-22 登記，在任何數字之前）

## 起因與決定

- 錄 v0.5.0 demo 時發現強度不是「標準」就沒有常談。維護者：「保守或積極都不應該覆蓋常談」。
- `colloquial::applies` 要求聊天、標準強度、配對的小模型，所以常談（P4d 那一格）和讀音通道項（P5）只在聊天標準生效。
- 研究顧問（Fable、Argon；全文在維護者本機的顧問資料夾）分析後，維護者 2026-10-22 三題選擇題：
  1. **現在做，在 main 上量**：R1 產品片出貨時再重跑傾印。
  2. **14 格**：保守 6、積極 8。
  3. **探索過了就出貨**：對這一片的例外，記在維護者的 `decisions.md`。
- **只做聊天**：常談是聊天語域的表，P4d／P5 沒在書面量過。書面的三檔不動。

## 融合（每一格）

- 和出貨的聊天標準同一個融合：n-gram 第一名當錨點，`P.eff_ll` 的口語項（μ 0.5、軟閘門 T 1.0），加 P5 的讀音通道項（lex、ν 1.0、c 4），再 `pick(ng, eff, α, τ, δ)`。
- 每一檔只換 (α, τ, δ)。μ、T、ν、c 固定。
- **口語項與讀音項在融合分數裡的權重和 α 無關**：s_i = ng_i + α·ll_i + g_i·μ·(col_i − col_0) + ν·(ch_i − ch_0)。eff 裡的係數是 μ/α、ν/α，**α 要用那一格自己的 α**；用標準的 0.5 去除會讓別的 α 下的 μ、ν 變大或變小。
- **不重匯出 `.sjtl`**：換檔頭會改掉檔案雜湊，`applies` 就會失效，兩項在每一檔都消失。產品片把每一檔的三個值寫成 `colloquial.rs` 的具名常數。
- τ「不限」＝每一列都重排（`pick` 的 margin 條件永遠成立）。

## 格點（事先固定，14 格；全部聊天、全部加常談與讀音通道項）

| 檔 | 格（α, τ, δ） |
|---|---|
| 標準（不選、固定） | (0.5, 2, 0.25)：現行出貨 |
| 保守（6 格） | (0.3, 2, 1.0)、(0.3, 2, 1.5)、(0.5, 2, 1.0)、(0.5, 2, 1.5)、(0.5, 2, 2.0)、(1.0, 2, 3.0) |
| 積極（8 格） | α {0.5, 0.7} × τ {2, 不限} × δ {0, 0.1} |

## 選格（只在 chatclause，n 5,761；改對／改壞對 n-gram 第一名）

- **保守**：條件是 改壞 ≤ 0.5 × 標準格的改壞，而且 改對 > 改壞。在合格的格裡取「改對 − 4×改壞」最大的一格。同分時依序取 δ 大的、α 小的。
- **積極**：條件是 改對 > 標準格的改對，而且 淨值 ≥ 標準格的淨值。在合格的格裡取「改對 − 2×改壞」最大的一格。同分時依序取 α 小的、τ 2 先於不限、δ 大的。
- 沒有合格的格 → 那一檔用標準那一格（仍有常談），不停。

## 判讀（選中的格；每一檔分開判）

1. **出貨標準四條**，對**那一檔現在的出貨值**：保守是檔頭 (1, 2, 3)、積極是 (0.3, 2, 0.25)，都沒有常談與讀音項，也就是使用者現在在那一檔看到的。
   - 條件 1：discordtune 不顯著變差（精確 McNemar p ≥ 0.05 或淨值 ≥ 0），而且改壞 ≤ 26 或改壞÷改對 ≤ 0.6。
   - 條件 2：打字測驗（聊天）逐列相同，或改壞 ≤ 2 且淨值 ≥ 0。dev302 聊天只報，改壞逐列標類別。
   - 條件 3：cvtune-clean 聊天 Δtop1 的 90% 配對 bootstrap 下界 ≥ −1.0 個百分點。
   - 條件 4：錯字回報（`eval/dev/user-reported.txt` 的前 157 列，聊天＋書面合計；書面不變）淨值 > 0 且改壞÷改對 ≤ 0.6。
     - 〔推論〕保守、積極在錯字回報上可能 0 改對 0 改壞（淨值 0），那就不過。那一檔改用標準那一格，再對該檔出貨值判一次四條；這是事先寫死的退路，不算改規則。
2. **順序門檻**，對標準那一格，都是對 n-gram 第一名數改對 F、改壞 B，同一次跑：
   - **保守**：B(保守) ≤ B(標準)，在 discordtune、cvtune-clean、打字測驗、錯字回報都要成立；而且 discordtune 淨值 > 0。
   - **積極**：discordtune 的 F − B ≥ 標準的，而且 F > 標準的；discordtune 的 B÷F ≤ 0.6。
- 任一條不過 → 那一檔用標準那一格。兩條都過 → 那一檔出貨選中的格。
- 用標準那一格的檔，也要對該檔出貨值過四條才出貨；不過就報給維護者，那一檔維持現狀，不結案。

## 資料與工具

- **CLI**（同一個 commit、同一台 GCP VM）：每個集合跑一次聊天標準的出貨設定，加上 `--colloquial-core`、`--dump --dump-words --rowstats --tinylm-scores`（融合只讀前 8 名的 ll，不需要 `--tinylm-scores-topk 64`，main 的 CLI 也沒有這個選項；〔同日更正，任何數字之前〕）。候選與 ll 和強度無關，14 格都從這一次離線算。
  - 集合：chatclause、discordtune、cvtune-clean、打字測驗、錯字回報（157 列）、dev302。
- **錨點**：
  - 錨點 1：聊天標準的出貨那一格離線重算，逐列等於 CLI 的選字。
  - 錨點 2：聊天保守、聊天積極各跑一次 CLI（`--rerank-level`），它們的出貨值離線重算（檔頭三個值，不加任何項），逐列等於 CLI。每個集合都要。
  - 任一錨點對不上就停。
- **工具**：`experiments/strength-colloq/sc.py`，重用 `p5.py`／`p4d.py` 讀列與口語項的函式。逐列只輸出 0／1 與數字，私人句子不出 VM。改到的工具程式走 `/code-review`。
- **預算**：GCP VM ≤ 3 小時（6 個集合 × 3 種強度的 CLI，約 18 跑），格點離線。超過 1.5 倍就停下來問。

## 停止條件、範圍外

- **停止**：
  - 錨點 1 或 2 對不上；
  - 列檔或模型的雜湊不符；
  - 任何需要重匯出 `.sjtl` 的情況；
  - 私人句子被帶回 Mac。
- **範圍外**：
  - 書面設定；
  - 重選 μ、T、ν、c；
  - R1 讀音解碼（它的產品片出貨時會重跑這些傾印）；
  - App 的設定介面。
- **之後**：任何一檔出貨都另寫產品契約，改 `colloquial::applies` 與每一檔的常數，並在同一個 PR 更新 `colloquial-term.md`、`reading-channel.md`、`s3a.md`（它們目前寫保守／積極逐位元組不變）。看過任何數字之後，不改格點、選格規則與門檻。

## 結果（2026-10-22，GCP VM 一台；工具 `d03efb00`）

- 錨點 1、2 在六個集合都逐列相符（聊天標準的出貨、保守與積極的現行出貨值）。
- **選格**（chatclause，對 n-gram 第一名；標準那一格 219／35）：保守選中 **(0.5, 2, 1.0)**（116／5）；積極選中 **(0.5, 2, 0.1)**。
- **判讀**（對各檔現在的出貨值；改對／改壞）：

  | 集合 | 保守 (0.5, 2, 1.0) | 保守退路：標準格 | 積極 (0.5, 2, 0.1) |
  |---|---|---|---|
  | discordtune | 71／10 | 159／48 | 108／42 |
  | 打字測驗（聊天） | **0／1** | **0／1** | 0／0 |
  | cvtune-clean | 41／7 | 93／12 | 64／12 |
  | 錯字回報（聊天；書面不變） | 8／1 | 25／3 | 21／6 |
  | dev302 聊天（只報） | 8／2 | 18／2 | 9／3 |

  - 積極：四條全過、順序門檻全過 → **出貨 (0.5, 2, 0.1)**（照維護者的決定，探索過了就出貨）。
  - 保守：條件 1、3、4 與順序門檻過，**條件 2 打字測驗淨值 −1，照登記不過**；退路的標準格同一列也不過 → 照登記保守維持現狀（不結案，報給維護者）。
- **差在哪**（零成本檢查，打字測驗是公開集）：被改壞的是第 61 列「老闆說下個月要導入生成式工具」。n-gram 第一名就是正解，常談把「導入」換成「倒入」；現行出貨的聊天標準也會這樣改壞這一列。打字測驗上保守的 6 格對 n-gram：(0.3, 2, 1.0) 2／0、(0.3, 2, 1.5) 1／0、(0.5, 2, 1.0) 3／1、(0.5, 2, 1.5) 3／0、(0.5, 2, 2.0) 2／0、(1.0, 2, 3.0) 3／0；δ 更大或 α 1.0 的格不會改壞這一列。這是看過結果之後的檢查，只能拿來提變體，不能改這次的選格。

# P4：口語計數表當獨立項＋聊天設定對疊加層詞扣分（探索；2026-10-20 登記）

零訓練診斷 D3（`experiments/diag-near-miss/README.md`）照登記開這一片：discordtune 的 C 列（n-gram 排序錯）裡，(ii) 贏的錯詞只在疊加層或詞包、(iii) 語料計數與詞庫先驗方向相反，合計 20.2%（壓線；只算兩側詞數相同的是 13.9%）。這一頁在跑任何 P4 的數字之前 commit。

這是探索片：只用調參層（chatclause）與開發層（discordtune、dev302、打字測驗、錯字回報）集合，不碰判讀集（chatjudge、chatjudge-2）與保留集；不訓練模型、不改核心、不出貨。結論只決定開不開下一片（P4b：核心載入第二張表、照新出貨標準判讀）。

## 要回答的問題

現在的 `data/lm/bigram.sjlm` 是維基計數 ×1 加口語計數 ×5 相加（`tools/build_lm.py` 的 `CORPORA`），口語只佔約 6%。把口語計數拆成**另一張表**，在聊天設定以 log-linear 加一項；再對只在疊加層（維基標題）或詞包的詞扣一個常數。這樣能不能在**不經融合**的情況下，直接把聊天的 n-gram 第一名改對？

## 量什麼

- **兩個層級**，都對基準比：
  - **n-gram 層**：s 的第一名和基準 n-gram 第一名比（改對、改壞、淨值、精確 McNemar p）。這是 P4 直接作用的地方，判讀用它。
  - **最後選字**：新前 8 名的集合都在原本的前 8 名裡時，`ll` 都有，融合可以照算；新前 8 名換進了沒有 `ll` 的候選，該列記「需重打分」，不算改對也不算改壞。需重打分超過該格受影響列（前 8 名集合或順序有變的列）的 10% 時，該格的最後選字標「不可靠」。只報。
- 另報：D3 的 (ii) 25 列與 (iii) 97 列各有幾列在 n-gram 層變對；C1、C3 桶的大小；基準重算檢查（下面）。

## 選格與判讀（事先寫死）

1. **選格只在 chatclause（調參層）**：20 格裡 n-gram 層淨值最大的一格；同分取 μ 小的、再取 γ 小的、再取 T1。這一步看的是 chatclause 的數字。
2. **判讀只在 discordtune（開發層）、只看選中的那一格**：
   - n-gram 層淨值 ≥ ＋25（約 n 的 0.5%）→ 開 **P4b**：核心在聊天設定載入第二張表與扣分、CLI 全部重打分，照新出貨標準（discordtune 對出貨值不顯著變差且改壞不多、dev302 與打字測驗不退步、錯字集有進步）判讀；P4b 另寫契約。
   - ＋10 ≤ 淨值 < ＋25 → 報告，維護者決定。
   - 淨值 < ＋10 → n-gram 資料側（口語表＋疊加層扣分）結案。
3. 同一格另跑 dev302、打字測驗、錯字回報集（聊天設定；公開集合，可以在 Mac 以外的機器跑）的 n-gram 層與最後選字，只報；P4b 才用它們擋。
4. 選中的格與數字寫進研究紀錄；看過 discordtune 的數字之後不改格點、不改門檻、不改表。

## 基準重算檢查（任一不符就停）

- μ 0、γ 0 時，每列 s 的第一名＝傾印的名次 0；用出貨融合重選的結果＝rowstats 的最後選字（全部列逐列相同）。
- discordtune 的基準最後選字對 n-gram 第一名的改對／改壞＝ D1 重算的 +107／−26。

# 蒸餾 L：L 規模的學生（探索片，不進 main）

計畫：維護者 2026-10-19 的選擇題。蒸餾 C（拿掉維基列）沒過，診斷顯示學生選錯的字對在訓練裡 99% 都看過；照 C 的登記，下一步是換容量。研究紀錄 2026-10-18 有 P2 一節，2026-10-19 有蒸餾 B、蒸餾 C 兩節。

程式一律不改：訓練用 `experiments/p2-distill/train_p2.py`（`--npz` 換成 L 起始模型），打分用 `experiments/s7a-tinylm/score.py`，判讀用 `experiments/p2b-reading/p2bana.py`，學生的檔名前綴給 `L`。

## 登記（2026-10-19，跑之前 commit）

探索片：只用調參層與開發層，不出貨，結論只寫方向；私人集合只記數字。不碰判讀集、保留集、chatjudge-2。

- **假設**：P2 學生（M 規模，約 1,400 萬參數、6 層）在 0c 的分佈上學到的有限，學生錯的字對在訓練裡也看過。學生變大到和 0c 同量級，應該更接近 0c。
- **和 P2 唯一的差別：學生的大小與起始模型**。
  - 起始模型是 L188：S7b 在另一台機器上用和 S7b 同一份資料訓練的 L（`tinylm-L.npz`，SHA-256 `0c7c7c48…`；8 層、8 個 head、d 512，30,227,968 參數，字表和 M 相同）。P2 從出貨的 M 起始；兩者的似然預訓練不完全相同，這是這一臂的已知混雜。
  - 其他照 P2：對 0c 的 KL、前文 `context_key`、資料（L0 的 287,914 列，維基加句子池）、3 個 epoch、batch 64、學習率 1e-4、warmup 100、留出 2%、種子 20261018。
  - 學生檔 `tinylm-L.npz`（P2 的輸出檔名），存成 `tinylm-Lst.npz` 以免和起始模型混淆。
- **打分**：GCP C4D。M、P2 學生、0c 的分數沿用蒸餾 C 那次在同型 C4D 上打的檔（打包在維護者另一台機器的私人目錄，`9bd3eca1…`）；四個聊天集合的 dump 也沿用那一份，學生只對同一份 dump 打分。核對：學生的 `ok` 欄必須和 M 逐列相同（`p2bana.py` 會檢查）。
- **主讀法**（照 P2）：chatclause 調參期用 `select_weighted(cap_ub=0.003)` 選 α／τ／δ；L 在 discordtune 上同時符合以下兩條才算過：
  - 對 M 出貨值（α 0.3、τ 2、δ 0.25）的淨值 ≥ +40；
  - 對 n-gram 第一名的改壞數 95% 上界 ÷ n ≤ 0.5%。
- **只報、不判**：P2 學生、0c、M 同規則的同一張表；L 的前沿表、單獨挑對率與留住率；留出 KL 與一致率對 P2（0.380、79.8%）；chatjudge-2 的 MDE；L 的記憶體與延遲沿用 rerank-size 量過的數（int8：RSS 增量 141 MiB、重排 p95 15–18 ms），這一片不重量。
- **之後怎麼走**：不論過不過，數字都交給維護者，不開確認片。過了，下一步是登記確認片（用 L 自己的不一致列數重算 MDE）並處理 L 的出貨格式。沒過，學生路線（P2、B、C、L）就全部結案，換方向的選擇交給維護者。

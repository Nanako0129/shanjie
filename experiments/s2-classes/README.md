# S2 類別實驗：詞類別回退（2026-10-05）

動機：使用者回報的錯誤有同一種形狀。兩個候選和下一個詞的 bigram 都沒出現過，分數退回 unigram 頻率，常用詞勝出：`量心電圖`→梁心電圖（動詞對姓氏）、`照建議`→趙建議（書面）、`已送出`→以送出（副詞對介系詞）、`打開診斷頁閃退`→業、`剛剛兩個都有綁`→榜。使用者要詞性知識；我們選擇從自己的語料做非監督詞類別（不用外部詞性資料，沒有授權問題）。本目錄只是研究，不動產品。

## 方法

**資料**：和 `tools/build_lm.py` 同一份加權計數（維基 20 萬篇 ×1、口語 ×5；31.2 萬詞、2,321 萬種 bigram、1.46 億詞次），不剪枝。`~/.cache/shanjie/work/s2-classes/edges.npz` 是它的陣列版（不進 git）。

**分群（`cluster.py`）**：Brown 式 exchange 演算法，目標是類別 bigram 的互資訊 I = Σ M(c,d)·log(M(c,d)/(O(c)·I(d)))，等價於最大化類別 bigram 似然。
1. 前 N=40,000 個高頻詞（涵蓋 93.9% 詞次）：前 K 個各自成類，之後依詞頻逐詞貼進使目標增量最大的類別（貪婪初始化）。
2. exchange：依詞頻順序逐詞試移到每個類別，增量為正才搬；最多 12 輪。增量用稀疏鄰居類別計算（只重算受影響的列與行）。`check_delta.py` 驗證預測增量等於整個目標重算後的實際差（N=1500、K=32、120 組，通過）。
3. 排名在 N 之外的 27.2 萬個詞：初始化與 exchange 期間統一放在一個固定的 RARE 類別（不動，但它的 bigram 仍進矩陣）；分群完成後，每個詞用它和已分類詞的 bigram 貼進最佳類別，不移動別人。271,880／272,025 有類別，其餘 145 個沒有任何已分類鄰居，維持原回退。
4. `<s>`、`</s>` 各自一個固定類別。

**目標改善**（每詞次的類別 bigram 互資訊，nats；單調上升）：

| K | 貪婪初始化 | 第 1 輪 | 第 6 輪 | 第 12 輪 | 搬動數（第 1／12 輪） | 牆鐘 |
|---|---|---|---|---|---|---|
| 256 | 0.5920 | 0.6217 | 0.6369 | 0.6400 | 10,490／1,181 | 約 7 分（機器空閒時） |
| 512 | 0.7066 | 0.7341 | 0.7505 | 0.7518 | 10,823／499 | 約 38 分（機器負載 20–70，每輪 85–405 秒） |

第 12 輪仍有搬動，未完全收斂，增量已小（<0.0004 nats/輪）。K=512 的最大類別 18,473 詞（接近「其他」的混合類），256 的是 24,714 詞。N=60,000 沒跑（時間改花在調參）。

**類別回退（`classlm.py`）**：只在 `BigramLM.prob` 的回退分支（詞 bigram 沒有保留條目，含沒有前文條目的情形）把 `back·pb` 改成
`back·[(1−μ)·pb + μ·P(c(w)|c(v))·P(w|c(w))]`。
P(d|c) = (M[c,d]+0.1)/(O[c]+K'·0.1)，M 為全部（剪枝前）加權 bigram 的類別計數；P(w|c) = uni(w)/類別 unigram 總和；`</s>` 的發射機率為 1。v 或 w 沒有類別（語料沒見過的詞庫詞）就不混入。保留條目的 bigram、詞庫分數、λ（chat 0.5、formal 0.7）、beam、PER_KEY、疊加層與 `cap_overlay` 全部不變，直接用 `reference/proto/lm.py` 的 `decode`。評測用的 LM 檔由 `tools/build_lm.py --out` 重建，和 main 的 `data/lm/bigram.sjlm` 用 `cmp` 逐位元組相同（sha256 9879fd8b…）。

重點觀察：類別項 P(c|c)·P(w|c) 比詞庫機率 pb 小一到兩個量級，所以 μ 要很大（0.9 以上）才有作用；μ=0.3 時五句幾乎不變。

## 成本

- **表大小**：類別陣列依 LM 詞彙 id 存 u16，31.2 萬詞 ≈ 0.6 MB；類別 bigram 表 (K+3)² 個 f32，K=512 ≈ 1.06 MB（K=256 ≈ 0.26 MB）；發射機率 uni(w)/類別總和只需 K 個 u64 的類別總和，不另存。合計 K=512 約 1.7 MB，對照現有 LM 檔 80 MB。
- **每個計分詞的額外工作**：只在回退分支，多 2 次類別查表、1 次類別 bigram 表查詢、1 次 unigram 查詢與除法、2 次乘法；seen 路徑零成本。無新記憶體配置。
- **實測**（Python 參考實作，機器負載 20–70，數字很吵）：cvtune chat 解碼 15.9 秒對 21.2 秒；wikitune chat 22.9 對 20.6。只能說 Python 下額外成本在 0–35% 之間，Rust 的實際延遲未量。
- **離線成本**：K=512 分群約 38 分（高負載），K=256 約 7 分。

## 注意事項

- 只有 1 個分群種子（確定性演算法，無隨機）；N、K、ε、μ 都只試了少數值。
- cvtune 的弄壞數隨 μ 單調上升，formal 的 p 值在 μ≥0.98 掉到 0.01 附近；dev302 的 15／3、22／5 是未調參結果，但 n 小。
- 排名在 N 之外的詞的類別是用鄰居貼的近似，沒有單獨評估。
- 未用私有資料；Discord 集請用 `aggregate.py` 自行跑。

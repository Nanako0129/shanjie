# P3：學生的前文從 2 字加長到 64 字（探索片，不進 main）

起因：維護者 2026-10-19 晚上在 Discord 才知道，P2 以來的學生只看 2 個漢字前文（`context_key`），教師 0c 看 64 字。charliie 提議「先加長前文、維度暫時不改」，維護者選擇題選「前文加長＋修量尺一起」（`.agent-local/CLAUDE.md`）。研究紀錄 2026-10-18 L0 一節量過「出貨 M 不重新訓練、直接餵 64 字」：chatclause 單獨挑對率 45.1% → 47.1%。但 M 的訓練序列都是單一一串漢字、從不跨標點（`experiments/s7a-tinylm/batching.py:1-2`），等於沒練過長前文，所以那個 +2 pt 不能代表「用長前文訓練」。

## 登記（2026-10-19，main 寫，跑之前 commit）

探索片：只用調參層與開發層，私人集合只記數字，不碰判讀集、保留集、chatjudge-2。判讀用維護者 2026-10-19 的新出貨標準（下面「判讀」），過了也只代表「值得做 App 的前文回傳」，出貨另開一片。

**兩邊各看得到什麼**（維護者要求先講）：

| | 前文 | 讀音 |
|---|---|---|
| 出貨 M、P2 學生 S（對照） | `context_key`：最後一串漢字的最後 ≤ 2 字，碰到非漢字就停 | 不看 |
| 新臂 S64 | `k_cross(前文, 63 − 候選字數)`：去掉非漢字後的最後 63 − \|c\| 字，**跨標點** | 不看 |
| 教師 0c（P1 打的分數） | 前文欄的最後 64 個原始字元（含標點） | 看 |

- **假設**：同一份資料、同一個種子、同一個配方下，只把學生的前文從 2 字改成跨標點的長前文，學生在聊天集合上會更接近教師，而且這個差別是前文本身帶來的。
- **兩臂**：
  - **S2（對照）**：P2 的學生 `tinylm-S.npz` `06a25d07…`，不重訓。
  - **S64（新）**：P2 的配方一字不改（出貨 M `tinylm-M.npz` `32308122…` 起始、架構不變、寬度 384、KL(q‖p) 對 0c 的候選分佈、L0 的 287,914 列＋P1 的教師分數、3 個 epoch、每批 64 列、AdamW、峰值 1e-4、暖機 100、cosine、種子 20261018、留出 2%），只把序列 `[BOS] k c` 的 k 換成 `k_cross(prefix, 63 − |c|)`（L0 的 `l0core.k_cross`，序列裡只有一個 BOS，所以是 63 不是 62）。
  - 另報 **M@64**（出貨 M、不重訓、k 同 S64）當參考，不判。
- **訓練**：Colab G4，1 個種子，預算 ≤ 1 單元。發散規則照 P2。
- **打分**：同一台 GCP C4D（和 P2 同型）上，所有臂一起打：
  - 四個聊天集合用出貨設定的 CLI（`--profile chat --context --packs acg`）重新 dump；S2、M 用 2 字前文打分，S64、M@64 用 `k_cross` 前文打分。
  - 公開集合（dev302、打字測驗、錯字回報）兩種設定都打，同樣各臂用自己的前文。
  - 聊天集合的前文欄只有「同一則訊息的前一串漢字（≤ 30 字），或 10 分鐘內上一則訊息的最後一串」（`experiments/e2-chateval/build_chatclause.py:248-252`），所以 S64 在聊天集合上拿到的前文比 App 前文回傳後少。這一點只報，不補。
- **選值**：每個學生臂在 chatclause 調參期用 `fusegrid.select_weighted(cap_ub=0.003)` 選聊天的 α／τ／δ（P2 的規則，數字才能和 P2 比）。書面一律用出貨檔頭的值（α 0.7、τ 2、δ 1，`e7c179d8` 的 SJTL0004 檔頭），不另選。
- **量尺修正（這片起照做）**：
  - 基準一律是出貨檔 `tinylm.sjtl` `e7c179d8`，打分前核對雜湊（10-19 曾誤用 `d07de71d`）。
  - 書面的值從出貨檔頭讀，不手寫。
  - 錯字回報集是「選錯過的句子」組成的單邊集：除了第一名正確數，另報改對、改壞、留住率（原本對的列有多少仍對）。
  - 寬鬆對照（`eval/variants.tsv` 把她妳它牠併進他你他他）之外，另報嚴格比對的第一名正確數。
- **判讀（新出貨標準，事先寫死）**：S64 用選到的值，對出貨 M（出貨值，2 字前文）同時符合以下各條，才算「值得做前文回傳」：
  1. discordtune：不顯著變差（精確 McNemar p ≥ 0.05，或淨值 ≥ 0），而且對 n-gram 第一名的改壞數不多於出貨值；
  2. dev302、打字測驗，聊天與書面：逐列相同，或改壞 ≤ 2 且淨值 ≥ 0；
  3. 錯字回報集：兩種設定合計淨值 > 0。
- **只報、不判**：S64 對 S2（前文本身的貢獻）、M@64 對 M；各集合的改對／改壞、淨值、p、上界；單獨挑對率、留住率；和教師同第一名的比例。
- **停止條件**：資料三方核對不符、訓練發散、出貨檔雜湊不對、聊天集合 dump 的第一名正確數和 P2 那次不同。碰到就停，回報維護者。
- **之後**：過了判讀 → 開「前文回傳＋S64 出貨」的產品片（契約、App 的前文回傳照 `oc-experimental.md` §5、Rust 用長前文打分、SJTL 不變）。沒過 → 寫進研究紀錄，S64 對 S2 的差就是「前文值多少」。

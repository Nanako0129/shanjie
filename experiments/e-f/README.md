# E-F 學習式閘門（探索；登記於跑之前）

`docs/iteration-plan.md` Phase 1 的 E-F。探索片：只用調參層與開發層集合，不出貨，結論只寫方向；私人集合只記數字。這個分支不合併。

- **假設**：現行融合用三個手調門檻（α 權重、τ 只在 n-gram 前兩名差距小於 τ 時重排、δ 換掉第一名需要的最小分差）。用現有分數檔訓練一個小分類器直接判斷「換成第 i 名會不會比較好」，在同樣的改壞率上界下能救更多列。
- **做法**（`gate.py`，只用 numpy）：
  - 資料：出貨小模型 M 的分數檔（聊天設定，Windows 機器上 rerank-size 的那一份；和 S7f 三種子用的相同）。
  - 特徵（只用數字，不看字串）：第 i 名對第一名的 n-gram 分差、小模型分差、名次 i、n-gram 前兩名差距、小模型分數的 softmax 機率（第 i 名與第一名）、小模型名次、候選數。
  - 標記：第 i 名對、第一名錯 → 1；第一名對、第 i 名錯 → 0；其他配對不訓練。
  - 模型：L2 邏輯迴歸。每列取分數最高的候選，分數超過門檻 t 才換。
  - 選門檻：在 chatclause 調參期做 5 折（連續區塊切）交叉驗證，選讓淨值最大、且改壞數 95% 上界 ÷ n ≤ 0.5% 的 t；再用全部調參列重訓。
- **比較對象**：M 出貨值（0.3／2／0.25），以及 M 同規則（同一上界規則在調參期選的 α／τ／δ）。
- **集合**：調參 chatclause 調參期；開發 discordtune、lytune（聊天）、chatjudge（已用過）。不碰判讀集與保留集；chatjudge-2 不讀。
- **指標**：開發層對 n-gram 的改對、改壞、淨值與改壞率上界；對 M 出貨值的改對／改壞與精確 McNemar p；error ratio（新造的錯 ÷ 修好的舊錯）。
- **停止條件**：學習式閘門在 discordtune 與 chatjudge 對 M 同規則的淨值都 ≤ 0，就結案，記方向。
- **沒做**：計畫裡「差異字的類別、是否句首」兩個特徵和「第一名是高次數的詞庫多字詞就不改」的消融需要字串，分數檔沒有，這次不做。
- **平台與預算**：Windows 機器，只讀分數檔，約 10 分鐘；GCP、Colab 0。

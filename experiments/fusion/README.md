# 融合實驗（離線）

規格：`docs/contracts/fusion-offline.md`。候選、前文、n-gram 分數、判斷器分數全部沿用 S5j／S5k 存好的逐列結果，不跑模型、不連網。問題：候選固定時，把 n-gram 與判斷器的分數合起來，能不能比 n-gram、判斷器單獨、現行 τ 門檻更好（#44 的第二個問題）。

## 怎麼跑

```bash
cd experiments/fusion
python3 test_fuse.py                                   # 單元檢查
python3 fuse.py --set cvtune dev302 typing76           # 公開集合，每個集合跑所有有檔案的判斷器
python3 fuse.py --repro --set cvtune --tau 0.6309      # 重現 S5k（cvtune 的 τ 是 discordtune 選的）
```

只印統計數字，不印句子。`rows.jsonl` 先用 `s5k.HASHES` 核對雜湊；`cli.dump` 的候選對不回 `rows.jsonl`、判斷器缺列或分數個數不等於候選數，都會直接停止（`fuse:` 開頭的訊息）。

### 給 main：discordtune

```bash
cd ~/side-project/shanjie-fusion/experiments/fusion
export SHANJIE_PRIVATE=~/side-project/shanjie-private   # 與 S5 腳本同一個環境變數
python3 fuse.py --repro --set discordtune                # 驗收 3：必須印 REPRO OK、結束碼 0
python3 fuse.py --set discordtune --judge Q8-ll Laya     # 主要檢定與預先登記的描述統計
```

第二行輸出裡 `primary_form ... <-- PRIMARY TEST` 是主要檢定（Q8-ll+ctxall，B 半，第 4 組對第 3 組，McNemar 精確雙尾）；`error_budget_B` 是兩個預先登記的列數（門檻漏掉、多採）。discordtune 沒有 Jev 檔，`--judge` 預設會自動略過。

## 實作上的決定

| 項目 | 做法 |
|---|---|
| 判斷器分數 | Q8-ll 直接用 `scores`；Jev 正序 c_j 對 `cands[j-1]`、反序 c_j 對 `cands[::-1][j-1]` 後平均；Laya 的存檔本來就依名次，直接平均；平均後取 `log(max(p, 0.005))` |
| 參數來源 | `select_params` 只看 A 半；τ 的格點也只用 A 半的 `margin`（`tau_grid(A)`） |
| 重現模式 | `--repro` 用 S5k 的做法：格點取全部列的 `margin`、τ 選在 A 半（`select_params(rows, grid_rows=rows)`）；平手取較小的格點 |
| a 為 0 或 1 | 契約沒寫。typing76 的 Jev 在 A 半全對，a = 1 會讓 log 爆掉，所以夾在 [0.5/m, 1−0.5/m]（m = A 半正解在候選內的列數）；只在退化時生效，其他集合不受影響 |
| 第 5 組的等效 τ | `T·ln(7a/(1−a))`，與推薦者的 n-gram 分差小於它就採用推薦。只在 a > 1/8 時成立（推薦者的似然高過其他候選）。Laya 在 cvtune、dev302 的 a 是 0.141、0.128，略高於 1/8，等效 τ 0.070、0.011；typing76 的 a 是 0.081，低於 1/8，這時等效式不成立：判斷器和第 1 名一致時，後驗反而會扣第 1 名，可能選到第三個候選 |
| 同分 | 一律取名次較前的候選；格點同分取較小的值 |

## 讀法與限制

* **cvtune／Q8-ll**：第 4 組（加權融合）在 B 半 91.4%，對第 3 組修好 15、弄壞 2（p = 0.002），對第 1 組 +30；第 3 組 88.8% 在 B 半不如它在 A 半的 90.0%。cvtune 是 S5k 的護欄集，不是 discordtune，這個結果**不是**預先登記的主要檢定。
* **cvtune／Jev**：第 4 組 91.0% 對第 3 組 6／1（p = 0.125），看不出差別（這個樣本量下）。
* **第 5 組（單參數 Bayes）** 與第 3 組在 cvtune 上差不多（Q8-ll 7／3 p = 0.34；Jev 4／1）。
* **Laya**：判斷器單獨只有 8–16%（和 S5k 的 L-choice 一致，不是這片的問題）。第 4 組選到很小的 w（0.05–0.07），和第 1 組只差幾列（cvtune B 半 2／1；typing76 A 半 86.8% 對 84.2%）。a 見上表說明。正反序第 1 名不同的比例 81–87%。
* **dev302／typing76**（Q8-ll、Jev）：B 半第 4、5 組對第 3 組的差別都在 0–2 列內，沒有可下結論的比較。
* **主要檢定（discordtune B 半，Q8-ll+ctxall，main 2026-10-07 執行，只記統計數字）**：第 4 組 89.2% 對第 3 組 87.8%，修好 13、弄壞 6，p = 0.17。照預先寫的規則：**這個樣本量下看不出差別**（不寫成沒有差別）。第 4 組對第 1 組（84.4%）33／9，p = 0.0003。選出的參數：τ 0.6384（A 半格點）、w 0.2、T 0.25、a 0.880、第 5 組等效 τ 0.986。
* **預先登記的錯誤預算**（discordtune B 半、Q8-ll+ctxall）：門檻漏掉的（判斷器對、第 1 名錯、沒採用）5 列；門檻多採的（判斷器錯、第 1 名對、卻採用）18 列。融合能改善的空間主要在少採錯的。
* discordtune 其他：第 5 組 88.0%（對第 3 組 6／5）；第 2 組（判斷器單獨）85.2%；第 5 組後驗的 ECE：候選內 0.059、全部列 0.075。Laya：判斷器單獨 9.4%，第 4 組選 w = 0.05、和第 1 組持平（5／5），它對第 3 組的 28／7 來自第 3 組比第 1 組差（80.2%）；順序敏感性：正反序第 1 名不同 82.2%。

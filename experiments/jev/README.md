# Jev（TypeSafe System One）實驗

2026-10-03，模型 `jev-1.13.0`（釘死版本），只送開發集句子（CC0）與詞庫裡的公開詞彙；不送使用者打的字、不送保留集。

## 設定

- key：申請處 <https://typesafe.ai> （早期存取）；放在環境變數 `TYPESAFE_API_KEY` 或 `~/.config/typesafe/api_key`（權限 0600）。程式絕不印出 key。
- 這是實驗，不是輸入法功能。若之後接進輸入法：預設關閉；沒有 key 時行為與沒有這個功能完全相同，並在選單顯示「Jev 不可用」。
- 只用 Python 標準函式庫（`jev.py`），不裝 SDK。

## J1：同音候選的語意判斷（`j1_choice.py`）

每句取 unigram N-best 前 8 名，Jev 用 Choice 挑一個。

| 開發集 | unigram | Jev | 正解在前 8 名 |
|---|---|---|---|
| 全部 300 | 52.0% | **81.0%** | 91.0% |
| existing 109 | 68.8% | 85.3% | 96.3% |
| homophones 165 | 46.1% | 81.8% | 91.5% |
| oov 25 | 20.0% | 60.0% | 68.0% |

- 正解在候選裡時 Jev 選對 89.0%（243/273）；confidence ≥ 0.9 的 160 句有 99.4% 正確，< 0.7 的 55 句約 62%。
- 只在 confidence 高時才推翻 unigram 反而變差（0.5 → 78%、0.9 → 63%），因為 Jev 沒把握時仍比 unigram 準。
- 還會錯的是經典同音：在／再、的／得、做／作、啦／拉、攻勢／公視、城市／台北市。
- 延遲（單題、台灣連線）：熱連線 p50 187 ms、p95 229 ms；冷連線（每次重新 TLS 交握）p50 206 ms、p95 243 ms。
- 花費：89,243 輸入 token，約 US$0.004。
- 原始輸出 `results/j1.txt`、`results/j1_raw.jsonl` 含使用者回報的句子，取得 CC0 同意前不進 git。

## J2：日常打字頻率（`j2_colloquial.py`）

1,592 個詞（同音組清單＋探針），Score 0–4。

- 探針：ㄍㄨㄥ ㄕˋ 依 Jev 排序為 公式 > 公事 > 公視 > 攻勢（詞庫原本「公視」第一）；那邊 2.86 vs 納編 0.71；常常 3.08 vs 嚐嚐 2.08。
- 事先宣告、不調參的調整 `score + 0.5 × (jev − 2)`：開發集 unigram existing 75 → 76、homophones 76 → 73、oov 5 → 5，**沒有量到改善**（同音陷阱集刻意兩個詞各寫一句，詞頻先驗本來就幫不上忙）。留到 S1 用自然分布的句子再評估。
- 花費：288,826 輸入 token，約 US$0.012。結果 `results/j2.txt`、`results/j2_scores.tsv`。

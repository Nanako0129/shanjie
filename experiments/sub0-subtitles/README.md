起因（維護者 2026-10-22）：「口語的訓練我想到可以用電影台詞」。版權照之前的決定：只拿來訓練與計數、不散布原文（和 HPLT 3.0 同一條）。兩位研究顧問的分析（Fable、Argon，報告在維護者本機，不進 repo）一致建議先做不花 GPU 的檢查。維護者同日選「先零成本檢查」，兩項：

1. **A 臂：S7f 舊權重重判**。S7f 的 A1（加真人口語）、A2（真人口語＋生成句）重訓過的會意，從沒在現在的出貨組合（會意＋常談＋讀音通道項）上判過。
2. **T 臂：字幕進常談**。OPUS OpenSubtitles 繁體字幕清理後的詞頻，併進常談的計數，建第三張口語表 T3。會意不動。

有訊號才開會意的重訓片（3 臂 × 3 種子，另寫登記）。這一頁在任何 SUB-0 的數字之前 commit。

修訂二（2026-10-22，任何數字之前；plan-verifier 第二次 REVISE）：A 臂改用 E-A 三個種子已匯出的權重並釘雜湊、A1／A2 分開選格與判讀並加條件 0、A 臂排除和訓練文字重疊的列。

修訂一（同日；第一次 REVISE）：基準那一跑的指令與四個錨點、A 臂以出貨權重那一跑算 C0、T2 先重建核對、T3-½ 改成抽一半、清理程式的來源、判讀集合不另外排除列。

探索片：只用調參層（chatclause、cvtune-clean）、開發層（discordtune）與回歸層集合；不碰判讀集與保留集；不改核心與 App；不出貨。

## 基準 C0＝現行出貨

會意 SJ-SR-6-14M ＋ 常談 T2（`2984eeb5…`，P4d 那一格：μ 0.5、α 0.5、軟閘門 T 1.0）＋ 讀音通道項（P5：lex、ν 1.0、c 4）；δ 0.25、τ 2。

**基準那一跑**（每個集合一次，和 P5 相同）：`shanjie-eval --lm data/lm/bigram.sjlm --profile chat --context --packs acg --tinylm data/lm/tinylm.sjtl --rows <集合> --dump D --dump-words W --rowstats R --tinylm-scores S`，**不帶** `--colloquial-core`（這一跑只有會意，就是 `p5.py` 的「SHIP」對照）。

**錨點**（不符就停）：

1. 離線的 SHIP 對照（不加常談、α 0.3）逐列等於上面那一跑的選字與 rowstats：`p5.py` 的 `check_anchor`。
2. 離線的 C0（P4d 那一格＋通道項 lex／1.0／4）對上面那一跑的改對／改壞，等於 P5 記錄的數字：chatclause 126／27、discordtune 88／34、cvtune-clean 49／12（`p5.py --cell lex,1.0,4 --clause report` 印的數字，main 對照）。
3. 離線的 C0 等於核心：帶 `--colloquial-core data/lm/colloquial.sjlm` 的 CLI 每列選的候選，等於 `p5.py --cell lex,1.0,4 --out-picks` 的選字（`docs/contracts/reading-channel.md` §0 的同一個核對），在 cvtune-clean 與 chatclause 各跑一次。

  種子 20261012 的 A1、A2 是 S7f 第二輪（修過「互助客棧」那一次）的權重；其他種子在 `seeds/seeds.sha256` 裡（main 核對過）。完整雜湊寫進這一片的 `weights.sha256`，和這一頁一起 commit。
- **和訓練文字重疊的列**：A1、A2 的訓練文字包含部分評測句（S7f 量過 discordtune 有 865 列整句出現在原句裡）。打分之前，在 VM 上用 `experiments/s7f-corpus/discord_overlap.py --rows <集合> --corpus chat-a2.txt --rows-out <列號檔>` 算 chatclause、discordtune、cvtune-clean 的重疊列（`chat-a2.txt` `dbfbe7ee…` 是 A2 的訓練文字，含 A1 的真人口語）。

- **打分**：
  - 權重本來就是出貨檔的形式（方法論 10-19），不重新匯出。
  - 每份 `.sjtl` 照「基準那一跑」的指令再跑一次（只換 `--tinylm`），產它自己的 dump 與 `--tinylm-scores`。n-gram 的候選與它無關，所以兩跑的 dump 與 dump-words 必須逐位元組相同，不同就停。
  - 新權重的雜湊不等於 `PAIRED_TINYLM_SHA256`，CLI 不會加常談與通道項，所以融合一律走 `p5.py` 的離線路徑。
  - C0 一律由出貨權重那一跑算（錨點 1–3 只在那一跑上做）；A 臂的格用新權重的分數算，和 C0 的最後選字逐列比。
- **格點**（事先固定，24 格，P4d 的格點）：μ ∈ {0.15, 0.25, 0.35, 0.5} × α ∈ {0.3, 0.5} × 閘門 ∈ {無, T 1.0, T 0.5}。常談用 T2，讀音通道項固定 lex／1.0／4，δ 0.25、τ 2。

## T 臂：字幕進常談

- **來源**：OPUS OpenSubtitles v2018 `mono/zh_tw.txt.gz`。只用這一份；v2024 `zh_TW` 簡體混入 22–38%，這片不用。下載後記 SHA-256，`LICENSES/data.md` 的研究語料列加一列並附 OPUS 的引用要求。原文不進 repo。
- **清理**：沿用 `experiments/p2-data/clean.py` 的順序，加三道過濾。每一步印計數與觸發最多的前 20 個樣式。
  1. 切句（`。！？!?` 與換行，不切逗號）。
  2. 去 cue 開頭的「-」與引號。
  3. 只留 4–40 個漢字、漢字比例 ≥ 70% 的句子。
  4. 去網址、信箱、帳號、電話與程式碼樣式。
  5. 新加：去含假名的句子。
  6. 新加：去 ≥ 30% 漢字不在詞庫的句子（亂碼）。
  7. 新加：去含 ≥ 2 個英文字的句子（中英並列）。
  8. 去含簡體專用字的句子（`TRAD_SIMP_ONLY`）。
  9. 去含 invade 詞的句子（兩字以上，和 S7f 生成句同一條規則）。
  10. 去重（NFKC、去空白、折疊大小寫）。
  11. 洩漏防護：`tools/holdout_guard.py` 加 P2 的 `Guard`，比對評測集、調參集、判讀集與保留集，含 4 字以上的包含比對。命中的句子丟掉（只回丟掉的句數與每個集合命中的列數）。判讀的集合不再另外排除列。
- **校對**：main 從清理後的句子抽 300 句（固定種子）看殘留（簡體、亂碼、英文、斷句錯）。
- **T2 重建（錨點 4）**：在 Windows 機器照 `docs/releases/sj-cl-1-68k.md` 的兩個指令重建 T2：
  - 輸入：`counts-colloquial3.pkl`（`work/modelv6/`，SHA-256 前綴 `1e7a15ef`）、兩份計數詞表 `acg-count.tsv`（`e8757303`）與 `names-count.tsv`（`5c14a359`，同一個資料夾）、口語池 `pool.tsv`（hermit `shanjie-cache/p2-public/`，`19fdc474…`）。每個輸入先核對雜湊。
  - 用 `build_counts_text.py` 從 `pool.tsv` 重產 `counts-pool.pkl`，再 `build_lm.py --corpora counts-colloquial3.pkl:1 counts-pool.pkl:1`。結果的 SHA-256 必須等於 `2984eeb5…`。
- **T3 表**：字幕清理後的句子用同一個 `build_counts_text.py` 指令（同樣的兩份計數詞表）計數成 `counts-subs.pkl`，再建兩張表：
  - **T3-1**：`build_lm.py --corpora counts-colloquial3.pkl:1 counts-pool.pkl:1 counts-subs.pkl:1`。
  - **T3-½**：字幕句子只留 SHA-256(句子的 UTF-8) 第一個位元組 < 128 的那一半（固定、可重現），照 T3-1 的指令計數、建表。字幕的句數遠多於公開口語池，全部放進去可能壓過原本的來源，所以另加這一張。`build_lm.py` 只吃整數權重，所以用抽一半代替權重 ½。
- **格點**：同 A 臂的 24 格 × {T3-1, T3-½}，共 48 格。會意用出貨的 SJ-SR-6-14M，讀音通道項固定。

## 選格（只在 chatclause，n 5,761；A1、A2、T 三臂各自選、各自判）

- 每一格對 C0 算改對、改壞與 U2＝改對 − 2×改壞。
- **T 臂**：在 U2 > 0 的格（24 格 × {T3-½, T3-1}）裡取 U2 最大的一格。同分時依序取：淨值大的、T3-½、μ 小的、閘門照「無、T 1.0、T 0.5」、α 0.3。
- **A1、A2**（分開選，A0′ 不選格；用排除重疊列後的 chatclause）：每一格有三個種子的 U2。只看三個種子 U2 都 > 0 的格，取三個種子 U2 中位數最大的一格。同分時依序取：最小值大的、μ 小的、閘門照上面的順序、α 0.3。判讀用那一格裡 U2 是中位數的那個種子。
- **A 臂另有條件 0**：選中的那一格，這一臂三個種子的 U2 最小值，要大於 A0′ 三個種子在同一格的 U2 最大值（只換種子與平台就能有的差，不算語料的效果）。
- **沒有合格的格，或 A 臂條件 0 不過 → 那一臂照登記不過**，不跑 discordtune 與後面的條件。

## 判讀（每臂一格，全部對 C0 的最後選字；事先寫死）

照 10-20 第三次放寬的出貨標準：

| # | 條件 | 集合 |
|---|---|---|
| 1 | 不顯著變差（精確 McNemar p ≥ 0.05 或淨值 ≥ 0），而且改壞 ≤ 26 或改壞÷改對 ≤ 0.6 | discordtune 聊天：T 臂 n 4,958；A 臂排除重疊列後 n 4,093 |
| 2a | 回歸層：逐列相同，或改壞 ≤ 2 且淨值 ≥ 0 | 打字測驗聊天；dev302 聊天只報，逐列標類別 |
| 2b | Δtop1 的 90% 配對 bootstrap 下界 ≥ −1.0 個百分點 | cvtune-clean 聊天（n 3,286；A 臂排除重疊列） |
| 3 | 淨值 > 0，而且改壞÷改對 ≤ 0.6 | 錯字回報（前 154 列，聊天，不帶學習檔） |

- 書面設定不受影響：常談與讀音通道項只在聊天設定生效，A 臂也不換書面的會意。所以這片只判聊天。A 臂的書面在決定會意重訓片時另量。
- 四條全過：報給維護者。下一步是「沒看過的判讀集確認一發」（chatjudge-3，十一月），A 臂另外要先補齊三個種子。
- 任一條不過：寫「照登記不過」，和維護者討論，不結案。
- **只報**：
  - 每臂的單獨挑對率與留住率（E-A 的診斷表）、error ratio、U2。
  - A0′ 三個種子在 A1、A2 選中那一格的 U2 與四條的數字，用來把「只換種子與平台」和「加語料」分開。
  - A 臂三個種子的範圍、整個集合（不排除重疊列）的數字。
  - T 臂的 T3 表大小（詞彙、詞對數）、記憶體的推算（不量 App）。
- 看過任何數字之後，不改格點、選格規則與門檻。

## 預算、停止條件、範圍外

- **預算**：
  - T2 重建與 T3 建表在 Windows 機器（計數檔在那裡），約 1.5 小時。
  - 打分、選格與判讀在 GCP c4d VM，≤ 6 小時：A 臂打分 2、選格與判讀 1.5，其餘留給重跑。同一個比較的所有臂在同一台、同一種 CPU 上跑；私人集合的傾印與分數檔跑完就刪（`trap … EXIT`）。
  - 不用 Colab。
  - executor 1–2 回合（兩支工具）。
  - main 校對 300 句約 1 小時。
  - 超過 1.5 倍就停下來問。
- **停止條件**：
  - 錨點 1–4 任何一個對不上，或任何一個輸入檔（含 9 份權重）的雜湊不符、找不到。
  - discordtune 和 `chat-a2.txt` 的重疊不是 865 列。
  - A 臂兩跑的 dump 不同。
  - 字幕清理後少於 400 萬漢字，或 300 句裡的殘留 > 2%。
  - 洩漏防護跑不起來。
  - 私人句子被帶回 Mac。
  - 用到判讀集或保留集。
- **範圍外**：
  - 會意的重訓（另寫登記）。
  - v2024 與 raw zip 接 cue。
  - 簡轉繁。
  - 改核心或 App、出貨。
  - 經典台詞詞包（另一片產品契約）。

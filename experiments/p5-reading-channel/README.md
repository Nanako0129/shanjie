# P5：讀音通道項 P(讀音｜字詞)（探索；2026-10-21 登記）

起因（維護者 2026-10-21）：錯字回報第 140 列「變快」在 App 選成「便會」。「會」讀ㄎㄨㄞˋ只出現在「會計」這類詞，但現在的分數只看字詞接得順不順（P(會｜便) 很高），不看「這個字讀成這個音的機率」。維護者的想法：每個讀音要和真實字詞連接的機率比對，「會」讀ㄎㄨㄞˋ的機率應該很低。研究紀錄同日一節量到：140 在前文「否則」離線也選「便會」，加常談（P4d 的口語項）時在 5 種前文下選「便會」。這一頁在任何 P5 的數字之前 commit。

和做過的不同：「讀音整類（B ≡ P2）」結案的是把讀音餵給小模型（同一組候選讀音都一樣，對排序是常數）；這一項是 P(讀音｜字詞)，每個候選的字不同，值就不同。「讀音計數 B」（同日重開，排在後面）要從語料按讀音重新計數、卡在語料的讀音標注；這一片先用詞庫本身按讀音給的分數，不用重新標注。

探索片：只用調參層（chatclause、cvtune-clean）、開發層（discordtune）與回歸層集合，不碰判讀集與保留集；不改核心與 App，不出貨。

## 做法

- **P(讀音｜詞)**：詞庫（引擎載入的那幾個檔：`mcbpmf-data.txt`、`overlay-add.tsv`、`sandhi-add.tsv`、acg 詞包、`names-add.tsv`；同一個 (讀音, 詞) 取最大分數，`experiments/diag-near-miss/d23.py` 的 `load_lex_scores`）裡，同一個詞的各讀音分數 s 換成 10^s 再正規化：P(r｜w) = 10^s(r,w) ÷ Σ_r' 10^s(r',w)。只有一種讀音的詞 P = 1。
- **通道項**：候選路徑上每個詞 w 和它在這一列的讀音 r（照路徑的分詞把這一列的音節依序切給每個詞），ch = Σ_w max(log10 P(r｜w), −c)；c 是懲罰上限（詞庫很多罕用讀音是地板值 −6.8，不是真的頻率，上限防止它一票否決）。詞庫找不到 (r, w) 的詞，P 照 1 算（不懲罰），並計數報告。
- **評分**：和 P4d 同一層、n-gram 第一名當錨點（`experiments/p4d-colloquial/p4d.py` 的 `final_index` 加一項）：ll_eff_i = ll_i + (ν/α)·(ch_i − ch_0) [+ 常談的口語項，照 P4d 那一格]，再照出貨的 `pick`（τ 2、δ 0.25）。常談不加時 α 0.3（出貨）；常談加時 α 0.5、μ 0.5、閘門 T 1.0（P4d 確認過的那一格）。
- **格點**（事先固定，24 格）：ν ∈ {0.1, 0.25, 0.5, 1.0} × c ∈ {1, 2, 4} × 常談 ∈ {不加, 加}。
- **對照**（不參與選格）：ν 0、常談不加＝出貨（錨點：逐列等於 CLI 的選字與 rowstats，另有 P4d 的設定錨點 discordtune 107／26、chatclause 111／26）；ν 0、常談加＝P4d 那一格（要等於 P4d 的 113／37、74／43）。
- 資料：每個集合用 CLI 的出貨設定跑一次（`--profile chat --context --packs acg --tinylm`，加 `--dump --dump-words --rowstats --tinylm-scores`），其餘離線算。

## 選格（只在 chatclause，n 5,761）

- 對出貨最後選字，在「改對 − 2×改壞 ≥ 0」的格裡取「改對 − 2×改壞」最大的一格；同分取淨值大的，再取 ν 小的，再取 c 大的（懲罰較寬），最後取常談不加。

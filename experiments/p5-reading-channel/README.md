# P5：讀音通道項 P(讀音｜字詞)（探索；2026-10-21 登記）

起因（維護者 2026-10-21）：錯字回報第 140 列「變快」在 App 選成「便會」。「會」讀ㄎㄨㄞˋ只出現在「會計」這類詞，但現在的分數只看字詞接得順不順（P(會｜便) 很高），不看「這個字讀成這個音的機率」。維護者的想法：每個讀音要和真實字詞連接的機率比對，「會」讀ㄎㄨㄞˋ的機率應該很低。研究紀錄同日一節量到：140 在前文「否則」離線也選「便會」，加常談（P4d 的口語項）時在 5 種前文下選「便會」。這一頁在任何 P5 的數字之前 commit。

和做過的不同：「讀音整類（B ≡ P2）」結案的是把讀音餵給小模型（同一組候選讀音都一樣，對排序是常數）；這一項是 P(讀音｜字詞)，每個候選的字不同，值就不同。「讀音計數 B」（同日重開，排在後面）要從語料按讀音重新計數、卡在語料的讀音標注；這一片先用詞庫本身按讀音給的分數，不用重新標注。

探索片：只用調參層（chatclause、cvtune-clean）、開發層（discordtune）與回歸層集合，不碰判讀集與保留集；不改核心與 App，不出貨。原登記（`427fb611`）的做法、格點、選格與判讀已被下面的修訂一取代。

## 修訂一（2026-10-21，登記集合的任何 P5 數字之前）

- **為什麼改**：
  - 程式審查量到：照原登記用 softmax 正規化，詞庫裡 13,256 個多讀音的詞有 9,404 個各讀音同分。這些詞不管打哪個讀音都被扣固定的 log10(k)（「了」「個」−0.301、「什麼」−0.602），扣的是「有幾個讀音」，不是「這個讀音罕不罕用」。
  - 研究顧問（Argon，報告在維護者本機，不進 repo）量到：單字的罕用讀音大多是佔位的地板值 −6.8，其中也包括常用讀音（「長」ㄓㄤˇ、「得」ㄉㄜ˙、「著」ㄓㄨˋ），照原式會被當成萬分之一重罰；多字詞的多讀音 99.9% 是變調或輕聲的同義變體。
- **揭露**：
  - 顧問在這次修訂之前，已經在公開集合離線跑過原登記的 24 格與下面兩種估法：dev302、錯字回報、打字測驗、第 140 列的 56 種前文、probe，以及舊保留集挑戰集。
  - 所以判讀第 2a 條（打字測驗）與第 3 條（錯字回報）的集合，對這兩種估法都**不是沒看過的**。這兩條照出貨標準留著，當回歸檢查。
  - 估法的選擇在 chatclause 做，不靠這兩份集合。出貨之前仍要在沒看過的判讀集確認一發。
- 和原登記不同的只有本節列的幾點；預算、停止條件、範圍外照舊（見最後一節）。

## 做法

- **通道項只算單字詞**：候選路徑上每個單字詞 w，和它在這一列的讀音 r（照路徑的分詞，把這一列的音節依序切給每個詞）。
  - 多字詞一律 0，因為它們的讀音已經綁定詞義。
  - 詞庫找不到 (r, w) 的單字照 0 算，並計數報告。
  - ch = Σ_w max(log10 P(r｜w), −c)，c 是懲罰上限。
- **兩種估法**，都對該字最常見的讀音取相對值：主讀音與跟它同分的讀音都是 0，罕用讀音才是負的。
  - **lex**：log10 P(r｜w) = s(r, w) − max_r' s(r', w)。s 是引擎載入的詞庫分數（`experiments/diag-near-miss/d23.py` 的 `load_lex_scores`，同一個 (讀音, 詞) 取最大）；r' 走 w 在這份詞庫裡的所有讀音。
  - **mc**：先算 M(r, w) = 10^s(r, w) + Σ 10^s(u)。加總走過 `data/lexicon/mcbpmf-data.txt` 每個至少兩字的詞 u，以及 u 裡每個「字是 w、對應音節是 r」的位置（一個位置加一次）；s(u) 是 u 的分數，同一個 (讀音, 詞) 在檔內出現兩列時取最大的一列、只算一次（和 d23 讀引擎詞庫的規則相同；檔內有 5 個兩字詞重複一列 −8.0，影響約 10⁻⁸）。
    - log10 P(r｜w) = log10 M(r, w) − max_r' log10 M(r', w)，r' 同樣走 w 在引擎詞庫裡的讀音。
    - 這是「這個字在詞庫各詞裡用這個讀音的機率質量」，用來補單字的 −6.8 佔位值。
    - 例（顧問量）：「長」ㄓㄤˇ −0.13 → 相對值約 0，「會」ㄎㄨㄞˋ 約 −2.4，「累」ㄌㄟˊ 約 −1.5。
  - 不加 reading-aware A1 的 44 字輕聲表：那是解碼層的另一片。
- **評分**：和 P4d 同一層，n-gram 第一名當錨點（`experiments/p4d-colloquial/p4d.py` 的 `eff_ll` 之後再加一項）。
  - ll_eff_i = ll_i + 常談的口語項（P4d 那一格：μ 0.5、α 0.5、閘門 T 1.0）+ (ν/α)·(ch_i − ch_0)；
  - 再照出貨的 `pick`（τ 2、δ 0.25）。
- **基準是 P4d 那一格**：常談（`docs/contracts/colloquial-term.md`）會比任何 P5 的產品片先出貨，所以 P5 量的是「加在常談上面」。不加常談的格不進格點。
- **格點**（事先固定，24 格）：估法 {lex, mc} × ν {0.1, 0.25, 0.5, 1.0} × c {1, 2, 4}，全部加常談。
- **對照**（不參與選格，不符就停）：
  - ν 0、不加常談＝出貨。要逐列等於 CLI 的選字與 rowstats（`p4d.check_anchor`），另有 P4d 的設定錨點：discordtune 107／26、chatclause 111／26。
  - ν 0、加常談＝P4d 那一格。對出貨的改對／改壞要等於 P4d 記錄的數字：chatclause 113／37、discordtune 74／43、cvtune-clean 45／17、打字測驗 0／0、錯字回報（前 154 列）17／4、dev302 9／2。
- **資料**：每個集合用 CLI 的出貨設定跑一次（`--profile chat --context --packs acg --tinylm`，加 `--dump --dump-words --rowstats --tinylm-scores`），其餘離線算。

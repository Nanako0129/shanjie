選字的修正：解碼時不再太早丟掉「最後一個詞不同」的斷法。

- **選字**：
  - 下一個詞接得順不順，要看前面最後一個「詞」是什麼。v0.4.2 以前，解碼器在每個位置，同樣的字只留分數最高的一種斷法，可能把後面接得比較順的那一種提早丟掉。例如書面設定（非聊天 App）打 `ㄒㄧㄚˋ ㄌㄞˊ ㄈㄣ ㄒㄧ`：單看前兩個字，「下來」比「下｜來」好，留下了「下來」；但接「分析」時是「來→分析」比較順，結果整句出現「夏來分析」。
  - 這一版起，同樣的字、最後一個詞不同的斷法會分開保留，這句變成「下來分析」。
  - 評測（v0.4.2 → v0.4.3）：公開評測集與保留集，聊天、書面兩種設定，每個集合改對的列數都不少於改壞的列數；立法院發言語料（lytune）四種組合都顯著變好。數字在 `docs/research-log.md`（2026-10-14 解碼器合併一節）與 `docs/benchmark.md`。
  - 名單裡同樣的句子只列一次之後，n-best 變短，有幾個集合「正解在前 64 名」的列數少了 1–4 列（例如 typing76 聊天 76 → 75）；第一名與語意校正用的前 8 名不受影響。
  - 每鍵延遲（dev302 重播的 p95）v0.4.2 3.3 ms、v0.4.3 4.0 ms；記憶體兩版都約 290 MB（`docs/benchmark.md`）。
- 其餘是評測工具、研究紀錄與文件的更新。

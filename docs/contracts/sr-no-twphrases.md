# 會意的訓練文字不套台灣用詞轉換（SR-TW）

狀態：**修訂五**（2026-11-04，任何會意分數之前）。修訂五：選種子時中位數平手取種子號碼最小的（量測腳本審查 A5 指出沒有事先登記的平手規則）。修訂四：常談重建的前提不成立（階段 4 的計數本來就沒套 TWPhrases），維護者選「不重建常談，180 照樣要對」，§2.4 改寫、常談相關的步驟與停止條件拿掉。修訂三：收尾審查指出常談是共同原因，main 量過（研究紀錄同日），維護者選「常談一起重建」，加 §2.4。修訂三的收尾審查 REVISE 兩項照最小修改：常談的方法核對（不帶旗標重建要等於 `81c2470d…`）與常談沒生效的停止條件。第五輪審查 REVISE 兩項照最小修改：常談計數的機器、平行方式與預算；口語計數一律重數。修訂一：plan-verifier 第一次 REVISE 的六項照改（產品的常談配對雜湊、摘要行核對、集合鎖定、第二份來源、判讀集正解的轉換、確認前的診斷）。修訂二：第二次 REVISE 的一項照改（179、180 的判準改成整句打對）。維護者 2026-11-03 選擇題「開片重訓會意（推薦）」。

## 1. 為什麼

- 錯字回報第 179、180 列（「權限加好了」「也加上權限了」）：n-gram 的第一名是「權限」，會意把它改成「全線」。
- 原因量到了（2026-11-03，研究紀錄同日一節）：
  - 會意 SJ-SR-7-15M 的訓練文字由 `experiments/s7a-tinylm/prep.py` 經 `build_counts.article_runs`、`text_runs` 產生，這兩個函式的 `trad_tw_phrases` 預設是 True，**繁體句也套 OpenCC `TWPhrases.txt`**（819 條）。其中一條是「權限 → 許可權」，訓練文字裡的「權限」因此全部不見。
  - 會意對兩個寫法的分數（對數機率，越大越像）：只有兩個字時「權限」−8.97、「全線」−4.59；前面接「管理員」時 −14.35、−10.87。原始語料裡「權限」2,255 次、「全線」1,309 次。
  - 通語 SJ-LM-7 §2.2 已經把計數改成繁體句不套 `TWPhrases`（`build_counts.py --no-trad-tw-phrases`），會意的前處理沒有跟著改。
- 影響不只這一個詞：819 條裡凡是會改寫台灣繁體原文的（例：「插件 → 外掛」「聯繫 → 聯絡」），會意都只看過轉換後的寫法。

## 2. 做什麼

### 2.1 前處理

- `prep.py` 的 `runs`、`text` 兩個子指令加 `--no-trad-tw-phrases`：維基與每一行口語都用 `trad_tw_phrases=False` 呼叫 `wiki_runs`、`text_runs`，`--holdout-guard` 的 `guard_matcher` 也傳同一個值（`build_counts.guard_matcher` 已支援；保留集的比對要涵蓋實際訓練的那種寫法）。不帶旗標時行為與輸出逐位元組不變。
- 簡體句照舊全套（`convert()` 的既有行為：簡體句一律套 `TWPhrases`）。
- 單元測試（`experiments/s7a-tinylm/test_prep.py`）：帶旗標時繁體句「權限」「插件」保留、簡體句照舊轉；guard 拿到同一個值；不帶旗標時與現行輸出相同。
- **口語池換成 §2.2 重產的那一份**（`colloquial-train.txt` `eb905936…`，86,802 句）：SJ-SR-7 用的 `3e833d06…` 本身就是套過 `TWPhrases` 的文字，只改 prep 救不回池子裡的「權限」。`prep.py` 的 `EXPECTED` 在帶旗標時改核對 `eb905936…`，不帶旗標時照舊核對 `3e833d06…`。
- 其他輸入照 SJ-SR-7 R1（研究紀錄 2026-10-26「階段 5——會意 SJ-SR-7 訓練開跑」）：維基 20 萬篇 ×1、口語池 ×5、`synth.txt`、g0v ×5、PTT 推文 ×5、PTT 內文 ×1、字幕 ×1，新來源用同一份凍結的 `dedup-final`，雜湊逐一核對。每一步都開 `--holdout-guard`。

### 2.2 訓練

- 配方照 SJ-SR-7 R1：大小 M（6 層、寬 384、6 頭、前文 64），步數規則、學習率排程同；字表照「出現 ≥ 5 次」在新的訓練文字上重算。
- Colab G4，三個種子 20261012、20261018、20261019，**一次跑一個種子**（2026-10-26 實測同時跑三個總吞吐沒變）；`prep.py text --procs` 平行前處理。
- 每訓練完一份就下載回 Mac、核對雜湊；driver 定期對 runtime 送請求，避免被當成閒置收回。
- 預算（推估，依 2026-10-26 的實測）：前處理約 3 分鐘，R1 每個種子 4,268 秒，三個種子依序約 3.6 小時；GCP 量測（選種子、出貨標準、檢查集、wikijudge6）約 1 小時，188 第二份來源約同長。超過推估的兩倍就停下來查。

### 2.3 匯出

- `export_sjtl.py --type int8` 匯出 SJTL0004，`--ngram-model`、`--kn-side` 綁現行出貨的 bigram 與 kn；標準檔、`--levels` 四組與聊天、書面的 α、τ、δ 從現行出貨 `data/lm/tinylm.sjtl` 的檔頭照抄。
- **方法核對**：同樣的參數從會意 SJ-SR-7-15M 的 npz（r1-s20261018）重新匯出，結果要和現行出貨 `f7d0ac63…` 逐位元組相同，不同就停。

### 2.4 常談不重建（修訂四，2026-11-03）

- 修訂三原本要重建常談，前提是常談 SJ-CL-2-69K 的口語池計數沒帶 `--no-trad-tw-phrases`。實作前讀到階段 4 的遠端腳本：那次計數**本來就帶了**這個旗標（C1 `81c2470d…` 就是出貨檔），`docs/releases/sj-cl-2-69k.md` 的指令漏寫，這一片一併更正。出貨常談表的單字次數「權限」24、「全線」4、「許可權」0，重建只會得到同一個檔。
- 維護者選「不重建常談，180 照樣要對」：常談沿用 SJ-CL-2-69K；第 180 列只在常談也生效時才錯，比較可能來自常談那一項在融合裡的算法（拿口語頻率和通語比）〔推論，未量〕。新會意可能自己蓋過；§4 第 3 條 180 仍是關卡，不過就照登記不過，再查常談的融合項（另一片）。
- 常談仍要和新會意配對：`PAIRED_TINYLM_SHA256` 換成新 `.sjtl` 的雜湊（§8），常談檔本身不變。

## 5. 確認一發（維護者 2026-11-03 選「書面 wikijudge6 判不變差」）

- 聊天判讀集每月最多抽一份：CE3 的 cjudge-1 在 2026-11-01 用掉並退役，下一份最早 2026-12-01。這一片的預期效果集中在少數詞，在判讀集上很可能不顯著。
- **新建 wikijudge6**：照 wikijudge5 的建法，`build_tune.py --part wiki --wiki-range 335000 340000 --wiki-name wikijudge6`（同一份 dump），列數與 SHA-256 在任何分數之前記進研究紀錄；之前沒有任何數字。用過退役。
- **正解的轉換**：`build_tune.py` 產生的正解（與從正解取的讀音）預設也套 `TWPhrases`（`bc.convert` 預設 True），例如原文的「權限」在正解裡是「許可權」；這會系統性地不利於這一片的候選。所以 wikijudge6 的正解用 `trad_tw_phrases=False`（`build_tune.py` 加 `--tune-no-trad-tw-phrases`，只影響 `--part wiki` 的參考句；單元測試：繁體句的「權限」保留、不帶旗標時輸出不變）。
- **既有集合的正解只報不改**：cvtune-clean、wikitune-clean 已鎖定、不重建。另報一項診斷：這兩份裡正解在 `convert(s)` 與 `convert(s, trad_tw_phrases=False)` 之間不同的列數（從原始句算），與判讀種子在這些列上的改對／改壞數（只報，不參與判讀）。
- **確認前的診斷**：§4 第 1～3 條過了之後、wikijudge6 打分之前，用 §4 已有的分數檔印書面標準與聊天標準的四項診斷（單獨挑對率、留住率、融合上限、oracle），與確認登記一起 commit。
- **主判讀**：判讀種子對現行出貨，書面、標準檔，wikijudge6 的 Δtop1 的 90% 配對 bootstrap 下界 ≥ −1.0 個百分點（不變差）。保守、積極兩檔與聊天設定只報。
- 聊天這一邊不另做確認：依 §4 的出貨標準四條與錯字回報 179、180。
- 這是對「探索片過關後在沒看過的判讀集確認一發（淨值 > 0、精確 McNemar p < 0.05、改壞÷改對 ≤ 0.65）」的這一次例外，記在 `decisions.md`；一般規則不變。
- 確認一發只在 §4 第 1～3 條都過之後跑；不過＝這次確認不成立，不換種子、不重建 wikijudge6 再試。

## 6. 停止條件

- 任何輸入的雜湊不符（訓練輸入、§4 表裡每一個集合的雜湊或列數）、§2.3 的方法核對不同：停，修好再跑，不算一次判讀。
- 任何一次執行的摘要行不符 §4 的標記核對：停，不算一次判讀。
- GCP 與 188 的 rowstats 不同：停下回報。
- D1 新訓練文字裡「權限」仍是 0：改動沒有生效，停。
- §4 判讀第 1～3 條任一不過：照登記不過，報數字與逐列結果，出選擇題；不在同一次判讀裡換種子、改門檻或改集合。

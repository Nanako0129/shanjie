# 契約：model-v5 與 classes-v3（詞包詞進斷詞詞彙；沒見過的疊加詞扣分）

狀態：收尾審查的最後一項照建議修正後，使用者 2026-10-10 決定直接開工（§6）。最終檔與修訂見 §9（加法計數、衝突詞與片段不進計數、舊詞沿用 classes-v2 的詞類、扣分維持 1.0）。使用者 2026-10-10 決定：宿儺這類問題用重建模型根治，和 ACG 詞包 A2、設定視窗一起出 v0.4.0（不發 v0.3.1）。

## 0. 起因與根因（量過的）

- **使用者回報**：
  - 「宿儺」打成「素娜」，詞包已收、仍贏不了；
  - 「沙漏會有玻璃膜擦聲」「那些越角」「黴變」：冷門的疊加詞（維基詞典標題）蓋過想打的字。
- **根因盤點**（研究紀錄 2026-10-10，A2 分支的 30,048 詞詞包）：
  - 詞包 30,399 列全部不在語言模型裡。解碼分數對沒見過的詞，就是「封頂後的詞條分數＋每個設定一個常數」，詞包詞的詞條分數是同長度基底詞的第 25 百分位減 1.0（兩字一律 −8.17）。
  - 沒見過的詞在三處吃虧：自己的詞條分數；自己的接續（`prob_c` 對沒有 vocab id 的詞不走詞類項，`core/src/lm.rs` 約第 316 行）；下一個詞的接續（前文是空的）。
  - 詞包詞 26.5% 輸。其中 88.7% 輸給常用字詞的組合（宿儺 → 素＋娜，「素娜」不是詞庫詞），99.9% 是輸在語言模型那一項。
  - 輸的比例看字數：兩字 98.7%、三字 38.9%、四字 7.9%、五字以上 2.6%。
- **現在的計數**（`experiments/s2/build_counts.py:303-304`）：斷詞用基底＋`overlay-add.tsv`，**不讀詞包**。疊加詞早就在斷詞詞彙裡。所以：
  - 重建、把詞包詞加進斷詞詞彙，能讓語料裡出現過的詞包詞（例如維基的作品與角色條目裡的名字）拿到真實的 unigram、bigram 與詞類。這是宿儺這一類的根治。
  - 擦聲、越角、黴變是語料裡**沒出現過**的疊加詞，拿的是「第 25 百分位減 `UNSEEN_OVERLAY_PENALTY`（1.0）」（`core/src/lm.rs:14-15`、`CappedLexicon::new` 約 495–518 行）。重建模型不會改變它們，要調這個扣分（§2.4）。
  - **〔更正 2026-10-10〕上一條的前提錯了**：這三個詞在 model-v3／v4 都有語料計數（擦聲 4、越角 3、黴變 12，main 用 `reference/proto/lm.py` 核對；PR #99 的 /code-review 先指出）。它們的分數走 min(檔案分數, log10(c/N))，不走沒見過的扣分，所以 §2.4 的扣分救不到這三列。扣分只作用在語料沒出現過的疊加詞與詞包詞。
  - 「零股」輸給「鈴谷」是語料裡股票用語少；「月繳」「根因」是缺詞。這三個不在這片（§5）。

## 1. 要做到什麼、怎麼看到

- 語料裡出現過的詞包詞，在模型裡有真實的機率與詞類；開詞包時，宿儺這類名字直接打得出來。
- 只有在 §2.4 的扣分被採用時：語料裡沒出現過的冷門疊加詞，不再輕易蓋過一般的字詞組合（§2.4 維持 1.0 時，這一條不宣稱）。
- 一般打字不退步（§3 的守門）。
- **怎麼看到**：
  - §3 的評測表與動漫集；
  - 使用者實機：打「宿儺」「乙骨憂太」，以及「沙漏會有玻璃摩擦聲」「那些月繳」（後者缺詞）。依 §0 的更正，這兩句不預期因扣分改善，只記結果。

## 2. 改動

### 2.1 計數：詞包詞進斷詞詞彙

- `build_counts.py` 與 `build_counts_text.py` 加一個選項 `--extra-lexicon FILE`（可以給多次）：把那個疊加層格式的檔（`讀音\t詞\t分數\t來源`）加進斷詞用的詞庫，和 `overlay-add.tsv` 同樣的方式（`ime.Lexicon` 的 overlay 清單）。沒給這個選項時，輸出和現在逐位元相同（單元測試）。
- 給的檔：A2 的 `data/packs/acg-add.tsv`。**前提**：A2（PR #96）先合併進 main，這個分支 rebase 到它之後才開始計數；計數時的 `acg-add.tsv` SHA-256 必須等於 main 上的（不同就停）。
- 語料、權重、選項照 model-v3（S2f 模型 F4）的配方，逐字照 `experiments/s2f/README.md` 的批次：維基 `build_counts.py --articles 200000 --procs 10 --expected`（×1；**不加 `--mw`**，那是使用者 2026-10-08 決定不出貨的 W2）、口語 `build_counts_text.py --expected` 讀 `colloquial-train.txt`＋`synth.txt`（×5）；`tools/build_lm.py` 的 `PRUNE=2`、`D=0.75` 不變。唯一的差別是多一個 `--extra-lexicon`。
- 在 192.168.123.188 跑，一律綁 P-core、絕對路徑。
- **輸入固定**（每一個都記 SHA-256，寫進研究紀錄的一張表：輸入、model-v3 的值、這次的值）（model-v3 的值取自 model-v3 建置那個 commit 的檔案，以及 188 上 `work/s2f4` 的紀錄）：維基 dump `zhwiki-20261001-pages-articles.xml.bz2`、`colloquial-train.txt`、`synth.txt`、`mcbpmf-data.txt`、`overlay-add.tsv`、OpenCC 表（含 `TWVariants.txt` `245b94eb…`、`STCharacters.txt`）、`acg-add.tsv`。除了 `acg-add.tsv`，這些資料檔都必須和 model-v3 那次相同。計數腳本的 commit 只記錄（S2w 之後加過 `--mw`，這片也加 `--extra-lexicon`），腳本行為是否不變由下面的重現核對與 `--extra-lexicon` 的單元測試把關。
- **重現核對**（先跑、不加 `--extra-lexicon`）：用同一套輸入重算一次計數，確認比較只會反映詞包的影響：
  - 口語計數（單一程序）：`counts-colloquial3.pkl` 的 SHA-256 等於 model-v3 的（`13d0ab5b…`，`docs/contracts/s2k-word-classes.md`）。
  - 維基計數：`build_counts.py` 用 `imap_unordered` 合併 10 個 worker，鍵的順序與期望次數的浮點加總順序每次不同，檔案位元組無法重現。所以改比內容：和 model-v3 的 `counts-200000.pkl`（`ca2f1361…`，在 188 的 `work/s2f4`）相比，鍵集合相同、`runs` 與 `articles` 相同、每個值的相對誤差 ≤ 1e-9。
  - 再用重算的計數跑 `tools/build_lm.py`。同一次、同一個 CLI 執行檔，兩邊都加 `--no-classes`、都不加 `--packs`：解碼重建的模型（不加指紋）與維護者本機的 model-v3（也不加指紋）兩邊，dev302、打字測驗、錯字回報，聊天與書面、加 `--context`；第一名逐列相同（兩邊的 `top1_sha256` 相同）。用 `--no-classes` 是因為詞類表綁模型雜湊，重建的模型位元組不同時 classes-v1 載不進來；不和歷史紀錄的雜湊比。模型檔位元組不同的話，記下差了幾個條目，但不以此為停止條件。
  - 任何一項不成立就停（輸入或腳本行為變了，比較會混進別的效果）。
- **覆蓋量測**（188 正式計數之前）：在同樣的 20 萬篇維基條目（照 `build_counts.py` 的取法與轉換）加口語兩個檔裡，數詞包詞至少出現一次的個數（n／30,048），以及「宿儺」「乙骨憂太」的出現次數，寫進研究紀錄（日期在計數之前）。`build_counts.py` 取的是 dump 順序的前 20 萬篇（最舊的條目），近年作品可能不在裡面；**「宿儺」是 0 次就停**，回報並問使用者（例如要不要換取條目的方式，那會改變整個語料，要另外量）。

### 2.4 沒見過的疊加詞扣分

〔2026-10-10 由 §9 取代：照選法會取 2.0，使用者決定維持 1.0。〕

- `UNSEEN_OVERLAY_PENALTY`（現在 1.0）在 model-v5 上掃 {1.0, 1.5, 2.0, 3.0}。
- **選法**（兩個人看同一張表會得到同樣的結果）：
  - 統計量：cvtune 與 wikitune、聊天與書面四格的 top1 合計（`tools/evalstats.py compare` 的 top1 新，基準＝同一個 model-v5 扣分 1.0）。
  - 候選：沒有被否決的值裡 top1 合計最高的；和 1.0 同分（差 0）就取 1.0。
  - 否決：cvtune、wikitune、dev302、打字測驗，以及動漫集（works、characters、charparts、recent，開詞包）任何一個集合、任何一種設定出現「配對檢定 p < 0.05 而且淨值為負」。
- 這個常數同時作用在沒見過的詞包詞上（語料沒出現過的名字）。所以要另外報開詞包時動漫集的變化。
- 2.1–2.3 與 2.4 分開量：先量「model-v5、扣分 1.0」對 model-v4，再量扣分的掃描。

### 2.5 順序、引用與釘選（照 model-v4 §3、§4 的兩個 PR）

順序固定如下，後一步用前一步的產物：

8. 以上全部通過後，**才問使用者**能不能建 Release；建好後下載回來核對雜湊，和第 3 步記的相同。

## 3. 驗收

### 3.1 評測表（照 repo `CLAUDE.md`「改到選字結果的改動」）

- 基準＝model-v4＋classes-v2；新＝model-v5＋classes-v3（扣分照 2.4 的結果）。
- dev302、打字測驗、錯字回報（當下列數），聊天與書面，**開詞包**（預設）各一行；不開詞包也各一行。
- Discord 調參集由 main 在本機跑，只貼表格數字。

### 3.2 守門與調參（cvtune、wikitune；不用 dev302 調）

- 照 methodology：cvtune、wikitune、dev302、打字測驗任何一格「配對檢定 p < 0.05 而且淨值為負」就否決。
- 2.4 的扣分只用 cvtune、wikitune 選；同分取 1.0（不改）。

### 3.3 動漫與名字

- `eval/dev/acg/*`（works、characters、charparts、recent）開詞包時的表；
- 「宿儺」在聊天與書面都是第一名；
- **詞包衝突重驗**：用 model-v5＋classes-v3 對合併後的詞包離線跑一次 `detect_collisions`（`tools/build_acg_pack.py`），報 (a)、(b)、(c) 各幾組。新的 (c)（詞包詞擠掉既有詞庫詞）或沒處置的 (a)、(b) 就停，問使用者。被 (c) 丟掉的詞不必重算計數：模型裡多幾個詞包已經沒有的詞，不影響解碼（它們不在詞庫裡，不會被列舉）。
- 詞包詞「輸」的比例按字數重量一次（同根因盤點的量法），寫進研究紀錄。這一項只報告，不設門檻。

### 3.4 固定探針

- 「大概十分鐘後到」兩種設定都對；
- s2f 的「竈門」、s2h 的「好吧」不退；
- `eval/probe/s2r-probe.txt` 照 s2r 的比法不退；
- 錯字回報裡的「沙漏會有玻璃摩擦聲」「那些月繳」記下結果（後者缺詞，只看「越角」是否還是第一）。

### 3.5 規模

- 模型 < 100 MB；
- 188 上每一批（重現核對的計數與正式計數各算一批）< 8 小時、記憶體 < 48 GB；
- 每鍵延遲照既有的 perf 測試。

### 3.6 收尾

- fresh verifier 照慣例跑一次保留集（新、舊各一次 `--set holdout --context --rowstats`，只回表格），在建 Release 之前；
- 指紋的私有核對由 main 做，照 model-v4 的標準：同一個模型加不加指紋，受影響的打字情境裡解碼與預測完全相同，只報「N 條；解碼 n 列、相同 n；預測 q 筆、相同 q」；
- 使用者實機（§1）。

## 4. 停止條件、預算、限制

- **停止條件**：
  - 守門否決；
  - 宿儺仍不是第一名（先回報原因再問）；
  - 重現核對任何一項不成立（口語計數雜湊、維基計數內容、重建模型的第一名，定義見 §2.1），或任何固定的資料檔雜湊和 model-v3 不同；
  - 覆蓋量測裡「宿儺」0 次；
  - model-v5 上冒出新的 (c) 或沒處置的 (a)、(b) 詞包衝突；
  - 一般集合的改壞列裡出現明顯的常用句退步（逐列列出、不調分）；
  - 188 超時或超過記憶體；
  - 下載回來的雜湊不符。
- **預算**：計數與建模由 main 在 188 跑；腳本改動（`--extra-lexicon`、單元測試）與 golden 重產交 executor 1 次＋修正 1 次。
- **限制**：
  - 建 Release 與刪 Release 都是對外動作，先問使用者；
  - agent 不讀 `eval/holdout`（verifier 照規則除外）、學習檔、`~/Library`、鑰匙圈、`~/side-project/shanjie-private`；

  - 在 model-v5 候選（A2 be628e9 的詞包；詞類表 classes-v3 候選；扣分 1.0–3.0）上，聊天與書面的第一名都還是「素娜」。
  - 原因（量過的）：它在語料裡的期望次數只有 2（覆蓋量測的原始字串是 7 次，其餘落到其他切法）。語料見過的疊加詞與詞包詞，分數會被壓到語料頻率：log10(2/1.46 億) ≈ −7.86，比詞包原本的 −7.17 還低。詞類項給它的發射機率也很小。所以「素＋娜」這種常用字組合仍然贏。
  - 結論：讓詞包詞進斷詞詞彙，只救得了語料裡出現夠多次的名字（角色名片段聊天 67→76、書面 71→81）。救不了宿儺這種罕見名字。
  - 罕見名字要另外找做法，例如詞包詞的分數下限，或不受語料頻率壓低；那要另寫契約。

## 8. 修訂二（2026-10-10）：加法計數

- **起因**：最終檔（詞包 677cb0db，§2.1 的「詞包詞直接進斷詞詞彙」）在守門被否決：wikitune 書面設定比 model-v4 少對 21 句（改對 30、改壞 51，p = 0.026，扣分 2.0；四種扣分都是顯著淨負）。使用者要出 model-v5，派 Fable 5.1 分析。
- **原因**（量過）：
  - 詞包裡的兩字片段在計數時吃掉常用字對。例如「萊＋恩」1,336 次變成 0 次（詞包詞「萊恩」1,445 次），「羽＋柴」562→0、「沃＋爾」2,508→0、「拉＋斯」11,964→2,849。
  - wikitune 與 cvtune 是不開詞包評測，這些片段打不出來，就輸給同音字（萊恩→來恩、羽柴→與柴）。不加詞類時，wikitune 書面改對 7、改壞 20。
  - 其餘改壞來自重新分群的差異。
  - 同一類兩字詞也是動漫進步的來源，所以用規則排除一部分詞包詞，分不開兩者。
- **改法**（`experiments/s2/build_counts.py` 的 `run_expected`，口語腳本同一個函式）：
  - 有 `--extra-lexicon` 時，每一段連續漢字算兩次期望次數。
  - lex0 是基底＋疊加層、不含詞包，它的全部單詞與二元組照收。
  - lex1 含詞包，只「加上」詞包詞的單詞，以及一端是詞包詞的二元組。
  - 詞包詞＝lex1 有、lex0 沒有的詞。lex0 切不開的段落整段不計，和沒有詞包時相同。
  - 所以不開詞包時，一般詞的計數和 model-v4 相同，只有含詞包詞的二元組讓前文的總數 t(v) 變大一點；開詞包時，詞包詞有自己的計數與詞類。
- **驗收與步驟**：
  - 單元測試：有詞包時，一般的單詞與二元組等於沒有詞包時；詞包詞的前後二元組加總等於它的單詞次數；沒有 `--extra-lexicon` 時輸出不變。
  - 188 用最終詞包（f5ab49a8，詞的集合和 677cb0db 相同）重算、加指紋、重新分群、建詞類表。
  - 扣分照 §2.4 重掃，守門與 §3 的表在新的最終檔上重做。守門仍被否決就停，回報使用者。

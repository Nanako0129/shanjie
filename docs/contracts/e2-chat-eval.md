## 0. 起因與使用者的決定（2026-10-12 晚上，選擇題；同一個 PR 寫進研究紀錄）

- 使用者：「eval 的題目或許才是問題」。Fable 的分析（研究紀錄 2026-10-12「評測的題目與計分」）：選值與判斷用的公開集合都不是聊天語域；「改壞 1 句 ≈ 改對 10 句」把量到的進步算成失敗。
- **使用者決定**：
  1. 計分改成「改對 − 改壞」（1:1）；語意校正要預設開，另外要求改壞率 ≤ 0.5%。
  2. 聊天評測集用**維護者自己的訊息**：Discord 個人資料包（維護者申請，下載後給路徑）與 Meta 官方匯出（Threads、Facebook、可能還有 Messenger；原本是 Threads 公開貼文由 Grok 抓，見 §7 最後一列）。
  3. **維護者 2026-10 起才主要用善解打字，之前用蘋果注音**。所以判斷只用 2026-09 以前的月份。
  4. **同意 main 逐句讀訊息原文、校對正解與讀音**，範圍是資料包的訊息資料夾與官方匯出裡自己的文字；內容會進到 session 的對話裡；repo 只記數字。
  5. 公開資料四組：
     - 立法院公報委員發言、維基錯字表：已取得，數字見 §2.2、§2.3。
     - SIGHAN 2013–2015、NTUML2021：等許可，這一片不做。
  6. S7g 的草稿不做，併入這一片。

這一片**只建評測與計分，並用它重判現有的設定**：不改核心的選字、不訓練、不出貨、不改出貨的值。

  - 欄位：n、top1 基準／新、改對／改壞、淨值、改壞率、改壞數 95% 精確上界、精確 McNemar p、CER、Δ 區間。

## 2. 資料

### 2.1 `chatclause`：維護者自己的聊天（私人資料，只有 main 在本機處理）

- **讀取範圍**：
  - Discord 資料包只讀**訊息資料夾**（每個頻道的訊息檔與索引），帳號、活動等其他資料夾不讀。
  - **Meta 官方匯出**（「下載你的資訊」，JSON；2026-10-12 修訂，見 §7）只開下面四個確切的相對路徑，每個都可以沒有，匯出裡的其他檔案（追蹤者、封鎖名單、按讚、搜尋等）一律不開，也不走訪資料夾：
    1. `threads/threads_and_replies.json`：`{"text_post_app_text_posts": [貼文]}`；一則貼文一列，文字是貼文自己的 `title`（有而且非空時），否則是 `media[0]["title"]`；時間是貼文自己的 `creation_timestamp`，否則是 `media[0]` 的。
    2. `facebook/your_posts__check_ins__photos_and_videos_N.json`（N 從 1 起，照這個檔名樣式）：每一則的 `data` 裡 `post` 字串用換行接起來，沒有就跳過；外層的 `title` 是 Meta 自己的句子，不用。
    3. `facebook/posts_on_other_pages_and_profiles.json`：文字是 `label_values` 裡解碼後標籤正好是「訊息」的 `value`。
    4. `facebook/comments.json`：`{"comments_v2": [...]}`，每個 `data[].comment` 一則，只留解碼後 `author` 等於維護者本人（`--self-name`）的；別人的留言只計數、不再讀；文字是 `comment["comment"]`，時間是 `comment["timestamp"]`（沒有就用外層的）；外層 `title` 不用。
    - 匯出的每個字串（鍵與標籤也是）都是 UTF-8 位元組存成 latin-1 碼位的亂碼，程式先還原再用。Messenger 這次沒有匯出，不讀。匯出是 Meta 原樣給的文字，所以原本「抽 10 則用網址核對原頁」的步驟取消。
  - **私訊排除與個資、密鑰過濾**（維護者 2026-10-12 選「排除私訊，再濾掉個資格式」，另加「token 也要過濾」，見 §7 最後一列）：
    - Discord 每個頻道資料夾先讀 `channel.json`，只用 `GUILD_TEXT`、`GUILD_ANNOUNCEMENT`、`PUBLIC_THREAD`、`ANNOUNCEMENT_THREAD`、`GUILD_VOICE`；`DM`、`GROUP_DM`、`PRIVATE_THREAD`、沒有 `channel.json` 或類型不認得的頻道整個跳過，不開它的訊息檔；各類型跳過幾個頻道會印出來。main 已在本機的匯出複本刪掉 DM、GROUP_DM、PRIVATE_THREAD 的資料夾與頻道索引 `index.json`；程式的過濾照樣要有、要測試。
    - 所有來源（Discord、Threads、Facebook 貼文與留言）的訊息，原文含下列任何一種就整則丟掉。每個來源的順序：沒有文字 → 含網址的整則排除（網址路徑裡的長英數字串算網址、不算 token）→ 去掉平台標記（只有 Discord：提及 `<@…>`、`<@!…>`、`<@&…>`、頻道 `<#…>`、自訂表情 `<:名稱:id>`、`<a:名稱:id>`、時間戳 `<t:…>`、`<id:…>`，各換成一個空格（成為斷句邊界：`我跟<@…>說好了` 變成「我跟」與「說好了」兩段；絕不因標記而丟整則）；它們帶 17–20 位數的 snowflake id，不是個資，不去掉的話會被電話與數字規則誤丟，使有提及與表情的聊天訊息被系統性排除）→ 個資與密鑰過濾（對去掉標記後的文字；標記以外的電話或 token 照樣丟）→ 程式碼排除 → 斷句，所以月份計數與機械計數不含被丟掉的訊息。被網址或個資丟掉的訊息也不會當下一則的前文。規則：電子郵件；電話樣式（8 個以上的數字，數字間可有空白、連字號、點或括號，含 09xx-xxx-xxx）；連續 6 個以上的數字；身分證樣式 `[A-Z][12]\d{8}`；token 或密鑰（`[A-Za-z0-9_\-+/=]` 連續 20 字以上而且同時有字母與數字；已知前綴 `sk-`、`sk_`、`ghp_`、`gho_`、`github_pat_`、`xox[abpr]-`、`AKIA`、`AIza`、`eyJ`＋base64（涵蓋 JWT）、`Bearer `；鍵含 token、secret、password、passwd、pwd、api_key、apikey（不分大小寫）的 key=value；PEM 標頭 `-----BEGIN`）。程式只印每個來源、每條規則丟了幾則，不印符合的文字。副作用：電話規則也會丟含 `2026-10-12` 這種日期的訊息（寧可多丟）。
  - 資料包留在維護者放的位置，不複製。衍生的列檔放 `~/side-project/shanjie-private/chat-eval/`（權限 700）。
  - 不進 repo、不上 Colab、不進任何訓練文字、種子、詞表或規則；agent 一律不讀。
- **月份與輸入法**：每則訊息依時間戳分月。研究紀錄的每月列數表有一欄「輸入法」：2026-09 以前是蘋果注音，2026-10 起是善解（使用者 2026-10-12 回答）。善解的月份不進判斷期。
- **列的單位：只有子句**（不做整則訊息：正解帶標點時讀音工具讀不了）。
  - 每則訊息在標點、空白與英數處切成連續漢字段，每段 2–30 字。超過 30 字的段，照 `build_tune.py` 的 regex 切。
  - **前文**：
    - 同一則訊息的第 2 段以後，前文是同一則訊息的前一段；
    - 第 1 段的前文是同一頻道、10 分鐘內本人的上一則訊息的最後一段；
    - 都沒有就空白。
    - Threads、Facebook（貼文與留言）：同一則的第 2 段以後是前一段；第 1 段空白。
    - （Messenger 若之後匯出：和 Discord 相同，只留本人寄的；目前程式不讀。）
    - 這和實際打字一樣：輸入法在標點處送出，下一段接著前文打。
- **排除**（每條的列數照報）：
  - 含網址、程式碼區塊、或沒有任何 2 字以上漢字段的訊息；
  - 整句和 discordtune、Discord 驗證集、錯字回報、打字測驗、dev302、功能字測試句的某一列相同的段；
  - 同一個月裡重複的段（留第一個）；
  - 讀音標 CHECK 而 main 沒有把握的列。
- **正解校對**（使用者同意的範圍內）：
  - 只改明顯的錯字（例如「在／再」「的／得」用錯）；用字變體不改（台／臺、甚麼／什麼、裡／裏 交給寬鬆對照）；沒把握的列丟掉。改了幾列、丟了幾列照報。
  - **校對時不看任何候選、分數或模型輸出**。
  - 每一期的正解在校對與讀音確認完成後**凍結**：寫出列檔與 SHA-256，記進研究紀錄（只有數字與雜湊），之後才產生那一期的候選與分數。建置程式在雜湊不符時拒絕產生候選。
- **調參期與判斷期**：
  - **月份的分法在第 (1) 步之前就定死**，只用不必讀內容的機械計數（網址、程式碼、和其他集合重疊、重複這幾條排除之後的列數）：
    - **判斷期**：2026-09；機械計數不到 2,950 列時（2,500 加約 15% 的校對與讀音流失），依序往前併 2026-08、07…，直到 ≥ 2,950。
    - 分法（哪些月是判斷期）與各月的機械計數 commit 進研究紀錄，之後不改。
    - 判斷期在校對與讀音確認之後少於 2,500 列：**照報、接受**，結論寫明列數；絕不從調參期借月份。
  - **調參期**：判斷期之前的其他月份全部是調參池；固定種子 20261012 從池裡抽 min(6,000, 池的列數) 列。
  - 2026-10 以後的月份這一片不用（善解打的）。
  - **順序**：(1) 建調參期、凍結；(2) 算 R3 並凍結它的值（commit 進研究紀錄）；(3) 才校對、建置判斷期並凍結；(4) 算判斷期的表。判斷期的文字不拿去當任何調參、訓練、種子、詞表或規則的依據。判斷期用過之後退役，下一片用新的月份。
- **2,500 列的依據**（推論，假設列獨立）：discordtune 聊天在 0.7／2／0 是改對 229、改壞 163（4,958 列），不一致的列約 7.9%，1:1 淨值約 +1.33%。要讓淨值 / 標準差 ≈ 1.96，約需 1,720 列（√(0.079n) ≈ 0.0133n / 1.96）。同一則訊息的子句彼此相關（discordtune 平均一則約 1.66 段），所以加上餘裕取 2,500。
  - 嚴格值（70／10）的擾動小，2,500 列下 z 約 4.8，判得出。
  - 改壞率上限 0.5% 在這個列數下只能當**點估計**：表上另報改壞數的 95% 精確（Poisson）上界。
- **停止條件**：
  - 資料包或任何一份匯出（Discord、Threads、Facebook）沒來：暫停，不算失敗；沒來的來源不用，照報。
  - 2026-09 以前全部的月份排除後不到 2,500 列：停下來問。
  - 讀音 CHECK 超過 10%：停下來回報。

## 3. 計分與工具（不改現有工具的預設行為）

### 3.1 `tools/evalstats.py`

- `compare` 加 `--net` 選項：多三欄，淨值（改對 − 改壞）、改壞率（改壞 ÷ n）、改壞數的 95% 精確 Poisson 上界。
- 不給 `--net` 時輸出逐位元組不變。
- `docs/contracts/eval-stats.md`、`CLAUDE.md`「評測與資料」、`eval/README.md` 的欄位說明一起改。

### 3.2 `experiments/s7a-tinylm/fusegrid.py` 與新的 `experiments/e2-chateval/judge.py`

- **`fusegrid.py`**：
  - `select_weighted` 與 `fixed_broken` 加參數 `names`（預設 `TUNING`）；
  - `select_weighted` 加參數 `cap`（預設 None）：改壞率超過 `cap` 的格點不選；
  - 不給這些參數時行為逐位元組不變，S7a 模式（不帶選項）照舊。
- **`judge.py`**（新）：
  - 輸入：分數資料夾、集合清單、一組或多組 `--fixed LABEL α τ δ`、`--select LABEL --tuning SET... --weight 1 --cap 0.005`。
  - 對每一組值與每個集合，用 `fusegrid.pick` 算出選擇、寫 rowstats，跑 `evalstats compare --net`，印出 §1 的表。
  - 只讀聊天（或指定的）設定的分數檔；不需要 discordtune 的格，也不跑 S7e 的判斷。
- **`run_sets.py`**：加集合名 `chatclause`（`--chatclause FILE`）、`lytune`（`--lytune FILE`）、`wikitypo`（`--wikitypo FILE`），少了路徑就結束碼非 0。

### 3.3 模型、集合與重現關卡

- **模型**：M8，即 S7a 的 `tinylm-M.npz`（SHA-256 `32308122782d3c5aba8a838521f031a466671d47d48ec0f54dcfb9256451815e`）。用 int8 numpy 打分（S7c-1 記過和 Rust 逐列相同）。候選走 `run_sets.py dumps`（出貨的 n-gram、`--context`、不開詞包）。
- **公開集合**：cvtune、wikitune、dev302、打字測驗、錯字回報 72 列、功能字測試句。沿用 `~/.cache/shanjie/s7f-public/a0/` 的分數，不重打。
- **重現關卡**（先做）：`judge.py --fixed R2 0.2 1 0.25` 在 `s7f-public/a0/` 的公開集合上，產生的表格行（不加 `--net`）必須和研究紀錄 S7e 一節「完整的 `evalstats` 表」的聊天列逐字相同。不同就停。
- **之後的出貨片用的門檻**（這一片不判斷）：判斷期上淨值 > 0、改壞率 ≤ 0.5%（點估計），公開與守門集合沒有「改對 < 改壞而且 p < 0.05」的格。

  - 校對由 main 一人判斷。

## 5. 驗收

1. **程式與測試**：
   - `evalstats --net` 三欄，不給時輸出不變；
   - `fusegrid` 的 `names`／`cap`，不給時不變（現有的端對端測試照過）；
   - `judge.py` 的固定值模式等於直接用 `pick` 算的結果，選值只讀 `--tuning` 的集合；
   - `run_sets` 三個集合名；
   - `chatclause` 建置：一則合成的、含三段的訊息，加上前一則 5 分鐘前與 15 分鐘前的訊息，斷言列與前文和 §2.1 相同；
   - 月份分組、2026-10 以後不進判斷期、已經在調參池的月份不會進判斷期；

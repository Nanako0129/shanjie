# 設定視窗固定大小

狀態：草稿（2026-10-30）。修改 `settings-sidebar.md` §2.2 的高度規則。

## 起因

維護者（2026-10-30）：「設定頁不要隨著內容長高，固定大小，在一個舒適的大小，但不要寫死避免太小的解析度超出邊界」。

現在的高度規則（`settings-sidebar.md` §2.2）：
- 五類各自量出內容高度，取最高那一類，再加上標題列；上限是螢幕可見範圍的高度。
- 每加一個設定項，視窗就跟著變高。「個別設定的 App」清單變長時，視窗也會重算變高。

## 要做到什麼

1. **高度改成一個舒適的固定值，再夾進螢幕**：
   - 視窗的 frame 高度（內容加上標題列）＝ min(`SettingsLayout.preferredHeight`, 螢幕 `visibleFrame` 的高度)。
   - `preferredHeight` 是具名常數 620 pt，寬度不變（左欄 160＋內容 420＝580）。
   - 620 pt 的理由寫在註解裡：寬高比約 1:1.07，和系統設定這類窗格的比例相近；在 13 吋筆電預設解析度（可見高度約 870 pt）下，上下各留出空間。這是挑的值，不是量的，第一輪由維護者實機調。
   - 「不寫死」的意思：在可見高度不到 620 的螢幕上，視窗縮成可見高度，不會超出上下緣。
2. **內容比視窗高的分類，在視窗裡捲動**：畫面上的 `Form` 已經沒有加 fixedSize，所以能捲；這一點不變。
3. **不再量內容高度**：拿掉 `fit()` 裡隱藏 `NSHostingView` 量測、`measureSlack`，以及「個別設定的 App」清單長度改變時的重算（`onRowCountChange`）。
4. **不變的**：
   - 螢幕參數改變（解析度、Dock、文字大小、拔掉螢幕）時，照舊重算高度，並把 frame 夾回 `visibleFrame`；
   - 打開時置中；
   - 切換分類時大小不變。
5. **計算放成 ShanjieKit 的純函式**：`SettingsLayout.frameHeight(visibleHeight:) -> CGFloat`，回傳 `min(preferredHeight, visibleHeight)`，App 端呼叫它。這樣單元測試測得到；App target 測不到。
6. 同一個規則寫在別處的一起改：
   - `settings-sidebar.md` §2.2 的「量法」「高度」「位置」三點（清單長度改變時不再重算；打開時置中、螢幕參數改變時夾回照舊），以及 §3 驗收裡講內容高度與清單重算的步驟（第 6、7 步）；
   - `profile-choice.md` §2.4 第 64 行「清單列數改變時，視窗高度跟著內容重新調整」加一行〔2026-10-30〕註記，指到這份契約；
   - `settings-window.md` §2.1 若提到高度；
   - `SettingsWindow.swift` 過時的註解（`fit()` 的說明、`refit()` 的說明、`sizingOptions` 那行、`onRowCountChange` 的宣告與呼叫處）；
   - `docs/PLAN.md` 的設定視窗一項、研究紀錄。
   - 改完後 grep `onRowCountChange|measureSlack|清單.*重算|最高那一類` 於 `docs/` 與 `macos/Sources/`，只剩歷史審查紀錄或加了〔…〕日期註記的句子。

## 怎麼看到它有效（誰看）

維護者打開設定視窗，在五個分類之間切換，視窗大小都不變；內容長的分類可以往下捲；把「系統設定 → 顯示器」改成更大的文字（可見高度變小）後再開，視窗不會超出螢幕上下緣。

## 驗收

1. **`make test-swift` 全過**，新測試 `SettingsLayoutTests`：
   - 可見高度 900 → 620；
   - 可見高度 500 → 500；
   - 可見高度剛好 620 → 620。
   - 突變：回傳固定的 620（不夾）→ 500 的斷言失敗。
2. **維護者實機**（開發版）：
   - a. 預設設定下打開：視窗比螢幕矮（上下都留有空間），五個分類切換時大小不變。main 另外在同一台機器讀視窗的 frame 高度（`CGWindowListCopyWindowInfo` 的 kCGWindowBounds），記下是不是 620。
   - b. 夾進螢幕：main 先算出維護者螢幕的可見高度；若不到 620 以下，請維護者在「系統設定 → 顯示器」選一個讓可見高度低於 620 的設定（例如更大的文字或較低的解析度；main 換算後指定是哪一個）。重開設定視窗：上緣緊貼選單列下面、下緣緊貼 Dock 上面（整個可見高度）。
   - c. 在 b 的狀態下捲動：「選字記憶」頁捲得到最下面的「清除選字記憶…」，或「一般」頁捲得到最後一列（選一頁在那個高度一定放不下的）。
   - d. 改回原本的顯示器設定，再開，同 a。

## 停止條件

- 維護者覺得 620 不舒適：照維護者說的值改常數，不算失敗。
- 實機超出螢幕上下緣：停下來查。

## 回退、預算

- 回退：revert 這一片的合併，`settings-sidebar.md` §2.2 量內容高度的規則跟著回來。
- 預算：一個 PR；實機調 `preferredHeight` 最多 3 輪，3 輪後仍不舒適或仍超出螢幕，停下來問維護者。

# 「紮」的口語讀音 ㄓㄚ（S2r 規則 R6）

狀態：READY（2026-10-22；plan-verifier REVISE 三項照改後 READY）。實作見 §5。

## 0. 起因與決定

- 錯字回報第 156 列（`|貓咪結紮的紮|ㄇㄠ ㄇㄧ ㄐㄧㄝˊ ㄓㄚ ㄉㄜ˙ ㄓㄚ`）：維護者打「結紮」用一聲 ㄓㄚ，出貨設定兩種都錯，**oracle@64 是 0**。詞庫裡「紮」只有 ㄓㄚˊ（駐紮）與 ㄗㄚ（包紮、結紮），收「紮」的 29 個基底詞也都只有這兩種讀音，所以打 ㄓㄚ 時候選裡沒有「紮」。萌典（教育部重編國語辭典）同樣只有 ㄓㄚˊ、ㄗㄚ。
- 維護者 2026-10-22 同意照建議補上這個讀音，另開一片照出貨標準量過才出貨。
- **和 S2r 原則的關係**：`s2r-sandhi-variants.md` §0 把「使用者個人打法」交給新手測驗與學習、不寫進散布的詞庫。那條的前提是候選裡有正確的字、學習學得到；ㄓㄚ 打不出「紮」時連學習都沒有東西可學。這片把 §0 放寬一類（同一個 PR 改 S2r 的文字）：**口語通行讀音**，也就是審訂音以外、但候選裡完全打不出那個字的讀音，經維護者逐字同意後可以收進 `sandhi-add.tsv`。本片只收「紮 ㄓㄚ」。

**怎麼看到它有效**：打 `ㄐㄧㄝˊ ㄓㄚ` 得到「結紮」；錯字回報第 156 列的 oracle@64 從 0 變 1（兩種設定），也就是錯字集的 oracle@64 從 153 變 154；打字的其他結果照出貨標準不退步（§3）。

## 1. 規則 R6（`tools/build_sandhi.py`）

- 基底（`mcbpmf-data.txt`）裡每一列，詞含「紮」、而且那個「紮」讀 ㄓㄚˊ 或 ㄗㄚ：把這些位置改成 ㄓㄚ，產生一列。
- **單字列也處理**（只限 R6）：S2r 其他規則只處理多字列，因為單字的變調讀音本來就在；「紮」單字沒有 ㄓㄚ，不加就打不出單字的「紮」。
- 分數照抄來源列；同一個（讀音, 詞）由兩列（ㄓㄚˊ 與 ㄗㄚ）產生時取最高分；（讀音, 詞）已在基底或疊加層就不產生。這些都沿用 S2r §1 的共同規則。
- 預期新增 **29 列**（28 個多字詞、1 個單字；2026-10-22 以 python 在 `mcbpmf-data.txt` 量得，例：紮 ㄓㄚ −5.25、紮實 ㄓㄚ-ㄕˊ、結紮 ㄐㄧㄝˊ-ㄓㄚ、包紮 ㄅㄠ-ㄓㄚ、駐紮 ㄓㄨˋ-ㄓㄚ）。生成器印出的 R6 列數和 29 不同就停。
- 疊加層（`overlay-add.tsv`）裡含「紮」的詞（包紮機、安營紮寨等）不處理，照 S2r 只讀疊加層去重。
- `s2r-sandhi-variants.md` §1 的規則表加 R6 一列，§0 照上面放寬。`LICENSES/data.md` 的那一列說明加上 R6（仍是 MIT 基底的衍生）。

## 3. 評測（照現行出貨標準，對 main 的出貨值）

- 基準與新版各跑一次 CLI 出貨設定（`--context --packs acg --tinylm`；聊天加 `--colloquial-core`），同一台 GCP VM、同一種 CPU，`--rowstats`，再 `tools/evalstats.py compare --net`：
  1. discordtune（聊天）：不顯著變差，而且改壞 ≤ 26 或改壞÷改對 ≤ 0.6；
  2. 回歸層：打字測驗（聊天、書面）、dev302 書面，逐列相同或改壞 ≤ 2 且淨值 ≥ 0；dev302 聊天只報；
  3. cvtune-clean 聊天：Δtop1 的 90% 配對 bootstrap 下界 ≥ −1.0 個百分點；
  4. 錯字回報（兩種設定合計，全部 157 列）：淨值 > 0 且改壞÷改對 ≤ 0.6。
- 另報第 156 列在兩種設定的選字（公開列，可寫句子）。
- 四條全過才出貨；照規則，改到選字的改動出貨前要在沒看過的判讀集確認一發。這片只加 29 列，確認集上幾乎不可能到 p < 0.05，所以**四條全過時一律報數字，請維護者決定要不要免確認**（不論是不是 0 改對 0 改壞；維護者逐次決定，記在 `decisions.md`）。維護者不給免確認時，照規則另寫確認登記（下一份判讀集、規則與預算），在任何確認數字之前 commit。
- 任一條不過：報「照登記不過」和數字，和維護者討論。

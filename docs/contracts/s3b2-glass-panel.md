# S3b-2 契約：自建玻璃候選窗

使用者 2026-10-05：「這是善解的…這是蘋果的… 兩個字的大小不一樣要比照蘋果 另外左右是選字，方向下要展開，展開要有動畫跟蘋果一樣」。接著問「自建有機會 liquid glass 樣式接近嗎」，看過原型後同意先寫這份契約。

**為什麼自建**（2026-10-05 實測，見 s3f §5 與 research-log）：
- `IMKCandidates` 用自己的字級畫整格文字，attributed string 的字型被忽略，所以名稱無法比標點小。
- 公開 API 沒有展開成網格的行為。
- 私有的 `IMKCandidate`（帶 annotation）兩條路都試過：`setCandidateData:` 和由 controller 的 `candidates(_:)` 提供。實機上都只畫出空框和展開箭頭，沒有任何候選。
- `NSGlassEffectView`（macOS 26 起公開）在一個無邊框、不搶焦點的 `NSPanel` 裡會畫出 Liquid Glass。原型截圖在 `/Users/nanako/shanjie-glass-prototype.png`（2026-10-05）。原型是獨立的小程式，不是輸入法程序，所以在輸入法裡能不能畫出來還沒驗證（§4.1 的停止條件）。

**怎麼算做到**：使用者在一般 App 打字開候選，看到的是玻璃膠囊候選列。對照蘋果注音的同比例截圖，下列項目一致或差異已逐項記下：號碼、候選字、名稱的字級與顏色、反白膠囊。按 ↓ 會展開，展開有動畫。按號碼、Enter、滑鼠點選都送出候選本身。

分兩片，各自一個 PR：

| 片 | 內容 | 動到核心 |
|---|---|---|
| **2a** | 自建玻璃候選列取代 `IMKCandidates`，只做收合狀態 | 否 |
| **2b** | ↓ 展開成網格、↑ 收回、展開動畫 | 是（每頁數量、↑↓ 的意義） |

本契約只把 2a 寫成可以實作的程度。2b 列出參考畫面看到的行為，資料介面另開一節修訂、再審。

## 2. 2a：收合的候選列

### 2.1 視窗

- app 的 `CandidatePanel` 實作（取代 `CandidatePanelAdapter`）持有一個 `NSPanel`；`Shell` 照舊只持有 `CandidatePanel` 協定，測試照舊用 `FakePanel`。
- `NSPanel` 的設定：
  - 樣式 `[.borderless, .nonactivatingPanel]`，`isOpaque = false`，背景透明，有陰影。
  - `level` 是 popUpMenu＋1（小麥注音同值，`HorizontalCandidateController.swift:410`），蓋過一般視窗與選單。
  - `canBecomeKey`／`canBecomeMain` 都是 false，所以不搶走 App 的焦點與按鍵。
  - `hidesOnDeactivate = false`：輸入法是 agent app，從來不是 active app。
- 內容是 `NSGlassEffectView`，裡面是一列格子。
- 深淺色模式跟著系統。強調色用 `NSColor.controlAccentColor`，跟著使用者的系統設定。
- 視覺參數（字級、間距、圓角、內距、反白膠囊）放在一個 enum 裡的具名常數，每個都附註解說明出處（§1 哪張截圖量的）。

### 2.2 資料流

**行矩形進來**：
- `TextClient` 加 `func lineRect(cursor: Int) -> NSRect?`（`cursor` 是組字區內的 UTF-16 游標）：
  - 用 `attributes(forCharacterIndex:lineHeightRectangle:)` 取得；
  - 索引是組字區內的位置（不是整份文件的位置；2026-10-05 實機修正），從游標前一個字開始，取不到（原點 0,0）就往前找，做法和小麥注音 `InputMethodController.swift:910` 一樣；
  - 都取不到就回傳 nil。
- `Session.apply` 顯示候選時，用核心的 `cursor_utf16` 讀自己 client 的 `lineRect(cursor:)`，傳給 `Shell.showCandidates(_:selected:lineRect:)`。顯示候選的一定是擁有者，所以矩形就是擁有者的。
- `CandidatePanel.show` 改成 `show(_ candidates: [String], notes: [String?], selected: Int, lineRect: NSRect?)`。

**點選出去**：
- `CandidatePanel` 加 `var onSelect: ((Int) -> Void)? { get set }`。
- `Shell.init` 設成 `{ [weak self] i in self?.owner?.candidateSelected(at: i) }`。
- `Session.candidateSelected(at: Int)`：
  - 只在 `shell.owner === self` 且位置在這一頁內時動作；
  - 動作是把數字鍵 `1`＋位置送進核心，和現在一樣由核心決定結果。

**刪掉**（點選有了位置，就不用整格文字對回位置；不留沒有作用的程式）：
- `Shell.cells`；
- `CandidateText`；
- `Session.candidateSelected(_ text: String)`；
- `Session.candidates`；
- IMK 的 `candidates(_:)`／`candidateSelected(_:)` 覆寫。

`Shell.candidates` 留著：用來判斷點選的位置是否在這一頁內。

### 2.3 位置

- 候選列的左上角放在行矩形的左下方，往下 4 pt。往左偏移一段距離，讓第一個候選字和組字區的字左緣對齊（§1 觀察，偏移量從 a-3 量）。
- 超出螢幕時夾回該螢幕的 `visibleFrame`：
  - 下方放不下就改放到那一行的上方；
  - 右邊超出就往左移，左邊超出就貼齊左緣。
- 用哪個螢幕：包含行矩形的那個 `NSScreen`；找不到時用 `NSScreen.main`。
- 行矩形是 nil 時，沿用上一次的位置；第一次就沒有時，放在主螢幕 `visibleFrame` 的左下角。
- 這段計算寫成純函式（輸入行矩形、窗大小、螢幕框陣列，輸出原點），可以單元測試。

### 2.4 顯示

- 每格依序是號碼、候選、名稱：
  - 號碼用次要文字色；
  - 名稱用比候選小的字，次要文字色；
  - 沒有名稱的格不留名稱的空間。
- 選取中的格子是強調色的圓角膠囊，裡面的文字都改成白色系。
- 一列顯示核心給的這一頁（最多 9 個），2a 不畫 ⌄（2b 才有展開）。
- 顯示和換頁沒有動畫，立刻換內容與大小，等同目前的行為。

### 2.5 不變的行為

- 候選窗不收按鍵。按鍵照舊全部由 `handle` 送進核心。
- 擁有者、`deactivate`、`commitComposition`、secure input、R2 日誌規則都照 s3b 不變。
- 候選窗不記任何日誌。

### 2.6 無障礙

- 每一格設定 `accessibilityLabel`：候選本身，有名稱時加上名稱。
- 選取中的格子設 `isAccessibilitySelected`。
- VoiceOver 實際念不念、念得對不對，由使用者實機看；契約不宣稱已驗證。

### 4.1 停止條件與預算

遇到以下任何一項就停下來回報，不繞過：
- 開始實作前，§1 的收合狀態截圖（深色與淺色）還沒拿到。

## 5. 2b：展開（定案見 §8）

§1 看到的蘋果行為：
- 已經開著候選時按 ↓：展開成網格。單字 6 欄、可見 5 列並可捲動；標點 3 欄。
- 展開時 ↓／↑：上下移動一列；←→ 左右移動。
- 在第一列按 ↑：收回成一列，選取不變。
- 號碼 1–6（或 1–3）只出現在選取所在的那一列，跟著選取移動。
- 底部的「詞頻／部首／表情／拆字」分頁不做（範圍外）。

要改的：
- 核心目前在候選開著時把 ↓ 當成移動選取（s3a §3 第 4 條），而且每頁只輸出 9 個。
- 展開要一次給更多候選，號碼也要跟著列走，所以核心的按鍵規則和 C ABI 都要改。做法：
  - 加 C ABI 設定每頁數量；或
  - 輸出整份候選清單，由殼排。
  
  兩者擇一，另開一節修訂本契約，經 plan-verifier 審過才實作。
- 展開動畫：用系統的動畫（`NSAnimationContext` 改視窗框），時間與曲線照 §1 的錄影；不自己調彈性（使用者偏好系統預設動態）。

**已知差異（2026-10-05 code review）**：第一個候選是多字詞（例如游標在句尾時的「你好」）時，候選列對齊的是游標前一個字，所以「你好」的「你」落在組字區的「好」底下。蘋果遇到這種情況對齊哪裡還沒拍到，等使用者實機看過再決定。

### 8.1 參考行為（§1 之後補拍，b-3 到 b-12 與錄影 bv.mov，深色）

| 檔 | 按鍵 | 蘋果 |

| b-5、b-6 | 展開時空白鍵 | 選取往下一列（不是翻一整頁） |
| b-7 | 展開時 Esc | 候選窗整個關掉，組字區回到開候選前的字 |
| b-8 | 空白鍵 | 重新開候選，是收合的一列 |

| bv.mov 420–438 格（60 fps 取樣） | 展開動畫 | 約 0.3 秒：第一列的格子從候選列的間距滑開到網格欄位，視窗同時往下長出其餘各列；收回（Esc）沒有動畫 |

標點（p-2）：3 欄。號碼只在選取所在的列，1 到欄數。

### 8.2 核心

較短的最後一列怎麼走，蘋果的行為還沒拍到；先定成「到那一列最後一個」，實機比對時若不同再改。

- 候選狀態加 `expanded: bool` 和欄數 `columns`：
  - 一般候選 6 欄；
  - 標點候選（開在標點 token 上的候選）3 欄。
  - 欄數是核心的常數，各附出處（a-4、p-2）。
- 按鍵規則（s3a §3 第 3–8 條，候選開啟時）：

| 鍵 | 收合 | 展開 |
|---|---|---|
| ↓ | 展開（選取不動） | 下一列同一欄；下一列沒有這一欄（最後一列較短）時到那一列最後一個；已在最後一列時不動 |
| ↑ | 上一個（照舊） | 上一列；在第一列時收回，選取不變 |
| ←→ | 上／下一個（照舊） | 上／下一個（跨列） |
| 空白鍵 | 下一頁（照舊） | 和 ↓ 相同，但在最後一列時回第一列同一欄 |
| 1–欄數 | 本頁第 n 個（收合時 1–9，照舊） | 選取所在那一列的第 n 個；那一列不足 n 個（最後一列）時吃掉、不動作 |
| 欄數＋1 到 9 | — | 吃掉、不動作，候選照開（不能落到第 8 條：標準鍵盤的 7、8、9 是 ˙、ㄚ、ㄞ，會關掉候選又開始新音節） |
| Enter | 選目前的（照舊） | 同 |
| Esc、Backspace | 關閉候選（照舊） | 同（不是收回） |

- Command＋Backspace（S4 的忘記）：收合與展開都照舊作用在目前選取的候選。
- 輸出：
  - 收合時照舊（一頁 9 個、`candidate_selected` 是頁內位置）。
  - 展開時輸出可見的列：從 `top` 列開始最多 5 列 × 欄數個。`top` 隨選取捲動，讓選取的列一直看得到（a-4：可見 5 列）。`candidate_selected` 是這次輸出裡的位置（整份清單的位置減 `candidate_first`），殼用它除以欄數得到號碼所在的列。
- C ABI 的 `ShanjieOutput` 在尾端加三個欄位（舊欄位位置不變）：
  - `candidate_columns`：0 表示收合的一列，大於 0 表示展開的欄數；
  - `candidate_first`：輸出的第一個候選在整份清單的位置；
  - `candidate_total`：整份清單的數量（捲軸用）。
- 滑鼠點選，新增：

  ```c
  int32_t shanjie_engine_pick(ShanjieEngine *engine, uint32_t index, ShanjieOutput **out);
  ```

  - `index` 是這次輸出裡的位置，核心選 `candidate_first + index`，走和 Enter、號碼鍵**同一個** `choose()`，所以 S4 的待學（pending learn）與固定詞語意完全相同。
  - 回傳碼照 s3a §6：1 是 `engine` 或 `out` 為 NULL；2 是候選沒開或 `index` 超出這次輸出；4 是內部錯誤，核心自己丟棄組字（和 `shanjie_engine_key` 一樣）。非 0 時 `*out` 是 NULL，碼 1、2 不改任何狀態。
  - 取代現在「轉成數字鍵」的做法，因為展開時號碼只對應一列。
- 標頭 `core/include/shanjie.h` 同一個 PR 更新：三個新欄位與 pick 的註解、`candidate_count` 的上限改成「收合 9、展開 5 × 欄數」。
- s3a 契約 §3 第 3–5 條與 §6 的結構同一個 PR 改成本節的規則。

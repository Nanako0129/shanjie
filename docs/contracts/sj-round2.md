### 3.1 架構

| XL | 8 | 768 | 12 | 約 6,400 萬〔估計〕 | 約 245 MiB | 約 62 MiB |

前文 64、優化器與學習率照 SJ-SR-6-14M（`s7a-tinylm.md`），步數照總 token 數等比例（同 `sj-lm-7.md` §2.7）。

## 5. 量測與選擇

### 5.1 方向（每份、每種規模，對 R1，在 §2 選定的底層上）

- 每份權重（含在底層上重新匯出的 R1）照 R1 的檔頭匯出（同一組 α、τ、δ），綁底層的 bigram 與 kn；方法核對：R1 的 npz（`cb351ed7…`）在底層上重新匯出，和底層上的 R1 匯出檔的權重段逐位元組相同。
- **量測建置**：每一份候選（含重新匯出的 R1）的建置都把 `PAIRED_TINYLM_SHA256` 換成它自己的 `.sjtl` 雜湊；聊天三檔的摘要行要有 `+tl:<自己的 sha8>` 與 `+colloq:`，不然那一格作廢。
- **聊天**（聊天標準檔）：過濾後的 chatclause（5,631 列）U2＝改對 − 2×改壞。一個規模「成立」＝三個種子 U2 都 > 0。
- **書面**（書面標準檔）：wikitune-clean 淨值與 newstune 淨值。一個規模「成立」＝三個種子兩者都 > 0。
- 每一份（聊天、書面）在成立的規模裡取三個種子中位數（聊天 U2；書面 wikitune＋newstune 淨值合計）最大的規模；同分取 L。用那個規模中位數的種子（同分取種子號小的）往下走。兩種規模都不成立＝那一份沿用 R1。

### 5.2 選值、出貨標準與退路（選中的組合，全部在數字之前定死）

- **聊天三檔**：照 `sj-lm-7.md` §2.9 的聊天規則與它的 24 格（α {0.3, 0.5, 0.7, 1.0} × δ {0, 0.1, 0.25, 1, 2, 3}、τ 2），過濾後的 chatclause。沒有合格的格 → 那一檔用出貨版的 cell。
- **書面標準與積極**：§2.9 的上界規則（`select_weighted(1, cap_ub=0.005)`），24 格 α {0.5, 0.7, 1.0} × τ {1, 2} × δ {0.5, 1, 2, 4}，cvtune-clean＋wikitune-clean；積極＝標準。沒有合格的格 → 用出貨版的書面標準值。
- **書面保守**：照 §2.10 的規則與它的 24 格（α {0.3, 0.5, 0.7} × τ {1, 2} × δ {0.75, 1, 1.5, 2}）；條件中的「書面標準」是上一條選出的值。沒有合格的格 → 保守＝標準。
- 「出貨版的值」＝PR #324 合併後 main 的值（聊天 cell 在 `core/src/colloquial.rs`，書面值在出貨的 `.sjtl` 檔頭）。
- 對出貨版照出貨標準四條判六個單位（同 §2.9 的單位與順序門檻），加共同關卡（動漫五集、名單三集）；discordtune 用過濾版（4,919 列）。**書面單位的第 2 條包含 dev302 書面**（逐列相同，或改壞 ≤ 2 且淨值 ≥ 0）：`sj-lm-7.md` §2.8 的「dev302 書面只報」是維護者對 PR #324 的例外，不延用到這一輪。
- **退路**：某一份（聊天或書面）有任何一個單位不過（判的條文、共同關卡或順序門檻）→ **那一份整邊退回 R1**，用出貨版的值，在同一次量測裡重判那一邊；仍不過就停下來報維護者。
- **int8 退路**：選中 XL 而 §4 的 int8 證明不成立 → 那一份改用 L（L 在 §5.1 成立的話），重做 §5.2 的選值與判讀；L 不成立就退回 R1。

### 5.3 確認一發

- **要確認什麼**：哪一邊和出貨版不同，就確認哪一邊（底層換了 bigram 時兩邊都算不同）。比較對象是出貨版的同一設定、標準檔。
- **聊天**：用 CE3 的判讀集（`docs/contracts/chat-eval-3.md` 的 cjudge-1；新建集合照 CE3 的來源規則，建之前先問維護者）。判讀集每月最多一份，2026-11 那一份是 PR #324 的確認一發，所以**最早 2026-12**。前提是 CE3 契約過審、cjudge-1 建好並 commit n 與雜湊；CE3 沒過審或 cjudge-1 建不出來 → 聊天那一邊停下來報維護者（不出貨聊天那一邊的變動）。舊的 chatjudge 系列不再用。
- **書面**：wikijudge4-clean：wikijudge4（第 325,000–329,999 篇，2,820 列，`00a5e54fb7dc`）拿掉和這一輪書面所有訓練與計數文字重疊的列：`tools/holdout_guard.py report --rows wikijudge4.txt --text <R1 的非維基檔、新聞三來源、書面來源 C、3b 選定臂的新聞計數文字> --wiki <同一份 dump> --articles 200000`。n 與 SHA-256 在任何分數之前另一個 commit 記。
- **診斷先印**：開確認之前，用既有分數檔印單獨挑對率、留住率、融合上限與 oracle。
- **規則**（數字之前 commit）：淨值 > 0、精確 McNemar p < 0.05、改壞÷改對 ≤ 0.65。
- **送不送**：不一致率 r 取選中種子在調參層的值（聊天：過濾後 chatclause 標準檔對出貨版的 (F+B)/n；書面：wikitune-clean 標準檔對出貨版的 (F+B)/n），D ＝ round(r × n(判讀集))，MDE ＝ `tools/evalstats.py mde --discordant D --alpha 0.05 --power 0.8`；預期淨值（同一層的 (F−B)/n × n(判讀集)）< MDE 或 `mde` 回傳 None → 先問維護者。
- **不過**：
  - 底層沒換 bigram（3b 選 N00 或 N10）：不過的那一邊退回出貨版的檔與值，另一邊照常；退回的那一邊就是出貨版，不需要再確認。
  - 底層換了 bigram：任何一邊不過 → 這一輪不出貨，報維護者（換 bigram 的組合沒有能單邊退回的版本）。
- 例外只由維護者逐次決定（記進 `decisions.md`）。

### 5.4 速度與記憶體

- 照 `formal-rerank.md` §3.3 與 2026-10-28 修正後的量法（研究紀錄：結束負載在最後一格後 60 秒看）：兩份都載入的重播量 RSS 與每鍵 p95，CLI 量兩種設定的重排 p95；Mac 閒置窗、三輪交錯，對出貨版。
- **這一輪的門檻**（取代 `formal-rerank.md` §2 的 ＋70 MiB；`sj-lm-7-pr2.md` §4 與 `sj-lm-7.md` §6 的 ＋40 MiB 只管 PR #324，不適用這一輪）：每鍵 p95 ≤ 16 ms；重排 p95 ≤ 300 ms；重排模型合計常駐 ≤ 250 MiB；重播與 CLI 的 RSS ≤ 出貨版同一格 ＋250 MiB。同一個 PR 改 FR §2 的那一句。

## 6. 出貨、PR 順序、回退與授權

- **分支**：PR #324 合併後從 main 開 `feat/sj-round2`。核心改動（§4，含 `MAX_FILE`、int8 常駐）、量測工具、選定的模型檔雜湊、下載切換與授權放在同一個 PR；新的模型 Release 照 `docs/releases/README.md` 先把說明檔進 main，再建 Release，最後這個 PR 才切換下載、合併（同 PR #324 的順序）。
- **最終綁定（任何臂都適用）**：出貨的通語一律帶指紋條目——3b 選 N00 或 N10 時就是出貨版的通語（`e3fb6056…`）；選到改 bigram 的臂時，新的通語照私有流程加指紋條目。每一個新換或重新匯出的檔（兩份會意、書面與聊天連文表、辨類、承接）都綁這個帶指紋的通語（不帶指紋的建置上匯出的檔，照 PR #324 的做法只改綁定雜湊位元組）。量測都在不帶指紋的同一份建置上做，最終檔要核對：加指紋（或重綁）之前、之後，出貨設定在 dev302、打字測驗、錯字回報兩種設定的 rowstats 逐位元組相同。
- **常談配對**：`PAIRED_TINYLM_SHA256` 一律等於最終聊天 `.sjtl` 的檔案雜湊（聊天沿用 R1、但 R1 重新綁定時也要換）。驗收：核心 `applies` 的 Rust 測試在最終檔上為真；CLI 聊天三檔的摘要行有最終檔的 `+tl:` 與 `+colloq:`。
- **回退**：`git revert -m 1 <這一輪的 merge commit>`，下載與雜湊回到 SJ-LM-7 那七個 Release；App 照常從 Release 抓檔。
- **授權**：書面會意的訓練文字含新聞，Release 說明、`LICENSES/data.md` 的會意列與關於頁的資料來源加：政府機關新聞稿（著作權法第 9 條；資料集另依政府資料開放授權條款第 1 版顯名）、維基新聞（CC BY 4.0，署名「維基新聞」）；書面來源 B、C 不具名；照 `news-corpus.md` §4 與 `sj-lm-7.md` §5 的寫法。3b 選到加新聞的臂時，通語或連文的列照 `news-corpus.md` §4 改。

## 2. 設計

### 2.1 通道項（核心）

- 對每一段的前 8 條路徑（n-gram 順序，第 0 條是錨點），把該段的音節依序切給路徑上的每個詞，一個字一個音節。
- 每個**單字詞** w 讀 r，算 t(r, w) = s(r, w) − max_r' s(r', w)。
  - s 是引擎詞庫裡 (r, w) 的分數：同一個 (讀音, 詞) 取最大的那一列。範圍是詞庫檔、疊加層、變調、人名，以及引擎建時開著的詞包，和 `experiments/diag-near-miss/d23.py` 的 `load_lex_scores` 相同。
  - 降權表與學習**不算**進 s。
  - r' 走 w 在這份詞庫裡的所有讀音。
- **多字詞**一律 0。
- 詞庫找不到 (r, w) 的單字照 0 算。路徑的詞對不上這一段的音節數時，整條路徑的通道項是 0。
- ch_i = Σ max(t, −4)。
- ll_eff_i = 常談的 `fuse` 結果 + (1.0 / 0.5)·(ch_i − ch_0)，再照 `colloquial::guarded_pick` 的規則選：常談的分數有任何不是有限值時，兩項都不加，用原本的 pick。
- ν 1.0、c 4 寫成具名常數，註解寫出處（P5 登記修訂一與結果）。α 用 `colloquial::ALPHA`，不另設。
- 多段的組字（標點、固定詞把組字切成幾段）：每段用自己的音節與路徑各自算。離線一列只有一段，所以兩者相同。
- 詞庫的查法由實作決定（例如載入詞庫時建「單字 → 最大分數」的表，(讀音, 單字) 用詞庫既有的查詢），但結果要和上面的定義相同。

### 2.2 CLI、重播、App

- **CLI**：`--colloquial-core` 生效時預設加讀音通道項。加 `--no-reading-channel`（研究用）只留常談，用來重現 P4d 那一格。
- **重播**：預設和 App 一樣（加）；`--no-reading-channel` 同 CLI。
- **App**：不用改 Swift，也沒有新的檔案或設定，跟著常談走（語意校正開關、強度、常談表）。
- **FFI 與按鍵規則都不變**。`docs/contracts/s3a.md` 的融合說明補一句。

## 3. 驗收

1. **核心單元測試**，每條規則一個「規則壞掉就會失敗」的測試：
   - 只算單字；對最高分讀音取相對值，同分是 0；上限 4；相對錨點；係數是 ν／α；
   - 只在常談生效時加；找不到的 (r, w) 是 0；音節對不上時整條是 0；
   - 降權不影響 s；多段各算各的。
   - 突變：拿掉相對錨點、多字詞也算、上限改成 2、α 不用 0.5，各要讓測試失敗。
2. **和離線逐列相同**：CLI（`--colloquial-core`）在 dev302、打字測驗、錯字回報（前 154 列）的聊天設定，每列選的候選和 `p5.py --cell lex,1.0,4 --out-picks` 的第三欄相同。比 rowstats 與選字；差異列要歸因，不能歸因就停。
   - 雲端的 chatclause、discordtune、cvtune-clean：對出貨的改對／改壞等於 126／27、88／34、49／12，對 P4d 那一格是 23／0、23／0、9／0（只帶回數字）。
   - 加 `--no-reading-channel` 時，CLI 逐列等於常談單獨的結果（P4d 那一格）。
3. **不變的部分**：書面設定、語意校正關、保守與積極強度、沒有常談表時，dev302、打字測驗、錯字回報兩種設定的 `top1_sha256` 和常談分支（`feat/colloquial-term` 合併後的 main）相同；golden 不變。
4. **重播一致**：`shanjie-replay --rerank each` 的第一次顯示和 CLI 相同。
5. **速度與記憶體**（雲端，單執行緒）：
   - 每鍵 p95 不超過 16 ms 的按鍵預算；
   - 常談加讀音通道項，相對出貨的 RSS 增加仍 ≤ 40 MiB（常談單獨是 +28.8～29.0 MiB）。另報讀音通道項本身增加多少。
6. **實機**（維護者，15 秒級）：打錯字回報第 102 列（「是不是很雷啊」）或第 140 列的公開句子。
   - 事先用重播確認：只有常談時選錯，加讀音通道項時選對。用的前文要是 App 實際會給的樣子。
   - 選第 140 列時，前文要是 App 給得到的（例如先送出「否則」再打「變快」）。
7. `/code-review` ＋ fresh verifier ＋ CI。

## 5. 停止條件、範圍外

- **停止條件**：
  - CLI 與離線有不能歸因的差異；
  - 要改 `pick`、解碼器或常談的常數才能做到逐列相同；
  - 記憶體或延遲超過 §3 第 5 點；
  - 核心詞庫的 s 和 `d23.load_lex_scores` 對不上，而且說不出原因。
- **範圍外**：
  - mc 估法、修詞庫的 −6.8 佔位值（例如「長」ㄓㄤˇ）、重新選 ν 或 c；
  - 常談不生效時單獨加這一項（P5 只在常談上面量過）；
  - 書面設定、保守與積極強度；
  - 降權表的輕聲 44 字（reading-aware A1）。

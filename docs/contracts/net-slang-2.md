# 契約：網路用語第二輪（打錯的口語詞組與迷因進主詞庫）

狀態：**過審**（2026-10-25 收尾審查 READY）。修訂一（2026-10-25；修訂二：第二次 REVISE 一項，C、D、E 各自的用量門檻寫清楚。plan-verifier 第一次 REVISE 六項：來源欄與署名、C 也要過「只留打錯的」與「讓不讓第一名」、兩邊用同一個計數工具、檢查集沒過 90% 的處置與解碼設定、二分的預算、回滾；同時加入維護者提的 Muse 來源 E）。

## 0. 起因、要做到什麼、怎麼看到

- **起因**（維護者 2026-10-25）：迷因詞包逐詞查出處後，維護者看到很多詞是生活口語、VTuber 術語，「越看越覺得這些迷因很多就算有出處都好想放到主詞包，因為太好用了」，選擇題選「冒犯的留包，其他進主詞庫」；接著說「這片做得很值得，非常的口語，這對同音字選字很有幫助，我覺得出現機率可以放寬一點看，搞不好更多」，選擇題選「門檻放寬＋再挖一輪」。
- **和第一輪（`net-slang.md`）的差別**：第一輪在試抓語料（21 個看板、13.7 萬頁）上挖，分類出的 4,357 個「一般詞組」全部不收。第二輪用完整快照（110 個看板、593,546 頁），而且**只看現在打錯的字串**：打錯的口語詞組正是對同音選字有幫助的，所以一般詞組只要是自然的一個說法就收。
- **要做到什麼**：`data/lexicon/slang-add.tsv` 加一批詞（來源見 §1），由 `tools/build_overlay.py` 照第一輪的方式接進常開的疊加層。
- **怎麼看到**：第二輪檢查集（§3）在聊天設定打出收錄的寫法；出貨標準不退步；維護者實機打 3–5 個（例如 演都不演、傑出的一手、投降輸一半）。

## 2a. PTT 快照挖掘

- **語料**：2026-10-25 的 PTT 快照（SHA-256 `174e972c…`，頁面目錄雜湊 `1f1ac2c0…`，593,546 頁），內文與推文都用，推文照 SJ-LM-7 §2.4 合併。只在 GCP 或 188 上算，只帶回字串與計數。
- **各來源的用量門檻**（事先固定，挖之前 commit）：C、E 是看板 ≥ 2、文章 ≥ 3（維護者要放寬；這兩個來源是人或模型挑過的候選）；D 是看板 ≥ 3、文章 ≥ 10（從語料直接挖的字串雜訊多）。「只留打錯的」「讓不讓第一名」與 §2 的分類三個來源都適用（A 已在迷因詞包用同一份快照、同一個工具過了這幾步；B 由維護者決定）。
- **候選字串**（D）：2–6 個漢字，計看板數與文章數（一篇只算一次）；去掉已在詞庫各層（基底、疊加層、名單、三個詞包）的字串（整串比對）；點互資訊與左右鄰接熵過門檻；只留最長的（被更長候選包住、文章數相差 10% 以內的短字串去掉）。
- **D 的門檻**：看板 ≥ 3、文章 ≥ 10（第一輪 5／20，維護者要放寬；和迷因詞包、名單增補相同）。點互資訊與鄰接熵的門檻用第一輪公開列表審出的 76 個詞在這份快照上重新校一次（取能留住其中 90% 的值），之後不改。
- **只留打錯的**：每個候選用 `tools/readings.py` 給讀音（CHECK 的不收），用出貨 CLI 解碼（聊天設定，動漫、資訊詞包開），**聊天的第一名不等於候選本身**的才留。
- **計數的工具**：門檻與「讓不讓第一名」比的文章數，候選與原本的第一名（X）兩邊都用 `experiments/names-creators/count_usage.py`（同一份快照、同一種數法，兩個計數檔的 `ptt_tree_sha256` 相同）；挖掘時另外算的次數只用來排序與點互資訊。
- **讓不讓第一名**：第二次計數數 X 字串的文章數；候選的文章數要多於 X 才收，X ≥ 候選就不收（第二輪一律不收，第一輪 §2 的「不搶第一」不適用：工具沒有讓網路用語排在基底詞後面的機制）。被擋掉的候選連同 X 與兩邊的文章數列進研究紀錄。
- **程式**：挖掘、解碼、兩次計數的腳本放進 `experiments/net-slang-2/`（第一輪的腳本沒進 repo，這次要能重跑）；計數工具沿用 `experiments/names-creators/count_usage.py`（`--jobs` 用滿核心）。

## 2. 分類、人工審、建置

- **分類**（C、D、E 的候選；A、B 已經人工決定過）：交給 subagent 分類，每個候選一類：口語或網路用語、一般詞組（自然的一個說法）、迷因、專有名詞（非人名）、人名、錯字、簡體或大陸用語、片段（不成一個說法）、冒犯（政治綽號、性與成人、毒品、族群或身分貶稱、粗口）。分類用的 subagent 只看候選字串與它的 PTT 計數，不讀 PTT 原文以外的私人資料。
- **收**：口語或網路用語、一般詞組、不冒犯的迷因、專有名詞（店家、品牌、公司、飯店、場館的名稱除外：另列交給名單層增補第二次 `names-stores.md`，建置前也去掉已在名單層的字串）。**另列**：人名（名單層）、冒犯（迷因詞包）。**不收**：錯字、簡體或大陸用語、片段。
- **分類筆數上限**：過了 §2a 全部過濾後若超過 5,000 個，依「點互資訊＋鄰接熵」排序取前 5,000 個分類（第一輪量過，依文章數排序時已知詞排得太後面）。
- **人工審**：main 看過全部「收」的詞；給維護者一份清單（詞、讀音、原本打成什麼、PTT 篇數、分類），維護者抽查。第一輪 §2 的「是固定說法（不是一般詞組）」這一條在第二輪不適用。
- **讀音、分數、工具**：照第一輪 §2（`length_scores` ＋ `MANUAL_BONUS`、`build_overlay.py` 讀 `slang-add.tsv`），不改程式。同一個讀音有好幾個新收的詞時照文章數排、後面的扣 `SLANG_BEHIND`。注意：A 的詞在迷因詞包是用 `BONUS` 3 量到第一名的，進疊加層後加分只有 0.75，可能不再是第一名，由 §3 的檢查集看出來。
- **迷因詞包那一邊**：A 的詞在迷因詞包的排除表已寫明去處；C、D、E 分出的「冒犯」交給迷因詞包另一個 PR。

## 3. 驗收

- **第二輪檢查集** `eval/dev/net-slang/round2.txt`：每個讀音上排第一的新收錄詞一列（無前文）；聊天、書面各報收錄前後的第一名，解碼用下一條出貨標準的同一組詞包（動漫、資訊；#293 合併後加迷因），研究紀錄寫明開了哪些。聊天至少 90% 打出收錄的寫法；沒打出的逐列寫原因與原本的第一名。
- **出貨標準**四條，對現行出貨（動漫、資訊詞包開；迷因詞包合併後一起開）：只加詞的片，第 4 條在錯字回報改壞 0 時算過（含 0／0）。
- **回歸**：動漫五集、名單檢查集、資訊詞包檢查集、第一輪網路用語檢查集、迷因檢查集 0 改壞。
- **找出改壞的詞**：出貨標準或回歸有改壞時，二分（每次拿掉一半新詞，只重量有改壞的那幾個集合）找出造成的詞，拿掉後重量；拿掉的詞與原因記進研究紀錄。二分最多 4 輪。
- **記憶體與延遲**：在 Mac 閒置窗（load < 2）量引擎記憶體與每鍵延遲，對 main 報差值；記憶體多 5 MiB 以上或每鍵 p95 多 1 ms 以上就停。
- **實機**：維護者打 3–5 個詞，第一名等於 CLI。
- **合併關卡**：程式改動（`/code-review` ＋ fresh verifier ＋ CI）。

## 4. 順序、停止條件、預算、範圍外

- **順序**：這份契約過審 → A、B 先做成一個 PR（不等挖掘）→ C、D、E 挖掘與分類 → 第二個 PR。迷因詞包 PR（#293）可以先合併，A 的詞在它合併後、這一片合併前暫時打不出來（詞從來沒出貨過，不算退步）。
- **停止**：出貨標準二分 4 輪後仍不過；第二輪檢查集聊天 < 90%（停下來回報每一列沒打出的原因與原本的第一名，再問維護者）；記憶體或延遲超過 §3；挖掘在 GCP 超過 3 小時；量測超過下面的預算。
- **預算**：GCP 挖掘與兩次計數（C、D、E 的候選與它們的 X）≤ 3 小時；量測每個 PR 一次完整的 ≤ 1 小時，加上二分最多 4 次、每次只重量有改壞的集合、≤ 30 分鐘；Muse 用維護者的 Muse CLI（不另花錢；回 402 就停下來問）；分類用 subagent（訂閱額度，不用 API 金鑰）。
- **回滾**：兩個 PR 各自 revert 自己的 merge commit：A、B 那個 PR 回滾後 `slang-add.tsv` 與 `overlay-add.tsv` 回到第一輪的內容；C、D、E 那個 PR 回滾後回到 A、B 合併後的內容。其他層與詞包不受影響。
- **範圍外**：改核心與 App 的程式；名單層的人名（另一個 PR）；迷因詞包的冒犯詞（另一個 PR）；PTT 重抓（快照凍結）。

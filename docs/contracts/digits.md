## A.3 行為規則

### A.3.1 名詞與狀態（核心 `engine.rs`）

- **數字字母表** A＝`{0–9 . / -}`（標準排列：1ㄅ 2ㄉ 5ㄓ 8ㄚ 9ㄞ 0ㄢ -ㄦ .ㄡ /ㄥ；3ˇ 4ˋ 6ˊ 7˙）。
- **生效**：`self.english && !self.abbr && layout == Standard`（共用中英混打的開關，不要求單字表已載入；A.3.7）。不生效時以下全部不存在，逐位元同今天。
- **數字串 token**：一個字一個 token，讀音 `_punct_` ＋那個半形字（`_punct_2`、`_punct_.`…），固定詞是那個字，走 `insert_token`（2412）；判斷「是數字串 token」＝`_punct_` 後恰一個 `[0-9./-]`（現有 token 都不是：單按標點 `[ ] \ ' = \``、Shift 表全形、英文 token 只有字母、空白單位 `" "`、22a 是聲調符號）。Backspace、方向鍵、40 單位上限、`token_width`（1049）、解碼與重排的切段（`is_punct` 2462）、`total_score` 邊界全沿用標點 token。
- **串**（run）：從第一個進字母表的注音鍵起、連續的字母表鍵；記 `run_ctx`（串開始時的歷史詞 C＝`lm::history(context_key(left + 串前的顯示字串))`，`<s>` 若沒有漢字）與 `run_len`（含已吐出的）。串在邊界鍵、或尾段收進非字母表鍵、或尾段完成音節時結束。
- **緩衝**：串裡還沒變成 token 的鍵，最多 4 個（更早的鍵一定不可能屬於任何音節：音節最多三個符號加一個聲調，所以**第 5 個起的舊鍵立刻吐成 token**）。
- **切分**：緩衝的 n 個鍵分成「前 m 個是數字、後 t 個是音節尾段」（m＋t＝n，t ≤ 4）；尾段要**合法**：符號照聲介韻順序、是詞庫某個去聲調音節的前綴（引擎建構時從 `lex` 的讀音表做一份去聲調音節集合，`Lexicon` 加一個列出音節名稱的方法）；尾段最後一個鍵是聲調鍵（3 4 6 7）時必須是詞庫裡的完整音節，而且那個音節的詞條至少一個含漢字（learn.rs 的 `is_han`，開成 `pub(crate)`；「ㄅ」「ㄉ」這種注音字母詞不算）。t＝0（全數字）永遠是合法切分。
- **顯示**：被選中的切分：前 m 個鍵（加上已吐出的 token）顯示成半形數字，尾段顯示成注音欄位；`shown`（1781）的「未完成部分」＝緩衝的數字＋尾段符號，游標在後面。所以「2」在句首顯示 ㄉ、「下午2」可能顯示 2，「20」依語境顯示 20 或 ㄉㄢ（答覆 4）。

### A.3.2 評分用的機率（表 `data/lexicon/digits.tsv`，C 建；`Engine::new` 讀；**可有可無**：缺檔或格式不對時數字功能不生效、其他照舊，不回錯誤碼，A.8-3）

- 前文 C（v）＝`lm::history(context_key(串前的文字))`，和建表的 v 是同一個函式（C.6 第 1 項）；沒有漢字時是 `<s>`。
- `P(D | C)`＝(N(C→D) ＋ β·P(D)) ／ (N(C) ＋ β)，P(D)＝N(D)／T（`T` 列），C 沒有 `D` 列時＝P(D)；β＝1（C 量測用的值，寫死）。
- `P_len(m | 結束)`＝N(L=m)／N(D)；`P_len(m | 未結束)`＝N(L ≥ m)／N(D)。
- `P_ch(k)`＝N(C=k)／ΣN(C)。
- `P(w | v, D)`＝(N(v,D→w) ＋ γ·P(w | D)) ／ (N(v,D→·) ＋ γ)，分母是 `Q` 列，沒有 `Q` 列時 `P(w | v, D)`＝`P(w | D)`、沒有 `P` 列時分子的 N 是 0；`P(w | D)`＝(N(D→w) ＋ γ·P(w)) ／ (N(D) ＋ γ)，沒有 `W` 列時 N(D→w)＝0；P(w) 是模型的單字後備機率（Python `reference/proto/lm.py` 的 `unigram_back`，含 KN 混合；Rust 要算出同一個 f64）；γ＝1（寫死）。缺列的規則照 C.3。沒有模型時這一片不生效（和預測列一樣，沒有模型就沒有分數可比）。
- 全部用 log10，和 `lm.rs` 一致。

### A.3.3 切分的分數與選擇（每個字母表鍵、聲調鍵、空白鍵各算一次）

- **基準**：Python `experiments/digits/digits_score.py` 是這一節的參考實作，`experiments/digits/README.md`「契約沒定、這裡定下來的」清單（1–11、13、15、21b）是本節的一部分；Rust 和它不同時以它為準（A.4.1 #49 逐位元比對）。
- 切分 (m, t) 的分數 S＝lpD ＋ lpZ；d＝已吐出的數字鍵數＋m（A.8-1：串中延續時，m＝0 的切分 d 也可能 ≥ 1）：
  - lpD：d＝0 → 0（沒有 1−P(D|C) 這一項）；否則 log P(D | C) ＋ log P_len(d | t > 0 或這是邊界 → 結束；否則未結束) ＋ Σ log P_ch(k_i)（串的前 d 個鍵，含已吐出的）；相加順序：P(D|C)、P_len、再依鍵序加 P_ch。
  - lpZ：t＝0 → 0；否則 log Σ_{w 與尾段相容} P(w | C′)：d＝0 時 C′ 是詞語境 C，用**機率** `lm.prob(C, w, pb)`（不是 `word_by_id` 的 λ 混合分數：lpD 與數字語境都是機率，同一鍵的各切分才可比）；d ≥ 1 時 C′ 是數字語境 (v＝C, D)，用 A.3.2。「相容」用 `predict` 同一套（`by_prefix` 桶、`compat_prefix`，每個詞取最佳相容讀音的 lp 算 P(w)），加總是候選順序（`predict.Index` 的桶順序去重）上由左到右的一般浮點加法。尾段是完成的音節時「相容」＝讀音以那個完整音節開頭；完整音節要出現在某個含漢字詞條的讀音裡（任何字數）。
- **θ＝3**（C 的 R2）：尾段是**完成的音節**（聲調鍵或空白）時，不含任何數字（d＝0）的注音切分的分數加 θ 再比，含數字的注音切分不加；全數字切分（t＝0）的分數要**嚴格大於**最好的注音切分（加過 θ 的）才贏，否則取最好的注音切分（注音之間平手取尾段較長者）。θ 只保護「整串都當注音」的讀法：串裡已經有數字時，只是在定數字串在哪裡結束（C.6 第 3 項；`1984⏎` 才會是 1984 而不是 19＋啊）。**修訂三**：不在字母表的注音鍵（A.3.4）當場決定、之後改不回來，所以也是「完成」：不含數字的注音切分同樣加 θ 再取分數最大者（這時沒有全數字切分，平手規則照下一項，用加過 θ 的分數）。
- **其他鍵**：分數最大的切分。**平手**：目前顯示的數字總數不變的那個優先，沒有就取 t 較大者（偏注音）；串的第一個鍵沒有「目前顯示」，平手取注音。
- 同一串的評分每鍵重算、可以翻轉（「ㄅㄞ」→「198」→「1984」）；翻轉只影響緩衝，已吐出的 token 不動。
- 時間：每鍵最多 5 個切分、每個切分一次相容掃描（和一次 `predict` 同量級），只在緩衝非空時；既有的 p95 < 16 ms 照舊適用（A.4.4）。

### A.3.5 數字後的預測列（答覆 1；C 的 R1 已過）

- **尾段怎麼餵預測列**（A.8-2）：字母表鍵的注音尾段在緩衝裡、不在 `pend`。被選的切分 t > 0 時，尾段的鍵就是預測列的未完成單位（`recompute_pred` 把它當成 `pend` 一樣用）：d＝0（串裡還沒有數字）時就是今天的預測列（歷史照舊、單位＝尾段），所以中英混打開著時以 ㄅ ㄉ ㄓ… 開頭的部分注音預測列照舊出現；d ≥ 1 時用數字語境（下一條）。
- `recompute_pred`（1644）的游標起點：串前的顯示以數字串 token（或被選切分的數字）結尾時，歷史不是 `<s>` 而是**數字語境 (v, D)**，v＝`run_ctx`；後繼層＝N(v,D→w) > 0 或 N(D→w) > 0 的詞（`Table.successors(v)`）。**順序**（修訂一寫死，和 Python 基準相同）：有未完成單位時照 `digits_score.digit_tiers`：候選同 `predict` 的相容與桶，分數＝λ·log10 P(w | v, D) ＋ (1−λ)·lp（λ 是設定的 λ，lp 是詞庫分數），後繼層一層、其餘一層，各層照 `predict.det_key`（分數由大到小，同分依字數、讀音序、詞）排。實作：`predict.rs` 加 `predict_digits(idx, lm, table, v, units, limit)`，和 `predict` 同一套相容、桶、去重、排序，只換分數與後繼層；`recompute_pred` 的其他步驟（學習權重、過濾、去重、截 9）照舊。
- **沒有未完成單位**（串剛打完、切分是全數字、或剛吐完 token）時也有列（這是「下午3 → 點」的時機）：後繼層裡是詞庫詞的那些，分數＝log10 P(w | v, D)（不混詞庫分數，同 `digits_score.digit_rank_empty`），照 `det_key` 排，取前 9。
- **Python 參考與 fixture**：executor 在 `experiments/digits/digits_score.py` 加 `digit_row(table, lm, lex, idx, v, units, lam, limit=9)`，兩種情形都回傳排好的詞（用上面兩條的程式路徑，`digit_rank_empty` 的名次和它的位置一致，單元測試斷言），並在 `golden_digits.py` 加 `--pred` 產 `eval/golden/digits-pred.txt`（macOS 產；固定 12 個情境：前文空／「下午」／「價格」各配 `3`、`2 0`、`1 0 1` 加一個注音尾段等，檔頭記表、模型、詞庫的雜湊）。Rust 的預測列和它逐項相同（A.4.1 #44、#45）。這個 fixture 是 A 新增的，C 的 `digits-score.txt` 不動。今天沒有未完成音節時，游標起點不出列、只有長起點的列（V3 §11，`engine_predict.rs` 608–609 一帶；A.8-4 更正）；數字後的空單位列是游標起點新增的一種。
- 長起點照舊略過含 token 的範圍（1671）。**緩衝裡顯示成數字的鍵（被選切分 m ≥ 1、還沒吐成 token）也照 token 算**：它們之前、跨過它們的長起點與詞中起點都不出項目，只有游標起點那一列，也就是預測列恰好是數字語境列（修訂二；否則長起點項目會讀成「下午＋ㄢ」跳過畫面上的數字，選它時 `apply_pred` 的 splice 會把剛吐出的數字刪掉）。
- 列的項目選了（Tab／數字／`pick`／B 的 ↓ 清單）：被選切分的**前 m 個鍵**吐成 token（數字留下）；尾段（t 個鍵）照 `pend` 一樣被選到的詞消化掉、清空，不吐成數字；項目的 `start` 指吐完 token 之後的位置，再照 `choose_pred` 插入（修訂一；草稿寫「緩衝先吐成 token」會把尾段也變成數字）。

### A.3.6 ↓ 清單裡的另一種讀法（答覆 4「另一種讀法留在 ↓」；(d)）

- **音節剛由字母表鍵完成**（聲調或空白、注音贏）：記住尾段的鍵（`last_digits`，下一個改狀態的鍵清掉）。這時 ↓（或空白）開的清單＝B 的預測項目＋詞庫項目＋**最後一項那串數字**（例：句首 `8 4` → 啊；↓ 最後是「84」）；選它：拿掉那個音節、在原位逐字插入數字串 token。
- **緩衝剛吐成 token**（數字贏、或邊界吐出）且最後 ≤ 4 個 token 的鍵能組成含漢字詞條的完整音節：↓ 的清單在全形項之後加**那個音節的第一個詞條**（例：下午 `2 0 3` 判成數字後 ↓ → …、「3」、「３」、「膽」）；選它：拿掉那幾個 token、插入那個音節並固定那個詞（和英文窗的中文項一樣，不學）。
- 兩種都用「索引在清單的哪一段」判斷，不用長度欄位（B.3.1 的陷阱）。

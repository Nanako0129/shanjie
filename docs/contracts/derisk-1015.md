    - 再加上詞庫分數，以及以「在」結尾的詞比較多（570 對 36）。
  - 錯字回報第 112、113 列（數字、英文切斷前文）是同一個機制。

  - **模型檔上限是 trigram 當初沒進核心的主因**。這輪把上限當成要量的變數，不當成限制。

**E1e 相對熵剪枝（修訂四，2026-10-16；維護者「接著研究 trigram」，Fable 排序第一）**

- 起因：E1d 的增益隨次數截斷單調變小（書面淨值 T1 +40、T2 +38、T3 +15、T15 −1）。E1c 說明體積在條目數、不在每個次數的位元數。所以要換的是「留哪些條目」，不是編碼。
- 剪法：從 T1 的表（`.sjt3` 存了剪枝前的前文總次數）算每個條目的分數，留分數最高的 K 個；其他規則和 E1d 相同（保留的前文總次數不變、沒有保留條目的前文不存、檔頭與模型綁定不變），所以分布仍然歸一。
  - 分數用 Stolcke 相對熵剪枝的一階近似：`s(u,v,w) = c(u,v,w) · ln( P3(w|u,v) / (back3(u,v) · P2(w|v)) )`，P3、back3 是 T1 表上的值（E1 README 的插值式），P2 是 B0 的機率（`--no-classes`，KN 開、β 1，和 E1d 的 trigram 臂相同的低階）。剪掉一個條目會改變 back3 的這一項不算（近似；寫進研究紀錄）。同分照 (u, v, w) 的 id 排序，結果可重現。
  - K 取三檔：分別等於 E1d 的 T15、T3、T2 的條目數（從 `tri-t*.sjt3.json` 讀），標籤 H15、H3、H2。前文數會和同名的 T 檔不同，大小照實報。
- 判讀：和 E1d 相同的臂、集合（凍結的檔，逐一核對雜湊與列數）與規則；BASE 是 B0ship 的 rowstats。a = 0.05 ÷ 3 ≈ 0.0167。
- 只報、不判：每個集合各一行；H_k 對同條目數的 T_k 一行（同大小，剪法的差）；每檔的前文數、條目數、總大小、無損壓縮與 zip 後的大小（`compress.py`）。

**E1g 書面設定不開 KN、加 trigram（修訂五，2026-10-16；維護者選擇題「書面設定關 KN 加 trigram」）**

### E4 標點、數字、英文之後不重設前文（n-gram；P1a 找到的根因）

- 現況：解碼器在標點、數字、英文 token 之後把下一段當句首（`<s>`），左文也只取漢字（s3e 規則）。
- 量兩種做法，Python 參考實作、`--context`、開 KN：
  - **(a) 只改解碼**：兩臂都用出貨的 model-v6。
    - 逗號、頓號這類句中標點之後，用標點前最後一個詞當前文；句號、問號、驚嘆號照舊重設。
    - 對照臂就是出貨的解碼。
  - **(b) 計數與解碼一起改**：兩臂都用 E1a 的計數、bigram、不加私有條目、出貨的 λ 與 β = 1，只差在對應這一步。
    - 對照臂：B0。
    - 新臂：B0m。計數時把每段數字與每段英文換成同一個記號 `<X>`，解碼時數字、英文 token 之後用 `<X>` 當前文。
    - 計數與解碼呼叫同一個切分函式。
- 判讀：(a)、(b) 各自對自己的對照臂比。
  - 主判讀：調參集＋判讀五集串接後，至少一種設定**顯著為正（a = 0.025）**。0.025 是 0.05 除以 2 種做法。
  - 守門格：調參集與判讀五集的**每個集合各自**、兩種設定，加上兩種設定的 discordtune，全都不能顯著為負。
  - 兩者都過 → 寫核心契約（s3e 的前文規則與計數）。
  - 沒過 → 記錄；數字前文的錯字列改由錯字回報追蹤。
- 另外報一個子集合：前文含句中標點、數字或英文的列，也就是錯字回報第 112、113 列那一型。只報，不判。
- **修訂一（2026-10-15，實作後發現；維護者選擇題「另建跨逗號的公開評測集」）**：
  - 起因：評測列的句子欄只有漢字，前文也幾乎都是乾淨的漢字。所有集合裡 (a) 能改到前文的只有錯字回報 12 列，discordtune 4,958 列是 0 列（`experiments/derisk-1015/e4/subset.py`）。照上面的主判讀，要 7:0 這種結果才判得出來，等於沒有檢定力。
  - 加一個公開評測集 **e4ctx**，產生方式如下。
    - **選哪些文字**：和 `experiments/s2/build_tune.py` 用同一組鍵。
      - cvtune 取 `is_tune(raw)` 為真的行（判斷時用未轉換的原文）。
      - wikitune 取 `bc.articles(305_000)` 裡序號 300,000–304,999 的條目。
    - **文字處理**：完全照 `build_tune.py` 在取 `HAN` 之前的步驟。保留標點、數字、英文。
      - cv：`bc.convert(raw)`。
      - wiki：`TEMPLATE` 三次 → `MARKUP` → `bc.SENT` 切分 → `bc.convert`。
      - 一個 `SENT` 的匹配算一個「原始句子」。
    - **怎麼切成一列**：句子裡出現句中標點，或出現一段數字或英文、而且後面接漢字時：
      - 前文＝那個標點、數字或英文之前的文字，加上它本身。
      - 句子＝後面接著的那一段漢字。
      - 「句中標點」就是 `experiments/derisk-1015/e4/punct_ctx.py` 的 `MID`；「數字或英文」就是 `experiments/derisk-1015/e4/subset.py` 的 `WORDLIKE` 字元類別。
      - 句子 2–25 字，讀音照 `tools/readings.py`；CHECK 列與拼不出的列丟掉。
    - **兩個子集**：`e4ctx-punct`（前文以 `MID` 字元結尾）與 `e4ctx-alnum`（前文以 `WORDLIKE` 字元結尾）。

      - 每個原始句子最多取 1 列。
    - **程式與測試**：產生程式放在 `experiments/derisk-1015/e4/`。單元測試從上面兩個模組 import `MID` 與 `WORDLIKE`，不自己重新定義。測試要斷言：

      - punct 子集的前文結尾是 `MID` 字元，alnum 子集的前文結尾是 `WORDLIKE` 字元；
      - 句子只有漢字。
    - 輸出放在 repo 外的快取，雜湊記進 README。
  - E4 只比兩種解碼或兩種計數，沒有選值，所以用調參集的原始句子不會污染判讀。
  - 判讀改成：主判讀的串接**加上** e4ctx（`e4ctx-punct` 再接 `e4ctx-alnum`，接在判讀五集後面）。McNemar 只算兩臂結果不同的列，所以沒受影響的列不會稀釋結果。門檻（a = 0.025）與守門格不變；e4ctx 兩個子集各自也是守門格。
  - (b) 的對照臂與新臂一樣在 e4ctx 上跑（B0、B0m），不另寫規則。

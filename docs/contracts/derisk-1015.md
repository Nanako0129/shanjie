## 0. 起因

- 錯誤桶表（`docs/triage.md` 的 full-run，出貨設定）：聊天錯列有 89%、書面有 93% 落在 C 桶，也就是正解在候選裡、只是排序錯了。其中：
  - D2c（小模型也選錯）：聊天 1,659 列、書面 1,263 列。
  - C1 功能字：1,035／1,147 列。
  - C3 斷詞：620／734 列。
- tinylm-v5（`docs/contracts/model-v6.md` §2.7，研究紀錄 2026-10-15）：
  - D2c-(i)÷D2c 合計 0.275。事先寫好的判讀是「融合與模型兩條路都是候選」。
  - 積極檔在兩種設定都等於標準檔，δ 這個旋鈕已經用完。
- 維護者 2026-10-15 的方向：
  - Discord：「先把 n-gram 做好應該更重要」「反而是 n-gram 壓不下來」「如果要做模糊輸入，讀更多的上下文，可能要做 trigram」。
  - 看過 Fable 的排序後，選擇題回答「提高模型上限試試看，其他照你建議，都做」。
  - 排序與理由記在研究紀錄同日一節。
- 體積：
  - model-v6 的模型檔：`bigram.sjlm` 83,445,569 bytes、`tinylm.sjtl` 14,638,352、`classes.sjc` 5,656,826、`kn.sjkn` 1,414,052。
  - v0.4.3 的 App zip（`shanjie-0.4.3.zip`）是 52,198,049 bytes。
  - SJLM 的每個 bigram 條目是 `next_id u32 + count u32`，8 bytes、未壓縮。
  - Discord 上有人提議參考壓縮的做法，所以壓縮列為 E1c。
- 原本建議的「功能字分類器」改成 E4，理由：
  - P1a（`docs/contracts/p1a-confusion.md` §0，研究紀錄 2026-10-11）已經做過分類器，第 1 階段就觸發了停止規則。
  - P1a 找到的根因在 n-gram 那一側：每段漢字（包括逗號、數字、英文之後）都從句首 `<s>` 算起。
    - P(在｜<s>) 是 P(再｜<s>) 的 26 倍。
    - 再加上詞庫分數，以及以「在」結尾的詞比較多（570 對 36）。
  - 錯字回報第 112、113 列（數字、英文切斷前文）是同一個機制。
- 第 10 輪的結果（研究紀錄）：
  - trigram 在書面有幫助、在聊天沒有。
  - 維基 trigram 當時只算得了 3 萬篇，受限於記憶體。
  - 為了 100 MB 的模型檔剪到 ≥ 8 之後，書面也不顯著了，所以核心只做 bigram。
  - **模型檔上限是 trigram 當初沒進核心的主因**。這輪把上限當成要量的變數，不當成限制。

## 2. 共同定義（各實驗的判讀規則只用這裡的詞）

- **基準設定**：model-v6＋classes-v4＋kn-v1＋名單層，也就是 PR #159 的出貨設定。Python 參考實作一律帶 `--context`。
- **集合**：
  - 調參集：cvtune、wikitune。
  - 判讀五集：dev302、打字測驗（typing76）、錯字回報、lytune、wikitypo。
  - 私人守門：discordtune，只由 main 跑、只帶回數字。
  - 不讀保留集。
- **設定**：每條規則**聊天、書面兩種設定各自判**，不合併兩種設定。
- **比較**：`tools/evalstats.py compare BASE CAND --net` 的一行。
  - 多個集合合併時，把各集合的 rowstats 依上面列出的順序串接、列號從 1 重編。串接由 `experiments/derisk-1015/` 的小工具做，有單元測試；兩邊用同一個順序。
  - 每一組比較都記錄哪一份是 BASE。
- **淨值**：改對 − 改壞。
- **顯著為正（門檻 a）**：改對 > 改壞，而且精確 McNemar p < a。
- **顯著為負**：改壞 > 改對，而且精確 McNemar p < 0.05。
- **只用 n-gram**：E1、E4 的判讀不接 tinylm。接上 tinylm-v5 的數字只報，不進判讀。
- **參考實作的錨點**：每個實驗對 `reference/proto/` 的延伸都放在 `experiments/derisk-1015/`。
  - 在「全關」設定下（不加 trigram、照舊重設前文、不縮寫），延伸版跑 dev302 兩種設定的摘要行，含 `top1_sha256`，必須和 `reference/proto/lm_eval.py` 在同一個模型、同一組選項下的摘要行逐字相同。
  - 不同就是停止條件（§4）。

**E1b 模型與選值**

- **判讀（trigram）**：T_k（選定點）對 B0（選定點），判讀五集串接，兩種設定各自比。

    - 至少一種設定**顯著為正（a = 0.0125）**。0.0125 是 0.05 除以 4 檔。
    - 另一種設定不顯著為負。
    - 兩種設定的 discordtune 都不顯著為負。

  - 通過 → 「只改參數」的小片列為候選。
  - 這條不影響 trigram 的判讀。
- **對照（只報）**：
  - B0（出貨 λ、β = 1）對出貨的 model-v6：說明重算計數與私有條目的差異。

**E1c 壓縮（Discord 的提議）**

- 對象：B0，以及通過的最小 T_k（都沒通過就用約 200 MB 那檔）。

  - (ii) 有損：在 (i) 之上，把次數量化成 8 位元與 4 位元的對數級距。每張表一組級距，讀回時還原成該級距的代表值。

### E4 標點、數字、英文之後不重設前文（n-gram；P1a 找到的根因）

- 現況：解碼器在標點、數字、英文 token 之後把下一段當句首（`<s>`），左文也只取漢字（s3e 規則）。
- 量兩種做法，Python 參考實作、`--context`、開 KN：
  - **(a) 只改解碼**：兩臂都用出貨的 model-v6。
    - 逗號、頓號這類句中標點之後，用標點前最後一個詞當前文；句號、問號、驚嘆號照舊重設。
    - 對照臂就是出貨的解碼。
  - **(b) 計數與解碼一起改**：兩臂都用 E1a 的計數、bigram、不加私有條目、出貨的 λ 與 β = 1，只差在對應這一步。
    - 對照臂：B0。
    - 新臂：B0m。計數時把每段數字與每段英文換成同一個記號 `<X>`，解碼時數字、英文 token 之後用 `<X>` 當前文。
    - 計數與解碼呼叫同一個切分函式。
- 判讀：(a)、(b) 各自對自己的對照臂比。
  - 主判讀：調參集＋判讀五集串接後，至少一種設定**顯著為正（a = 0.025）**。0.025 是 0.05 除以 2 種做法。
  - 守門格：調參集與判讀五集的**每個集合各自**、兩種設定，加上兩種設定的 discordtune，全都不能顯著為負。
  - 兩者都過 → 寫核心契約（s3e 的前文規則與計數）。
  - 沒過 → 記錄；數字前文的錯字列改由錯字回報追蹤。
- 另外報一個子集合：前文含句中標點、數字或英文的列，也就是錯字回報第 112、113 列那一型。只報，不判。

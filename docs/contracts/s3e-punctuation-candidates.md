# S3e 契約：標點候選清單（使用者 2026-10-04）

使用者實測 s3d（標點進組字區）通過後要求：「應該學 Mac，標點符號也要有候選清單」，並選擇「**執行時讀系統檔**」：輸入法在使用者自己的 macOS 上讀 Apple 的標點候選表，repo 與 Release 都不放任何 Apple 的資料（不散布）。

**怎麼算做到**：使用者打「，」後按空白鍵或 ↓，出現「，、　《〈＜」這類候選（第一個是「，」本身），選「、」後組字區的「，」變成「、」，按 Enter 一起送出。由使用者在本機建置實測。

## 1. 資料來源

- 系統檔：`/System/Library/PrivateFrameworks/CoreChineseEngine.framework/Versions/A/Resources/CIMPunctuationCandidates.plist`（2026-10-04 在 macOS 27.0.1 上找到並讀過）。XML plist，最外層是字典：鍵是一個標點字，值是替代標點的陣列。例：`，` → `、 　 《 〈 ＜`；`。` → `⋯⋯ 　 ・ · ． 》 〉 ＞`；`「` → `『 【 〖 〔 ［ ｛`；`：` → `；`。
- 這是私有框架的路徑，系統更新可能改位置或格式（**未驗證**哪些版本有這個檔）。讀不到、解析失敗、結果是空的，或核心拒收時，**用核心內建的預設表**（§3，取自小麥詞庫，MIT）；這些情況殼都記一筆固定文字的 log（R2：靜態字串加回傳碼），不讓功能靜靜消失。
- 殼不把系統表寫到任何地方，只在記憶體裡交給核心。

## 2. 殼（Swift）

- `ShanjieKit` 新增 `PunctuationTable.load(from: URL) -> String?`：用 `PropertyListSerialization` 讀 plist，轉成核心要的文字格式（§3）。驗證規則和核心相同：鍵必須是單一 Unicode scalar；鍵或任何一個替代是空字串、或含 `\t`、`\n`、NUL 的項目整筆略過；值不是字串陣列的略過；陣列略過不合法元素後若沒有剩下任何替代，整筆略過。結果沒有任何項目時回 `nil`。
- `Shell` 的建構子多一個參數 `punctuationTable: URL`，預設是 §1 的系統路徑（測試可以傳別的路徑）。每次建好引擎後（`init` 與切換排列重建時）：
  - `load` 回 `nil` → 不呼叫核心（核心用預設表），記 log「punctuation candidates: system table unavailable, using the built-in list」；
  - 呼叫 `shanjie_engine_set_punctuation` 回非 0 → 記 log「punctuation candidates: core rejected the system table」加回傳碼（核心保持預設表）。

## 3. 核心與 C ABI

- 新增：
  ```c
  int32_t shanjie_engine_set_punctuation(ShanjieEngine *engine, const char *table); // UTF-8；每行「標點\t替代1\t替代2…」
  ```
  - 格式：以 `\n` 分行；空行（含結尾的換行）略過；每行以 `\t` 分欄，第一欄是鍵（恰一個 Unicode scalar），其後至少一欄替代，每欄非空。同一個鍵出現多次時，後面的取代前面的。整份表只有空行時視為不合法。
  - 回傳碼照 s3a §6：0 成功、1 指標是 NULL、2 不是 UTF-8 或格式不合法（某行沒有替代欄、鍵不是單一字元、某個替代是空字串、沒有任何有效行、整個表超過 64 KB 或超過 1,000 行）、4 panic。失敗時引擎原本的表不變。
  - 成功時**取代**整張表（不是合併）：系統表沒有列到的標點就沒有替代。
  - 呼叫後組字區不重算（不影響目前顯示，同 `load_lm`）。`reset` 不清這張表（同 LM 與設定）。
  - 包 `catch_unwind`，錯誤不帶任何輸入內容（R2）。
- 預設表（沒呼叫過 `set_punctuation`，或呼叫失敗）：**寫在核心程式碼裡的常數**，內容取自 `data/lexicon/mcbpmf-data.txt`（MIT，已隨附；詞庫載入時會略過 `_` 開頭的行，所以不從已載入的詞庫取），程式碼註解標出行號：

  | 標點 | 預設替代 | 來源（mcbpmf-data.txt 行號） |
  |---|---|---|
  | ， | 〈 《 ︿ ︽ | `_punctuation_Standard_<`，1093–1097 |
  | 。 | ． 〉 》 ﹀ ︾ | `_punctuation_Standard_>`，1098–1103 |
  | ： | ； | `_punctuation_:`，1044–1045 |
  | 「 | 『 《 〔 ｛ 〈 【 〖 | `_punctuation_{`，2302–2308（`_punctuation_[` 只有「，借用同一顆鍵 Shift 後的清單） |
  | 」 | 』 》 〕 ｝ 〉 】 〗 | `_punctuation_}`，2313–2319 |
  | 、 | ＼ ／ | `_punctuation_\`，1105–1106 |
  | 『 | 「 《 〔 ｛ 〈 【 〖 | 本專案自訂（2026-10-05 起 Shift+[ 打『，借用「的清單） |
  | 』 | 」 》 〕 ｝ 〉 】 〗 | 本專案自訂（同上，Shift+]） |
  | ‘ | ’ | 本專案自訂（單按 ' 打 ‘，沒有系統表時仍打得出右引號） |
  | “ | ” | 本專案自訂（Shift+' 打 “） |
  | ？ ！ （ ） ～ ｜ ＋ ＝ · | （無） | 各自的 `_punctuation_` 只有本身；後四個是 2026-10-05 起的新按鍵（s3a §4） |
- **候選**（s3d §3 的「游標緊鄰標點右邊 → 不開候選」改為）：游標左邊緊鄰的記號是標點（或游標為 0 而第一個記號是標點）時，空白鍵與 ↓ 開啟候選：清單第一個是**原本按鍵打出的標點**，接著是表裡這個標點的替代，去重；沒有替代時清單只有它自己。分頁、選取、數字鍵照 s3a 規則 3–8。
- **選擇**：選中的字串取代那個標點記號的顯示（固定詞的 `word` 改成它），讀音維持 `_punct_<原本的標點>`，所以再開候選時清單不變、第一個仍是原本的標點。它仍是標點記號：仍是句子邊界（s3d §4）、仍一格（s3d §1）。
- **多字元的替代**（例 `⋯⋯`）：組字區顯示與游標位置要正確。目前 `view` 假設「每個記號顯示一個字」（`ponytail:` 註解）；改成依記號計算：音節記號一個字，標點記號是它固定詞的字數。`total_score` 判斷標點改看記號本身（`_punct_` 讀音），不再看字（`is_punct_word` 刪除），因為替代標點不一定在 s3a §4 的集合裡。

## 4. 驗收

1. 核心（`core/tests/engine.rs`，不需要系統檔）：
   - 預設表（沒呼叫 `set_punctuation` 的引擎）：打「，」後空白鍵 → 候選是「，〈《︿︽」；`「` 的候選包含「『」；「？」只有它自己。
   - `set_punctuation("，\t、\t《\n")` 後：打「你好，」空白鍵 → 候選是「，、《」；選第 2 個 → 組字區「你好、」，Enter 送出「你好、」；選完再開候選，清單相同、第一個仍是「，」。
   - 多字元：表給「。\t⋯⋯」，選「⋯⋯」→ 組字區「你好⋯⋯」，游標（`cursor_utf16`）在最後；之後再打一個音節，游標與顯示都正確。
   - 標點選了替代後仍是句子邊界：沿用 s3d 的「他長，在換」句，把「，」換成「《」後仍是「他長《在換」，而且 `total_score` 和換之前相同（標點判斷看記號，不看字；「《」不在 s3a §4 的集合裡）。
   - 突變：讓 `view` 回到「每記號一個字」時，多字元那條測試失敗。
2. FFI（`core/tests` 的 ffi 測試或 `abi_smoke.c`）：NULL → 1；非 UTF-8 → 2；沒有替代欄的行、空替代、鍵多於一個字、只有空行 → 2，且失敗後原本的表仍有效；超過上限 → 2；正常表（含結尾換行與空行）→ 0；重複的鍵後者生效。C 冒煙測試加一次 `set_punctuation` 呼叫。
3. 殼：
   - fixture plist（自己寫的，不是 Apple 的檔）的轉換測試：含一個替代裡有 `\t` 的項目被略過、一個鍵是兩個字的項目被略過、空結果回 `nil`。
   - 系統檔測試：讀**本機實際的系統檔**、轉換、交給真的核心，斷言回傳 0，且「，」的候選含「、」。檔案不存在時**測試失敗**並說明路徑（不靜靜跳過）。實作時先在 CI 量一次 runner 上有沒有這個檔：沒有的話，這個測試改成只在本機跑的 `make` 目標，由 verifier 在本機執行，記在 §7。
   - `Shell` 用一個不存在的 plist 路徑建立：LogTests 的擷取方式找到「system table unavailable」那句，且「，」的候選等於預設表「，〈《︿︽」。
4. `make test`、`cargo test --release`、`scripts/check-app.sh` 全綠；dev302 top-1 不變。
5. 使用者實測（見開頭）。

## 5. 範圍外

全形／半形切換；英文模式的標點；系統表裡非標點的鍵（例：`＃`→`３` 這類數字對照）會照收，但只有在組字區出現那個標點時才用得到；標點候選的學習（S4）。

## 6. 停止條件、預算與回滾

- 停止：系統檔在使用者的機器上讀不到或格式不同；FFI 的錯誤路徑測試有任何一條存活的突變；dev302 top-1 變動。
- 預算：實作加審查最多三輪。
- 回滾：revert 本片的 merge commit。ABI 只新增函式，舊的呼叫不受影響。

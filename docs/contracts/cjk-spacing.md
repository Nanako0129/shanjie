# 中英文之間自動加空格（俗稱「盤古之白」）

狀態：READY（2026-10-18，plan-verifier 第一次審查）。

## 0. 起因與名稱

- Discord 回饋串 2026-10-18：三位使用者想要漢字和英文、數字之間自動有空格，其中一位建議做成設定開關。維護者同日決定開這一片，並用選擇題決定兩件事：英文與數字都加；送出時開頭也看游標前一個字補空格。
- 名稱：「盤古之白」出自 pangu.js 的 README，是半開玩笑的暱稱，不是正式術語。W3C《中文排版需求》（clreq）講的「中西文間距」是排版上約四分之一字寬的間距；輸入法只能插入真的空白字元，做不到那種窄間距。所以設定項目用直白的名稱「中英文之間自動加空格」，說明文字再提「盤古之白」。

## 1. 規則（殼 `ShanjieKit`；核心不改）

- **只改善解自己送出的文字**：也就是 `Session.apply(o)` 的 `o.commit`。殼呼叫 `client.insertText` 的只有這一處（`s3b.md`「`commit` 非空」那一條）。
  - 核心送出、學習、前文用的字串都不變：學習用的是核心內部的送出文字，殼加的空白不進核心。
  - 組字區顯示的 marked text 不加空白，只有送出時加。
- **字元分類**：
  - 漢字：`LeftContext.isHan`，和核心的 `is_han` 相同。
  - 半形英數：ASCII `A–Z`、`a–z`、`0–9`。
  - 其他字元（全形與半形標點、符號、空白、注音符號、全形英數、emoji 等）一律不觸發，也不會在它們旁邊加空白。
- **送出的文字裡面**：一個漢字和一個半形英數直接相鄰時（兩個方向都算），中間插入一個半形空白 U+0020。例如：
  - 「我用claude寫」變成「我用 claude 寫」。
  - 「2026下午3點」變成「2026 下午 3 點」。
  - 已經有空白的（例如中英混打打出的「我用 claude 寫」）不變。
  - 「（2026）」、「，claude」也不變：標點旁邊不加。
- **開頭**：令 p 是這次送出之前、游標前面的最後一個字元。p 是半形英數而送出文字的第一個字元是漢字，或 p 是漢字而第一個字元是半形英數時，在開頭補一個空白。p 的來源：
  - 組字開始時殼本來就會讀游標前最多 32 個 UTF-16 單位（`Session.send` 的 `leftContext()`，`learning-gate` 那條規則）。在同一次讀取裡另外記下原始文字的最後一個字元，不只是漢字尾巴。
  - 讀不到時 p 是「無」：沒有插入點、client 還留著 marked text、範圍長度是 0，或學習暫停（`applyLearningGate` 判定暫停，例如安全輸入或排除的 App）。暫停時照現在的規則不讀 client，所以也不補開頭空白。
  - 同一個組字裡前面已經送出過文字時（例如碰到 40 個單位的上限先送出一部分），p 改成上一次送出的最後一個字元。這裡用的是加空白之後的字元。
  - p 是「無」時開頭不補。
- **結尾**：不加空白，因為不知道接下來會打什麼。
  - 已知限制：在 Mac 上切換中英文用的是系統的 Caps Lock（`s3b.md` §3），切到英文時善解不在作用中。之後在其他輸入法打的英文，前面不會有空白。反過來的情況（先用 ABC 打英文，再切回善解打中文）由上面的「開頭」處理。
- **關閉時**：`insertText` 收到的字串和 `o.commit` 逐字相同，和現在一樣。

## 2. 設定與介面

- `SpacingStore`（`var spacing: Bool?`，nil 表示沒設過，當作關），照 `AbbreviationStore` 的做法：
  - `MemorySpacingStore` 給 Kit 與測試用。
  - `DefaultsSpacingStore` 只在 `Shanjie` target，UserDefaults 鍵 `cjkSpacing`。
  - `Shell.init` 加這個參數；`Shell.spacingOn` 加 setter，和其他開關一樣發設定改變的通知。
- 設定視窗：放在「選字」區塊，「英文的顯示」選擇器之後。
  - 開關文字「中英文之間自動加空格」。
  - 下一行說明（`.font(.caption)`，和中英混打的說明同樣式）：「在漢字和半形英文、數字之間自動加一個空格（俗稱「盤古之白」）。只改善解送出的文字。」
  - 不受中英混打開關或排列影響，永遠可以操作（ABC 打的英文、數字列打的數字都會用到）。
- 輸入法選單不加這一項，只在設定視窗。

## 3. 驗收

- **單元測試**（`macos/Tests/ShanjieKitTests`）：
  - 純函式 `CJKSpacing.apply(previous: Character?, text: String) -> String` 的表格測試，至少涵蓋：
    - 上面 §1 的每個例子。
    - p 是英文字母、數字、漢字、空白、全形標點、無，各一個。
    - 補充平面的漢字（例如 U+20000）兩邊。
    - 只有標點的送出。
    - 空字串。
  - Shell／Session 測試：
    - 開關關著時 `insertText` 收到的字串等於 `o.commit`（現有測試照舊通過）。
    - 開著時送出加了空白。
    - 同一個組字分兩次送出時，第二次的開頭依第一次送出的最後一個字元判斷。
    - 學習暫停時不補開頭空白，但送出文字裡面照樣加。
    - store 沒設過時是關。
  - 突變（每一項都要讓某個測試失敗；build error 不算）：
    - 拿掉開頭的判斷。
    - 拿掉數字。
    - 標點旁邊也加。
    - 關著時也加。
    - 部分送出後不更新 p。
- `make test-swift` 通過；core 沒改。
- **實機**（維護者，備忘錄，開關打開）：
  1. 中英混打打「我用claude寫」→ 送出「我用 claude 寫」。
  2. 打「2026下午3點」→「2026 下午 3 點」。
  3. 用 ABC 打 `claude`，Caps Lock 切回善解打「寫」→「claude 寫」。
  4. 關掉開關重做 1 → 「我用claude寫」，沒有空白。

## 4. 範圍外

- 結尾空白，以及其他輸入法打的字。
- 半形符號（`%`、`@`、`#`、`$`、括號等）的規則。pangu.js 有，這一片不做。
- 全形英數、改組字區顯示、核心與 FFI、Windows 與 Linux 移植版。
- 整理已存在的多餘空白。

## 5. 停止條件、預算

- 實機如果發現某些 App 回報的游標前文字不可靠，導致開頭多出空白，先停下來問，不自行加 App 清單。
- 實作一次交給 executor；合併關卡照「改動分級」的程式一級：`/code-review`＋fresh verifier＋CI。

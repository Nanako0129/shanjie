# 中英混打第二片：英文留在組字區、打字時就顯示英文（選項）

狀態：READY（2026-10-14 收尾審查）；plan-verifier 兩次 REVISE 都照改（§8）。接在 `docs/contracts/zhen-mixed.md`（PR #149 已合併）之後。

## 0. 起因

- 維護者實機試中英混打（2026-10-14）：「我以為是直接顯示英文出來」。現在的做法是打字時組字區一直顯示注音（`rust` 顯示成「ㄔㄧ」），按空白才跳英文窗。
- 維護者選擇題選「組字區直接變英文」，接著：「做成選項好了，可以允許設定兩種」。
- 維護者同日接著：「但是轉英文不能斷掉組字」。現在英文窗選了英文項，會把整個組字區（前面已組好的中文＋英文）一起送出，組字就斷了。
- 這一片做兩件事：(A) 選了英文，英文**留在組字區**，可以接著打中文，最後一起送出；(B) 中英混打開著時多一個設定「英文的顯示方式」：**打字時就顯示**（新，預設）或**按空白才顯示**（PR #149 的做法）。中英混打本身仍預設關。

## 1. 規則（核心 `core/src/engine.rs`）

### 1.0 英文留在組字區（A）

- 英文窗選了英文項（1–9、Enter、滑鼠），不再送出：清掉未完成音節與影子，然後在游標處插入一個**英文 token**，顯示的字就是選的那一項（`rust`／`Rust`／`RUST`），游標在它後面，組字區繼續。
- **英文 token 的讀音**固定是 `PUNCT_PREFIX` ＋ 選的那一項（例如 `PUNCT_PREFIX + "rust"`），用 `insert_token` 插入、固定詞就是那一項；判斷「英文 token」＝標點 token 而且它的文字全是 ASCII 英文字母（標點不會是這種文字）。
- 因此它和第 2 條的標點 token（`docs/contracts/s3e.md`）一樣：切開解碼的段落、它後面的字以「前面不是漢字」處理（看前文選字與學習的前文都一樣）、Backspace 一次刪掉整個 token、方向鍵一次跳過、Enter 和其他送出時照順序一起送出、算進組字區的單位上限（到上限照現行規則全部送出）。英文本身不學（不產生以英文為詞的學習紀錄）。
- **兩個和標點不同的地方**（寫死，兩種實作不能不一樣）：
  1. 緊接在英文 token 後面按 ↓（`open_candidates` 的「緊接標點」那一支；修訂三起空白不再開清單，見 §1.3e）：列出這個 token 的寫法清單：照打的原樣（token 目前的文字）在前，再接小寫、首字大寫、全大寫，去掉重複的；選了就把 token 換成那一項；不查標點的替代表。自動固定的 token 另外多一個中文項（§1.3c）。
  2. 第 8 條的「後面的音節」：句首的詞後面緊接英文 token 時，學習與查詢的鍵用固定的 `NEXT_PREFIX` ＋ `PUNCT_PREFIX` ＋ `"en"`（不含英文字本身）；換算放在 `learn::next_key` 裡（`record_key` 與改選時的 `pick_key` 都經過它），所以解碼、送出、預測列、改選用的鍵一致：`next` 是英文 token 的讀音（`PUNCT_PREFIX` 加上全是 ASCII 英文字母的文字）時，換成 `PUNCT_PREFIX + "en"`。
- 英文窗的中文項不變（照 PR #149：在游標處變成固定詞）。
- 選了英文之後預測列照「選了候選」的現行規則重算。

### 1.1 顯示條件 D（B）

「打字時就顯示」開著時，每個按鍵處理完之後判斷 D；D 成立時組字區把未完成音節的注音換成影子的字母。D 成立的條件全部要滿足：

1. 影子在記錄（`shadow_on()`：中英混打開、單字表已載入、不是可省略韻母、標準排列）；
2. 游標在尾端、只有一個未完成的單位（和 `english_trigger` 相同：`cursor == syls.len()`、`pend_prev` 是空的）；
3. 影子至少 3 個字母；
4. 覆寫條件和觸發相同：`shadow_over ≥ 2`，或 `shadow_over ≥ 1` 而且未完成音節（一聲）不在詞庫；
5. 單字表裡有字以影子開頭（影子是某個字的前綴，含整個字）。

D 不成立時顯示照舊（注音）。D 每個按鍵重新判斷，不記狀態。

### 1.2 顯示

`shown()`：D 成立時，游標位置插入影子的字母（`shadow` 依序），不插入 `pending()`；游標在字母之後。候選窗、預測列照現行規則（D 不改變它們）。

### 1.3 按鍵（D 成立時只有 Enter、Backspace 與「接不下去的注音鍵」和現在不同）

| 按鍵 | D 成立時 |
|---|---|
| 空白鍵 | 不變：`english_trigger()` 成立（影子是完整的單字）就開英文窗；不成立就照第 10 條處理未完成音節（D 之後重新判斷） |
| Enter（含 Shift+Enter） | 送出組字區顯示的整串：已組好的字（含英文 token）＋影子的字母，**不加空白**；清掉未完成音節與影子；學習照 Enter 的送出規則（英文本身不學）。這和 Enter 平常送出整個組字區相同，只是未完成的部分送字母而不是注音 |
| Backspace | 畫面上是字母，所以不照第 11 條（它刪顯示位置最後的符號，和最後一個字母不一定對得上）：丟掉影子最後一個字母，再把剩下的字母依第 9 條重放，欄位和覆寫次數都由重放重建（欄位永遠等於那些鍵打出來的）；然後重新判斷 D，不成立就顯示重放出來的欄位的注音。D 不成立時照第 11 條 |
| 注音符號鍵（不含聲調鍵、空白鍵），而且**影子本身是單字表的完整單字**、影子加上這個鍵**不是**任何單字的前綴（修訂二，維護者 2026-10-14「接著打中文英文就不見了…應該要自動保持」） | **自動固定**：先把影子的字母照 1.0 變成英文 token（和英文窗選第一項、小寫原樣相同：留在組字區、讀音 `PUNCT_PREFIX + 字母`、學習與前文照 1.0），清掉未完成音節與影子，再把這個鍵當成新音節的第一個鍵照第 9 條處理（影子從這個鍵重新開始記）。影子不是完整單字（例如 `windo`）、或加上這個鍵仍是某個字的前綴（例如 `win` 後面的 `d`）時照舊 |
| 其他所有鍵（其餘注音鍵、聲調鍵、Esc、標點、方向鍵…） | 和現在完全相同；處理完再判斷 D（例如 Esc 清影子，D 不成立，回到注音；聲調鍵把音節打完，影子清掉） |

- **所有「照組字區顯示的樣子送出」的路徑都一樣**：`shown()` 在 D 成立時給字母，所以 Enter 與 `reset(ResetMode::Commit)`（殼在失去焦點時呼叫）都送出字母，不送注音。
- **有窗開著時，窗的規則優先**：英文窗或候選窗開著時，Enter 照窗的規則（英文窗選中的項目照 1.0 留在組字區），不走上表「D 成立時的 Enter」。
- **英文窗開著時打注音鍵**（修訂二）：不是選項目的數字鍵的注音符號鍵，先把英文窗**目前選中的項目**照 1.0 變成英文 token（和按 Enter 選它相同），關窗，再把這個鍵當成新音節的第一個鍵照第 9 條處理。所以 `r u s t ␣` 之後直接打中文，英文會留著。標準排列的聲調鍵（3、4、6、7）在英文窗開著時是選項目的數字鍵，照現在的規則（超出項目數的忽略），不走這一條。
- **自動固定碰到組字區上限**（修訂二）：自動固定（含上一點）插入英文 token 時，若達到 40 個單位的上限而送出整個組字區，送出的文字放在**觸發這個鍵的那一次輸出**的 `commit` 裡，同一次輸出裡這個鍵已經在清空的組字區開始新音節（`preedit` 是那個符號）。不得把送出的文字留到之後的輸出。

### 1.3b Shift＋字母開始一段英文（修訂二，維護者 2026-10-14「shift W也會跳脫組字」）

中英混打開著（`shadow_on()` 成立；兩種顯示設定都適用）時，**Shift＋英文字母（A–Z）**不再照 s3a 第 13、21、22 條處理（忽略、送出再直通、直通），而是開始或延續一個「英文段」。中英混打關著或倚天排列時，這三條照舊，照蘋果注音直接送出。

- **開始**，依當下狀態：
  - **組字區空的，或有字但沒有未完成音節**：在游標處開一個新的英文段，第一個字母是 Shift 打的大寫。
  - **有未完成音節，而且影子全是英文字母**：包括 D 成立、字母在畫面上的時候；也包括影子不是完整單字的時候，例如 `windo`、`i`。這時影子的字母照打的樣子變成英文段的開頭，未完成音節的符號清掉，再接上這個大寫字母。所以 `i`＋Shift+P＋`hone` 是 `iPhone`，`rust`＋Shift+W 是 `rustW`。
  - **英文窗開著**：關窗，照上一條處理。英文窗是從影子開的，所以影子的字母變成英文段的開頭。
  - **有未完成音節，但影子含非字母**（數字、標點鍵打出的注音）**或影子是空的**：照 Esc 丟掉那個音節的符號與影子，再照第一條開新的英文段。
- **單位**：英文段開著時不算組字區單位。結束變成 token 時用 `insert_token` 插入，照它的上限規則：插入後到 40 個單位就送出整個組字區（含這個 token）。送出的文字放在**結束英文段的那個鍵那一次輸出**的 `commit`，和 §1.3「自動固定碰到組字區上限」同一條規則；這個鍵接著在清空的組字區照原本的規則處理（自動固定的字母開始新音節、標點插入標點、第 33 個字母開始新的英文段）。空白與 Enter 結束時若因此送出，就到此為止（空白照樣吃掉，Enter 不直通、不另外送出）。
- **進行中**：英文段開著時，英文字母鍵（有沒有 Shift 都算，照打的大小寫）接在英文段後面，不進注音欄位、不記影子。組字區照樣顯示，游標在英文段之後。最多 32 個字母，第 33 個字母先結束英文段，再開一段新的英文段，從這個字母開始。
- **結束並保留**：英文段照 1.0 變成英文 token，讀音 `PUNCT_PREFIX + 字母原樣`。判斷「英文 token」時大小寫字母都算。學習、前文都照 1.0。結束的情況：
  - **空白鍵**：結束。這個空白鍵被吃掉，不插入空白、不直通。
  - 〔修訂三拿掉〕英文段**不自動固定**：沒按 Shift 的英文字母也一律接在英文段後面（照打的大小寫），要回中文先按空白結束（維護者 2026-10-14：自動固定之後 Backspace 一次就刪掉整個英文，很挫折）。
  - **其他鍵**（聲調鍵、數字鍵、標點、Enter、Tab、方向鍵）：先結束，再照原本的規則處理這個鍵。例如 Enter 一次送出整個組字區，標點插入標點。
- **Backspace**：刪英文段最後一個字母；刪到沒有字母就關掉英文段，那個單位也一起拿掉。
- **Esc**：拿掉整段英文、關掉英文段，組字區其他部分不變。
- **送出**：`reset(ResetMode::Commit)` 與 Enter 照組字區顯示的樣子送出，英文段的字母原樣。

### 1.3c 英文 token 改選（修訂二，維護者 2026-10-14「要保持送出的英文還能選字…支援向下選字」）

- 游標緊接在英文 token 後面（可以用方向鍵移到那裡）時，↓ 照 1.0 開出這個 token 的寫法清單（修訂三起空白插入空白，§1.3e）。有未完成音節時方向鍵與 ↓ 照現行規則不動，要先打完或刪掉那個音節。
- **自動固定產生的 token**（§1.3 的兩種自動固定，以及英文窗開著時打注音鍵）：清單是 1.0 的寫法（原樣就是小寫，所以是小寫、首字大寫、全大寫），再加一個中文項。中文項＝自動固定當下組字區欄位上的未完成音節（`pending()`，一聲）在詞庫裡的第一個詞條，和英文窗的第四項同一規則；那個音節不在詞庫就沒有中文項。
  - 選中文項：token 換成那個中文字（照第 10 條插入、固定那個詞），英文不見。
  - 自動固定判斷錯了，這樣就能改回中文，不用刪掉重打。
  - 所以這種 token 記住那個音節（不記按鍵：第 11 條的 Backspace 刪的符號和影子刪的字母不一定對得上，重放按鍵會和英文窗的第四項不同）。
- **英文段（§1.3b）與英文窗選的 token**：清單只有 1.0 的寫法，沒有中文項。

### 1.3e 空白鍵插入空白（修訂三，維護者 2026-10-14）

- 游標緊接在**英文 token 或空白單位**後面、沒有未完成音節、沒有開著的窗時，空白鍵在游標處插入一個半形空白，作為一個單位：讀音 `PUNCT_PREFIX + " "`、固定詞 `" "`，和標點 token 相同（切開解碼段落、後面的字以「前面不是漢字」處理、Backspace 一次刪掉、方向鍵一次跳過、Enter 與其他送出照順序一起送出、算進單位上限）。
- 所以英文段結束是「第一下空白斷開（被吃掉，§1.3b），第二下空白才是空白」，例如 Shift+W＋`indows`＋空白＋空白＋「很好」送出「Windows 很好」；只按一下就是「Windows很好」。
- 空白單位**沒有清單**：緊接在它後面按 ↓（或游標在 0、它在最前面時按 ↓）什麼都不開，鍵被吃掉、狀態不變。
- 游標在 0、最前面是英文 token 或空白單位時按空白鍵，**不**開寫法清單（吃掉、狀態不變）；寫法清單只用 ↓ 開（最前面是 token 時 ↓ 照 §1.0 開）。
- 這一節的規則只在中英混打開著（`shadow_on()`）時成立；關著時，英文 token 後面的空白鍵照修訂三以前的行為（第 16 條，開寫法清單）。
- 學習的鍵：空白單位跟英文 token 一樣算同一種鄰居，句首的詞後面緊接它時，第 8 條的鍵是 `^>_punct_en`（`learn::next_key`），不另開 `^>_punct_ `。
- 其他位置的空白鍵照舊（未完成音節照第 10 條、漢字後面照第 15／16 條、標點後面照「緊接標點」）。

### 1.3f 英文段的回饋（修訂三，維護者 2026-10-14 選「粗底線＋一行提示」）

- `ShanjieOutput` 結尾加兩個欄位 `english_run_utf16_start`、`english_run_utf16_len`：英文段開著時是那段字母在 `preedit` 裡的起點與長度（UTF-16），其他時候都是 0。`core/include/shanjie.h` 與 `docs/contracts/s3a.md` 的 ABI 一節同步：兩個新欄位各有註解（`preedit` 裡的 UTF-16 位置、沒有英文段時是 0），`shanjie_engine_set_english` 的註解改寫成修訂三的行為（英文段不自動固定、英文 token 與空白單位後面的空白插入空白單位、寫法清單只用 ↓ 開）；既有欄位與函式簽名不變。
- 殼：組字區的 marked text 在那個範圍用粗底線（`NSUnderlineStyle.thick`），其他照舊細底線；英文段開著時，候選窗的位置顯示一行提示「空白：英文斷開」（和預測列同一種視窗樣式，不能選、不吃鍵）。英文段結束（空白、送出、Esc、Backspace 刪光、其他結束的鍵）時粗底線與提示一起消失。英文段開著時沒有候選與預測列（修訂二的審查修正），提示不和它們搶位置。選了直式候選窗時，提示用直式預測列的樣式（`vertical` 2），不用橫條；提示沒有數字（連數字的位置都不留）、沒有展開箭頭、不能選：點它不會送到核心（`Session.candidateSelected` 回傳 false）。從展開的網格換成提示時直接清掉重畫，不播收合動畫。提示對齊英文段的起點（`english_run_utf16_start`），整段英文段只向輸入 App 問一次行位置（`lineRect`），不隨每個字母重問。
- 粗底線是 App 畫的，有些 App 可能不顯示〔推論，實機時看〕；提示是善解自己的視窗，每個 App 都看得到。

### 1.4 「按空白才顯示」與關閉

「按空白才顯示」時 D 一律不成立，打字當下的顯示和 PR #149 相同（1.0 的「英文留在組字區」兩種設定都適用）。中英混打關著時這兩個設定都沒有作用。

### 1.5 單字表的前綴查詢

第 1.1 條第 5 點每個按鍵最多一次查詢，成本不能隨單字表線性成長（例如排序陣列＋二分搜尋）；`load_english` 的上限、錯誤碼與「失敗保留舊表」不變。

## 2. 設定與介面

- 文件：`docs/contracts/s3a.md`（中英混打的規則表加 D 與 Enter 這一列；修訂二：第 9 條加「自動固定」的例外；第 13、21、22 條加「中英混打開著時 Shift＋字母開始或延續英文段」的例外；英文窗表「其他鍵」那一列加「注音鍵先固定選中的項目」；英文 token 的改選清單（含自動固定的中文項）；都指到本契約 §1.3、§1.3b、§1.3c；修訂三：英文段不自動固定、英文 token 與空白單位後面的空白鍵插入空白、改選只用 ↓、輸出的兩個新欄位，指到 §1.3b、§1.3e、§1.3f）、`core/include/shanjie.h`（修訂三的兩個欄位與 `shanjie_engine_set_english` 註解的改寫，§1.3f）、`docs/contracts/zhen-mixed.md`（狀態列指到這份）、`docs/contracts/settings-window.md`（新的選擇）、`docs/PLAN.md` 的中英混打一項。

## 3. 量測（打中文時的「顯示誤觸」）

- `english-sim`（`cli/src/english.rs`）加一個選項 `--inline`：同樣的打字模型，另外計算「打中文時某個按鍵之後 D 成立」的音節數（同一個音節只算一次）。**D 由引擎回報**（一個 `#[doc(hidden)]` 的查詢，和 `english_open()` 同一種做法），工具裡不能有第 1.1 條條件的另一份；輸出多一欄 `inline_per_1000_mean`（每千音節、5 個種子的平均）與 `inline_per_1000_max`。不開 `--inline` 時輸出完全不變。
- 集合與設定照 `docs/contracts/zhen-mixed.md` §4.3（cvtune、wikitune 選門檻用；dev302、typing76 驗證），出貨的單字表（`3352d050…`），`--p 0.02`（覆寫與 Backspace 兩種修正）與 `--p 0`。在 Mac 以外的機器跑。
- **門檻**：`--p 0` 是 0；`--p 0.02 --repair overwrite` 的 `inline_per_1000_mean` 在 cvtune、wikitune 都 ≤ 2。
- 不過門檻時的**事先寫好的收緊**：第 1.1 條第 4 點改成一律 `shadow_over ≥ 2`，重量一次；還不過就停（§6）。
- **自動固定的誤觸**（修訂二）：`english-sim --inline` 另外計算打中文時發生「自動固定」（§1.3）的次數，由引擎回報（和 D 同一種 `#[doc(hidden)]` 查詢），輸出再多兩欄 `autokeep_per_1000_mean`、`autokeep_per_1000_max`。模擬器在**每個鍵之後、比對欄位之前**問引擎這個鍵有沒有觸發自動固定；有的話記一次，然後按 Esc（清掉新開始的那個音節的符號）、Backspace（刪掉英文 token），再把被打斷的那個音節**不含錯打**地從頭重打，讓後面的列照常進行（寫進工具註解）。重打時若又觸發自動固定照樣記（不含錯打時預期不會發生）。**門檻**：`--p 0` 是 0；`--p 0.02 --repair overwrite` 的 `autokeep_per_1000_mean` 在 cvtune、wikitune 都 ≤ 0.5（和中英混打觸發誤觸的門檻相同）。不過門檻就停，回報數字再議（不預設收緊方式）。

## 4. 驗收

1. 引擎測試（`core/tests/engine_english.rs` 加或改，真實詞庫與 `eval/golden/english-tiny.txt`）：
   - **Shift＋字母英文段**（修訂二，§1.3b）。每一條至少有一個會讓它失敗的突變：
     - 組字區空：Shift+W＋`indows` → 組字區 `Windows`，沒有送出。
     - 「我在用」＋Shift+W＋`indows`＋空白：組字區「我在用Windows」，`Windows` 是 token，沒有開窗、沒有送出。再打「很好」、Enter，一次送出「我在用Windows很好」。
     - 同上，不按空白直接打 `c`：英文段變成 `Windowsc`（修訂三：英文段不自動固定）；Backspace 一次 → `Windows`；空白 → token；再打「很好」、Enter，送出「我在用Windows很好」。
     - 「按空白才顯示」設定下，上一條的結果相同（英文段在兩種設定下一樣）。
     - 空白兩下：「我在用」＋Shift+W＋`indows`＋空白＋空白＋「很好」、Enter → 送出「我在用Windows 很好」；第二下空白插入的空白是一個單位，Backspace 一次刪掉它；英文 token 後面按 ↓ 開寫法清單，按空白插入空白、不開清單。
     - 輸出欄位：英文段開著時 `english_run_utf16_start`／`len` 指向那段字母（前面有中文字、標點 token 時也對），結束後兩個都是 0；FFI 測試斷言 struct 最後兩個欄位。
     - `Windows`＋Shift+X：接成 `WindowsX`，不固定。
     - `i`＋Shift+P＋`hone`＋空白 → `iPhone` token。
     - `r u s t`（字母顯示中）＋Shift+W → 英文段 `rustW`。
     - `r u s t ␣`（英文窗開著）＋Shift+W → 英文段 `rustW`、英文窗關掉。
     - `1`（ㄅ）＋Shift+W：丟掉 ㄅ，英文段 `W`。
     - 「我在用」＋Shift+W＋`in` 再 Backspace → 「我在用Wi」；再 Esc → 「我在用」，英文段關掉。
     - 32 個字母之後第 33 個字母：前一段變成 token，新的一段從第 33 個字母開始。
     - Shift+W＋`indows` 再按 `，`：先結束、再插入標點。
     - 組字區有 39 個單位（例如 39 個標點）時 Shift+W＋`indows`＋空白：這一次輸出的 `commit` 是原本的 39 個單位加 `Windows`、`handled` 1，組字區空。同樣 39 個單位時 Shift+W＋`indows` 再按 `，`：`commit` 相同，組字區只剩「，」。
     - 中英混打關著時，Shift+W 照第 21 條送出組字區再直通。
   - **英文 token 改選**（修訂二，§1.3c）：
     - `g o o g l e` 再 `j` 自動固定之後，Backspace 刪掉 ㄨ（游標在 token 後面、沒有未完成音節），按 ↓：清單依序是 `google`、`Google`、`GOOGLE`、中文項（ㄍㄠ 的第一個詞條）。選中文項，token 換成那個中文字。`r u s t` 的殘餘音節 ㄔㄧ 不在詞庫，同樣的步驟清單只有三種寫法。
     - 英文段 `Windows` 的 token 按 ↓：清單依序是 `Windows`、`windows`、`WINDOWS`，沒有中文項。
     - `i`＋Shift+P＋`hone`＋空白 的 token 按 ↓：清單依序是 `iPhone`、`iphone`、`Iphone`、`IPHONE`。
     - 突變「自動固定的 token 不記原本的按鍵」讓它失敗。
   - **殼**（修訂三，`make test-swift`）：英文段開著的輸出（兩個欄位非 0）送進殼時，marked text 在那個範圍是粗底線、其他細底線，提示 view 顯示「空白：英文斷開」；欄位回到 0 時提示隱藏、底線都是細的。突變「不畫粗底線」「提示不隱藏」各讓一個斷言失敗。
   - **英文窗開著時打注音鍵**（修訂二）：`r u s t ␣` 再 `j`，組字區是「rust＋ㄨ」，`rust` 是英文 token；突變「先關窗清影子再處理」讓它失敗。
   - **自動固定碰到上限**（修訂二）：組字區先放到差一個單位滿，再 `r u s t` 然後 `j`：這一個鍵的輸出 `commit` 非空、以 `rust` 結尾，`preedit` 是 `ㄨ`。
   - **模擬器**（修訂二）：`cli/tests/english_sim.rs` 跑一列會觸發自動固定的合成資料，工具不會因「欄位不同」中止，`autokeep` ≥ 1，那一列最後送出的文字和沒有自動固定時相同。
   - **自動固定**（修訂二）：打「兩個中文音節」再 `r u s t`，接著打一個接不下去的注音鍵（例如 `j`ㄨ）：組字區是「兩個中文字＋rust＋ㄨ」，`rust` 是英文 token（和英文窗選 1 的狀態逐項相同）；再打完一個中文音節、Enter，一次送出全部。影子是某字的前綴但本身不是完整單字時（`windo` 再 `j`），照舊不固定。加上這個鍵仍是前綴時（表裡有 `win` 與 `windows`：`w i n` 再 `d`），不固定、繼續顯示字母。聲調鍵、空白鍵不觸發自動固定。「按空白才顯示」時不會自動固定（D 不成立）。突變「拿掉完整單字的條件」「拿掉接不下去的條件」各讓一個斷言失敗；
   - **英文 token 的兩個寫死行為**：學習開著，句首打一個兩字詞的讀音（例如 `ㄨㄛˇ ㄕˋ`），改選成不是預設的那一個（例如 `我試`，改選前後不同才會學），接 `r u s t ␣ 1`、Enter：學習檔的位元組裡那筆紀錄的鍵正好是 `NEXT_PREFIX + PUNCT_PREFIX + "en"`、詞是改選的那個（不含 `rust`）；再打一次同樣的鍵（不改選），組字區出現改選過的詞（證明查詢用同一個鍵）。突變「只在送出時換算」與「鍵用 `PUNCT_PREFIX + 英文字`」各讓一個斷言失敗；緊接在 `rust` token 後按 ↓，候選窗正好是 `["rust","Rust","RUST"]`，選 `2` 後組字區是 `Rust`；同一個位置改按空白則插入一個空白單位、不開候選窗（修訂三）。各一個會失敗的突變；
   - **送出路徑**：`r u s` 之後 `reset(ResetMode::Commit)` 送出 `rus`；`r u s t ␣` 之後按 Enter，選的是英文窗的第一項、沒有送出、`rust` 留在組字區；
   - **英文留在組字區**：先打兩個中文音節，再 `r u s t ␣ 1`：沒有送出、組字區是「兩個中文字＋rust」、游標在最後；接著打「編譯」再 Enter，一次送出「中文＋rust＋編譯」；Backspace 在 `rust` 後面一次刪掉整個 `rust`；`rust` 後面那個詞的前文與學習照「前面不是漢字」（和標點 token 相同的斷言）；組字區單位上限照現行規則。PR #149 的 `left_composition_is_committed_too` 等「選英文就送出」的測試改成這個行為；
   - `r u s` 之後組字區是 `rus`（影子 3 個字母、覆寫 1 次、殘餘不在詞庫、`rust` 以 `rus` 開頭），`t` 之後是 `rust`，空白開英文窗，`1` 之後 `rust` 留在組字區；
   - 同樣的鍵在「按空白才顯示」時，組字區是注音（和 PR #149 相同）；
   - D 成立時 Enter 送出已組好的字＋字母，不加空白；
   - D 成立時 Esc 回到注音、再空白照第 10 條；Backspace 讓影子少一個字母後重新判斷；
   - 影子不是任何字的前綴時（例如覆寫過但字母組合不在表裡）顯示注音；
   - 影子少於 3 個字母時顯示注音；
   - 倚天、可省略韻母、中英混打關、游標不在尾端時，D 都不成立；
   - 每一條規則一個會失敗的突變（看結束碼與斷言，編譯錯誤不算）。
2. FFI 與 C 冒煙：新函式的回傳碼；`abi_smoke.c` 加一段。
3. 殼：設定存取（沒有值是 true）、選擇在開關關掉或倚天時反灰、每次建引擎都把值送進去。
4. 不變：中英混打關時所有 golden 與重播逐位元組不變；`replay_with_english_on` 在「打字時就顯示」下也是 302 列送出相同（重播是打中文，D 不會出現在送出結果裡），p95 < 16 ms。
5. §3 的門檻；數字進研究紀錄。工具的 D 由引擎回報：把引擎第 1.1 條第 4 點拿掉的突變會讓 cvtune `--p 0.02` 的 `inline_per_1000_mean` 改變。
6. 保留集：收尾的 fresh verifier 照規則跑一次（中英混打預設關，選字結果應不變）。
7. 實機（維護者，≤ 15 秒）：開中英混打、「打字時就顯示」，`imeshot` 先打「我在用」，再逐鍵打 `r` `u` `s` `t`：`s` 之後的截圖組字區是「我在用rus」，`t` 之後是「我在用rust」；空白看到英文窗；`1` 之後組字區是「我在用rust」、沒有送出；再打「編譯」、Enter，送出「我在用rust編譯」。第二段（修訂二）：「我在用」＋`r u s t` 之後**不按空白**直接打「編譯」、Enter，同樣送出「我在用rust編譯」；「你用」＋Shift+W＋`indows`＋空白＋「好」、Enter，送出「你用Windows好」。第三段（修訂三）：Shift+W＋`indows` 打到一半截圖，那段英文是粗底線、候選窗位置有「空白：英文斷開」；按空白後粗底線變細、提示消失；再按空白出現空白；在瀏覽器（Chrome）裡也打一次，看粗底線有沒有顯示（沒有也不擋，提示仍在）。改成「按空白才顯示」後打 `r u s t`，組字區是「ㄔㄧ」。

# 契約：設定視窗改成左側清單

狀態：修訂二，收尾審查 READY；實作後的 /code-review 修正見 §6（2026-10-15）。

## 0. 起因

- Discord 回饋（2026-10-15，附截圖）：v0.4.3 的設定視窗在筆電上從選單列一路佔到 Dock，最下面的「選字記憶」被 Dock 蓋住。
- 原因（讀程式）：`SettingsWindowController.fit()` 直接用 `NSHostingView.fittingSize` 設內容高度，沒有上限；`docs/contracts/settings-window.md` §2.1 也沒有寫高度的上限。之後加了英文、語意校正強度等設定，內容越來越高。
- 維護者：「設定的patch先出」「重新設計設定頁」，選擇題選「左側清單」（像「系統設定」：左邊一列分類，右邊是那一類的設定）。

## 1. 要做到什麼、怎麼看到

- 設定視窗左邊一列分類，右邊顯示選到的那一類。視窗在任何螢幕上都不超出可用範圍（不被選單列、Dock 蓋住），放不下的內容可以捲動。
- 設定項目、文字、灰掉規則、預設值都不變；`SettingsModel` 不動。
- **怎麼看到**：
  - `make test-swift` 全過（設定模型的殼層測試不變）；
  - 使用者實機（§3）：在筆電內建螢幕打開設定，視窗整個看得到；點每一類，右邊換成那一類，每一項照舊有效。

## 2. 改動

### 2.1 版面

- 左欄是固定寬度的 `List(selection:)`（`.sidebar` 樣式），四類，順序與內容如下（每一類右邊仍是 `.grouped` 的 `Form`，原本的段落標題保留）。不用 `NavigationSplitView`：它的左欄可以收合，而這個視窗沒有工具列或「顯示方式」選單能把它叫回來（/code-review）。選取不會變成空的（點左欄空白處或 ⌘點不會取消選取），換類時右邊從最上面開始：

| 分類 | 內容（原本的段落） |
|---|---|
| 一般 | 「鍵盤」（鍵盤排列）、「聊天／書面」（切換方式、說明、個別設定的 App） |
| 選字 | 「選字」整段（即時預測、可省略韻母、英文、敏感字詞、語意校正、強度、動漫與遊戲詞、資料更新行） |
| 外觀 | 「外觀」整段（候選窗方向、玻璃深淺、預覽） |
| 選字記憶 | 「選字記憶」整段（狀態列、不要備份、清除…） |

- 左欄每一項是系統的 `Label`（文字＋SF Symbol），外觀用系統預設；第一輪不調任何視覺參數，之後照實機回饋一輪改一處。
- 預設選「一般」。視窗不釋放（`isReleasedWhenClosed = false`），同一次執行裡再打開時停在上次選的分類；不存到 UserDefaults。
- 背景、標題列、置中、帶到前面、層級都照 `settings-window.md` §2.1，不改。

### 2.2 尺寸

- 寬度：左欄寬度（具名常數）加上原本的內容寬度 420。
- **量法**：每一類的 `Form` 各自放進一個不顯示的 `NSHostingView`，加上 `.fixedSize(horizontal: false, vertical: true)` 讀 `fittingSize` 的高度，四類取最大值。畫面上的 `Form` 不加 vertical fixedSize，所以放不下時可以捲動。畫面上只畫選到的那一類，所以不從畫面上的 hosting view 量。量測用的 hosting view 暫時加進視窗裡（隱藏）：不在視窗裡量，每列會多算約 4.5 pt；在視窗裡量仍比實際畫的少約 3 pt，所以加 4 pt 的餘量（/code-review 量測）。畫面上的 hosting view 不加內容尺寸的限制（`sizingOptions = []`），視窗大小只由下面的規則決定。
- **高度**：視窗的 frame 高度（內容加上標題列）＝ min(最高那一類的高度＋標題列高度, 螢幕 `visibleFrame` 的高度)。切換分類時視窗大小不變。
- **用哪個螢幕**：`show()` 用滑鼠所在的螢幕（和置中相同）；重算時用視窗目前所在的螢幕。
- 視窗開著時螢幕參數改變（Dock、解析度、文字大小、拔掉螢幕）也重算高度並夾回（/code-review）。
- **位置**：`show()` 設好大小之後置中。「個別設定的 App」清單變長或變短時重算高度，之後把 frame 夾回那個螢幕的 `visibleFrame` 裡（超出下緣就往上移、超出上緣就往下移），所以長高之後也不會跑到 Dock 下面。

## 3. 驗收

- `make test-swift` 全過。
- 實機（使用者，筆電內建螢幕；安裝由 main 執行）：
  1. 從輸入選單打開「善解設定…」：視窗整個在螢幕裡，上緣在選單列下面、下緣在 Dock 上面，左邊四類，選在「一般」。
  2. 依序點四類：右邊換成那一類，視窗大小不變。
  3. 「選字」頁關掉再打開「即時預測」，輸入選單的勾跟著變；「外觀」頁拖玻璃深淺，預覽跟著變。
  4. 「選字記憶」頁按「清除選字記憶…」，跳出原本的確認（按取消）。
  5. 關掉再打開，停在上次的分類。
  6. **超出上限的路徑**：「系統設定 → 顯示器」選比較大的文字（讓可用高度變小），或在輸入選單把夠多個 App 勾成個別設定，再打開設定視窗：上緣在選單列下面、下緣在 Dock 上面，右邊捲得到最下面一項（「一般」頁的最後一個 App；「選字記憶」頁的「清除選字記憶…」）。之後把顯示器設定改回原本的。
  7. **重算的路徑**：在可用高度沒被佔滿的情況下（第 6 步之前，或把顯示器設定改回之後），先把設定視窗往下拖到下緣剛好在 Dock 上面，再到另一個 App 從輸入選單勾「這個 App 用聊天設定」：清單多一列，視窗往上移，下緣仍在 Dock 上面（沒有夾回的話，下緣會跑到 Dock 下面）。

## 4. 範圍外

- 不改任何設定項目、文字、預設值，不加新設定。
- 不做 SwiftUI `Settings` scene 或「系統設定」整合（`settings-window.md` §0 的理由仍成立）。
- zhen-inline（PR #153）新增的設定項，在那一片合併時放進「選字」類，衝突由那一片處理。

## 5. 停止條件、預算、限制

- **停止條件**：
  - 實機上左欄看不到或點了沒反應；
  - 視窗仍超出可用範圍；
  - 設定視窗開著時打字或候選窗的行為有任何改變。
- **預算**：實作 1 次＋修正 1 次；外觀照使用者的實機回饋收斂。
- **限制**：agent 不安裝、不啟動 App、不呼叫 TIS、不在 .app 裡執行任何東西、不碰 `~/Library` 與鑰匙圈。
- **回退**：這一片只動畫面，revert 那個 PR 即可。

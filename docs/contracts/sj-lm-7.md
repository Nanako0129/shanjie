# 契約：通語 SJ-LM-7（規模待定）——常開詞庫自己計數、讀音修正、口語語料（草稿）

狀態：**過審**（2026-10-24；plan-verifier 三輪，最後一輪只剩 §4 的一句矛盾，改完維護者選「視為過審」；原本的選項維護者同日選定；修訂一處理第一次 REVISE 的十項，修訂二處理第二次的四項）。前提：pack-oov（PR #276）合併，選用詞包的哪些詞不走通語統計已經由詞包第 4 欄標好（`docs/contracts/pack-oov.md` 第 1b 節）。

## 0. 依據（維護者的決定與量過的事）

- **方向**（維護者 2026-10-23，通語計畫的選擇題；Fable、Argon 報告在維護者本機）：只對常開詞庫（小麥＋萌典補詞＋名單）計數、選用詞包詞的計數另外決定（下一條）；繁體句不套大陸用語轉換；修分數倒掛；加口語語料。單字讀音與疊加層讀音修正「等 model-v7 一起」。下一版通語的代號是 SJ-LM-7。
- **選用詞包詞的計數**（維護者 2026-10-24）：Fable 建議「詞庫去重、計數保留」取代「拿掉選用詞包詞的計數」→ 兩臂都量再定（§2.1）。量過的事實：pack-oov 把通語認得的詞包詞當未知詞時，對 main 的動漫名字 22／25（淨 −3），改壞的是通語認得的名字（莉茲 90 次、蘭琪 123、艾蓮 121）；拿掉計數的那一臂會讓兩萬個名字都變成這樣（Fable 的推論，要量）。
- **書面 KN**（維護者 2026-10-23）：書面開 KN、β 0.75 當 SJ-LM-7 要量的一臂，現在不單獨出貨（研究分支 `exp/kn-research`）。
- **萌典**：維護者 2026-10-23「用萌典或開源詞典建詞庫，我們不算改作，這我覺得可以放寬」。
- **口語語料**（2026-10-24，探針結果在研究紀錄）：g0v `#rand0m`（CC0）相對 cc0-sentences 新增 16,756 句；PTT 試抓 7 個看板，內文 94,720 句、推文 219,939 句（維護者「PTT直接抓吧，不用問」，之後選「熱門看板 × 最近 300 頁」、每秒 10 次）；OASST2 繁體 3,615 句、WildChat 全量 22,755 句，不用。挑句兩臂（全收、Moore–Lewis）、常談重算當一臂、萌典 ≥ 2 次、單位上限 50 句、倒掛字主讀音高於又讀、記憶體 +40 MiB、GCP NT$2,000，都是維護者同日選的。
- **已知的資料問題**（Argon、Fable 10-23 實測）：
  - 小麥基底 3,584 個破音字裡 3,063 個前兩名讀音同分，`readings.py` 平手時取檔案順序；9 個字 −6.8 底分倒掛（鈸、乜、掇、鉈、癘、嘁、誒、溴、跩）。
  - `build_overlay.py` 不查萌典，`overlay-add.tsv` 裡萌典有收的 41,075 詞中 5,236 詞讀音和萌典第一讀音不同。
  - `experiments/s2/build_counts.py` 對繁體句也套 OpenCC `TWPhrases`（「插件」被換成「外掛」）。

## 1. 要做到什麼、怎麼看到

- 出貨的通語換成 SJ-LM-7：計數只來自常開詞庫的詞（加上 §2.1 選定那一臂的詞包詞），讀音修正後的詞庫，繁體句保留原用詞，口語語料加量。
- **怎麼看到**：出貨標準四條對現行出貨不退步，聊天要有看得到的進步（§3）；動漫與名單照 §3 的關卡、資訊詞包檢查集只報；實機打「插件」「伊莉絲」與錯字回報的幾列。

## 2. 改動

### 2.1 計數詞表與選用詞包（兩臂）

- 常開詞庫＝小麥基底（`mcbpmf-data.txt`）＋萌典補詞（§2.1a）＋疊加層＋變調列＋名單。計數詞表從這一份產生；指紋條目照舊由 main 在私有流程加回。
- **臂 A（拿掉動漫詞包詞）**：動漫詞包詞不進計數詞表，它們全是通語沒看過的詞，核心照 pack-oov 處理（`PACK_OOV = PACK_ACG`：強制詞不封頂，其他詞包詞封頂但不扣未見分）。**資訊詞包詞留在計數詞表**（資訊詞包不在 `PACK_OOV`，拿掉會被扣 `UNSEEN_OVERLAY_PENALTY`）。強制標記留著，由下一條重算。
- **臂 B（保留計數、詞庫去重）**：動漫與資訊詞包詞照 model-v6 的規則進計數（`count_lexicon.py` 的衝突讀音規則照舊），但不進常開詞庫。
- **兩臂都對 SJ-LM-7 重算詞包處置**：用該臂的計數重新凍結 `acg-counts.tsv`（`build_acg_pack.py --freeze-counts` 現在只收 model-v6 的雜湊、一般建置也核對釘住的計數表雜湊：PR 1 給 `--freeze-counts` 加 `--expected-model SHA`，預設仍是 model-v6，既有「計數表被改→中止」的測試照舊通過；釘住的計數表雜湊常數和新的 `acg-counts.tsv` 一起在 PR 2 換），重跑 `build_acg_pack.py --regrade`（強制詞、`kept_caps` 都跟著新計數；臂 A 的動漫詞次數都是 0，「通語認得就不強制」不會成立，處置過的讀音上的詞全部強制）。接著重跑 `detect_collisions`（動漫、資訊、名單），`--recheck --recheck-packs acg,it` 對該臂的模型重驗。
- 兩臂用同一份語料快照、同一個建置配方，只差計數詞表。

### 2.1a 萌典補詞

- **落點**：`tools/build_overlay.py` 加一個來源「萌典補詞」，輸出照舊寫進 `data/lexicon/overlay-add.tsv`。不新增檔案，Rust、Python 的載入與 `build-app.sh`、`check-app.sh` 都不改。
- **挑詞**：萌典有收、不在小麥基底、疊加層、名單、任何詞包（`data/packs/*-add.tsv` 的字串一律排除，維持 pack-oov「詞包字串和各層沒有交集」）、在 §2.4 語料快照裡**子字串**出現 ≥ 2 次（不在詞庫的詞斷不出來，所以數子字串；維基 20 萬篇＋所有口語檔）。讀音取萌典第一讀音。
- **分數**：同字數的 `length_scores`（不加手動詞的 0.75）。
- **測試**：`tools/test_build_overlay.py` 加一條：合成的萌典條目，出現 2 次進、1 次不進、是詞包字串不進，分數等於同字數 `length_scores`。分數只是檔案值，核心載入路徑不變，所以 Rust 不加測試（既有 `overlay-add.tsv` 載入測試涵蓋）。

### 2.2 繁體句不套大陸用語轉換

- `build_counts.py` 對判為繁體的句子只做字形層（異體字表 `VARIANTS`、`POST_TRAD`），不套 `TWPhrases`；簡體句照舊。單元測試：「插件」在繁體句保留、在簡體句照舊轉。
- **評測集與調參集一律凍結**：`cvtune-clean`、`wikitune-clean`、dev302、打字測驗、錯字回報、動漫與名單檢查集、discordtune、保留集都用 main 上現有的檔與雜湊，不重建。量測前核對每個的 SHA-256 等於 main 上的值。
- **`colloquial-train.txt` 重產**：`build_tune.py` 加一個只輸出 train 的選項：切分照舊用現行轉換算（所以 cvtune 的抽樣與參考句不變），train 那一側的句子再從原始句用新轉換重寫。輸出記 SHA-256；檢查「插件」保留。`holdout_guard.py`、`build_digits.py` 共用的 `convert()` 預設行為不變，新行為只由 `build_counts.py` 與這個選項帶參數使用。

### 2.3 讀音修正（單字平手、倒掛、疊加層）

- `tools/readings.py` 加規則 3b：單字讀音平手時，用基底多字詞裡這個字各讀音出現的（分數加權）次數決定；沒有多字詞證據的，用 Unihan `kMandarin` 的台灣值後備，還是決定不了的進 CHECK 清單給維護者。
- 9 個倒掛字照 3b 的結果改底分：主讀音高於又讀。
- `build_overlay.py` 標讀音改成萌典第一讀音優先、`readings.py` 其次；5,236 個不同的詞列成清單，抽樣 100 個給維護者核對方向。
- 評測列已凍結（§2.2），這三項不會改到評測列的讀音。它們改的是詞庫檔，和計數無關，也影響不重建模型的使用者：§3 階段 0 單獨量一次（只換詞庫、模型照 SJ-LM-6），只報；出貨跟著 SJ-LM-7 的 PR 2（§4），不單獨出貨。

### 2.4 口語語料

- **快照**：現在這一輪 PTT 抓取跑完就停，清理後的各來源檔凍結成快照、記 SHA-256，這一片之後不再抓、不再改。兩臂與所有階段用同一份快照。
- **配方不變的部分**（照 model-v6 §2.1）：維基 `build_counts.py --articles 200000 --expected`（×1）、`tools/build_lm.py` 的 `PRUNE=2`、`D=0.75`；現有口語池（`colloquial-train.txt`，§2.2 重產）×5。
- **新來源、權重、單位**：

| 來源 | 權重 | 單位（每單位最多 50 句） |
|---|---|---|
| g0v `#rand0m` CC0 增量 | ×5 | 一則訊息 |
| PTT 推文 | ×5 | 一篇文章底下的全部推文合起來算一個單位 |

- **清理**：照 `exp/p2-data` 的規則（切句、4–40 漢字、漢字比例、網址與帳號、簡體專用字等）。PTT 的一則推文有長度上限，一句話常分成兩則以上：同一篇文章裡，同一個帳號、相鄰、時間差 ≤ 3 分鐘的推文先接起來再切句（維護者 2026-10-24）。
- **和評測集去重**：用 `holdout_guard.py` 的比對器，把新句子對保留集（現役與 `next/`）、dev302、打字測驗、錯字回報、cvtune-clean、wikitune-clean、動漫與名單、資訊詞包檢查集比對，命中就拿掉。私人的 discordtune 與聊天保留桶（下一條）在 188 上用同一個比對器比對，命中也拿掉，只回數字。每個來源、每個集合的命中數在階段 1 有數字之前記進研究紀錄。

- **輸入表**：`experiments/sj-lm-7/README.md` 照 model-v6 列輸入表，每一列有 SHA-256（維基 dump、`colloquial-train.txt`、三個新來源檔、`synth.txt`、`mcbpmf-data.txt`、`overlay-add.tsv`、兩臂各自的計數詞表、OpenCC 表）。兩臂的語料輸入雜湊相同，只有計數詞表不同。

## 3. 量測的順序、選法與驗收

各階段依序做，前一階段選定的結果帶進下一階段。

| 階段 | 臂 | 要量的集合 | 選法 |
|---|---|---|---|
| 0 | 只換詞庫（§2.1a、§2.3），模型照 SJ-LM-6 | 出貨標準四條的集合 | 只報 |
| 1 | 臂 A、臂 B（全收、常談沿用表、書面照現行）；兩次完整重建 | 出貨標準四條、動漫五集、名單檢查集、資訊詞包檢查集、pack-oov 的兩份確認抽樣；重驗（下面） | 過「兩臂共同關卡」的臂才能選；都過時把數字給維護者選（推薦 discordtune 淨值大的） |
| 2 | 選定的詞包臂 × Moore–Lewis（另一臂＝階段 1 的全收）；一次完整重建 | 同階段 1 | 同階段 1 |
| 3 | 書面照現行、書面 KN β 0.75；不重建 | 出貨標準第 2、4 條的書面列、wikitune-clean | 數字給維護者選（推薦淨值大的） |
| 4 | 常談沿用表、常談重算；只重建常談 | 出貨標準四條 | 數字給維護者選 |
| 定案 | 選定組合；重選 α、τ、δ 與常談 cell | 全部；確認一發 | 照下面 |

- **兩臂共同關卡**（每一臂、每一階段都適用，§1、§4 指的都是這一條）：
  - 出貨標準四條對現行出貨（兩個詞包都開）都過；
  - 動漫五集＋名單檢查集合計（聊天、書面兩種設定）改壞 ≤ 改對；
  - 重驗（§2.1）：first_named 全部第一（例外清單照 pack-oov）、未處置的 (a)(b) 為 0、`detect_collisions` 沒有新衝突沒處置、交集為空的測試通過。
- **資訊詞包檢查集**：只報。
- **確認**：選定的那一組組合，在沒看過的聊天判讀集 chatjudge-3 一發。規則照出貨標準的確認規則（淨值 > 0、精確 McNemar p < 0.05、改壞÷改對 ≤ 0.65），數字之前 commit。
- 記憶體（RSS）與延遲（按鍵 p95 ≤ 16 ms）在閒置窗量；模型檔大小。
- 跨語言：Rust 與 Python 在出貨集合上的摘要行逐字相同（照 model-v6 §2.3）。
- 常談在新配對下生效：`applies` 對新 `.sjtl` 為真（Rust 測試），CLI 聊天三檔摘要行有 `+colloq:`。
- 保留集：問 Release 之前由 fresh verifier 跑一次。

## 4. 順序、PR 與回退（照 model-v6 §2.6）

1. 前提：pack-oov 合併；本分支從含它的 main 開出。PTT 這一輪抓完、快照凍結；聊天保留桶的切法 commit（§2.4）。確認一發還要 chatjudge-3 從保留桶抽好、凍結並記雜湊（最早 2026-11），其他階段不等它。
2. 工具改動與測試（§2.1a、§2.2、§2.3、Moore–Lewis 腳本）→ 階段 0 → 階段 1–4 的建置與量測（建置與量測在 GCP，每一步用滿核心；Moore–Lewis 的打分與挑句只在 188，見 §2.4，挑出的公開句子才送 GCP 計數）。
3. 定案組合的所有檔是最終檔，記 SHA-256，完整指令記進 `experiments/sj-lm-7/README.md`；跨語言核對、所有 golden 在最終檔上重產。

# 契約：通語 SJ-LM-7（規模待定）——常開詞庫自己計數、讀音修正、口語語料（草稿）

狀態：**草稿，還沒送 plan-verifier**（2026-10-24）。標「〔待定〕」的地方要維護者先選，選完才送審。前提：pack-oov（PR #276）合併，選用詞包的哪些詞不走通語統計已經由詞包第 4 欄標好（`docs/contracts/pack-oov.md` 第 1b 節）。

## 0. 依據（維護者的決定與量過的事）

- **方向**（維護者 2026-10-23，通語計畫的選擇題；Fable、Argon 報告在維護者本機）：只對常開詞庫（小麥＋萌典補詞＋名單）計數、選用詞包詞的計數另外決定（下一條）；繁體句不套大陸用語轉換；修分數倒掛；加口語語料。單字讀音與疊加層讀音修正「等 model-v7 一起」。下一版通語的代號是 SJ-LM-7。
- **選用詞包詞的計數**（維護者 2026-10-24）：Fable 建議「詞庫去重、計數保留」取代「拿掉選用詞包詞的計數」→ 兩臂都量再定（§2.1）。量過的事實：pack-oov 把通語認得的詞包詞當未知詞時，對 main 的動漫名字 22／25（淨 −3），改壞的是通語認得的名字（莉茲 90 次、蘭琪 123、艾蓮 121）；拿掉計數的那一臂會讓兩萬個名字都變成這樣（Fable 的推論，要量）。
- **書面 KN**（維護者 2026-10-23）：書面開 KN、β 0.75 當 SJ-LM-7 要量的一臂，現在不單獨出貨（研究分支 `exp/kn-research`）。
- **萌典**：維護者 2026-10-23「用萌典或開源詞典建詞庫，我們不算改作，這我覺得可以放寬」。
- **口語語料探針**（2026-10-24，結果在研究紀錄）：g0v `#rand0m`（CC0）相對 cc0-sentences 新增 16,756 句；OASST2 繁體只有 3,615 句（不用）；PTT 試抓兩看板約 2.7 萬句（維護者「PTT直接抓吧，不用問」）；WildChat 全量待量。
- **已知的資料問題**（Argon、Fable 10-23 實測）：
  - 小麥基底 3,584 個破音字裡 3,063 個前兩名讀音同分，`readings.py` 平手時取檔案順序；9 個字 −6.8 底分倒掛（鈸、乜、掇、鉈、癘、嘁、誒、溴、跩）。
  - `build_overlay.py` 不查萌典，`overlay-add.tsv` 裡萌典有收的 41,075 詞中 5,236 詞讀音和萌典第一讀音不同。
  - `experiments/s2/build_counts.py` 對繁體句也套 OpenCC `TWPhrases`（「插件」被換成「外掛」）。

## 1. 要做到什麼、怎麼看到

- 出貨的通語換成 SJ-LM-7：計數只來自常開詞庫的詞（加上 §2.1 選定那一臂的詞包詞），讀音修正後的詞庫，繁體句保留原用詞，口語語料加量。
- **怎麼看到**：出貨標準四條對現行出貨不退步，聊天要有看得到的進步（§3）；動漫名字、名單、資訊詞包檢查集不退步；實機打「插件」「伊莉絲」與錯字回報的幾列。

## 2. 改動

### 2.1 計數詞表與選用詞包（兩臂）

- 常開詞庫＝小麥基底（`mcbpmf-data.txt`）＋萌典補詞（萌典有收、語料出現 ≥ 2 次、現在不在任何一層的詞；讀音取萌典第一讀音）〔待定：門檻 2 次〕＋疊加層＋變調列＋名單。計數詞表從這一份產生；指紋條目照舊由 main 在私有流程加回。
- **臂 A（拿掉）**：選用詞包詞不進計數詞表；它們在模型詞彙外，詞包分數決定排序（pack-oov 的強制標記這時不再需要）。
- **臂 B（保留計數、詞庫去重）**：選用詞包詞照 model-v6 的規則進計數（`count_lexicon.py` 的衝突讀音規則照舊），但不進常開詞庫；pack-oov 第 1b 節的強制詞規則照用。
- 兩臂用同一份語料、同一個建置配方，只差計數詞表；§3 的量測兩臂各一份，維護者看數字選。

### 2.2 繁體句不套大陸用語轉換

- `build_counts.py` 對判為繁體的句子只做字形層（異體字表 `VARIANTS`、`POST_TRAD`），不套 `TWPhrases`；簡體句照舊。單元測試：「插件」在繁體句保留、在簡體句照舊轉。

### 2.3 讀音修正（單字平手、倒掛、疊加層）

- `tools/readings.py` 加規則 3b：單字讀音平手時，用基底多字詞裡這個字各讀音出現的（分數加權）次數決定；沒有多字詞證據的，用 Unihan `kMandarin` 的台灣值後備，還是決定不了的進 CHECK 清單給維護者。
- 9 個倒掛字照 3b 的結果改底分〔待定：改成同分還是改成主讀音高〕。
- `build_overlay.py` 標讀音改成萌典第一讀音優先、`readings.py` 其次；5,236 個不同的詞列成清單，抽樣 100 個給維護者核對方向。
- 這三項改的是詞庫檔，和計數無關，也影響不重建模型的使用者（詞庫隨 App 出貨）：在 §3 和模型一起量，也單獨量一次（只換詞庫、模型照 SJ-LM-6），分開看效果。

### 2.4 口語語料

- 現有的口語池（Phase 2 公開句子池 143,895 句，權重 ×5）照舊。
- 新增〔待定：哪幾個〕：g0v `#rand0m` CC0 增量；PTT（推文與內文分開，推文權重另定）；WildChat 全量繁中（要先量）。每個來源記句數、漢字數、清理步驟的計數、洩漏防護命中數，原文不進 repo、不散布。
- 每個來源設單位上限（一則訊息、一篇文章最多貢獻 N 句）〔待定：N〕，避免一篇轉貼長文佔掉大量計數。
- 加權與挑句（Moore–Lewis 以私人聊天當語域分數，只在 188 上算、不出貨）〔待定：要不要挑句〕。

### 2.5 KN 與書面

- 聊天照現行（開 KN、β 1）。書面兩臂：照現行（有三連詞表時不用 KN）、開 KN β 0.75（`exp/kn-research` 的設定）。

### 2.6 連鎖重建

- 辨類（SJ-WC，新版本）、承接 KN 側檔（SJ-KN，新版本）、連文三連詞表（SJ-CX，新版本）跟著重建；會意（SJ-SR-6-14M）權重不變，三檔的 α、τ、δ 在新底層上重選（綁新模型雜湊，SJTL0004）；常談（SJ-CL-1-68K）綁的模型雜湊換掉，表本身照舊〔待定：常談要不要用新口語語料重算〕。
- 規模：照模型實際大小命名（SJ-LM-7-xx.xM），App 關於頁的模型列表同一個 PR 更新。

## 3. 驗收

- 出貨標準四條，對現行出貨（兩個詞包都開），兩臂各一份；KN 書面兩臂各一份。
- 動漫五集、名單檢查集、資訊詞包檢查集、pack-oov 的兩份確認抽樣：只報，但動漫與名單合計改壞 > 改對時停。
- 確認：沒看過的聊天判讀集（chatjudge-3）一發，數字之前 commit 規則。
- 記憶體（RSS）與延遲（按鍵 p95 ≤ 16 ms）在閒置窗量；模型檔大小。
- 跨語言：Rust 與 Python 在出貨集合上的摘要行逐字相同（照 model-v6 §2.3）。
- 保留集：推 tag 前由 fresh verifier 跑一次。

## 4. 停止條件、預算、範圍外

- **停止**：出貨標準任一條不過；確認照登記不過；兩臂都讓動漫或名單合計變差；記憶體超過現行 +40 MiB〔待定〕。
- **預算**〔待定〕：GCP（計數與量測）、188（Moore–Lewis）、Colab（不訓練會意權重，只重選融合參數時不用）。
- **範圍外**：會意重訓（字幕 × 寬度 2×2，另一片）；讀音計數 B 的語料標注（暫停中）；前文回傳；R1 讀音解碼器的候選窗那一部分。

# SP：前文＋半截注音的即時預測（issue #44）——第一片：離線研究

charliie-dev 在 #44（2026-10-06、10-07）補充原始需求：**根據輸入框裡已寫好的前文，以及目前輸入到一半的注音，隨著每一鍵更新候選字詞的預測**。例：前文「我想喝一杯」，打 `ㄋ` 時「奶茶」「拿鐵」就該出現。使用者 2026-10-07 排入，範圍是**前綴補完與縮寫都做**。設計經 Fable 5.1 審查（2026-10-07，用模型 E 跑過探針），契約已照它的意見修改。

研究拆成兩個問題，分開量（#44 第三則留言的建議）：

1. **用前文與尚未完成的注音，能不能讓正確的詞更早出現在候選中？**——這一片。
2. **候選固定時，融合方法能不能再改善排序？**——PLAN 的融合實驗，另寫契約。

這一片只做離線研究，不動核心、殼層、介面；介面另寫契約，使用者看過才開工。這一片不調任何參數，所以沒有 A／B 切分；之後若要調參數，先依原句切分再產生逐鍵序列（§6）。

## 1. 模型

`P(W | h, z) ∝ P(z | W, h) × P(W | h)`

- **詞庫**（候選與切詞共用同一個物件，和 `reference/proto/lm_eval.py` 第 49–52 行完全相同）：`ime.Lexicon(mcbpmf-data.txt, overlay=ime.OVERLAYS)`（`overlay-add.tsv` 與 `sandhi-add.tsv`），再 `lm.cap_overlay(base, overlay-add 的詞集, lm)`。叫它 `lex`。語言模型是出貨的 model-v2（`data/lm/bigram.sjlm`，雜湊等於 `data/bigram.sjlm.sha256`）。
- `W`：`lex` 裡的詞。**候選身分是去重後的字串**：同一個字串有多個相容的（讀音, lp），取分數最高的一個。
- `h`：前文。歷史詞 `v` = `lm.history(lm.context_key(前文), lm)`；前文是空的就是 `<s>`。
- **先驗** `P(W | h)`：`lm.word(λ, v, W, lp)`（`reference/proto/lm.py`），λ 依設定（§3.1）。只用來排序。
- **觀測模型** `P(z | W, h)`：決定式，相容（§2）就是 1、否則 0。排序等於「相容的字串按先驗分數由高到低」。打錯鍵的容錯、注音欄位覆寫不在這一片（§6）。
- **兩個結構事實**（Fable 量測，契約據此設計指標）：
  - 前文只拉抬 `v` 的**二元組後繼詞**（模型裡 `v` 後面出現過的詞）。其他詞的分數是 `λ·log10 back(v) + (常數)·lp`，對所有非後繼詞是同一個位移，排序和沒有前文時相同。所以前文的效果上限是「`W*` 是 `v` 的後繼詞」的比例。
  - 決定式觀測模型下，沿著前綴按鍵序列多打一鍵，相容字串集合只會變小或不變，`W*` 一直在集合裡。這是**斷言**（§4）。**`W*` 的名次可能變差**：字串的分數取相容讀音裡最高的 lp，下一鍵可能排除高 lp 的讀音（「大」打 `ㄉ` 時用 ㄉㄚˋ 的 lp，打到 `ㄉㄞ` 只剩 ㄉㄞˋ 的 lp），所以名次是量到的結果，不是斷言。
- **同分**：疊加層分數量化，大量同分。**指標一律用悲觀名次**（同分的對手都算排在前面）；需要決定性順序時（輸出前 64 名、一致性檢查）用 **(−分數, 音節數由少到多, 讀音字串, 字串 code point)**。
- 輸出前 64 名。

## 2. 相容

- **音節的字元序列**：照詞庫讀音的寫法，一個音節拆成「聲母、介音、韻母」的注音字元（有幾個寫幾個）；聲調另記。一聲沒有符號，輕聲是 `˙`。例：`ㄋㄞˇ` → 字元 `ㄋ ㄞ`、聲調 ˇ；`ㄐㄩㄝˊ` → `ㄐ ㄩ ㄝ`、ˊ；`ㄚ` → `ㄚ`、一聲；`ㄅㄚ˙` → `ㄅ ㄚ`、˙。
- **單位**：`(字元, 完成旗標, 聲調)`。按鍵序列裡按下聲調鍵（一聲是空白鍵）就把目前的音節標成完成並記下聲調；之後再打的字元開始新的單位。完成旗標由按鍵序列決定，不由字串有沒有調號推斷（一聲打完和沒打完的字串相同）。
- **單位 `u` 和音節 `s` 相容**：`u` 未完成時，`u` 的字元是 `s` 字元序列的前綴（不限聲調）；`u` 已完成時，字元與聲調都和 `s` 相同。
- **前綴解讀**：前 k−1 個單位都已完成、和 `W` 的前 k−1 個音節相容；第 k 個單位（已完成或未完成）和 `W` 的第 k 個音節相容；`W` 的音節數 ≥ k。
- **縮寫解讀**：n 個單位都未完成，`W` 剛好 n 個音節，第 i 個單位和第 i 個音節相容。
- **一次查詢的候選 = 兩種解讀的聯集**，同字串去重取最高分（系統不知道使用者用哪一種）。
- **單元檢查**（`experiments/sp/test_predict.py`）：`ㄋ`、`ㄋㄞ`、`ㄋㄞˇ（完成）ㄔ` 和「奶茶」相容；`ㄋㄧ` 不相容；縮寫 `ㄋ ㄔ`、`ㄋㄞ ㄔㄚ` 相容，`ㄋ ㄔ` 不和三字詞相容；`ㄐㄩㄝˊ` 的介音；`ㄚ` 的首字元是 `ㄚ`；輕聲；**一聲**：`ㄊㄚ`（完成）只和一聲的 ㄊㄚ 相容，`ㄊㄚ`（未完成）和四個聲調都相容；同一個字串有兩個讀音時只出現一次；同分的決定性順序；空的查詢回空集合。

## 3. 評測

- **樣本 = 每個詞界**：正解句用 `ime.segment_words(lex, 句)` 切詞；第 j 個詞 `W*` 的前文 = 該列前文欄＋句中前 j−1 個詞，讀音 = 讀音欄裡對應的音節。
- **丟掉並計數**：讀音欄缺或音節數和字數不同；`segment_words` 回 None；`W*` 在 `lex` 裡沒有那個讀音的詞條。每張表報丟掉的樣本數。
- 兩字以上的 `W*` 是主要結果，單字另報。不讀保留集。

### 3.2 按鍵、位置與指標

- **按鍵序列（前綴）**：每個音節依字元序列一鍵一字元，再一個聲調鍵（一聲是空白鍵）。總鍵數 `K` = Σ(每個音節的字元數＋1)。
- **語意位置**（取代絕對鍵數）：P1 第一鍵後；P2 第一個音節的字元打完、還沒按聲調；P3 第一個音節完成；P4 P3＋第二個音節的第一鍵（兩字以上才有）。**縮寫**：A1 每個音節的首字元；A2 每個音節的前兩個字元（只有一個字元的音節取那一個）。
- **hit@k**：在每個位置，悲觀名次 ≤ k 的比例，k = 1、5、9。
- **省鍵率 KS(k)**，k = 1、3、9：`i` = 前綴按鍵序列中悲觀名次第一次 ≤ k 的鍵數；`KS = max(0, K − i − 1) / K`（打 `i` 鍵再按一次選取）；沒進就是 0。報平均與「每 100 個詞淨省幾鍵」。
- **後繼覆蓋率**：`W*` 是 `v` 的二元組後繼詞的比例（前文效果的上限）。
- **單字干擾**：(i) 候選只留兩個音節以上的字串、在其中重算悲觀名次，兩字以上 `W*` 在 P1–P4、A1、A2 的 hit@k；(ii) 單字 `W*` 的樣本中，P3（音節打完）時決定性順序的第 1 名是兩個音節以上字串的比例（分母＝單字 `W*` 的樣本數）。
- **縮寫打不出來的比例**：兩字以上 `W*` 中，第 2 個以後的音節沒有聲母的比例（現行組字器會把它接到前一個音節，§6）。
- **第一名翻轉率**（給介面參考）：兩字以上 `W*` 的樣本，沿前綴按鍵序列，第 i 鍵（2 ≤ i ≤ K）決定性順序的第 1 名和第 i−1 鍵的不同，算一次翻轉；翻轉率＝所有樣本的翻轉次數總和 ÷ Σ(K−1)。
- **給 Rust 的規模數字**（聊天設定、所有公開集合）：
  - (i) **掃描深度**：`lex` 的條目依第一個音節的第一個字元分桶（兩種解讀的第一個單位都要和第一個音節相容，所以查詢第一個單位的第一個字元決定桶），桶內依 (−lp, 音節數, 讀音, 詞的 code point) 排序。對每個樣本的每個前綴鍵與 A1、A2，從桶頭掃到出現 9 個去重後、相容、不是 `v` 後繼詞的字串為止；深度＝掃過的條目數。整桶不到 9 個就記桶的大小，另報件數。報中位、p95、最大。
  - (ii) 前文非空的樣本，`v` 的後繼詞數（中位、p95、最大）。
  - (iii) Python 每次查詢（一個樣本的一個位置）的時間 p50／p95。

### 3.3 三組對照與配對檢定

- (a) 只用詞庫分數（分數 = `lp`）；(b) 語言模型、歷史詞一律 `<s>`；(c) 語言模型＋前文。
- 主要檢定是 **(c) 對 (b)**：每個樣本的對錯 = 「P1 位置、悲觀名次 ≤ 9」，只計兩字以上的 `W*` 且前文非空的樣本；每個集合、每個設定一個 McNemar 精確檢定（雙尾）。另報 P3 的同一個檢定。(a) 只報告。
- λ 只改變後繼詞被拉抬的幅度，兩種設定的結果會很接近，報告不另做解讀。

- **驗收**：

     另外兩組測試：**讀音換掉**——「大」`ㄉ`→`ㄉㄞ`、「得」`ㄉㄜ`→`ㄉㄜ˙`，集合單調、字串仍在、分數從 ㄉㄚˋ／ㄉㄜˊ 的 lp 換成 ㄉㄞˋ／ㄉㄜ˙ 的 lp；**指標**——單字干擾 (ii)、第一名翻轉率、掃描深度各用一個手造的小詞庫算一次，期望值手算寫在測試裡。
  2. **一致性**（typing76 全部樣本、兩種設定）：(i) 每個候選的分數和 `lm.word(λ, v, W, lp_max)` 逐位元組相同（`lp_max` 是該字串在相容讀音裡最高的 lp）；(ii) 查詢是 `W*` 的完整讀音（每個單位都完成）時，候選裡「音節數等於 `W*`」的字串集合，等於 `lex.by_reading[讀音]` 去重後的字串集合。任一樣本不符就是停止條件。

  4. 公開集合的所有表都印出來並寫進 README；discordtune 由 main 跑、只報統計數字。
  5. `git diff` 不含 discordtune 的路徑或任何一列的內容。

## 5. 停止條件、預算、限制

- **停止條件**：一致性或單調性不過；查詢時間 p95 超過 2 秒；需要改 `core/`、`macos/`、`data/`、`eval/`。
- **預算**：executor 1 回合加 1 次修正；main 跑 discordtune 一次。
- **executor 不可以做的事**：不連網；不讀 `eval/holdout/`、`~/side-project/shanjie-private/`、使用者的 Discord 資料、學習檔或聊天紀錄（測試的 `--rows` 一律指向公開檔或暫存檔）；不改 `core/`、`macos/`、`data/`、`eval/`；不安裝、不啟動 App，不呼叫 TIS 或 lsregister，不碰 `~/Library` 與鑰匙圈；不 push、不開 PR。

## 6. 下一步（另寫契約，使用者看過才開工）

- **組字器規則**：現行同一欄再按一次是取代（先 ㄋ 再 ㄔ 會變成 ㄔ，`core/src/engine.rs` 約 788 行），縮寫要改成「開新單位」；介音或韻母接在只有聲母的單位後面，有「接續」和「無聲母的新音節」兩種解讀。
- **介面**：預測什麼時候出現、放在哪裡（是否排除單字）、怎麼選取、和組字區與標點的互動；先整理手機注音輸入法的公開做法。
- **核心**：Fable 估的最小結構是「依第一個注音符號分桶、桶內依 lp 降冪」加上現有語言模型，不需要 trie；這一片的規模數字決定要不要提前結束。
- **觀測模型與先驗**：打錯鍵容錯、注音欄位覆寫。若要調參數，參數只由 A 半決定，而且**先依原句（或來源群組）切 A／B，再產生逐鍵序列**。
- **融合（問題 2）**：固定同一版解碼器、同一份前文與候選、同一批原始分數，比 n-gram 基準、正反序平均後的判斷器、τ 門檻、加權融合、Bayes 更新五組；正反序先對齊候選身分再平均，報平均後剩下的順序敏感性。

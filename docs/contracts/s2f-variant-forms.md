# S2f：字形修正（台灣正字被當成簡體換掉；異體寫法由詞庫決定）

使用者 2026-10-07 回報「起床」打成「起牀」（「沒有人會這樣打」）。main 查到根因，Fable 5.1 獨立查核後同意，兩邊的共識由使用者選定：下面四件一起做，重建一版取代 model-v2。

## 1. 根因（2026-10-07 量測）

- OpenCC `STCharacters.txt` 把「床、秘、灶、粽、痴、庄、晒、霉、虱、峰、群…」對到另一個字形（床→牀、秘→祕、灶→竈、粽→糉…），而且對照裡不含原字。
- `experiments/s2/build_counts.py` 的 `load_conv` 把「對照裡不含自己」的字當成**簡體專用字**，繁體句也照換。OpenCC 自己的簡轉台流程會在之後套 `TWVariants.txt` 把台灣字形換回來（牀→床、竈→灶、糉→粽…），我們的流程沒有這一步，只用手挑的 12 字 `VARIANTS`。
- `tools/build_overlay.py` 另外算了一份同樣的簡體專用字，含這些字的維基標題一律不進疊加層。
- **結果**（模型 E）：「床」0 次、「牀」12,397 次；「秘」0、「祕」40,328；「灶」0、「竈」1,971；「粽」0、「糉」663；「庄」0。詞庫偏好「起床」（基底 −4.93），疊加層的「起牀」（−7.17，維基詞典）因為有次數而勝出。Fable 用解碼器實測：model-v2 會打出 起牀、牀上、臨牀、祕密、祕書、神祕。model-v1 也一樣。
- **只合併計數不夠**（Fable 量測）：詞庫裡只有台灣寫法的詞，模型 E 的次數全是 0，例如「床」字詞 69 個（鋪床、木床）、「秘」13（秘書室）、「灶」12（病灶）、「粽」9（肉粽、粽子）、「庄」4、「痴」5。

## 2. 做法

### 2.1 台灣字形表（一個來源，三處共用）

- 讀 OpenCC `TWVariants.txt`（和 `STCharacters.txt` 同一個 commit `3ac34aa…`；SHA-256 寫進 PLAN 的來源表，讀之前核對），每條取第一個值，**排除 4 條**：污→汙、癡→痴、樑→梁、蔘→參（Fable 逐條對照基底詞庫的成對詞偏好：污 32:2、癡 12:4、樑 9:9、蔘 1:2，詞庫不偏向轉換後的寫法）。結果叫 `TW_VARIANTS`。
- `build_counts.py` 定義一次，`build_overlay.py`、`build_tune.py` 都 import 同一個，不另抄。

### 2.2 不再把台灣字形當簡體（`load_conv`）

- `load_conv` 裡的「簡體專用字」有三種用途，這一片只改前兩種：
  - (a) **繁體句的字表 `char`**：用**縮小後的集合**＝原集合扣掉 `TW_VARIANTS` 的所有目標字，再扣掉 `{秘 庄 晒 霉 虱 么 肴 洒 痒}`（OpenCC 沒有換回、但基底詞庫有 5 條以上用到的字）。繁體句裡這些字保留原樣。
  - (b) **繁體句的詞組篩選**（只收含簡體專用字的 STPhrases 詞組）：也用縮小後的集合，所以「秘密→祕密」這類詞組不會套到繁體句。代價：繁體句裡夾著的「什么」不再轉成「什麼」（么 在扣除名單），照實接受。
  - (c) **判斷簡繁句的 `SIMP_ONLY`、`MARKERS`、`TRAD_ONLY`**：**不變**，和 S2n 相同，句子的簡繁分類不因這一片改變（含 床、灶、粽 的句子照舊多半判成簡體句，由 §2.3 換回台灣字形）。
- **簡體句**照舊（庄→莊、晒→曬、么→麼… 在簡體原文裡幾乎都對），只有「秘」加進 `TAIWAN_KEEP`（簡體句保留「秘」，再由 §2.4 讓詞庫決定 秘／祕）。
- `build_overlay.py` 的簡體專用字改用同一個繁體句集合（不再自己從 STCharacters 算）。

### 2.3 轉換完再套台灣字形

- 轉換完成、套完 `TW_PHRASE` 之後，整句再套一層字表，兩種句子各自的字表：
  - **簡體句**：`TW_CHAR ∪ TW_VARIANTS`（`TW_CHAR` 是現有的 `VARIANTS` 加 臺→台，照舊保留）。
  - **繁體句**：`VARIANTS ∪ TW_VARIANTS`（不套 臺→台，繁體句的「臺」照舊）。
  - `VARIANTS` 有而 TWVariants 沒有的 綫、敎、説 照舊；兩者重疊的 9 條方向相同。
- `TWVariants` 有 喫→吃，所以 S2n 的「輸入句有喫就保留」規則拿掉，「喫」一律成「吃」。

### 2.4 計數時合併同讀音的異體寫法（`tools/build_lm.py`）

- **合併字表** `MERGE` = `VARIANTS` ∪ {佔→占, 佈→布, 祕→秘, 臺→台, 牀→床, 汙→污}。**不含** 週／周、唸／念、嚐／嘗、它／牠、妳（台灣用法有分工）。
- **類別**從詞庫推：讀基底＋疊加層（§2.5 之後的），同一個讀音、把 `MERGE` 套到兩邊後字串相同的詞，併成一類（union-find）。讀音不同的不會併（占卜 ㄓㄢ 不會和 佔 併）。
- **合併的位置**：各語料加權相加、四捨五入之後，算總數與剪枝之前。unigram 與 bigram 以（類, 類）為 key 加總，再寫回類裡每個成員。**每個前文的總數必須在寫回之後才算**（Fable 先算後寫，有 900 個前文的回退權重變成負數）。
- 效果：同讀音兩種寫法在語言模型裡次數相同，預設由詞庫分數決定，使用者改選一次由選字記憶（S4）記住。

### 2.5 拿掉疊加層裡只是基底詞異體寫法的詞（`tools/build_overlay.py`）

- 疊加層的詞，若同讀音的基底詞在套 `MERGE ∪ TW_VARIANTS` 後和它相同，就拿掉（例：疊加層「尿牀」−7.17 與基底「尿床」−7.47；不拿掉的話合併後疊加層的寫法會勝出）。Fable 量到約 1,025 條。
- 完整清單寫進 `experiments/s2f/overlay-variant-removed.tsv`（詞、基底寫法、讀音），比照 S2n 的 `overlay-removed.tsv`。

### 2.6 重建

照 S2n 修訂四的流程（期望次數 `--expected`），在 188 上：疊加層 → `build_tune.py`（參考句跟著新轉換）→ 口語計數 → 維基計數 → `build_lm.py`（合併）→ 候選模型 F。

## 3. 驗收

1. **單元檢查**（`experiments/s2/test_convert.py`、新的 `tools/test_build_lm.py`）：
   - 每一列先斷言 `is_simplified` 的判斷，再斷言輸出：
     - 繁體句（`not is_simplified`）：「南庄鄉」→「南庄鄉」；「秘書說了」→「秘書說了」；「他說什么」→「他說什么」（§2.2 (b) 的代價）；「貪污的國家」→「貪污的國家」（排除條目）。
     - 簡體句（`is_simplified`）：「台湾的」→「台灣的」（臺→台 照舊）；「他在床上」→「他在床上」；「秘书」→「秘書」；「什么」→「什麼」；「我们吃饭」→「我們吃飯」；「我们喫饭」→「我們吃飯」（TWVariants 的 喫→吃）；「病灶」「肉粽」→ 原字不變（判成簡體句，由 §2.3 換回）。
   - 突變：(i) 拿掉 §2.3 這一層，「他在床上」那條必須失敗；(ii) 把 §2.2 (a)(b) 的扣除拿掉，「南庄鄉」與「秘書說了」兩條必須失敗。
   - 合併：同類成員的 unigram 與 bigram 次數相同；所有前文的回退權重 ≥ 0；建出的模型 Rust 讀得進來（`cargo test`）。
2. **字形探針**（`experiments/s2f/probe.txt`，執行前寫死，main 審過）：每列只有目標詞本身：`前文|期望寫法|讀音`。目標詞：起床、床上、臨床、病床、秘書、秘密、神秘、病灶、肉粽、粽子、佔領、宣布、分布、佈置、市占率、貪污；前文是一個兩字的常見前文（executor 選、寫進檔案）。**期望寫法是基底詞庫裡同讀音、兩種寫法中分數較高的那個**（executor 從 `mcbpmf-data.txt` 算出寫進檔案，main 核對）。**通過規則**：用 `lm_eval.py --context`（模型 F）解這個讀音，第一名等於期望寫法。聊天與書面每一列都要通過；有一列不過就是停止條件，報分數拆解。
3. **使用者的句子**：「大概十分鐘後到」兩種設定都對；「好」＋ㄅㄚ˙ 仍是「吧」。
4. **守門（否決）**：dev302、typing76、cvtune-native，聊天與書面，對模型 E 配對比較；任何一格淨值為負且 p < 0.05 就否決。
   - **篩選的檔案**：模型 E 那一版的 cvtune 參考句檔 `~/.cache/shanjie/work/s2n/tune/cvtune.txt`（3756 列，SHA-256 `7f9b35e6deba78c84c9c9c4786d217c054f45718cb8b43c902faf4062c46bbb4`），讀之前核對雜湊。模型 E 與模型 F 都在這份篩過的檔上評分。重建產生的新 cvtune 不拿來當守門。
   - **cvtune-native 的定義**：cvtune 的原始來源句（Common Voice、Tatoeba）裡，**修改前與修改後的轉換都不改變**的句子（`raw == convert_舊(raw)` 而且 `raw == convert_新(raw)`）所切出的子句；一個子句只要也出現在任何「被任一轉換改變」的句子裡就不算。cvtune 列的參考句屬於這些子句的才留下。程式 `experiments/s2f/cv_native.py`（讀檔與 `is_tune` 照 `build_tune.py`）。**列數在重建前算好、寫進 README 與研究紀錄**，驗收時核對相同。錯字回報（34 列）、完整 cvtune、wikitune 新舊參考句只報告（參考句隨轉換改變，有方向偏誤）。
5. **次數報告**（對模型 E）：床／牀、秘／祕、灶／竈、粽／糉、庄／莊、痴／癡 的字次數；S2n 的七個殘留詞（≤ 6,282）；段落數下降不超過 1%；模型大小 ≤ 100 MB；被拿掉的疊加層詞數。
6. **golden 與測試**：依賴模型的 golden 照各自指令重產（`s2-lm.txt`、`s2-lm-dev302-top1.tsv`、`s2r-probe-top1.tsv`、`s2h-lm-context.txt`），疊加層改變帶動的 golden（`s1-dev302.txt`、`s1-overlay-sets.txt`、`s2r-probe-unigram.txt` 等）照各自指令重產，每一列的變動要能追到字形或疊加層的改變；`cargo test`（debug、release）、`swift test`、C 冒煙測試全綠。
7. **保留集**：片收尾時由 fresh verifier 跑一次，只回數字。
8. **出貨**：全部通過後先問使用者是否建立 GitHub Release `model-v3`；建好、下載回來比對雜湊相符，才改 `.sha256` 與所有 `model-v2` 的引用、推分支、開 PR。

## 4. 停止條件、預算、範圍外

- **停止條件**：字形探針不全對；守門否決；「大概十分鐘後到」不對；段落數下降超過 1%；模型超過 100 MB；188 整批超過 8 小時或記憶體超過 48 GB；需要改 `core/`、`macos/`。停下時報數字，不另外調表或門檻。
- **預算**：executor 實作 1 回合加 1 次修正；188 重建一次。
- **範圍外**：S2w（MediaWiki 轉換）——之後它的台灣字形層改用同一個 `TW_VARIANTS`；週／周 等有分工的字；詞庫增刪（除了 §2.5 的異體寫法）；介面。
- **executor 不可以做的事**：不連網（OpenCC 檔案已在 `~/.cache/shanjie/sources/opencc/`）；不讀 `eval/holdout/`、`~/side-project/shanjie-private/`、使用者的 Discord 資料、學習檔或聊天紀錄；不改 `core/`、`macos/`；不安裝、不啟動 App，不呼叫 TIS 或 lsregister，不碰 `~/Library` 與鑰匙圈；不連 188、不 push、不開 PR、不建 Release。

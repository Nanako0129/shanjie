# 句首單字的選字記憶（產品片 SINIT）

狀態：草稿（修訂二：第一次 REVISE 三項照改；第二次 REVISE 的第 2、3 項照改，第 1 項不採納（見 §8）），待收尾審查。

## 0. 起因與現況

- 錯字回報第 16 列「照建議」：句首（前文不是漢字）打 ㄓㄠˋ ㄐㄧㄢˋ ㄧˋ 得到「趙建議」，維護者改選「照」之後下次照樣是「趙」。`docs/PLAN.md`「句首單字的選字記憶」寫好了做法：句首的單字改選也學，只在句首鍵之下、同讀音，規則 7 為這一片另外放寬。
- 現在丟掉的地方（`core/src/learn.rs`）：`learn_commit` 在句首把前文鍵 `^` 換成規則 8 的合成鍵 `^>`＋下一個音節（這裡是 `^>ㄐㄧㄢˋ`）；`Learner::teach` 遇到單字、而鍵不是兩個漢字（`is_full_context`）就整個返回，所以「照」沒有紀錄，「趙」也沒有減半。`learn_store::valid` 在載入時也丟掉「單字配合成鍵」。規則 7、8 在 `docs/contracts/s4-learning.md` §14、`docs/contracts/learn-single-ctx.md`。

## 1. 要做到什麼

1. **規則 10（句首單字）**：1 個字的詞在句首，鍵是 `^>`＋下一個注音音節的讀音（規則 8 的合成鍵；不含 `^>$`，也不含 `next_key` 收成一類的英文／空白鍵 `ENGLISH_NEXT` 與數字鍵 `DIGIT_NEXT`）時也學：`teach` 產生紀錄、照現有規則把被換掉的字減半。鍵是 `^>$`（單字在組字區最後、後面沒有音節）、英文／空白類或數字類的 `^>` 鍵、單獨 `^`、一個漢字的鍵時，單字照舊不學（這兩類鍵涵蓋後面接任何英文或任何數字，教一次就會讓那個字在所有這種句首加分，和第 2 點「讀音相同才生效」不合）。`teach` 與 `learn_store::valid` 用同一個判斷。
2. **查的時候**：解碼與預測列查到 `^>`＋讀音之下的單字紀錄就照現有的學習加分；只有句首、而且那個字後面接的讀音相同時才生效（規則 8 本來的範圍）。最後一個字那一層與全域那一層不變（單字照舊不參加全域）。
3. **舊紀錄與檔案**：`learn_store::valid` 的合法鍵加一條「單字配 `^>`＋注音音節的讀音」；單字配 `^>$`、配英文／空白類或數字類的 `^>` 鍵、配一字鍵、單獨 `^` 照舊丟掉。檔案仍是五欄、檔頭不變，舊檔照讀。
4. **不變**：2 個字以上的詞的規則（含規則 8）、`LEARN_EPS`、忘記（⌘⌫）、`context_key`、學習開關與守門、新詞 B。

## 2. 怎麼看到它有效

- 單元測試（`core/tests/engine_learn.rs`，照現有的寫法）：
  - 第 16 列：用 `engine_learn.rs` 既有的 `tiny()` 寫法建一個小詞庫，讓單字「趙」的分數高於「照」、而且有「建議」一詞（結果固定，不靠出貨模型）。打 `ㄓㄠˋ ㄐㄧㄢˋ ㄧˋ`，前置斷言預設是「趙建議」；在音節 0..1 改選「照」、Enter；紀錄鍵是 `^>ㄐㄧㄢˋ`；再打同一串，顯示「照建議」。另外在書面設定、出貨模型下打同一串一次，只記下預設是什麼（研究紀錄 2026-10-05 量到書面錯、聊天對；這裡只當參考，不當斷言）。
  - 同讀音才生效：教完上面那一筆之後，句首打 `ㄓㄠˋ ㄒㄧㄤˋ`（後面接的音不同），結果和沒有學習時相同。
  - 不在句首不生效：前文是兩個漢字時打 `ㄓㄠˋ ㄐㄧㄢˋ ㄧˋ`，結果和沒有那一筆紀錄時相同。
  - 單字在最後不學：句首只打一個音節、改選單字、Enter，不產生紀錄（`^>$`）。
  - 在／再污染（`pollution_zai_taught_under_two_contexts` 再加一組）：在句首、後面接某個音節的位置教單字「再」（較少見的那一個），再跑一次 dev302 所有含 ㄗㄞˋ 的列；`row_collides` 擴充到 `^>`＋音節的鍵；不衝突的列改壞與變動都是 0。
  - 同鍵的兩字詞：句首 `ㄗㄞˋ ㄐㄧㄚ` 教單字「再」（來自「再加」）之後，句首再打 `ㄗㄞˋ ㄐㄧㄚ` 想打「在家」：照實記下顯示「在家」還是「再家」。顯示「再家」時停下，交給維護者決定這個代價收不收（同讀音、同下一個音節，學習分不出是哪一句）。
  - 後面接英文或數字不學：句首單字後面接英文 token、或接數字時改選，不產生紀錄。
  - 載入：含單字配 `^>`＋注音讀音的檔案載入後保留；單字配 `^>$`、配英文／空白類、配數字類鍵的那幾列丟掉。
  - 既有測試會改變的只有斷言「句首單字配 `^>` 讀音不學」的那幾處（例如 `single_character_rules_in_the_learner` 的 `^>` 部分），每一處在 PR 說明寫理由；其他測試失敗就停。
- 真引擎重播（GCP，main 執行，用 `.agent-local` 的共用函式庫，腳本送出前由 fresh verifier 審）：main 與這片在 dev302、打字測驗、錯字回報各跑 `shanjie-replay --learn on --correct`（兩種設定），逐列比送出文字與改選次數；報有變化的列與方向。
- 出貨標準的四個集合：評測 CLI 不開學習，這片只改學習（`lm.rs` 與解碼器的行為不動，只可改註解），所以同一次 GCP 工作裡兩臂在出貨標準的 8 個集合各跑一次評測 CLI，rowstats 逐位元組相同就代表四條和 main 一樣。
- 實機（維護者，佔鍵盤 ≤ 15 秒）。前提：改選之前，句首那個單字在畫面上和要教的字不同（出貨模型在聊天設定可能本來就選對「照建議」，研究紀錄 2026-10-05）。
  - 先在聊天 App 句首打 `ㄓㄠˋ ㄐㄧㄢˋ ㄧˋ`：顯示「趙建議」就改選「照」、送出，再打一次要顯示「照建議」。
  - 已經是「照建議」：改用書面設定（`defaults write` 把 `profileMode` 設成 formal）再打一次；仍是對的，就反過來教：改選成「趙」、送出，再打一次要顯示「趙建議」，句首打 `ㄓㄠˋ ㄒㄧㄤˋ`（後面接的音不同）不受影響，最後用 ⌘⌫ 忘掉那一筆。
  - 回報寫下改選前畫面的字、改選後的字，以及後面接不同音時沒有變。

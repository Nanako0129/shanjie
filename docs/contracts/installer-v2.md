# 契約：安裝流程第二版（安裝程式重做、brew 自動註冊與升級接手）

狀態：草稿（2026-10-08）。使用者 2026-10-08：「安裝流程先處理好一下，現在太簡陋了」，選「重做自己的安裝程式」（分步驟、白話、品牌外觀、最後內建試打）；brew 那條路一起改：安裝後自動註冊、升級時自動結束舊程序。排在 App 沙盒之前；沙盒那一片要用的註冊輔助程式在這片先做。

## 0. 要做到什麼、怎麼看到

- 第一次安裝的人照著安裝程式按下一步，最後在安裝程式裡的試打框用善解打出字，中間不用看任何技術名詞。看得到：使用者實機走一次（或 main 用拋棄式 bundle ID 的組建走一次並截圖給使用者看）。
- 用 brew 的人 `brew install --cask shanjie` 之後不用再手動跑指令；`brew upgrade --cask shanjie` 之後選單直接是新版（不用登出、不用 pkill）。看得到：選單出現新版才有的項目、`ps` 的啟動時間晚於升級時間。
- 起因：v0.3.0 發佈當天，Discord 上有使用者 brew 升級後仍在跑舊版（`docs/research-log.md` 同日）。

## 1. 安裝程式（`macos/Sources/ShanjieInstaller`）

步驟與畫面（文字以實作時的版本為準，原則是白話、不出現路徑與檔名，技術細節收進「詳細資訊」）：

| 步驟 | 內容 | 按鈕 |
|---|---|---|
| 歡迎 | 印章＋「善解輸入法 <版本>」＋一句「開源的 macOS 注音輸入法，專心把同音字選對」；「只裝在你的帳號，不需要管理員密碼」；已裝舊版時寫「會從 X 更新到 Y」；已裝同版時寫「已經裝好了」；已裝較新版時寫「已經有更新的版本，不會降版」。可展開的「詳細資訊」：安裝位置、上一版保留、授權（連到授權檔） | 取消／安裝（或更新、啟用、重新安裝，邏輯沿用 `InstallerPlan`） |
| 安裝 | 進度轉圈與一句白話狀態（「正在複製…」「正在請系統啟用…」）；失敗時白話說明＋「拷貝錯誤細節」 | 期間不能關閉（沿用 `isBusy`） |
| 啟用 | 系統需要登出時：分三步說明（登出、登入、再打開這個安裝程式按「啟用」），附「現在登出」按鈕（呼叫系統的登出對話框，由使用者確認）；不需要時自動跳過 | 重新檢查／完成 |
| 試打 | 「✓ 已經裝好了」＋一個可輸入的文字框（預設 focus）＋「切換到善解」按鈕（`TISSelectInputSource` 選善解，只在使用者按下時做）＋說明「之後從選單列的輸入法選單，或按 Caps Lock／⌃空白 切換」 | 完成 |

- 頂端的步驟指示：四個點，目前步驟實心；跳過的步驟顯示為完成。
- 外觀跟系統的淺色／深色；印章色、字型比照網站（朱紅印章、宋體標題）。視覺參數放具名常數，外觀收斂照使用者的實機回饋（CLAUDE.md「外觀與行為」）。
- 中英文沿用 `L(zh, en)`。
- 預覽模式：環境變數 `SHANJIE_INSTALLER_PREVIEW=<步驟>` 只畫出那個步驟的畫面、不做任何安裝動作，用來截圖給使用者看與寫測試；正式流程不讀它以外的東西。

## 2. 註冊輔助程式

- 新增 `善解輸入法.app/Contents/Helpers/shanjie-install`：由現有 `ShanjieInstall` target 建出的命令列程式，簽章時不帶 entitlements（之後沙盒那一片，主程式加沙盒、這支不加）。
- 行為同現在的 `shanjie install`：註冊、啟用、確認系統接受，結束碼沿用（0 完成、3 需要登出，其餘失敗），輸出不含使用者資料。
- 新增一個子命令 `restart`：用完整路徑 regex 結束執行中的善解程序（同 `install-ime.sh` 的 `pkill -f` 規則與 HOME 檢查），沒有在跑也算成功。
- 主程式的 `shanjie install` 這一版保留（舊版 caveats 與使用者習慣），改成呼叫同一份程式碼；沙盒那一片再決定是否移除。
- `install-ime.sh` 改用輔助程式。

## 3. Homebrew cask（`packaging/Casks/shanjie.rb`，發佈時由 `release.yml` 寫進 tap）

- `postflight`：執行輔助程式 `restart`，再執行 `install`。`install` 結束碼 3 時不讓 brew 失敗，改印出「請登出再登入，然後執行 …/shanjie-install install」；其他非 0 也只印訊息。
- 保留 `uninstall on_upgrade: :signal`（多一層保險）。
- `zap trash:` 加上學習資料 `~/Library/Application Support/shanjie`（安全審查 F5）。
- `caveats` 改成只在需要時才有的說明（自動註冊之後，正常情況不必再做任何事）。

## 4. 驗收

1. 單元測試：步驟狀態機（每個 `InstallerPlan` 與每個 `Registration.Outcome` 走到哪個步驟）、預覽模式不呼叫任何安裝動作（以注入的假動作計數斷言）。
2. `swift test`、`make test`、`scripts/check-installer.sh` 全過；輔助程式在 bundle 裡、簽章不帶 entitlements、hardened runtime。
3. 截圖：用預覽模式拍四個步驟（淺色、深色），交給使用者看；外觀照使用者回饋改。
4. 實機（main 執行，使用者授權過安裝）：
   - 拋棄式 bundle ID 的組建：安裝程式走完「歡迎 → 安裝 → 試打」，在試打框打出字。
   - 正式 bundle ID：在已裝 0.3.0 的機器上用新安裝程式走「重新安裝」或「更新」，選單是新版、`ps` 啟動時間晚於安裝時間。
   - brew：用本機的 cask 檔做一次 `brew reinstall`（**做之前先問使用者**，會動到已安裝的輸入法），確認 postflight 讓新程序接手、不用手動指令。
5. 研究紀錄記錄：brew 升級沒換版的原因（量到的）、新流程的實測。

## 5. 停止條件

- 輔助程式從終端機或 brew 執行時註冊失敗，而主程式的 `install` 成功。
- postflight 的 `restart` 結束了不是善解的程序（regex 檢查要有測試）。
- 預覽模式能觸發任何安裝或系統變更。

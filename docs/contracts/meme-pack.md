# 契約：迷因詞包（meme-pack）

狀態：**過審**（2026-10-25；收尾審查一項照最小修改處理後，維護者選擇題「當作過審」）。修訂二（第二次 REVISE 三項逐項處置：判斷用聊天設定、計數工具與兩次計數的先後、測試清單對上規則；之後收尾審查）。修訂一（plan-verifier 第一次 REVISE 五項：讓不讓第一名改成一條可判定的規則、PTT 用量的數法與計數檔、授權與 App 署名、檢查集的母體、回滾）。

## 0. 起因、要做到什麼、怎麼看到

- **起因**：
  - 維護者 2026-10-24（Discord）：「可以找一下迷因相關的百科網站，迷因可以獨立作詞包，再開一片」。網路用語那一片（`docs/contracts/net-slang.md`）把迷因、有出處的台詞排除在主詞庫外，留給這一片。
  - 維護者 2026-10-24／25 問統神等實況主講過的話；Muse CLI（Meta 平台）整理了統神與其他創作者的台詞表。
  - YouTube 事件索引（`docs/contracts/youtube-events.md` §1 分流）把「有明確出處的台詞」送到這一片。
- **選擇題**（維護者 2026-10-25）：
  - 預設**開**（和動漫、資訊詞包一樣），設定裡可以關。
  - 範圍：**迷因用語＋實況主、YouTuber 的台詞**。
- **要做到**：聊天裡常打的迷因與台詞，開著詞包時直接是第一名；關掉時選字和沒有這個詞包時逐位元組相同。
- **怎麼看到**：§3 的評測，加上實機打幾個（§3.6）。

## 2. 收錄規則與建置 `tools/build_meme_pack.py`

- **用量**（事先固定，量之前 commit）：PTT 這一輪抓取（SJ-LM-7 凍結的同一份原始頁面）裡，字串出現的看板 ≥ 3、文章 ≥ 10（和名單增補相同；迷因比一般網路用語少見）。
- **怎麼數**（照 `net-slang.md` 與名單增補的 `experiments/names-creators/count_usage.py`）：一篇文章（內文加全部推文）裡出現這個字串（子字串比對）就算 1 篇，不論出現幾次；看板＝這些文章所在的不同看板數。
- **計數工具**：`experiments/names-creators/count_usage.py`（名單增補那一片，前提是它已合併）。這一片的工具 PR 加兩個選項與一個檔頭：`--include-known`（已在詞庫的字串也照數，第二次計數要用）、`--jobs N`（按頁面分給 N 個程序再合併，結果和單程序逐位元組相同，有測試），以及輸出的檔頭（PTT 頁面目錄的雜湊、輸入字串檔的 SHA-256、工具的 commit，由 `count_usage.py` 自己寫）。輸入照舊是一行一個字串。
- **計數檔**：每次計數寫 `~/.cache/shanjie/meme/counts-<日期>-<次>.tsv`：檔頭記 PTT 頁面目錄的雜湊（照 `english-next.md` §1 的目錄雜湊做法）、輸入字串檔的 SHA-256、工具的 commit；每列 `字串<TAB>文章數<TAB>看板數`。建置工具用 `--counts` 讀（兩個檔），`meme.json` 記兩個計數檔與輸入檔的雜湊。兩次計數都由 main 在 GCP 或 188 跑（`--jobs` 用滿核心），順序見 §5。
- **去重**：詞庫任何一層（基底、疊加層、名單層含增補、網路用語）或任何詞包（動漫、資訊、經典台詞）已有的字串不收。
- **讓不讓第一名**（照 `net-slang.md` §2「用量多的留第一」；取代動漫詞包 A.1 的 (c)）：用出貨的 CLI（動漫、資訊詞包開，沒有這個詞包）在**聊天**設定對每個候選的讀音單獨解碼（照「聊天優先、書面只守門」；書面靠 §3.4 的書面集合 0 改壞守門），第一名是字串 X（可能是詞庫詞，也可能是解碼器拼出來的詞組）。建置工具的第一段（`--emit-x`）寫 `meme-x.tsv`（候選、讀音、X、書面的第一名；最後一欄只給「已經打得對」的雙設定檢查用）與第二次計數的輸入 `meme-x-strings.txt`（一行一個 X、去重、照位元組排序），兩個都記雜湊；main 用 `count_usage.py --include-known meme-x-strings.txt` 做第二次計數；第二段讀兩個計數檔，核對 `meme-x.tsv` 的雜湊：
  - X 就是這個候選 → 屬於下一條「已經打得對」，不收。
  - X 在 PTT 的文章數 ≥ 候選 → **不收**（照 `names-creators.md` §2 的結果：讓不了第一名的不放進詞包當候選）。
  - X 的文章數 < 候選 → 收，它應該是第一名。
  - 兩個候選讀音相同：文章數多的照上面判，少的不收。
  - 不收的列進報告（候選、X、兩邊的文章數）。
- **「已經打得對」的不收**：照 `it-pack.md` §2（出貨 CLI 單獨解碼，聊天與書面第一名都已經是這個字串）。
- **人工審**：main 逐條看候選（人名、一般詞組、錯字、只紅一天的事件詞剔除；事件詞送熱詞清單），維護者抽查；剔除的原因分類計數記進研究紀錄。
- **讀音**：`tools/readings.py`；CHECK 與多音字由 main 逐條看，諧音梗照它實際打的讀音（例如「蝦」當「瞎」打 ㄒㄧㄚ）。
- **分數**：照資訊詞包（同字數第 25 百分位＋`BONUS` 3，受 `CappedLexicon` 封頂）；不另做格點。
- **衝突**：照 `acg-pack.md` A.1、A2 的 (a)(b)；(c) 改用上面「讓不讓第一名」的規則。和資訊、動漫詞包的詞衝突時，先出貨的詞包勝（迷因不收）。
- **輸出**：`data/packs/meme-add.tsv`（疊加層格式，標籤 `meme`）、`meme-sources.tsv`（每詞的來源與 PTT 文章數）、`meme.json`（版本、各來源筆數與雜湊、各條規則擋下的數量）。同一份輸入建兩次逐位元組相同。

## 3. 引擎、App 與評測

1. **引擎**：`PACK_MEME = 8`（位元 3；動漫 1、經典台詞 PR #272 用 2、資訊 4），`PACK_FILES`、`PACK_ALL`、C ABI 的遮罩說明、`core/include/shanjie.h`、`docs/contracts/s3a.md` 一起改。載入、封頂、缺檔照動漫詞包 A.2。CLI `--packs` 接受 `meme`。
2. **App**：設定「詞包」區塊加「迷因與實況用語」開關，偏好鍵 `memePack`，**沒設過當成開**；切換時重建引擎；選單「已開啟的詞包：」照 `loadedPackMask` 列名稱（照 `it-pack.md` §3.2）。`scripts/build-app.sh` 打包、`check-app.sh` 核對雜湊、selftest 加這個檔。`README.md`、`site/` 的詞包清單一起改。
3. **關掉時**：dev302、打字測驗、錯字回報的 `top1_sha256` 和 main 相同（聊天、書面）；golden 不變。
4. **開著時**，對 main 的出貨（動漫、資訊開），出貨標準四條（第 4 條：只加詞的詞包，錯字回報改壞 0 時算過）。每一列不同都列出來（公開集合寫句子，私人集合只寫數字；私人集合在 GCP，main 跑）。
   - 動漫五集、名單檢查集、資訊詞包檢查集、網路用語檢查集：**0 改壞**，有就停。
5. **檢查集** `eval/dev/meme/words.txt`：母體是收進詞包的詞（照上面的規則，它們都應該是自己讀音的第一名），用固定種子 20261025 抽 60 個（不到 60 個就全收），一列一詞、沒有前文；聊天至少 75% 第一名正確；書面只守門（0 改壞）。達不到先回報每個沒對的原因再問。
6. **實機**（維護者）：開著詞包打 3–5 個（從檢查集挑，例如統神的台詞），組字區第一名就是；設定關掉後回到原本的選字。
7. **記憶體與延遲**：照 `it-pack.md` §3.7（記憶體 +≤ 40 MiB 對動漫＋資訊；`timing_typing76_keys` 加 `PACKS=acg,it,meme`，p95 ≤ 16 ms）。

## 4. 驗收

- `make test-python`（建置工具，夾具、不連網：長度與英數過濾、標點切段、用量門檻（看板 2／文章 10 擋、看板 3／文章 10 收）、去重、讓不讓第一名的四種情形（候選比 X 少不收、比 X 多收、同讀音兩個候選只留文章數多的、聊天與書面的 X 不同時照聊天的 X 判）、`meme-x.tsv` 雜湊不符就停、`count_usage.py` 的 `--include-known` 與 `--jobs`（和單程序逐位元組相同）與檔頭（三個欄位都在，建置工具讀進 `meme.json`）、第二次計數的 X 文章數來自 X 字串本身（夾具：`meme-x-strings.txt` 一行一個 X，數出來的是那個字串的文章數，不是整列）、「已經打得對」、街頭字典的候選沒有 PTT 用量時不收、同輸入建兩次逐位元組相同）、`make test-rust`、`make test-swift`（`memePack` 沒設過時遮罩含 `SHANJIE_PACK_MEME`）。
- §3.3–§3.7 全部通過；人工審的剔除表維護者看過。
- **授權**：詞包檔照 CC BY-SA 4.0 散布（迷因 Wiki、PTT 鄉民百科的 CC BY-SA 3.0 依「或更新版本」條款改用 4.0；中文維基本來就是 4.0）。
  - `LICENSES/data.md` 加 `meme-add.tsv` 一列：標題來自迷因 Wiki（Fandom）、PTT 鄉民百科、中文維基，收錄依 PTT 用量；候選另有模型建議與公開網站（只當候選），不含任何釋義或原文。
  - `scripts/build-app.sh`：第 81 行必備檔清單加 `meme-add.tsv`、`meme-sources.tsv`、`meme.json`；`CC-BY-SA-4.0-attribution.txt` 加 `packs/meme-add.tsv` 一段，署名 Fandom 迷因 Wiki 貢獻者、PTT 鄉民百科貢獻者、Wikipedia contributors。
  - `scripts/check-app.sh`：必備檔清單、manifest 迴圈（`("meme.json", "meme-add.tsv")`）、`grep -q 'packs/meme-add.tsv'` 署名檢查各加一處；從分支建的 App 拿掉那一段署名時 `check-app.sh` 要失敗。

## 5. 順序、停止、預算、範圍外

- **順序**（每一步用的工具在那一步之前都已存在）：
  1. 名單增補（`names-creators.md`）合併，`count_usage.py` 進 main；PTT 抓取完成並凍結。
  2. main 抓候選來源（MediaWiki、街頭字典），整理候選檔、人工審、讀音。
  3. 工具 PR（executor）：`count_usage.py` 的兩個選項、`tools/build_meme_pack.py`（`--emit-x` 與正式建置兩段）與測試；合併關卡照程式改動。
  4. main 第一次計數（候選）→ 建置第一段 `--emit-x` → 第二次計數（X）→ 建置第二段 → §3 評測。
  5. 引擎與 App PR。經典台詞詞包（PR #272）先合併的話照它的位元配置；它沒合併，這一片照樣用位元 3，不動位元 1。
- **停止**：收錄後不到 30 個詞（先回報各來源的數量再問）；§3.4 任一條不過或回歸集合有改壞；§3.5 門檻不過；記憶體或延遲超過。
- **回滾**：revert 本片的 merge commit；詞包檔不在時其他詞包與基底照舊（`acg-pack.md` A.2）。
- **預算**：抓取一次（main）；計數兩次（main）；PTT 用量計數在 GCP 或 188（`--jobs`，用滿核心）；§3.4 私人集合 GCP ≤ 1 小時；executor 實作 1 次＋修正 1 次。
- **範圍外**：迷因圖片與貼圖；英文迷因；多句的長台詞（照標點切開後超過 10 個漢字的段）；熱詞清單（YouTube 事件那一片）；把迷因放進通語 SJ-LM-7 的詞表。
- **限制**：executor 不連網（只用快取 `--offline`）、不讀 `~/.cache/shanjie/` 以外的私人資料與 `eval/holdout/`、不安裝軟體、不啟動或安裝 App、不 push、不開 GCP、不碰其他 worktree；Mac 只跑改到的測試檔。

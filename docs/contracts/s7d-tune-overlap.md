# S7d：調參集去掉和訓練文字重疊的列，重選 α、τ（離線研究片）

接續 S7b（`docs/contracts/s7b-larger-lm.md`）。L（3,000 萬參數）在 cvtune＋wikitune 上比 M 好，聊天設定卻選到 α 2（格點最大值），在使用者的聊天（discordtune）上沒過 S7a §4，還輸給 M 97 列。推論：cvtune 有 13%、wikitune 有 24% 的正解句整句出現在訓練文字裡，模型越大記得越多，調參集就偏好越大的 α。**使用者 2026-10-11**：停掉 XL，先修 α 的選法，再決定要不要訓 XL。

這一片只換「選 α、τ 用哪些列」，模型、候選、分數、格點、判斷都不變。

## 1. 要做到什麼、怎麼看到

- 回答三件事：(a) 只用不重疊的調參列選，M、L 各選到什麼 α、τ；(b) 用新的值，M、L 各自是否通過 S7a §4，L 對 M 如何；(c) 要不要訓 XL（依 §2.3 的規則，由使用者決定）。
- **怎麼看到**：研究紀錄的表格（每個模型 × 兩種設定 × 每個集合一行 `evalstats`，新舊凍結值並列），以及 §4 逐項 PASS／FAIL。

## 2. 做法

### 2.1 標記重疊的列（188）

- `experiments/s7a-tinylm/buildcheck.py substr` 加 `--flags DIR`：每個 rows 檔寫一個 `DIR/<檔名主幹>.flags`，第 i 行是第 i 列（照 rows 檔順序、和 `score.py` 的列號 `i` 一致）的正解句是否整句出現在 `runs-wiki.txt` 或 `runs-coll.txt`（1／0）。只有 `0`、`1` 與換行。判斷方式和 S7a 記錄用的比例完全相同（同一個函式）。
- 在 188 跑（訓練文字在那裡），拷回 Mac。**核對**：cvtune 的 1 共 507 個、wikitune 共 671 個（S7a 研究紀錄的數字）；不等就停。

### 2.2 選法

- `fusegrid.py` 加 `--tune-keep DIR`：選 α、τ 時，cvtune、wikitune 只用旗標為 0 的列（cvtune 3,284 列、wikitune 2,156 列）。格點（`ALPHAS`、`TAUS`）、同分規則、16 字前文那組的做法都不變。
- 加 `--tune-keep` 時，每個模型 × 設定的標題行（`pooled top1 X -> Y of N`）與增幅都只算保留的列（基準、選到的值的 top1、分母都是 3,284＋2,156＝5,440 列），標題寫明「kept rows」。S7a 的「增幅都 < +0.5 個百分點就停」照舊適用，用這個增幅算（列進 §4 的停止條件）。
- 表格照舊用每個集合的全部列。
- 模型：S7a 的 M（`32308122…`）與 S7b 的 L（`0c7c7c48…`）；分數用 S7b 已經有的檔（公開集合：M 為 Mac numpy、L 為 188 torch；discordtune：Mac numpy，S7b 重新產生的同一份候選）。不重新打分。
- **重現關卡**（先做）：同一批分數檔、不加 `--tune-keep` 跑 `fusegrid.py`，必須逐項等於 S7b 記的：M 兩種設定都是 α 0.7、τ 2（聊天 5,431 → 5,752、書面 5,501 → 5,747），discordtune M 聊天 4,209 → 4,276、書面 4,143 → 4,223；L 聊天 α 2、τ 2（5,431 → 5,804）、書面 α 1、τ 2（5,501 → 5,812），discordtune L 聊天 4,209 → 4,179、書面 4,143 → 4,223；以及 S7b 研究紀錄裡 L 的 12 列表格。任何一項不同、或缺分數檔，就停。（S7b 沒有記分數檔的雜湊，所以用重現結果來證明是同一批檔。）

### 2.3 判斷（事先寫死）

- **對 n-gram**：M、L 各自用新的凍結值照 S7a §4 判斷。
- **L 對 M**：兩者都用新的值，照 S7b §2.2 的比較方式（discordtune 聊天，M 為基準）算出「選大模型／多對但不顯著／維持 M」。**這一片三種結果都只記錄**，不換選定的模型、不改 `.sjtl`：模型的選擇由之後的出貨片（含保留集）決定；只有下面的 XL 規則會產生行動。
- **XL**：只有 L（新值）通過 §4，而且對 M 的 Δtop1 > 0、p < 0.05，才回報使用者決定要不要訓 XL（XL 放不進 8 GB GPU，要改做法，另寫契約）。其他情況不訓 XL。
- **出貨的值**：這一片不改出貨的 α、τ（S7c-1 的 `.sjtl` 是 M、0.7／2）。M 的新值和 0.7／2 不同時，記錄 M（新值）對 M（0.7／2）的 discordtune 兩列，由之後的出貨片決定。
- **限制（寫進結論）**：discordtune 在 S7a（選 M）、S7b（判 L、重跑 M）已經用來判斷過，這一片是**第三次**用它判斷；而且「去掉重疊列」這個選法，是看到 L 在 discordtune 上沒過之後才提出的（S7b 紀錄也寫了 discordtune 不能拿來重選 α）。所以這一片的結論是**探索性**的；任何出貨決定都要在出貨片由 fresh verifier 的保留集確認。

## 3. 驗收

1. 旗標：cvtune 1 的個數 507、wikitune 671；檔案只含 `[01\n]`、行數等於列數（3,791、2,827）。
2. 重現關卡（§2.2）全部相等，記進研究紀錄。
3. 單元測試：`--tune-keep` 時 `select` 只讀旗標 0 的列（旗標 1 的列改成會讓結果不同的分數，選出的值不變；把旗標全設 0 時和不給 `--tune-keep` 選出同樣的值）；一個小資料的測試斷言 kept-rows 標題行的基準、top1 與分母。突變：選法忽略旗標 → 測試失敗。
4. 表格與判斷：M、L × 兩種設定 × 六個集合（cvtune、wikitune、dev302、打字測驗、錯字回報前 66 列、discordtune），新舊凍結值；§4 逐項；L 對 M 兩行；M 新值對 M 舊值兩行（若不同）。
5. 研究紀錄（含 §2.3 的限制句）、本契約的結果一節、PLAN 的 S7 狀態行；`make test` 全綠；`experiments/s7a-tinylm` 的 Python 測試全過；fresh verifier 確認第 1–4 項可以從檔案重現（discordtune 那幾行照 S7a 的做法核對內部一致）。

## 4. 範圍外、停止條件、預算、限制

- **範圍外**：改格點、另做口語調參集、重新訓練或重新打分、XL、改出貨的 α、τ、保留集（出貨片才跑）。
- **停止條件**：旗標個數或行數和 S7a 不符；重現關卡任何一項不同或缺分數檔；選法讀到旗標 1 的列（第 3 項不過）；加 `--tune-keep` 後所有模型的聊天增幅（kept rows）都 < +0.5 個百分點。
- **預算**：程式改動只有 `buildcheck.py --flags`、`fusegrid.py --tune-keep` 與測試（main 做）；188 跑一次 substr（S7a 約數分鐘）；Mac 跑 fusegrid（分數已在）。
- **限制**：188 綁 P-core、絕對路徑；discordtune 只在 Mac、只回數字、這一片結束後刪除 S7b／S7d 的 discordtune 候選與分數檔；不讀 `eval/holdout`；agent 不讀 `~/side-project/shanjie-private`、`~/.cache/shanjie/work`、學習檔、`~/Library`、鑰匙圈。

## 5. 回滾

只加兩個選項與測試、文件；不給新選項時行為不變；revert 即可。不出貨。

## 6. 結果（2026-10-11）

- 第 1 項：旗標 cvtune 507／3,791、wikitune 671／2,827，只含 `[01\n]`。
- 第 2 項：重現關卡全部相等（M、L 的凍結值、合計、discordtune 列、L 的 12 列表格）。
- 第 3 項：`--tune-keep` 的測試（被標記的列不影響選擇；全 0 與不給相同；kept-rows 標題行的基準、top1、分母）通過；突變（`kept` 忽略旗標）讓兩個測試失敗。
- 第 4 項：保留的列上選到的值和原本完全相同（M 0.7／2 兩種設定；L 聊天 2／2、書面 1／2），表格與 §4 和 S7b 相同：M 通過、L 沒過；L 對 M「維持 M」；不訓 XL；出貨值不動。
- 結論（探索性）：S7b 的「重疊讓大模型選大 α」推論不成立；L 在聊天上輸的原因未知。

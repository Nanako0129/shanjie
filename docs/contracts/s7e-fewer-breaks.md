# S7e：少改壞——重選融合參數，讓語意校正少把對的字改錯（離線研究片）

接續 S7c-2b（PR #118，殼與開關）。使用者 2026-10-11 裝著測試版打字，回報三句（錯字回報第 70–72 列，PR #119）：其中「你在這裡再這樣的話」n-gram 本來是對的，小模型把它改成「在」；「下一版是出哪一版」一處改對、一處改壞（是→釋）。量過的數字也一樣：S7c-1 的表裡，discordtune 聊天改對 229、改壞 163。

**使用者決定（2026-10-11）**：#118 先不合併，先做「少改壞」；選參數時「改壞 1 句 ≈ 改對 3 句」。照這個權重，現行出貨的值（α 0.7、τ 2）在 discordtune 聊天是 229 − 3 × 163 = **−260**，也就是比不重排還差。

這一片只做離線的選法與量測，不改核心、不改 `.sjtl`、不出貨。出貨是下一片（§5）。

## 0. 依據（2026-10-11，main 的探索，只用公開調參集與新寫的測試句）

- 在 `pick` 多加一道門檻 δ（融合分數最高的候選要比 n-gram 第一名的融合分數高出 δ 以上才換）：cvtune＋wikitune 合計（6,618 列，M8 分數）聊天設定的現行值是改對 398、改壞 77；α 0.7、τ 2、δ 0.25 是 344／48；δ 0.5 是 291／33；只改 α、τ（0.5、0.5、δ 0）是 307／44。照「改對 − 3 × 改壞」，聊天選到 0.7／2／0.25（200），只用 α、τ 的最佳是 0.5／2／0（187）；書面選到 0.5／1／0.25。腳本在 main 的暫存區，這一片照 §2 寫進 `fusegrid.py` 重做，探索的數字不當結論。
- **功能字測試句**（§2.1）：main 寫的 186 句，在寫完、凍結雜湊之後才量（Rust CLI、`--context`、詞包開）。現行出貨值對 n-gram：第一批 122 句聊天改對 9、改壞 0，書面 7／0；第二批 64 句（專挑「再這樣→在這樣」這種搭配陷阱）聊天 8／1、書面 8／2。第一批在聊天設定的改壞（0／122）比 discordtune 聊天（163／4,958，3.3%）少；第二批列數太少，看不出差別（書面 2／64 和 discordtune 書面 147／4,958 接近）。已量過的依據是 S7b 的字元計數：discordtune 聊天重排新弄錯的 259 個字裡，事先列出的功能字組合計 19 個。**推論**（沒量過）：使用者聊天裡的改壞大多不在這幾組功能字上。所以判斷以 discordtune 為準，測試句當功能字的回歸檢查。

## 1. 要做到什麼、怎麼看到

- 回答：照使用者的權重，在公開調參集上選到的 (α, τ, δ)，在使用者的聊天（discordtune）上是否比「不重排」好、比現行值好；功能字測試句與錯字回報有沒有變差。
- **怎麼看到**：研究紀錄的表格——每種設定 × 每個集合兩行 `evalstats`（對 n-gram、對現行值），加上每格的「改對 − 3 × 改壞」；§3 的判斷逐項 PASS／FAIL。

## 2. 做法

### 2.1 功能字測試句（進 repo）

- `eval/probe/s7e-function-words.txt`，186 列，格式 `前文|句子|讀音`（前文都空），**CC0**、專案自寫（main 2026-10-11 撰寫）。第一批 122 列（凍結時 SHA-256 `b35705bb…`）：在／再、是／事／試／式／市、那／哪、的／得／地、做／作、已／以、及／即、帶／代／待／戴、到／道，每組兩種正解都有；第二批 64 列（`28d628bd…`）：功能字後面接的字能和它的同音字組成常見詞（再這樣、是出、再繼續這一類）。合併檔 SHA-256 `6b853a32…`。
- 讀音由 `tools/readings.py` 產生。工具標 CHECK 的 10 列由 main 逐列確認：9 列照台灣習慣改（什麼 ㄕㄣˊ ㄇㄜ˙、那 ㄋㄚˋ、我們的 ㄇㄣ˙、得 ㄉㄜ˙、放 ㄈㄤˋ、怎麼 ㄗㄣˇ ㄇㄜ˙、這麼 ㄇㄜ˙），「幹嘛」照工具的 ㄍㄢˋ ㄇㄚˊ；另外改了工具沒標的 2 處（「說得對」ㄉㄜˊ → ㄉㄜ˙、「再那樣」ㄋㄚˇ → ㄋㄚˋ）。每列音節數等於字數。**句子凍結後不因量測結果改動**；之後要加句子就加在最後面、另記雜湊。
- 和訓練文字的重疊：188 上跑 `buildcheck.py substr`，只記比例，不是停止條件。

### 2.2 門檻 δ 與新的選法（`experiments/s7a-tinylm/fusegrid.py`）

- `pick(r, alpha, tau, col, delta=0)`：原本的規則（n-gram 差距 < τ 才重排、融合分數最高、同分取 n-gram 名次較前）選出 j 之後，**只有** `s[j] − s[0] ≥ delta` 才回傳 j，否則回傳 0。δ = 0 時和現在完全相同。
- `--objective w3`：在 cvtune＋wikitune 合計上，對每種設定找讓「改對 − 3 × 改壞」最大的 (α, τ, δ)；改對／改壞是相對 n-gram 第一名。格點：`ALPHAS`、`TAUS` 不變，`DELTAS = [0, 0.25, 0.5, 1, 1.5, 2, 3, 4]`。同分依序取：改壞較少、δ 較大、τ 較小、α 較小。
- 不給 `--objective` 時行為完全不變（只用 top1、δ 0）。**公開集合的重現關卡**（先做）：同一批 M8 分數檔、不給新選項，必須選回聊天、書面都是 0.7／2，並逐格重現 S7c-1 表格的這 10 格（n、top1 基準 → 新、改對／改壞；錯字回報是前 66 列，動漫集合不在內）：
  - 聊天：cvtune 3,791 列 3,364 → 3,504（178／38）、wikitune 2,827 列 2,067 → 2,248（220／39）、dev302 241 → 276（38／3）、打字測驗 66 → 68（4／2）、錯字回報 15 → 32（19／2）；
  - 書面：cvtune 3,370 → 3,497（167／40）、wikitune 2,131 → 2,250（165／46）、dev302 248 → 273（28／3）、打字測驗 69 → 69（2／2）、錯字回報 18 → 30（14／2）。
  任何一格不同就停。

### 2.4 表格

## 3. 判斷（事先寫死）

照 §2.2 在公開調參集上選出的值（每種設定一組），看 **discordtune 聊天**：

1. 「改對 − 3 × 改壞」（相對 n-gram）**> 0**，而且比現行值的 −260 大；
2. 改壞的列數比現行值的 163 少；
3. 對 n-gram 的 Δtop1 ≥ 0；
4. cvtune、wikitune、dev302、打字測驗、錯字回報、功能字測試句在兩種設定都沒有「改對 < 改壞，而且精確 McNemar p < 0.05」的格（對 n-gram；和 S7a §4、`fusegrid.decision` 同一條規則，1:1 比較，因為 McNemar 檢定比的就是改對與改壞的列數）。表格另列的「改對 − 3 × 改壞」只供參考，不進這一項。

四項都過 → 寫出貨片的契約（§5）。第 1 項不過（照使用者的權重，新值在真實聊天上仍不如不重排）→ **停下來問使用者**，選項寫進研究紀錄：出貨但預設關、改 δ 格點再試一次、或換做法（例如只在小模型的分數差距很大時才換）。其他項不過也停下來回報。

**限制（寫進結論）**：discordtune 已在 S7a、S7b、S7d 用來判斷過，這是第四次；選法是看到使用者的回報之後才改的。這一片的結論是探索性的，出貨片要由 fresh verifier 跑一次保留集確認。

## 4. 驗收

1. 單元測試（`experiments/s7a-tinylm/test_fusegrid.py`）：δ = 0 時 `pick` 和原本相同（以現有測試資料逐列比對）；δ 很大時一律回傳 0；`--objective w3` 的選擇只讀 cvtune、wikitune（改動其他集合的分數，選出的值不變）；同分規則（一個小資料的例子斷言選到改壞較少、δ 較大的那組）。突變：δ 的比較改成 `>`、或 w3 的權重改成 1 → 測試失敗。
2. 公開集合的重現關卡（§2.2 的 10 格）、錯字回報前 66 列的一致性、discordtune 的重現關卡（§2.3）都相等，72 列檔的雜湊，都記進研究紀錄。
3. 表格與 §3 逐項，記進研究紀錄；本契約的結果一節；PLAN 的 S7 狀態行。
4. 功能字測試句進 repo（§2.1），`eval/README.md`、`LICENSES/data.md` 各一列；重疊比例記進研究紀錄。
5. `make test` 全綠；`experiments/s7a-tinylm` 的 Python 測試全過；fresh verifier 確認第 1、2、4 項與公開集合的表格可以從檔案重現（discordtune 照 S7a 的做法核對內部一致）。**verifier 的輸入**：main 把公開集合的分數與候選複製到 `~/.cache/shanjie/s7e-public/`，分兩個資料夾（檔名相同，不能放在一起）：`s7b/` 放 S7b 的 `M8.{chat,formal}.{cvtune,wikitune,dev302,typing76,user-reported}.jsonl`（錯字回報是前 66 列那份）與對應的 dump；`s7e/` 放這一片新產生的錯字回報 72 列與 `fw` 的分數和 dump。verifier 只讀那裡：用 `s7b/` 跑不給新選項的 fusegrid 重現 §2.2 的 10 格，並拿 `s7e/` 的 72 列分數的前 66 列和 `s7b/` 的 66 列逐列比對；**順序**：discordtune 的衍生檔先刪、確認刪掉之後，verifier 才開始。

## 6. 範圍外、停止條件、預算、限制、回滾

- **停止條件**：公開集合或 discordtune 的重現關卡不符；錯字回報前 66 列的一致性不符；錯字回報不是 72 列或前 66 列雜湊不符（#119 沒併進來）；缺分數檔；§3 第 1 項不過（問使用者）；其他項不過（回報）。
- **預算**：程式改動只有 `fusegrid.py`（δ、`--objective`）、`run_sets.py`（集合名 `fw`）與測試，main 做；Mac 打分（discordtune 兩種設定、錯字回報、測試句）；188 只跑一次 substr。
- **限制**：discordtune 只在 Mac、只回數字，衍生檔在 verifier 開始前刪除；不讀 `eval/holdout`；agent 不讀 `~/side-project/shanjie-private`、`~/.cache/shanjie/work`、學習檔、`~/Library`、鑰匙圈（verifier 只讀 §4 第 5 項的 `~/.cache/shanjie/s7e-public/`，那裡只有公開集合的檔）。

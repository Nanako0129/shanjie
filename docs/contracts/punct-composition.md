# 整行連標點一起打時的選字（探索片 PUNCT-0）

狀態：草稿（修訂三：第一次 REVISE 五項、第二次一項（送出文字要逐位元組比）、收尾審查一項（正解檔要固定、附雜湊）都照最小修改處理）。審查次數已到上限，開始實作要維護者同意。

## 0. 起因

v0.6.1 demo 的整句台詞實打（虛擬機 App，19 句、每句一行，標點也在同一個組字區裡打）和量具不一致：以 App 送出的文字當正解，切成 46 個子句（前文是同一行前面的子句）重跑，詞包關時 CLI 與真引擎重播都是 44／46，不同的兩句都在「縱得莞莞，莞莞類卿，暫排苦思，亦除卻巫山非雲也」這行（App「關關類青」「意除卻巫山飛雲也」，CLI 與重播「關關累清」「亦除卻巫山飛雲也」）。詞包開時 46／46 相同。紀錄在研究紀錄 2026-11-01「v0.6.1 demo 台詞牆『App 與 CLI 選字不同』重查」（PR #346，commit bd6fdf1d；這片實作前先合併進 main）。

〔推論〕App 裡標點留在組字區，整行是一個組字區一起解碼與重排；CLI 與重播都是一個子句一列、前文是已送出的文字。所有評測集也都在標點處切成子句（例如打字測驗），所以量的路徑可能和使用者連著打整句的路徑不同。

## 1. 要做到什麼

1. **重播能在一列裡打標點**：`shanjie-replay` 的列可以含 `，` `。` `？` `！` `：`（Shift＋`,` `.` `/` `1` `;`）與 `、`（不按 Shift 的 `\`），讀音欄在那個位置寫同一個標點當一個記號（列解析已經以空白切讀音欄，不必改）。重播照 App 送出 `core/src/engine.rs` 的 `SHIFT_PUNCT`／`PLAIN_PUNCT` 對應的鍵，標點和注音留在同一個組字區。其他標點（例如 `；`，標準排列沒有直接的鍵）不支援：含有它的列照現在的行為報錯。改動只在 `cli/src/replay.rs` 的 `keys_of` 與標點處理；`cli/src/common.rs` 的列解析與核心都不改。每個標點鍵算進 `ideal`／`actual` 各一鍵。
2. **詞包選項**：`shanjie-replay` 加研究用的 `--packs LIST`（`acg`、`it`、`quotes` 的逗號清單）。不給時等於現在的常數 `ACG|IT`（App 預設），輸出逐位元組不變；給了就把詞包寫進摘要的設定標記。
3. **重現**：用 demo 的整行（19 行，詞包關與開；列檔由 demo 錄影紀錄做，只含公開台詞）整行一列重播，和 App 送出的文字逐位元組比。38 次全用同一組事先定好的設定（第 2 節），不逐行換設定。
4. **找出差在哪一步**：對不同的那兩句，分別看 n-gram 解碼的第一名、重排前的候選、重排後的選字，寫出是解碼還是重排造成的，以及整行與子句兩種打法在這一步的輸入差在哪裡（例如重排看到的句子範圍、前文）。可以加 `--rerank final` 當診斷，不算進驗收。

## 2. 固定的輸入與設定（38 次都用這一組）

- 正解與列檔：由 demo 的錄影紀錄（`w1`～`w5` 各兩次的 take log，每份只有一行 `text: "…"`，即 App 送出的文字）抽出，只含公開台詞，隨這片的 PR 放進 `experiments/punct0/`。實作開始前先核對雜湊：
  - `gold-off.txt`（詞包關，19 行）`4b4618dbfbe19f599a1369654963b9f3767a501791576e76636431ab670e9e1a`
  - `gold-on.txt`（詞包開，19 行）`7e563778e7a212f4e52736100fd3b883c8aaa3aff9dc9517dd2696d7c74a2acd`
  - `W.rows`（19 列，前文空白，句子欄是詞包關的 App 文字，讀音欄在標點處寫那個標點）`7a74e4d678caf8ac6e34489eed4170945a4bc7271e325e5848093d5edd0a51f9`
  兩臂按的鍵相同，所以共用一份 `W.rows`；句子欄只影響 rowstats，不影響送出的文字。

- 詞包關：`shanjie-replay --rows W.rows --profile chat --learn off --rerank each --rowstats OFF.r --firsts OFF.txt`（`--packs` 不給，等於 `acg,it`，和 demo App 當時的預設相同；不加 `--correct`，所以 `--firsts` 的第一個顯示就是按 Enter 送出的文字）。
- 詞包開：同上加 `--packs acg,quotes,it`（demo App 開了「經典台詞」）。
- 每行的前文欄一律空白（demo 每行打完按換行，下一行從空的前文開始）。
- App 與重播已知的差異照 `docs/contracts/engine-replay.md` §2–§3：重播沒有預測列、英文判斷關、非同步重排只模型化成 each／final。這些照舊，不為了重現另外調。

## 3. 怎麼看到它有效

- 第 1 項：單元測試，每個支援的標點各一列，送出的文字與逐鍵打的路徑一致（標點鍵進組字區、Enter 一起送出）；含 `；` 的列報錯。
- 第 2 項：單元測試，不給 `--packs` 時摘要標記與現在相同；給 `acg,quotes,it` 時標記帶 `quotes`。dev302 的列（不含標點）在改動前後的 rowstats 與摘要逐位元組相同。
- 第 3 項：19 行 × 詞包關／開，`--firsts` 寫出的送出文字和 `gold-off.txt`／`gold-on.txt` 逐位元組相同（`cmp`），38／38。rowstats 與摘要的 `top1` 走寬鬆對照，不當這一項的判準。
- 第 1 項的單元測試比對送出的字串本身（逐字相等），不走寬鬆對照。

## 4. 驗收

- 第 3 項 38／38。不到就停（第 6 節）。
- 第 4 項寫進研究紀錄，標明量到的與推論。
- 改到的 Rust 測試檔在 Mac 通過；完整 Rust 測試照規則在 188 跑。

## 5. 範圍外

- 改核心或 App 的行為（整行打要不要改成像子句一樣解碼，是看完第 4 項之後另一片的事）。
- CLI（`shanjie-eval`）與共用的列解析（`cli/src/common.rs`）。
- 把打字測驗、錯字回報接回整行量影響：要先定出哪些列原本是同一句、怎麼接回、怎麼把整行的輸出切回原列號對齊 rowstats；放到下一片（看完第 4 項再決定要不要做）。
- 私人集合（discordtune 等）：這片只用 demo 台詞。

## 6. 停止條件

- 支援標點後，重播仍重現不了 App 的兩句：停下報告，不在重播裡加特例去湊。
- 需要改核心才能讓重播走 App 的路徑：停下報告。

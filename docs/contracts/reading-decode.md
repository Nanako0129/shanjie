## 1. 規則

- **讀音項 ch**：沿用 P5 的單字詞 log P(讀音｜字)，相對於該字最常見的讀音，每個單字最多扣到 −c（c 4）。
  - 多字詞、詞庫沒有的單字算 0；詞不能完整覆蓋音節的候選，整條算 0。
  - B-f 的兩個例外：
    - **變調讀音不扣分**：「一」的 ㄧˊ、ㄧˋ 與「不」的 ㄅㄨˊ 算 0（照 r1.py `SANDHI`；「不」ㄅㄨˊ 在詞庫本來就是 0，列出來是為了和工具一致）。
    - **詞庫底分**：合併後詞庫分數等於底分 −6.8 的單字讀音，改用 mc 值。
- **mc 表**：
  - 多字詞的質量只取 `mcbpmf-data.txt` 本身的列：同一個（讀音, 詞）取最大一列；每個至少兩字的詞，每個「字是 w、音節是 r」的位置加一次 10^s。
  - 10^s(r, w)、各讀音的最大值、底分判斷，用合併後的詞庫分數，含 `sandhi-add.tsv` 的 R6「紮」列。這是 P5 `mc_logp` 加上 r1.py `floor_mc` 的算法。
  - 表由核心擁有，載入詞庫時建一次。CLI 和引擎用同一個建表函式，聊天、書面都建。記憶體要量（§2.5）。
- **排序**：s_j = ng_j + λ·ch_j，λ 2.0，同分取原本 n-gram 名次前的。取新的前 8 名。
- **融合**：新前 8 名的 **s 當融合的 n-gram 欄**，τ、δ 的窗都用 s 算，連同各自的 ll（與聊天的 col），照現行出貨：
  - 聊天三檔：常談格各用自己的三個值（`colloquial::cell(level)`），**沒有 ν 項**；
  - 書面：檔頭三個值；
  - col 不是有限值時的退路也吃 s，用各檔的檔頭三個值。
- **退路**：
  - 進了重排工作，但新前 8 名裡有候選太長（`TooLong`），或沒有 ll：取 s 的第一名，對應 r1.py 的 `nollcand`／`none`。
  - **學習保護擋下的段不變**：照現行顯示 n-gram 第一名，不算 ch。使用者教過的選字不被讀音項推翻，按鍵路徑也不多算。
- **引擎**：
  - 重排工作帶整份候選表：`BEAM_S1`，去掉重複字面後最多 64 條，和 CLI 給 r1.py 的 64 名同一份。聊天、書面都帶這一段的音節、詞庫與 mc 表。現在 `syls` 只在讀音通道開時保留，`channel_lex` 只在聊天常談時有，這兩點要改。
  - **套用時的錨點仍是 n-gram 第一名**（`Choice.expect` 取原本的 `paths[0]`，不取重排後的第一名）。
  - 選中的候選不是 n-gram 第一名就換字；s 的第一名不是 n-gram 第一名時的退路也算。
  - 重排工作套用之前，組字區照舊顯示 n-gram 第一名。
- **開關與標記**：
  - 拿掉 ν 項與它的開關：`--no-reading-channel`（CLI 與 replay）、`Engine::set_reading_channel`。換成 R1 的開關：`--no-reading-decode`、`Engine::set_reading_decode`。關掉時是 λ 0，**沒有 ν 項**。
  - **摘要行的標記**：R1 生效時，在設定標記的**最後**加 `+rd`。CLI 與 replay 照同一條規則印。`+rc` 不再出現（main 上它只接在聊天的 `+colloq` 後面）。

    | 情況 | R1 開 | `--no-reading-decode` |
    |---|---|---|
    | 聊天，常談生效 | `…+colloq:<sha8>+rd` | `…+colloq:<sha8>` |
    | 聊天，常談不生效 | 不生效，和 main 相同（沒有 `+rd`） | 同左 |
    | 書面，有小模型 | `…+tri:<sha8>+rd`（照書面原本的標記，最後加 `+rd`） | 原本的標記，沒有 `+rd` |
    | 語意校正關、沒有小模型 | 不生效，沒有 `+rd` | 同左 |
  - C ABI 與殼目前沒有用到這個開關（grep 過），不改。
- **常數**：λ、c、變調免扣的讀音、底分值寫成具名常數，註解寫出處（R1 README 的 R1c 一節）。不重匯出 `.sjtl`。

   - **r1.py 跑核心比對時的模式**：
     - 基準那一跑是產品 commit 的 `--no-reading-decode`，標記沒有 `+rc`、沒有 `+rd`；

     - 錨點 2 不跑（產品 commit 沒有 `--no-reading-channel`）。
   - **比對範圍**：§2.1 的判讀與選格那 19 個「設定 × 集合」（探索片 README「設定、基準與每一次 CLI」那張表，即 r1.py 的 `ROLES`），全部要比。只為錨點跑的 6 次（4 次 `--no-reading-channel`、2 次 N 8）不在比對範圍裡：產品 commit 上沒有對應的設定。

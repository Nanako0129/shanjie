# 契約：讀音解碼（R1 產品片，reading-decode）

狀態：草稿（2026-10-23），送 plan-verifier。

## 0. 起因、要做到什麼、怎麼看到

- **起因**：維護者 2026-10-22：「變快」被選成「便會」是 n-gram 只看字、不看讀音，應該從根本修，不該靠常談。R1 探索把讀音的機率放進候選的排序（`experiments/r1-reading-decode/README.md`，分支 `exp/r1-reading-decode`）。
- **探索的結果**：
  - R1b、R1c 兩次，各臂在六種設定（聊天、書面 × 保守、標準、積極）都照出貨標準四條全過。
  - 維護者選 **B-f**：λ 2.0、c 4，「一」的變調讀音 ㄧˊ／ㄧˋ 不扣分，詞庫底分 −6.8 的單字讀音改用多字詞估（mc）。
  - 維護者同日決定「探索過了就出貨」，對這一次的例外，記在維護者的 decisions。
- **要做到**：重排工作的候選改成這樣取：
  1. 把 n-gram 解碼的整份候選表（beam 的全部）依 **s = ng + λ·ch** 重新排序；
  2. 取新的前 8 名，再照現行出貨的融合選字；
  3. 融合層的 P5 讀音通道項拿掉，讀音只在 s 這一步算一次。
  - 聊天、書面，三種強度都這樣做。
  - 語意校正關、沒有小模型時不變：探索只量了重排開的設定。
- **怎麼看到**：
  1. **重量**：R1 探索量的是「對 R1b 當時的出貨」。之後常談在保守、積極生效（#271），「紮」也補了讀音（#269），所以出貨又變了。出貨前，**用同一套工具對現在的出貨值重量一次**，照出貨標準四條判，六種設定都要過（§2.1）。
  2. **核心等於工具**：核心的選字和工具的離線選字逐列相同（§2.2）。
  3. **實機**：錯字回報第 140 列，前文「否則」，打「變快」：v0.5.0 選錯，新版選對。在繁中虛擬機實測，設定用 `defaults write` 切換。

## 1. 規則

- **讀音項 ch**：沿用 P5 的單字詞 log P(讀音｜字)，相對於該字最常見的讀音，每個單字最多扣到 −c（c 4）。多字詞、詞庫沒有的單字算 0；詞不能完整覆蓋音節的候選，整條算 0。B-f 有兩個例外：
  - 「一」的 ㄧˊ、ㄧˋ 算 0（變調讀音）。
  - 詞庫分數等於底分 −6.8 的單字讀音，改用 mc 值：這個字在 `mcbpmf-data.txt` 多字詞裡用這個讀音的質量（P5 `mc_logp` 的算法）。
  - mc 表在載入詞庫時算一次，記憶體要量。
- **排序**：s_j = ng_j + λ·ch_j，λ 2.0，同分取原本 n-gram 名次前的。
  - 取新的前 8 名進融合，每個都要有 ll。
  - 新前 8 名裡有候選太長（`TooLong`），或這一段不重排（學習保護等），就取 s 的第一名，對應 r1.py 的 `nollcand`／`none`。
- **融合**：照現行出貨。
  - 聊天三檔：常談格各用自己的三個值（`colloquial::cell(level)`），**不加讀音通道項（ν 項拿掉）**。
  - 書面：檔頭三個值。
- **常數**：λ、c、變調免扣的讀音、底分值寫成具名常數，註解寫出處（R1 README 的 R1c 一節）。不重匯出 `.sjtl`。
- **CLI**：`shanjie-eval` 用同一個函式，摘要行的設定標記加一段 R1 的標記。另提供關掉 R1 的選項（`--no-reading-decode`），給對照與錨點用。
- **畫面**：重排工作套用之前，組字區照舊顯示 n-gram 的第一名；工作套用後換成新選字，和現在的非同步重排一樣。

## 2. 驗收

1. **重量（探索工具，GCP）**：
   - 把 `r1.py` 的出貨模型更新成現在的出貨：聊天三檔有常談格與 P5 項，書面是檔頭。用現在 main 的 CLI 重跑 R1c 的 23 跑，B-f 一臂。
   - 對**現在的出貨值**照四條判，六種設定。錨點 1–3 照 R1（出貨格離線重算等於 CLI）。
   - 四條全過才往下做；任一條不過就停下來報數字，和維護者討論，不結案。
2. **核心等於工具**：
   - 核心實作後，CLI（R1 開）在 23 跑的每個集合、每種設定，選字（`--tinylm-scores` 的 `c`）與對錯都等於 `r1.py` B-f 的離線選字，0 列不同。
   - 公開集合在 Mac，私人集合在 GCP。
3. **不變的部分**：語意校正關、沒有小模型、`--no-reading-decode` 這三種情況，dev302、打字測驗、錯字回報兩種設定的 `top1_sha256` 都和 main 相同。golden 照實際變動更新：只有重排開的 golden 會變，變了逐行列出。
4. **測試**：
   - 單元：ch 的兩個例外、s 的排序與同分規則、取前 8 名、`TooLong` 時取 s 第一名。
   - 引擎：重排工作的候選是 s 的前 8 名，不是 n-gram 的前 8 名，用公開的列，索引事先寫好。
   - 突變：拿掉變調免扣、拿掉 mc、λ 改成 0、取 n-gram 前 8 名，各至少一個測試失敗。
5. **延遲與記憶體**：
   - 重排工作多算整份候選表的 ch：`RerankJob::run` 的 p95 照現行量法量，門檻 300 ms。
   - mc 表的記憶體：RSS 增加 ≤ 10 MiB。
   - 每鍵延遲不變（ch 在工作裡算，不在按鍵路徑）。超過就停。
6. **實機**：§0 第 3 點。

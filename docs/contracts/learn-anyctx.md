# 換了前文也記得改選過的詞（產品片 LANY）

狀態：修訂四（2026-11-03）。修訂四只改第 3 件的範圍（維護者選「移到別項再移回來才算」）。修訂一照第一次 plan-verifier 的五項；修訂二照第二次的四項，其中兩項由維護者選（守門改成只保護學過的詞；確認一發代替出貨標準第 4 條）；修訂三補收尾審查的三項寫法，維護者選「補完直接實作，不再送審」（decisions 2026-11-03）。維護者在 Orca 改選「權限」很多次都沒記住；三位顧問（Fable、Argon、Astra）指向同一個根因，維護者選「三件一起做」。

## 0. 起因

- 錯字回報第 179、180 列：ㄑㄩㄢˊ ㄒㄧㄢˋ 的 n-gram 第一名是「權限」，會意（語意校正）換成「全線」。CLI 聊天：關語意校正 5／5 對、開 0／5。
- 兩字以上的詞照前文分開學：改選一次只記在那一次的前文鍵底下（句首是 `^>`＋後一個音節）。下一次前文不同時，`Learner::lookup` 的完整鍵、最後一個字兩層都查不到；通用紀錄（GLOBAL）要兩個不同前文才有，而且 `LEARN_EPS_GLOBAL` 是 0，不加分（s4-learning §12、§13）。沒有加分，學習守門（`boosted`，s7c2a §2.2）就不開，會意照樣把「權限」換掉。
- Orca（`com.stablyai.orca`，Electron＋xterm.js）回給輸入法的游標前文字是隱藏輸入框累積的舊字，不是終端機那一行（VM 診斷版量到：送出「權限加好了」、Enter 換行後，下一次讀到的前文仍是「權限加好了」）。每次改選記在對不上的前文底下。
- 改選時畫面已經是那個詞（`pre == word`）時不學（`learn_commit` 的過濾）。〔推論〕維護者「改很多次只有一筆」可能部分來自這裡。

## 1. 機制

1. **跨前文的學習保護（只保護學過的詞）**：現行守門（第一條路徑有學習加分就整段不送重排，s7c2a §2.2）不變。新增：一段照常送重排時，第一條路徑裡若有兩字以上的詞，在任何前文鍵（含句首鍵與 GLOBAL，不含新詞 B 的 NEWWORD）有它這個讀音下衰減後權重 ≥ `ACTIVE`（0.5）的紀錄，重排的候選池只留在同一個位置保有同一個詞的路徑（池的順序與第一條不變）；留下少於 2 條時這一段沒有重排工作（等於守門）。同一段其他位置照常由會意選，SINIT 的句首單字項照常在這個池裡算。
   - 比對：觸發的詞是第一條路徑裡的一個兩字以上的詞（佔第 s 到 e 個音節），它在讀音 `syls[s..e]` 下有合格的紀錄。池裡一條路徑「保有」它＝那條路徑在第 s 到 e 個音節上顯示的字等於這個詞，不管那條路徑怎麼斷詞。第一條路徑有好幾個這樣的詞時，要每一個都保有。
   - 順序：先篩池，再做 SINIT 的 `sinit_chars`／`sinit_swap`。SINIT 抬升解碼找到的路徑也要保有那些詞才換進池；不保有就不換，算進 `missing`。「池少於 2 條就沒有重排工作」在篩完之後、換路徑之前判斷。不改任何分數：`LEARN_EPS_GLOBAL` 維持 0，解碼器只對完整鍵與最後一個字兩層加分，照舊。單字不適用（再／在、他／她照 SINIT 與現行規則）。
2. **前文不可信的 App**：殼多一份清單（`LeftContext.untrusted`），清單裡的 App 一律不讀游標前的字：`leftContext` 回傳 `(nil, nil)`，不呼叫 `attributedSubstring`。所以在這些 App 裡，跟前文有關的東西全部當成「前面沒有字」：n-gram 的前文與學習鍵（每次組字都是句首，句首合成鍵與 SINIT 的句首單字規則因此生效）、會意的前文（context-return §1 的 `left_full` 是空的）、預測列、英文後接預測的前文判斷、中英間空白（cjk-spacing）讀的前一個字。先放已量過的 Orca；其他 App 量過才加（研究紀錄記下量法與結果）。終端機清單（只傳漢字尾巴）照舊。
3. **畫面已是那個詞也照記**：候選窗選的就是畫面上那一段的字（`pre == word`），而且是兩個字以上的詞時，送出時照預測列選取的方式學（s4-learning §1.2 那一列）：被換掉的字當成空字串交給 `teach`，詞 +1.0；`teach` 的鍵規則（句首合成鍵，不記裸 `^`）與通用化照舊；`at_pick` 不減半（沒有被換掉的字）。單字不適用（照舊不學，SINIT 的句首單字學習不擴大）。只有確認過的才算：候選窗開著時選取離開過畫面上那個詞（移到別項再移回來），或之前挑過別的詞再選回原字（`pre_pick` 留著第一次選字前的字，原字 +1.0，X 不學、不減半）。開窗後直接選第一個（等於畫面上的字）不算，直接 Enter 送出也不算，否則習慣用空白或 ↓ 加 Enter 送出的人每個詞都會被記（維護者 2026-11-03 選）。新詞 B 的 `new_word_spans` 過濾不變。
4. **不變**：學習的鍵、檔案格式、`LEARN_EPS`、通用化規則（兩個不同前文）、SINIT 的三層前綴、⌘⌫ 忘記（拿掉這個讀音與詞的所有紀錄，守門也跟著消失）。核心在沒有任何學習紀錄時行為不變；殼的第 2 點不屬於這一條，它在清單裡的 App 本來就改變行為（上面列的那幾項）。

## 2. 測試（核心與殼；Mac 跑改到的測試檔，完整 `make test-rust` 在 188）

- 比對：池裡有一條路徑在同一段音節上顯示「權限」但斷詞不同（例如「權限加」是一個詞），它算保有、留在池裡；第一條路徑有兩個學過的詞時，只保有其中一個的路徑被篩掉。SINIT：句首單字有紀錄、同一段有學過的兩字詞、而抬升路徑沒有那個兩字詞時，池不換進它（`missing` 加一）。
- 保護：學過「權限」（前文 A）之後，前文 B 的一段第一條路徑含「權限」時照常送重排，但重排池裡每條路徑在那個位置都是「權限」；同一段另一個位置的字照常可以被會意換掉；池剩不到 2 條時沒有重排工作；權重衰減到 < 0.5 後池不篩；單字的紀錄、NEWWORD 不觸發；⌘⌫ 之後不觸發；同一段有句首單字紀錄時 SINIT 的學習項照常算（`sinit_chars` 有值）。
- 出貨模型（聊天，語意校正開）：錯字回報第 179 列在句首改選一次「權限」，之後在三種前文（句首、「也加上」、「token」）打 ㄑㄩㄢˊ ㄒㄧㄢˋ ㄐㄧㄚ ㄏㄠˇ ㄌㄜ˙ 都是「權限」；反例：教過「權限」後打「全線通車」那一串（n-gram 第一名本來就是「全線」）仍是「全線」。
- 殼：清單裡的 bundle 不呼叫 `attributedSubstring`，送給核心的前文是 nil，cjk-spacing 用的前一個字（`last`）也是 nil；不在清單的照舊。
- `pre == word`：開窗後直接選第一個（畫面上那個兩字詞）不學；選取移到別項再移回來後選它，送出後學到的紀錄鍵是 `^>…`（不是 `^`），原本這個詞的權重沒有減半而是 +1.0；單字選畫面上那個字照舊不學；先選別的再選回原字算確認原字。現有「選同一個詞不學」的測試改成新的斷言。

## 3. 量測（確認一發：GCP 主跑、188 第二份；新版對 main 臂）

- 出貨標準（維護者 2026-11-03 同意，比照 SINIT）：第 1–3 條由學習關時兩臂逐位元組相同滿足（下面的前置比對）；第 4 條與「探索片出貨前在沒看過的判讀集確認一發」由這一發代替。一發、不開子片救同一次確認；集合、前提結果與門檻在任何學習數字之前一起 commit；GCP 與 188 的 rowstats、keys、摘要逐位元組相同才算數。

- 前置比對（`--learn off`）：出貨標準 8 個集合逐位元組相同（沒有學習紀錄時行為不變）。
- 否決集合（`--learn on --correct`，聊天與書面，標準檔）：dev302、打字測驗、錯字回報 0 列變差（送出由對變錯或改選次數變多）。
- 新的跨前文學習集 `eval/learn/anyctx-cases.tsv`（main 新寫的公開句子；集合、前提結果表與下面的門檻在任何學習數字之前一起 commit，`eval/README.md` 加一列）。格式：五欄 `group\tkind\tleft\tsentence\treading`，kind 是 teach／pos／negA／negB／sinit；轉成 replay 的 `left|sentence|reading` 列，保持檔案順序（每組 teach 在前），每種設定一個 replay 程序跑整份（`--learn on --correct --strict`）。每組：前文 A 教一次（改選），再在前文 B、C 各打一次。
- 「對」一律指那一列那種設定的 `first_ok` 是 1（第一次顯示就對）；「錯」是 0。以下的修好、變錯、由對變錯、前提，都用這個欄位，聊天與書面兩種設定加總，只算前提成立的設定。
- 每組的前提（逐組、逐設定記在前提表）：(a) teach 列在 main 臂、學習關時，那種設定第一次顯示只錯在那個兩字詞，`--correct` 改選的範圍就是那個詞；(b) main 臂學習開、教過之後，B、C 仍然錯（`first_ok` 0；B、C 和 A 的完整鍵與最後一個字都不同）。一組只在前提成立的設定上計分；兩種設定都不成立的組換掉（換掉的組與原因記下）。

  - 反例 negA：至少 4 組。教過的兩字詞出現在另一句的 n-gram 第一條路徑上，但那一句的正解是另一個詞，main 臂（學習開、教過同一個詞）`first_ok` 是 1（會意改對）。照機制 1 這類列會變錯，是接受的代價。
  - 反例 negB：至少 4 組。同一段裡有教過的兩字詞，另有一個別的錯字，main 臂（學習開）`first_ok` 是 1（會意改對）。
  - SINIT 組 sinit：至少 2 組。同一段裡同時有句首單字紀錄（同一份檔先教過）與一個在別的前文教過的兩字詞；main 臂學習開時 `first_ok` 是 1。
  - 通過（全部都要）：pos 的修好列數（新版對、main 臂錯）減 negA 的變錯列數（main 臂對、新版錯）> 0，而且 negA 變錯 ÷ pos 修好 ≤ 0.6；negB 與 sinit 由對變錯 0 列。
- 否決（新版對 main 臂，學習開，聊天與書面，標準檔）：dev302、打字測驗、錯字回報、句首學習集、SINIT 三份確認組，由對變錯 0 列（送出由對變錯或改選次數變多）。

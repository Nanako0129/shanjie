# 換了前文也記得改選過的詞（產品片 LANY）

狀態：初版（2026-11-03），送 plan-verifier。維護者在 Orca 改選「權限」很多次都沒記住；三位顧問（Fable、Argon、Astra）指向同一個根因，維護者選「三件一起做」。

## 0. 起因

- 錯字回報第 179、180 列：ㄑㄩㄢˊ ㄒㄧㄢˋ 的 n-gram 第一名是「權限」，會意（語意校正）換成「全線」。CLI 聊天：關語意校正 5／5 對、開 0／5。
- 兩字以上的詞照前文分開學：改選一次只記在那一次的前文鍵底下（句首是 `^>`＋後一個音節）。下一次前文不同時，`Learner::lookup` 的完整鍵、最後一個字兩層都查不到；通用紀錄（GLOBAL）要兩個不同前文才有，而且 `LEARN_EPS_GLOBAL` 是 0，不加分（s4-learning §12、§13）。沒有加分，學習守門（`boosted`，s7c2a §2.2）就不開，會意照樣把「權限」換掉。
- Orca（`com.stablyai.orca`，Electron＋xterm.js）回給輸入法的游標前文字是隱藏輸入框累積的舊字，不是終端機那一行（VM 診斷版量到：送出「權限加好了」、Enter 換行後，下一次讀到的前文仍是「權限加好了」）。每次改選記在對不上的前文底下。
- 改選時畫面已經是那個詞（`pre == word`）時不學（`learn_commit` 的過濾）。〔推論〕維護者「改很多次只有一筆」可能部分來自這裡。

## 1. 機制

1. **跨前文的學習守門**：一段的第一條路徑裡，只要有一個兩字以上的詞，在任何前文鍵（含句首鍵與 GLOBAL，不含新詞 B 的 NEWWORD）有它這個讀音下衰減後權重 ≥ `ACTIVE`（0.5）的紀錄，`boosted` 就算成立，這一段不送重排。不改任何分數：`LEARN_EPS_GLOBAL` 維持 0，解碼器只對完整鍵與最後一個字兩層加分，照舊。單字不適用（再／在、他／她照 SINIT 與現行規則）。
2. **前文不可信的 App**：殼多一份清單（`LeftContext.untrusted`），清單裡的 App 一律不讀游標前的字，送給核心的前文是空的（句首）。先放已量過的 Orca；其他 App 量過才加（研究紀錄記下量法與結果）。終端機清單（只傳漢字尾巴）照舊。
3. **畫面已是那個詞也照記**：候選窗改選時選的就是畫面上的字（`pre == word`），送出時照樣在送出的前文鍵底下加一次（`bump`），被換掉的字沒有，不減半。只有從候選窗選的才算（`choose` 走過的 `Fixed`）；直接 Enter 送出不算，否則每次送出都成了教。
4. **不變**：學習的鍵、檔案格式、`LEARN_EPS`、通用化規則（兩個不同前文）、SINIT 的三層前綴、⌘⌫ 忘記（拿掉這個讀音與詞的所有紀錄，守門也跟著消失）。

## 2. 測試（核心與殼；Mac 跑改到的測試檔，完整 `make test-rust` 在 188）

- 守門：學過「權限」（前文 A）之後，前文 B 的一段第一條路徑含「權限」時不送重排；權重衰減到 < 0.5 後照常送；單字的紀錄不觸發；NEWWORD 不算；⌘⌫ 之後不觸發。
- 出貨模型（聊天，語意校正開）：錯字回報第 179 列在句首改選一次「權限」，之後在三種前文（句首、「也加上」、「token」）打 ㄑㄩㄢˊ ㄒㄧㄢˋ ㄐㄧㄚ ㄏㄠˇ ㄌㄜ˙ 都是「權限」；反例：教過「權限」後打「全線通車」那一串（n-gram 第一名本來就是「全線」）仍是「全線」。
- 殼：清單裡的 bundle 不呼叫 `attributedSubstring`，送 nil；不在清單的照舊。
- `pre == word`：候選窗選了畫面上那個詞，學習檔多一筆（或權重加一）。

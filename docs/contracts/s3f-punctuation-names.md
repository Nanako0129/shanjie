# S3f 契約：標點候選的名稱

使用者 2026-10-05 用 v0.1.2 打「好了，」後說：「還是沒有我說的跟蘋果一樣的說明啊」，並附上 macOS 內建注音的兩張截圖。

**參考畫面**（使用者的截圖，2026-10-05，macOS 27.0.1）：
- 橫列：每格依序是號碼、標點、名稱，名稱的字比標點小、比較淡：「1 ，全形逗號」「2 、頓號」「3 全形空格」「4 《 左雙書名號」。反白的那一格整格是藍色膠囊。因為名稱佔寬度，一列只放 4 格。
- 按 ↓ 展開：3 欄網格，每格一樣是「標點＋名稱」，只有第一列有號碼（「《 左雙書名號」「〈 左書名號」「< 全形小於」）。

**怎麼算做到**：使用者在一般 App 打「，」並打開候選，看到每個標點旁邊有和內建注音一樣的名稱；點選或按號碼，送出的是標點本身，不含名稱。

## 1. 名稱從哪來

- 執行時讀使用者自己 macOS 上的 `CIMPunctuationDescription_zh_Hant.strings`，和 s3e 的候選表在同一個私有 framework 的 Resources 目錄。不複製進 repo 或發佈檔。2026-10-05 實測：141 筆，最長 8 個字（「全形西式左單引號」），「，」是「全形逗號」、「　」是「全形空格」。
- 和 s3e 一樣的風險：私有 framework 的檔案可能在系統更新後移動或改格式。讀不到時候選照常顯示、沒有名稱，記一句 log。
- 過濾：鍵或名稱空白、含 tab、換行、NUL，或名稱超過 16 個字的筆略過；超過 1,000 筆的檔不當名稱表。
- 只有完全等於某個鍵的候選才有名稱，所以詞的候選永遠沒有名稱。

## 2. 顯示與選取

- 殼把每格的名稱一起交給候選窗（`CandidatePanel.show(_:notes:selected:)`）。app 裡的 `IMKCandidates` 收到的是純文字「標點＋en space＋名稱」，和標點同樣字級。
- 核心與殼內部照舊用原本的候選字串；滑鼠點選時 IMK 交回整格文字，殼用同一個 `CandidateText.display` 對回位置，再當成號碼鍵送進核心。絕不把名稱送出。

## 3. 驗收

1. 自動（`PunctuationTableTests`）：
   - 名稱表過濾（自寫的 fixture）；檔案不存在得到空表；
   - **本機實際的系統名稱表**：打「，」開候選，候選窗收到「，」→「全形逗號」、「、」→「頓號」；點第二格（帶名稱的文字）選到「、」，組字是「、」不含名稱。檔案不存在時測試失敗（不靜靜跳過）；
   - 名稱表不存在時沒有名稱；詞的候選沒有名稱。
   - 突變：不傳名稱、點選不用整格文字對回，兩者都以斷言失敗（2026-10-05 實測）。
2. 使用者實機（agent 不能開輸入法）：打「好了，」開候選，和參考截圖對照名稱、字的大小與顏色、反白；點選與按號碼都只送出標點。

## 4. 範圍外（下一輪）

- 按 ↓ 展開成網格：先實驗系統候選窗能不能自己展開（目前核心把 ↓ 吃掉了）；不行再做自己畫的候選窗（S3b-2）。
- 名稱的顏色、膠囊內的排版：等使用者看過第一輪再調。

## 5. 使用者兩輪實機的結果（2026-10-05）

- **第一輪**：名稱出現了，但比蘋果大。用同比例截圖量，蘋果的「全形逗號」寬 46 px、高 10 px，善解是 62 px、14 px（約 0.73 倍，等於 9 pt）。
- **第二輪**：名稱改成 9 pt，同時實驗讓 ↓ ↑ 交給系統候選窗。結果名稱大小和第一輪一模一樣，↓ 也沒有展開。
- **結論**：`IMKCandidates` 用自己的字級畫整格文字，attributed string 的字型被忽略；公開 API 也沒有展開成網格的行為。小麥注音用自己的 `CandidateUI.HorizontalCandidateController`／`VerticalCandidateController`（2026-10-05 從本機安裝的執行檔字串確認）；蘋果內建注音怎麼畫沒有查證。使用者決定先合併「名稱同字級」的版本，接著做自建候選窗（S3b-2），在那一片做到名稱小字、↓ 展開 3 欄網格與展開動畫。字級設定與 ↓ 實驗都已移除，不留沒有作用的程式。

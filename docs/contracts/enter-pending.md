# 契約：有未完成音節時，Enter 送出顯示的整串

狀態：收尾審查 READY（2026-10-09，§5）；本地 code review 之後補了 §2 的失焦送出與修飾鍵說明。這一片改 `docs/contracts/s3a.md` §3 的按鍵規則與 §6 的 reset。

## 0. 起因與量測

- **回報**：Discord 上的回饋（2026-10-09，使用者轉來的截圖，這裡只轉述）。只打注音時按 Enter 送不出去，要先按空白；轉述的人問能不能和蘋果注音一樣，直接按 Enter 送出注音。
- **實測**（2026-10-09，`tools/imeshot.swift`，使用者的機器，研究紀錄同日）。同一串按鍵各打一次：
  - 只打 ㄅ 再按 Enter；
  - 打 ㄋㄧ（沒打聲調）再按 Enter；
  - 打「落檔」兩個音節，再打 ㄅ、按 Enter。

  | | 蘋果注音（`com.apple.inputmethod.TCIM.Zhuyin`） | 善解（0.3.0 正式版） |
  |---|---|---|
  | 送出的文字 | 「ㄅ」「ㄋㄧ」「落檔ㄅ」 | 三次 Enter 都被吃掉，沒有送出任何字 |
  | 原因 | 把畫面上顯示的整串原樣送出 | s3a 第 13 條：有未完成音節時，其他鍵「已處理，忽略」 |

- **Shift+Enter**（同日另量，plan-verifier 指出沒有規定）：

  | 按鍵 | 蘋果注音 | 善解 0.3.0 之後的本機組建 |
  |---|---|---|
  | ㄅ、Shift+Enter | 送出「ㄅ」，再換行 | 吃掉，沒有送出 |
  | 「你好」、Shift+Enter | 送出「你好」，再換行 | 送出「你好」，沒有換行（第 19 條不看修飾鍵、吃掉按鍵） |

  蘋果的 Shift+Enter 是先送出顯示的整串，再把按鍵交給 App（聊天 App 裡就是換行）；一般 Enter 只送出、不換行（上表三列都沒有換行）。
- **游標在中間**（同日另量一次）：打「你好嗎」三個音節，← 兩次，再打 ㄅ。畫面顯示「你ㄅ好嗎」，Enter 送出的也是「你ㄅ好嗎」。未完成的符號照它在畫面上的位置送出。

## 1. 要做到什麼、怎麼看到

- 有未完成音節時按 Enter，送出組字區顯示的整串，未完成的注音符號照顯示的位置和順序一起送出，然後清空組字區。和蘋果注音實測的行為相同。
- **怎麼看到**：
  - 引擎測試（§3）；
  - 使用者實機：在 TextEdit 打 ㄅ 按 Enter，出現「ㄅ」；打「你好」再打 ㄇ、按 Enter，出現「你好ㄇ」。

## 2. 規則（`s3a.md` §3 新增第 12a 條，放在第 13 條之前）

| # | 狀態 | 按鍵 | 行為 |
|---|---|---|---|
| 12a | 有未完成音節 | Enter（沒有修飾鍵） | 送出組字區顯示的整串：游標前的顯示文字、未完成音節的符號（照顯示順序：聲母、介音、韻母）、游標後的顯示文字。然後清空組字區，和第 19 條相同 |
| 12b | 有未完成音節 | Shift+Enter | 照第 12a 條送出，然後直通這個鍵（`handled = 0`、`commit` 非空，和第 21 條相同） |
| 19a | 組字區有字（沒有未完成音節） | Shift+Enter | 送出組字區顯示的整串，然後直通這個鍵（取代第 19 條對 Shift+Enter 的處理：原本送出後吃掉，App 收不到換行） |

- 第 19 條改成「Enter（沒有修飾鍵）」。⌘、⌥、Ctrl＋Enter 照第 1 條直通、不改狀態，和現在相同。九宮格 Enter 和一般 Enter 同一種按鍵，規則相同。

- **優先順序不變**：
  - 第 1 條（帶 ⌘、⌥ 等修飾鍵直通）照舊。
  - 預測列已進入時，Enter 照第 1d 條選取。
  - 候選窗開著時照第 6 條。有未完成音節時候選窗不會開（第 15 條在第 9–13 條之後），所以不會衝突。
- **學習**：照第 19 條的送出處理，學習只看組字區已解出的部分（`learn_commit` 的輸入是解碼後的顯示文字，不含未完成符號）。未完成的符號不學、不進前文鍵。
- **預測列**：清掉，和其他送出相同。
- **只有未完成音節**（組字區沒有已完成的音節）：送出那幾個注音符號。
- C ABI 欄位不新增。第 12a、19 條 `handled = 1`；第 12b、19a 條 `handled = 0`、`commit` 非空，殼層先插入 `commit` 再讓按鍵通過，和第 21 條相同。`core/include/shanjie.h` 在 `shanjie_engine_key` 旁說明。
- **候選窗開著、預測列已進入**：Enter 與 Shift+Enter 都照第 6、1d 條選取，不送出、不換行。蘋果在這兩個狀態下按 Shift+Enter 怎麼做沒有量過，這是選擇：選取在先，和現在的 Enter 一致。
- **失焦時的送出**（`shanjie_engine_reset` 模式 0：殼層在失焦、切換 App、換擁有者、表外按鍵時呼叫）：也送出顯示的整串，含未完成的注音，和 Enter 一致。原本只送解碼後的文字，未完成的注音會不見。蘋果在失焦時怎麼做沒有量過；選一致是為了不讓使用者打的字無聲消失（推論）。reset 照舊不學習。

## 3. 驗收

1. （已量，§0）蘋果在游標位於中間時，送出的就是顯示的整串，和 §2 相同。
2. **引擎測試**（`core/tests/engine.rs` 或同層，不載入模型也能跑的寫在不載入模型的測試裡）：
   - 只有 ㄅ 時按 Enter：`commit == "ㄅ"`、`handled == 1`、`preedit` 是空字串、候選欄位歸零。
   - ㄋㄧ 按 Enter：`commit == "ㄋㄧ"`。
   - 「你好」加 ㄇ 按 Enter：`commit == "你好ㄇ"`。
   - 游標在中間：「你好嗎」，← 兩次，打 ㄅ，按 Enter：`commit == "你ㄅ好嗎"`。
   - 學習：未完成音節放在改選的詞**前面**。例如打三個音節，在候選窗改選第三個位置的詞，用 Home 把游標移到最前面，打 ㄅ、按 Enter。斷言學到的記錄（前文鍵、讀音、詞、權重）和同一串按鍵不打 ㄅ、直接按 Enter 時的記錄完全相同，而且前文鍵不含注音符號。
   - 預測列：未進入時有未完成音節，按 Enter 照第 12a 條送出；已進入時按 Enter 照第 1d 條選取。
   - 帶 ⌘ 的 Enter 照第 1 條直通，狀態不變。
   - Shift+Enter：
     - 只有 ㄅ 時：`handled == 0`、`commit == "ㄅ"`、`preedit` 是空字串；
     - 「你好」時：`handled == 0`、`commit == "你好"`；
     - 游標在中間時：`commit == "你ㄅ好嗎"`、`handled == 0`。
   - 第 13 條的其他鍵（例如 ↑）仍然吃掉、不動作。
   - `reset(Commit)`：有未完成音節時，`commit` 等於當下顯示的整串（含未完成符號）。
   - 殼層（Swift，`ShellTests`）：打「你好」按 Shift+Enter，`handle` 回 false，App 的文字是「你好」。
3. **既有測試與 golden**：重播測試、golden 一個位元組都不改。如果有既有測試斷言「有未完成音節時 Enter 不送出」，改成新行為，逐項列在 PR 裡寫明原因。
4. **突變**（每一項都要讓某個測試失敗；build error 不算）：
   - 拿掉第 12a 條，回到吃掉；
   - 送出時不含未完成符號；
   - 未完成符號放在整串最後（游標在中間時）；
   - 送出前沒有清掉組字區；
   - Shift+Enter 改回吃掉，有未完成音節與沒有兩種情況各一個突變；
   - 把含未完成符號的送出字串交給 `learn_commit`（學習那一項要以斷言失敗）；
   - `reset(Commit)` 改回只送解碼文字（reset 測試要失敗）。
5. `make test`、CI 全綠。
6. **實機**（使用者）：
   - TextEdit 打 ㄅ 按 Enter，出現「ㄅ」；
   - 打「你好」再打 ㄇ、按 Enter，出現「你好ㄇ」；
   - 在 Discord 打「你好」按 Shift+Enter：送出「你好」並換行，訊息沒有送出去；
   - 一般打字照常：打完音節按 Enter 送出整句，不受影響。

## 4. 停止條件、範圍外

- **停止條件**：
  - 第 3 項的既有 golden 改變；
  - 實作上做不到「送出顯示的整串」（例如殼層另外改寫了送出的文字），要先問使用者。
- **範圍外**：
  - 蘋果注音按 Esc 不清空組字區（同日實測看到，和這次回報無關），不改；
  - 有未完成音節時的其他鍵（第 13 條）照舊。
- **預算**：main 自己實作，加 1 次修正。
- **限制**：subagent 不安裝、不啟動 App、不呼叫 TIS，不讀 `eval/holdout`、學習檔、`~/Library`、鑰匙圈。

# 組字區上限 128，超過 61 字的前段固定

狀態：修訂一送審（2026-10-22）。原版 READY（plan-verifier 兩次 REVISE、收尾 REVISE 後經維護者同意再審兩項，READY；處置在 §6）；實作後量到延遲超過 §3，維護者選「已送出的前段不再解碼」，改法在 §1.2 與 §7。

## 0. 起因與決定

- 維護者：「輸入的底線要改成更長不中斷」「句子要夠長才會斷」「其他app 也可能會，不要只測終端機」。
- 量到的原因（繁體中文的 tart 虛擬機，imeshot 打同一句 51 字、不送出）：善解在第 40 個音節把前段整段送出（`core/src/engine.rs` 的 `MAX_SYLLABLES = 40`），組字區只剩 11 字、底線只在後段；蘋果注音 51 字都還在組字區。蘋果注音打 150 字，組字區停在 101 字、全部仍在組字，之後的鍵沒有作用。Terminal 與文字編輯的截圖是同一個現象。標準文字框裡兩者的底線逐像素相同（粗 4 像素、整段連續），問題不在底線的畫法。
- 維護者的選擇（同日三題）：
  1. 上限：「至少64才有進會意校正的機會，可能128送出」→ **上限 128 個單位，滿了照現在的做法送出整段**。
  2. 超過會意視窗的長段：**只校正最後 64 字**（推薦項）。修訂一起由 §1.2 做到：前段先固定，重排的自由段最長 61 字。
  3. 離開校正範圍的前段：**離開範圍就固定**（推薦項）。
- 會意（`.sjtl`）的視窗是 64 字：候選長於 `ctx − 1` 字時 `TinyLm` 回 `TooLong`，`RerankJob::run` 那一段保留 n-gram 第一名（`core/src/engine.rs` 83 行）。上限 40 時一段最長 40 字，永遠在視窗內；上限拉到 128 就會出現超過視窗的段。

## 1. 規則

### 1.1 上限

- `MAX_SYLLABLES` 40 → **128**（音節、標點、英文 token、數字 token、空白單位都照現在的算法各算一個單位）。到上限的行為不變：插入第 128 個單位後立刻送出整段（`handled = 1`），所有「第 40 個單位」的規則（s3a、s3d、zhen-inline、digits、cjk-spacing、s4 的學習表、newword-b）都改成第 128 個，行為本身不變。
- 預測的單位上限（`ABBR_MAX_UNITS`）不變；「完整音節數加單位數不超過 `MAX_SYLLABLES`」跟著變成 128。

### 1.2 超過範圍的前段先固定（取代「只重排尾段」）

名詞：**自由段**＝組字區裡兩個固定詞（使用者改選的詞、凍結詞、標點、英文 token、數字 token、空白單位）之間、或組字區頭尾到固定詞之間的連續音節，也就是重排工作會拿去當一段（stretch）的範圍。**W** ＝ 載入的會意檔頭的 `ctx − 3`（現行 ctx 64，W 是 61）：`ll_many` 會先丟掉前文 key 的字讓 key＋候選塞進視窗，留 2 個字的位置，`context_key`（最多 2 個漢字）才不會被丟掉。維護者說的「最後 64 字」照這個換算成 61。

**前提**（修訂一）：不論重排開或關都固定。前段固定之後不再重新解碼，每鍵的解碼時間就不隨組字區變長（§7 的量測）。沒有載入會意時 W 用 61（出貨會意的 ctx 64 換算）。

**緩衝 H**（修訂一）：固定時一次固定到剩下的字數 ≤ **W − H**（H ＝ 16 字，具名常數，註解寫出處：§7），不是剛好 ≤ W。超過 W 的那一鍵要解碼兩次（`dispatch` 一次、第 4 步一次）；有了緩衝，往尾端打字時大約每 16 個字才有一鍵解碼兩次，其他鍵只解碼一次。自由段的長度因此落在 45～61 字之間。

**長度的算法**：自由段與 W 都以**字數**（候選的字元數，`TooLong` 用的同一個單位）計，不用音節數；字數和音節數不同的條目（repick-freeze 253 行）照字數。

**每一個鍵（`key()` 與 `pick()`），照這個順序**（第 3、4 步只在**這一鍵的 `dispatch` 真的重新解碼了**（generation 變了）而且組字區不是空的時候才跑；第 4 步只在第 3 步至少固定了一個詞時才跑。←→、Home、End、空白與 ↓ 開窗、窗內移動等不解碼的鍵，`path`、`display`、generation 與等著的重排工作一律不動）：

1. 進 `key()`／`pick()` 時、`dispatch` 之前，存下當下的 `path` 與 `syls`（已經套用的重排結果都在 `path` 裡；還沒套用的重排工作不算）。
2. 照現在的規則處理這個鍵（`dispatch`）：插入、刪除、改選、預測選取、凍結詞的釋放（repick-freeze §6.1、§7.4、§15）、⌘⌫ 遺忘、第 128 個單位的自動送出，都和今天相同。自動送出時組字區已經空了，送出的是今天這一步解碼的結果，以下各步不做事。
3. 第 1 步的 `path` 各詞音節數加起來不等於第 1 步的 `syls` 長度時（和 `freeze_outside` 的對齊檢查相同，engine.rs 3239 行），這一鍵什麼都不固定。否則，對每一個自由段，字數 > W 時，從這段的開頭往後，**一個詞一個詞固定，直到剩下的字數 ≤ W − H**（跨過「段尾往前 W − H 字」那一點的詞也固定），固定成凍結詞（`Fixed { frozen: true }`，repick-freeze 的同一種），詞的內容取第 1 步存下的 `path` 裡的那個詞。只有第 1 步的 `syls` 和現在的 `syls` 的**最長共同前綴**之內、而且完整落在裡面的舊詞才能固定；碰到以下情況就停在那裡、不再往後固定：
   - 詞超出最長共同前綴（這一鍵插入、刪除或預測 splice 改到的位置及其後面），**或詞的結尾離最長共同前綴不到 M 個音節**（M ＝ 4，具名常數；修訂二：游標在長段中間打字時，剛打的音節不能在下一鍵就被固定成單字，多音節詞要還組得起來；`/code-review` 2026-10-22 指出 `b <= lcp` 會把「ㄉㄧㄢˋ ㄋㄠˇ」固定成「店腦」）；
   - 詞落在這一鍵被 ⌘⌫ 遺忘而放開的範圍（遺忘要在畫面上生效，不能被立刻固定回去）。
4. 照現在的規則重新解碼、建重排工作（在 `recompute_pred` 之前），然後**用新的狀態重建這一鍵回傳的輸出**（`view()`，`handled` 照 `dispatch` 的，再接預測列），畫面上的組字、游標與之後 Enter 送出的 `display` 是同一份。照第 3 步，往尾端打字時每個自由段都 ≤ W 字。第 3 步因為上面兩種情況停下、這段仍超過 `ctx − 1` 字時，照現在的規則保留 n-gram 第一名（`RerankJob::run`，engine.rs 83 行）；這只發生在游標在前段插入、或 ⌘⌫ 遺忘的那一鍵，下一鍵往尾端打字就會照第 3 步收回 W 以內。

**凍結詞的來源與釋放**：這樣固定的詞和 repick-freeze 的凍結詞是同一種，釋放規則照舊：新音節和它組成詞（§6.1、§7.4）、Backspace 把它切開留下的單字遇到下一個音節（§15）都會釋放；釋放後同一鍵的第 3 步若這段又超過 W，就重新固定（以第 1 步的樣子）。這是 repick-freeze「被放開的詞與新音節都是自由的」（247 行）的例外，只在自由段超過 W 時發生；那份契約要註明。使用者改選的詞本來就固定、不是凍結詞，第 3 步不碰它。凍結詞不學習（照 repick-freeze）。

**非同步重排**：重排在背景跑，套用（`apply_rerank`，engine.rs 975 行）可能晚於下一鍵。所以「固定成會意改過的字」只對那一鍵之前已經套用的結果成立；在 `shanjie-replay --rerank each`（每鍵套用後才送下一鍵）下是確定的，`final` 下前段固定成 n-gram 的字。

### 1.3 不變的部分

- 重排本身（候選、前文 key、融合、常談、讀音通道項、`TooLong` 的保護）照現在的規則，一個字都不改。
- 組字區裡還沒有 §1.2 第 3 步固定的詞時（這個組字區從來沒有自由段超過 W 字），解碼與輸出和今天逐位元組相同（重排開或關、有沒有載入會意都一樣）。

## 2. 怎麼看到它有效

- 繁中虛擬機（`tart run --no-audio`），imeshot 從 .app 執行，打第 0 節那句 51 字：組字區 51 字全部還在、底線連續；打 150 字：第 128 個單位時送出整段、剩下 22 字在組字區。Terminal、文字編輯、Safari 的文字框各截一張（送鍵前確認輸入法切成功）。
- 引擎測試（`core/tests/`，每一條寫明按鍵序列與 `--rerank each` 的套用時機）：
  1. 沒有標點連打 70 個音節，挑一句在第 62 個字那一鍵開頭是兩個字以上的詞：從第 62 鍵到第 70 鍵，每一鍵 `take_rerank_job()` 裡每個 stretch 的每個候選都 ≤ W 字、沒有一段走到 `TooLong`，前段整詞固定成上一鍵的樣子；每一鍵回傳的 preedit 等於 `display`，也等於凍結詞加自由段的文字（挑的句子要有至少一鍵是 `dispatch` 第一次解碼改寫了前段的詞）；在重排會改字的句子上（從開發集挑一句會意會改的接在前面），改過的字移出範圍後仍是改過的樣子。
  2. 61 字的自由段，游標移到第 1 個音節後面再打一個音節：新音節與它之後的詞不固定、不出錯，照 §1.2 第 3 步跳過。
  2b. （修訂二）同樣的狀態，Home 之後連打「ㄉㄧㄢˋ ㄋㄠˇ ㄓㄨㄛ」：顯示「電腦桌」開頭，前兩個音節沒有被固定成單字；拿掉 M（當 0）時這個測試會失敗。
  3. 連打 78 個音節後（修訂一：有 16 字緩衝時 70 個音節的尾段只有約 53 字，釋放後到不了 W），← 移到凍結前段與自由尾段的交界，打一個會和左邊最後一個凍結詞組成詞的音節（測試挑一句讓這件事成立，並寫明尾段字數 R，R 要讓釋放後的自由段超過 W）：凍結詞照 §6.1 釋放，同一鍵再固定。斷言 `fixed` 裡的凍結詞範圍與字等於測試裡事先寫好的清單，而且每個自由段 ≤ W；拿掉第 3 步的重新固定時這個測試會失敗。
  4. 連打 78 個音節 → ← 移到交界 → ⌫ 刪掉緊鄰自由尾段的最後一個多音節凍結詞的最後一個音節 → 打一個音節（寫明 R）：§15 釋放、再固定。斷言方式同測試 3。
  5. 重排關（`.sjtl` 已載入、`rerank_on` 0）、連打 70 個音節（修訂一）：`take_rerank_job()` 是 None；前段照第 3 步固定，每個自由段 ≤ W 字；顯示等於凍結詞加自由段的 n-gram 第一名；組字區 ≤ W 字的每一鍵，顯示等於同一個解碼器對當下全部音節的 n-gram 第一名。
  9. 緩衝與前提（修訂一）：四臂各連打 128 個音節（沒有標點）：(a) `.sjtl` 已載入、重排開；(b) `.sjtl` 已載入、`rerank_on` 0；(c) 沒有載入 `.sjtl`（斷言 W 是 61）；(d) `.sjtl` 已載入、重排開、降權表關。每一臂每一鍵之後每個自由段 ≤ W 字；打完第 127 個音節（第 128 個自動送出之前）時檢查一次：到這一鍵為止，解碼兩次的鍵（`Engine::decodes` 一鍵加 2）的數目 ≤ ⌈(這時組字區的字數 − W) ÷ H⌉ + 1。拿掉緩衝（H 當 0）、或把固定的條件寫成 `jobs_on()`、`tinylm.is_some()`、降權表開（任一種）時，這個測試都會失敗。
  6. 兩段各 40 字、中間一個標點，刪掉標點：同一鍵前段固定，自由段 ≤ 61。
  7. 第 128 個單位送出整段；第 127 個不送。
  8. 重排開：拿到並套用一個會改字的重排工作，然後按 ←、再按 ↓：每一鍵之後 preedit 與 `display` 不變、generation 不變、`take_rerank_job()` 是 None。另斷言第 3 步沒有固定任何詞的鍵只解碼一次（generation 和只跑 `dispatch` 相同）。
- 評測：`shanjie-replay --rerank each`（與 `core/tests/engine_replay.rs`）在 dev302、打字測驗、錯字回報，聊天與書面兩種設定，`top1_sha256` 和改動前相同（eval/ 裡沒有超過 32 個音節的列，不會碰到新規則；不同就停）。CLI 評測（`shanjie-eval` 的 LM 模式）不經過 `MAX_SYLLABLES` 與重排工作，照構造不受影響。
- 延遲：在 `timing_typing76_keys` 旁加一個 release 測試，重播 128 個音節、沒有標點的長句（語意校正開、會意載入）。報三個數字：重排開時按鍵路徑的 p95 ≤ 16 毫秒、`RerankJob::run` 的 p95 ≤ 300 毫秒（PLAN A3 的上限）；重排關時（`.sjtl` 已載入、`rerank_on` 0；修訂一起也固定前段，每鍵最多解一個 W 字的自由段）按鍵路徑的 p95 ≤ 16 毫秒。另報兩種設定下單鍵的最大值；任何一鍵超過 50 毫秒，要找出是哪一步、寫進研究紀錄（實作時量到第一次固定的那一鍵約 90 毫秒，修訂一要找原因）。M5 Mac、低負載（`uptime` 的 1 分鐘平均 < 2），各跑 5 輪取中位數，和 commit SHA 一起記進 PR 與研究紀錄。

## 3. 停止條件

- 長句的按鍵路徑 p95（重排開或關任一種）超過 16 毫秒，或 `RerankJob::run` p95 超過 300 毫秒：停下來報數字，和維護者討論（例如上限改小）。
- replay 的 `top1_sha256` 有任何一格和改動前不同。
- 第 3 步改到使用者改選過的詞。

## 4. 範圍外

- 蘋果注音「滿了之後的鍵沒有作用」：維護者選了滿了就送出。
- 把長段切成好幾個小段各自校正（維護者沒有選）。
- 會意的視窗本身（模型不換）。
- 前文回傳（另一片）。

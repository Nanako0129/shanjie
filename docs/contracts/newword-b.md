## 2. 規則

### 2.1 什麼時候學

- 送出路徑照 S4 §1.2 的表：Enter、規則 21、滿 `MAX_SYLLABLES` 自動送出學；reset、Esc、解碼失敗不學。
- 這次組字至少有一段由候選窗 `choose()` 改選成**單字**，而且改選前畫面上的字和選到的字不同（S4 §1.2 的「改選」定義）。從預測列選取的詞不算（它們是詞庫詞，不是逐字改選）。
- 學習旗標在改選當下與送出當下都是 1（S4 §3，privacyGate）。
- 這段組字期間學習旗標曾經是 0（`set_learning(0)`），送出時就不學新詞：暫停期間打的字不會因為相鄰的改選而被存下。引擎在 `set_learning(0)` 時設一個旗標，`clear_all` 時清掉。

### 2.2 學什麼

1. 取送出當下組字區最後路徑上的詞（顯示用的切分，和 `refresh_lm` 相同）。
2. 找出**連續的單字詞**段落（每個詞一個音節、一個漢字）。遇到下列任一就切開：
   - 標點替代字（讀音以 `_punct_` 開頭）、非漢字；
   - 功能字表 `NEWWORD_BREAK` 裡的字（具名常數；初始值是模擬用的表：的了是在再嗎呢吧啊喔耶囉啦欸也而就和或與及跟你我他她它們這那有沒要會很都還又給把被讓。§3.2 在 cvtune、wikitune 重定，定案的表與量測寫進研究紀錄）。
3. 切開後的每一段，同時符合下列條件才學：
   - 至少含一個 2.1 的改選字；
   - 2–4 個音節（`NEWWORD_MIN`、`NEWWORD_MAX`）；
   - 這一串讀音下，詞庫（基底、`overlay-add.tsv`、`sandhi-add.tsv`、目前載入的詞包）沒有這個詞；
   - 不是全由數字字組成（具名常數 `NEWWORD_DIGITS`：〇零一二三四五六七八九十百千萬億兩壹貳參肆伍陸柒捌玖拾佰仟），數字、代碼、金額不學。
4. 已經學過的同一個（讀音, 詞）：權重照 S4 衰減後加 1。

### 2.3 存在哪

- 和 S4 同一個 `learning.tsv`、同一套寫入（追加、完整重寫、`must_rewrite`、bit0）、衰減（半衰期 14 天）、修剪（`PRUNE_FLOOR`）、清除與 Time Machine 規則。
- 一筆新詞的前文欄是 `#`（新的哨兵，和 S4 的「^」、全域的空字串不同）：`#\t讀音\t詞\t權重\t日期`。`learn_store.rs` 的 `valid()` 只接受前文剛好是 `#`、詞是 2–4 個字而且每個字都是漢字（重用 `learn.rs` 的 `is_han`）、讀音音節數等於字數的列；§12 的單字規則不放寬。
- 標頭版本不升（`#shanjie-learning v1`）：升了的話，舊版會把整個檔案改名成 `.corrupt`。
- S4 的前文查詢（完全比對、1 字、全域）永遠不會比對到 `#`。
- 新詞最多 `NEWWORD_CAP`＝2,000 筆（具名常數）；超過時先刪權重最低的，和 S4 的 50,000 筆上限分開算。載入後的修剪就套用，不只在寫檔時。
- **舊版相容**（讀程式碼的推論，§3.4 用單元測試確認解析結果）：現有版本的 `valid()` 對 `#` 算出 `context_key("#") == "^"`，和 `#` 不同，所以舊版載入時逐行略過這些列。降回舊版時，舊版第一次完整重寫會把它們刪掉。退回說明加這一句。

### 2.4 解碼時怎麼用

- 解碼時，衰減後權重 ≥ 0.5 的新詞，和詞庫詞一起列舉在它的讀音上，**不看前文**。
- 它的詞條分數（log10）是 `S(w) = NEWWORD_S_MIN + (NEWWORD_S_MAX − NEWWORD_S_MIN) × w／(w + 1)`，w 是衰減後的權重。兩個常數在 §3.2 定。語言模型那一項的處理，和詞包裡模型沒看過的詞相同（例如「碇源堂」）。
- 現在的解碼器只在詞庫有這個讀音時才列舉（`lm.rs` 的 `base.find`）；新詞的讀音在詞庫裡通常沒有任何詞（研究：9 個缺詞的整串讀音在詞庫裡都是 0 個詞），所以要另外列舉。
- store 是空的、或沒有 `#` 列時，解碼與現在逐位元相同；store 只有 `#` 列、但打的讀音沒有碰到任何新詞時也相同（`words_of`、`has_reading`、預測列的 `reading_matches` 都看得到 `#` 列，要確認不影響輸出）。
- 學到之後詞庫或詞包才收了同一個詞：解碼時遇到詞庫已有的（讀音, 詞）就不另外列舉新詞。
- **候選窗**：新詞照讀音和詞庫詞一起列進候選窗，排在同長度的詞庫詞前面，所以 ⌘⌫ 找得到它。`docs/contracts/s3a.md` §3.1（候選窗只列詞庫的詞）在同一個 PR 改。
- **從候選窗選新詞**：照一般選字固定成 `Fixed`。
  - `refresh_lm` 給固定的新詞的分數是它 `#` 紀錄的 S(w)；這裡不看 0.5 的門檻（門檻只管列舉），所以固定之後就算權重衰減也不會出錯。現在的 `best_lp_delta` 只查詞庫（`lm.rs`），要另外處理這個情況。
  - 固定中的新詞，紀錄不在了（被 ⌘⌫ 忘記、被清除）：那一段解除固定，照未固定重新解碼，不回錯誤。
  - 選新詞**不走** S4 的教學（`learn_commit` 不為它寫 S4 紀錄）；送出時照 2.5 算「用到」。
  - 另外，S4 的全域化計數（`Learner::teach` 算「幾種完整前文」）排除 `#` 列，`#` 永遠不算一種前文。

### 2.5 用到時與被改走時

- **用到**：學習旗標在送出當下開著的送出（2.1 的送出路徑），最後路徑上有新詞、而且那一段沒被改選走：權重照 S4 衰減後加 1，**每個新詞每個本地日最多一次**（紀錄的日期已經是今天就不加、不寫）。
  - 沒有改選的送出也算，這一點和 S4 不同；只更新既有的 `#` 列，不建立新列、不加新內容。
  - 每日一次讓寫檔頻率降到每詞每天最多一次，檔案透露的時間精度和日期欄相同，解碼器自己放上路徑的碎片也不會無限自我強化；每 60 天用到一次就不會被修剪。
  - `learn_commit` 的提早返回條件改成「沒有待學改選，而且路徑上沒有今天還沒算過的新詞」；`must_rewrite` 重試的說明跟著改。
- **被改走**：改選的範圍和路徑上某個新詞重疊時，那個新詞的權重減半（S4「改選走」的做法）。
- 這兩條讓常用的新詞不會在 60 天後被修剪掉，打錯學到的碎片則會被改走而淡掉。

### 2.6 忘記與清除

- 候選窗開著時對新詞按 ⌘⌫：刪掉它的 `#` 列，一律完整重寫（S4 §1.5、§4）。之後回到沒學過時的解碼。
- 同時，這段組字裡和該讀音任何出現位置重疊的固定段，待學的改選一律丟掉（`pre = None`）。否則畫面上的「版」（帶著改選）在下一次 Enter 又會照 2.2 把「版控」學回來（S4 在 2026-10-05 修過同類問題）。
- ⌘⌫ 只忘記這個新詞；同一次改選留下的 S4 單字紀錄（例如前文「陳」下的「怡」）不會跟著刪，要另外在候選窗忘記，或用「清除選字記憶…」。揭露文字寫明這一點。
- 不留「刪過的詞不再學」的排除表：排除表本身就會把刪掉的詞留在檔案裡，和「忘記之後檔案裡沒有該詞」（S4 §4）衝突。同一個詞只有在使用者又逐字改選一次時才會再學回來。
- 「清除選字記憶…」一併清掉新詞。

## 3. 驗收

### 3.1 量測工具（進 repo，可重現）

- 一個 ignored 測試（例如 `core/tests/engine_newword.rs` 的 `measure_newword`），走正式的 `Engine`，用環境變數給集合、設定與輸出位置。模擬照事前研究：
  - **教**：同一個引擎、學習開著、記憶體裡的 store，依序打每一列（帶前文）。第一個錯字後面開候選窗，選「結尾在游標、和正解相符的最長候選」；重複到整句正確或無法再改，按 Enter。
  - **重播**：學習關掉，再解一次（集合本身或另一個集合）。
  - **基準**＝同樣的教與重播，但新詞 B 關掉（只有 S4）；**新**＝S4＋新詞 B。
- 輸出 `--rowstats` 同格式的逐列檔，用 `tools/evalstats.py compare` 比。

### 3.2 定參數（cvtune、wikitune，main 在本機跑；不用 dev302 調）

- 掃 `NEWWORD_BREAK` 的候選表（模擬用的表、libchewing 的 41 字表、兩者之間的變化）與 `NEWWORD_S_MIN`／`NEWWORD_S_MAX`（−6 到 −1）。
- 在 cvtune、wikitune 上「教該集合、重播該集合」，選改壞 0、改對最多的組合；同分取最保守（分數最低）的。
- 照 methodology 的守門：配對檢定 p < 0.05 而且淨值為負就否決。掃描的表與選定值寫進研究紀錄。

### 3.4 單元與引擎測試

- 2.2 的每一條：功能字切開、2–4 音節、詞庫已有不學、不含改選字的段不學、標點與非漢字切開。
- 2.1：沒有改選不學；改選成多字詞不學；改選前後同字不學；改選當下或送出當下學習關著都不學；reset、Esc 不學。

# 錯誤桶工具 `tools/triage.py`（研究工具，不出貨）

狀態：READY（2026-10-14 收尾審查）；plan-verifier 兩次 REVISE 都照改（§9）。

## 0. 起因

- 維護者 2026-10-14 選擇題定了迭代流程：沒有固定週期，有空就開下一片，方向先和研究顧問（Fable）討論再出選擇題；**第一個做錯誤桶工具**（`.agent-local` 的「迭代流程」一節、`docs/PLAN.md`「迭代流程與錯誤桶工具」）。
- 目的：每輪開始時，用同一張表看出貨設定在各評測集合**錯在哪裡、各有多少列**，照「桶大小 × 預估救得回的比例 ÷ 成本」排出候選題目；每輪的表和 `docs/benchmark.md` 並排，看桶有沒有變小。
- 設計稿：研究顧問 2026-10-14 的分析（研究紀錄同日記重點）。

## 1. 要做到什麼

1. `shanjie-eval`（`cli/src/main.rs`）加兩個**只增加輸出、不改既有輸出**的東西：
   - `--dump-words FILE`：每列前 64 名的詞切分，一行 `列號\t名次\t詞1 詞2 …`（詞以半形空白分隔；順序與 `--dump` 相同），另加名次 0：正解用核心的 `segment_words`（`core/src/lib.rs`）切出來的詞（切不出來就寫 `-`）。不改 `--dump` 的欄位（`tools/bench.py`、`experiments/x0c/score_0c.py` 照四欄讀）。
   - `--tinylm-scores` 每列多一個整數欄位 `"c"`：重排實際選到的名次（從 0 起；沒有重排時 0）。
2. `tools/triage.py`：
   - `run`：讀列檔、`--dump`、`--dump-words`、`--rowstats`、`--tinylm-scores`（出貨設定一次）與第二次不帶 `--context` 的 `--rowstats`，加上詞庫（和引擎與 CLI 載入的完全相同，`core/src/engine.rs` 的 `load_lexicon_packs_detailed`：`data/lexicon/mcbpmf-data.txt`、`data/lexicon/overlay-add.tsv`、`data/lexicon/sandhi-add.tsv`、`data/packs/acg-add.tsv`），把每個錯列歸到一個主桶與幾個標記（§3），寫 `eval/bench/triage/<label>.json`。
   - `table`：從 JSON 產生 `docs/triage.md`（每種設定一張表；第二張表是修法家族的排序，§4）。不手改。
3. 單元測試 `tools/test_triage.py`（合成的小列檔、dump、詞庫），每條規則一個會失敗的突變。

## 2. 出貨設定與要跑的集合

- 出貨設定 S：`--lm data/lm/bigram.sjlm --profile <chat|formal> --context --packs acg --tinylm data/lm/tinylm.sjtl`（App 預設；`tools/bench.py` 的 `VERSIONS2` 最新一版）。
- 每個（集合, 設定）跑兩次：S 加 `--dump --dump-words --rowstats --tinylm-scores`；S 去掉 `--context` 只加 `--rowstats`（§3 的 E）。
- 集合：套件 v2（`tools/bench.py` 的 `SETS2`）：dev302、typing76、probe、錯字回報（全部列）、fw、cvtune、wikitune、lytune、wikitypo、discordtune。**保留集不跑、不分桶**，`docs/triage.md` 不列保留集（照保留集規則，只由 fresh verifier 跑：2026-10-18 起只在推 `v*` tag 前，之前是每片收尾；要看保留集照 `docs/benchmark.md`）。
- 在哪裡跑：重的評測一律在 Mac 以外的機器（Windows 主機或 Colab）；cvtune、wikitune、lytune、wikitypo 與 discordtune 一定在那裡跑，先在那台機器上確認 dev302 兩種設定的 `top1_sha256` 和 Mac 相同才用。dev302、typing76、probe、錯字回報、fw（合計約 750 列）也可以在 Mac 上跑，但只當快速檢查。私人集合的 dump 與切分只留在那台機器，分桶在那裡算完只帶回計數。（2026-10-18 起）CLI 的 `--threads N`（只有 LM 模式，預設 1）用 N 條執行緒共用同一份模型解碼各列，輸出檔與摘要行和 N = 1 逐位元組相同，N > 1 時 stderr 的小模型延遲行時間數字不同（在爭用下量的），且行尾多一段 `(threads N: measured under contention)`，N 是工作執行緒數（上限為列數除以 32 的區塊數）；次數相同；`run --cli-threads K` 把 `--threads K` 傳給每一次 CLI 呼叫（K = 1 不傳）。`run --jobs N` 用 N 條執行緒同時跑（集合, 設定）各格（每格的重活是 CLI 子程序，同 `tools/bench.py`），寫出的 JSON 與逐列檔和依序跑逐位元組相同；某一格失敗時，之後不再開始任何格、正在跑的跑完（它們的暫存目錄含句子，由它們自己刪），再丟出第一個錯；重複的 `--set` 名稱只算一次。每一格的逐列檔在該格結果回到主執行緒時就寫出，JSON 最後一次寫。

## 3. 分桶（每個錯列一個主桶，依序判定；E、子標記另計）

錯列＝S 的 rowstats `ok=0` 的列。**起算方式**：名次＝`--dump` 的名次，從 1 起（名次 0 是 `segment_words` 那一行）；`c`、`j` 與 `ok[]`、`ng[]`、`ll[]` 的索引從 0 起，名次＝索引＋1。**比對**一律用寬鬆比對（`reference/proto/eval.py` 讀 `eval/variants.tsv` 的那一套，和 CLI 的 `ok`、`oracle@64` 相同）。**正解名次**＝前 64 名裡第一個（分數最高）寬鬆比對等於正解的名次；正解路徑＝那一名在 `--dump-words` 的切分；前 64 名都不符時用名次 0（`segment_words` 的切分），並標 `seg=lex`（名次 0 是 `-` 時標 `seg=none`，差異段落就是差異位置本身）。**差異位置**：選到的句子（重排後）與正解先寬鬆正規化，再逐字比；長度不同就退回原字串比。**差異段落**：把每個差異位置往兩側擴到正解路徑的詞界，相鄰或重疊的合併。

**B1 的真正意思與已知的漏**：名次 0 的切分來自 `segment_words`，只會切出詞庫裡的詞，所以 ≥ 2 字的差異段一定拼得出詞庫的詞；B1 因此量的是「正解不在名單、差異段 ≥ 2 字」，**不證明詞庫缺詞**（原先的子標記 B1b 恆等於 B1，已刪）。缺詞但差異的部分只有 1 字的列落在 B2（例：dev302 第 300 列）。

| 序 | 桶 | 規則 |
|---|---|---|
| 1 | F 離線對（只錯字回報） | 錯字回報檔的 `ok=1` 列（實機錯、離線對；不是錯列，另列一欄） |
| 2 | A1 讀音不在詞庫 | 差異段落裡**任一個正解詞**（正解路徑的詞，逐詞判斷）不在列檔對應讀音下的詞條，但詞庫在其他讀音下有這個詞 |
| 3 | B1 差異段 ≥ 2 字 | 正解不在前 64 名，且**任一個**差異段落 ≥ 2 字、整段不是任何讀音下的詞條 |
| 4 | B2 不在名單 | 正解不在前 64 名，其餘 |
| 5 | D1 重排改壞 | 有 `--tinylm`、n-gram 第一名對（`ok[0]=1`）而選到的 `c≠0` 錯 |
| 6 | C 排序錯 | 其餘（正解在前 64 名，n-gram 第一名錯、重排沒救） |

已知限制：A1 用名次 0 或正解名次的切分（`segment_words` 不看列的讀音）判斷哪些是正解詞，所以讀音和詞庫的最長切分不一致的列可能判錯（例：`一個`、`ㄧˊ ㄍㄜ˙`，切分不看讀音）。這一點先不處理。

C 的子類（互斥，依序；選到的句子的切分取它在 `--dump-words` 的那一名）：**C4 多處**（≥ 2 個差異段落）→ 以下只看只有一個段落的列：**C3 斷詞不同**（段落上兩邊的詞界不同）→ **C1 單字同音**（段落 1 字，兩邊在段落上都是一個單字詞；子標記「正解是功能字」：只看正解那一側的字在不在具名常數表，出處寫在常數旁；兩側都是功能字的列另計為 `c_func`，見 §4 的家族表）→ **C2 多字詞輸給同音詞**（段落上兩邊各是一個多字詞、詞界相同；子標記「來源」：正解詞只在 `overlay-add.tsv` 或詞包，`sandhi-add.tsv` 的變調讀音不算來源）→ **C5 其他**（剩下的，例如段落上兩邊各是幾個詞但詞界相同）。C 的另兩個維度：正解名次（2、3–8、9–64）、n-gram 分差（第 1 名減正解，log10：<0.25、0.25–0.5、0.5–1、1–2、≥2）。

名次 ≤ 8 的 C 另標 D2（重排沒救），照核心 `pick` 的順序（`core/src/tinylm.rs`）：**D2a**＝`ng[0] − ng[1] ≥ τ`（沒重排）；否則 j＝`argmax(ng + α·ll)`（同分取 n-gram 名次較前的，和 `pick` 相同）：`ok[j] = 1`（任一個寬鬆比對等於正解的候選）→ **D2b**（`s[j] − s[0] < δ`，融合分差不到 δ）；否則 **D2c**（小模型也選錯）。這一列沒有 `ll`（候選太長被略過，或只有一個候選）→ **D2-none**。α、τ、δ 讀 `.sjtl` 檔頭，依設定。

E（第二次不帶 `--context` 的 rowstats）：E1 有前文才對、E2 有前文反而錯；前文欄空或不是漢字的列不標。

## 4. 輸出

- `eval/bench/triage/<label>.json`：每個（集合, 設定）各桶與標記的計數、n、錯列數、版本 commit（工作樹有未提交的改動時尾端加 `-dirty`）、CLI 執行檔與三個模型檔的雜湊；公開集合另存逐列數字檔（`列號\t桶代碼\t名次\t分差帶\tE`）在 repo 外，只用於驗證與跨輪比對。私人集合只有計數。
- `docs/triage.md`：每種設定一張表（列＝集合，欄＝n、錯、各桶）；第二張表＝修法家族與可救的桶、可救比例（具名常數，量過的寫出處，沒量的標〔推論〕）、成本（片數）、排序值。三個數都印出來，不只印結果。家族的列數會重疊（`c_func` 的列同時在 C1／C2／C3 與 D2b／D2c，C3 的列也在 D2c），表上註明不能相加。

## 5. 驗收

1. CLI：不帶新選項時所有既有輸出逐位元組不變（`make test-rust` 的 golden 全過）；`--dump-words` 的列數與名次和 `--dump` 一一對應；`c` 與重排實際選的句子一致（有測試）。
2. `tools/test_triage.py`：每條規則的合成例子，突變（規則反過來或拿掉）會失敗；至少包含：正解詞只在 `sandhi-add.tsv` 的讀音下的列不是 A1（拿掉 sandhi 檔就失敗）；正解在索引 1、2 都寬鬆相等、j＝2 而且 `s[2] − s[0] < δ` 的列是 D2b；兩個段落、只有一段符合 B1 的列照「任一個」歸 B1；只在寬鬆比對下才等於正解的句子（歸 C，不是 B2）；正解出現在兩個名次、切分不同（用第一名的切分）；缺詞列用名次 0 的切分（段落固定）；兩個段落的列即使其中一段是單字也歸 C4；融合後選錯而且分差不到 δ 的列歸 D2c；沒有 `ll` 的列歸 D2-none。守恆：各主桶合計＝錯列數＝n − 摘要行 top1。
3. **盲標**：main 在看工具的分桶輸出之前，從 `ok=0` 的列用固定種子均勻隨機抽 60 列（錯字回報 30、dev302／typing76／fw 合起來 30；種子與列號記進研究紀錄），手標主桶與 C 子類，再和工具比，印混淆矩陣與三個數：(i) 60 列主桶一致率 ≥ 90%；(ii) 兩邊都判成 C 的列裡 C 子類一致率 ≥ 80%；(iii) 手標 ≥ 5 列的每個桶各印 n、precision、recall；手標不到 5 列的桶印「樣本不足」，在 `docs/triage.md` 標成未驗證，但不算這一關失敗。這一關以 (i)、(ii) 判定；不到就改一次規則（或改標準）並寫研究紀錄，再不到就停（§7）。研究紀錄引用這些數字。
4. 第一張表：在當時的 main（出貨設定）跑完全部集合，`docs/triage.md` 與 JSON 進 PR；研究紀錄記重點（各桶大小、哪幾個家族排最前）。

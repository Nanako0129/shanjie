# S4 契約：選字記憶（使用者學習）

使用者 2026-10-04 回報「改字後也沒有學習」：v0.1 沒有任何學習，同一個錯每次都要重改。使用者同意 S4 與 S2r-2、判斷器實驗平行進行。這份契約過了 `pilotfish:plan-verifier` 與 `pilotfish:security-reviewer`（審查與處置見 §10），要經使用者核准才開工。

**怎麼算做到**：使用者打一句話，在候選窗把某個詞改成另一個詞並按 Enter 送出。下次在**相同的前文**下打同樣的讀音，會直接出現他改過的詞；其他句子的常用詞不受影響。這由 A2 的自動測試證明，並由使用者實機確認（§7）。

## 0. 依據（PLAN 已定的設計）

- PLAN §S4：
  - 前文 key 用 ≤ 2 字、天級衰減；
  - 2 個字以上的詞在 ≥ 2 種前文都被改選才全域化；單字不全域化，而且只在完整前文相同、非「^」時學與加分（§12）；
  - 分數取 `max(系統分, 混合分)`；只有打開候選窗改選才學；
  - 候選窗一鍵忘記；改選走時舊紀錄減半。
- PLAN §7：
  - R2：不進任何 log；學習檔除了 ≤ 2 字的漢字前文，不含沒被改選的內容。
  - R3：`privacyGate`；使用者決定終端機照樣學，理由是「只學改選的中文詞，英數直通不學」。
  - R4：前文截斷、只活在記憶體。
  - R5：`~/Library/Application Support/shanjie/`，0600；只存「前文、讀音、詞、分數、日期」；一鍵清除；揭露 Time Machine。
- A2：改選一次冷門詞後，常用詞句 0 退步；同前文的冷門詞句 ≥ 80% 學會（`eval/learn/cases.tsv`，14 組）。
- 現況：
  - 核心有 S0 移植的 `Learner` trait，但正式路徑的 LM 解碼（`core/src/lm.rs::decode_segment`）沒有接學習；解碼每個讀音只列舉前 `PER_KEY`（12）名。
  - 候選窗選字是 `engine.rs::choose()`，把那段固定成 `Fixed`；候選窗的順序來自詞庫，不受學習影響。

## 1. 學習模型（核心）

### 1.1 前文：學習端與解碼端共用同一個函式

```text
context_key(prefix: &str) -> Key
  從 prefix 的尾端往前取連續的漢字（\p{sc=Han}），最多 2 字；
  遇到任何非漢字（標點、英數、空白、控制字元、emoji）就停。
  一個字都沒取到時，回傳句首哨兵「^」。
```

- **prefix** = 殼傳入的前文（§2）＋組字區裡、這個段落之前的已顯示文字。
- 學習端在**送出當下**計算；解碼端用「segment 之前的文字（新參數）＋路徑上已經走過的 `h.surface`」計算。兩邊呼叫同一個 `context_key`。
- **查詢順序**：完全比對 → 只看最後 1 字 → 全域。
  - 每次教學只寫**一筆**紀錄，key 是完整的前文 key（1 或 2 個漢字，或「^」）。
  - 「完全比對」這一步：key 完全相同才算，包括 1 個字的 key 與「^」。
  - 「1 字」這一步（單字的紀錄不參加，§12）：比對所有 1 或 2 個漢字的 key，**最後一個字**和查詢的最後一個字相同就算。永遠不比對「^」與全域 key。
  - 例：在「管把」後面教一次，之後在「肯把」後面能查到（1 字這步），而且不產生全域紀錄。
  - 依這個定義，`cases.tsv` 中標 same_ctx=1 的 14 列，前文能對上的上限是 13 列（92.9%）。不能對上的是「發炎」那列：「喉嚨」對「嚨又」。這個數字由 plan-verifier 從 `cases.tsv` 算出，executor 在第 0 步要重算確認。
- **哨兵**：
  - 句首用「^」，全域用空字串，兩者不同。在句首教一次，不會變成全域。
  - TSV 仍然只有 §4 的五個欄位。

### 1.2 什麼時候學

| 送出路徑 | 學不學 |
|---|---|
| Enter | 學 |
| 規則 21（組字中按了引擎不處理的鍵，先送出再交給 App） | 學 |
| 滿 `MAX_SYLLABLES` 自動送出 | 學 |
| 核心的 `reset`（不論 Commit 或 Discard、不論殼從哪裡呼叫：deactivate、commitComposition、換擁有者、收到 nil 鍵、切換排列…） | **不學**。這些多半是焦點或 App 改變，常和安全輸入切換同時發生 |
| Esc 清空 | 不學 |
| 解碼失敗（`Err`，錯誤碼 4 的那條路徑） | 不學。註：`emit` 回 4 發生在 `key()` 已經學完之後，那條分支學到的是使用者在沒被擋的 App 裡選的詞，沒有隱私影響；§6.8 的測試用解碼失敗那條路徑 |

- 只學由候選窗 `choose()` 固定、而且「選字前畫面上那一段的字」和「選到的詞」不同的段落。選字前的字在 `choose()` 當下記下來。
- **標點替代字不學**：讀音以 `_punct_` 開頭的段落。
- 學習在算出 commit 之後才執行，並包在內層 `catch_unwind` 裡。學習或寫檔出錯（含 panic）時，只放棄這一次學習，`key()` 照樣回 0 並帶著 commit。

### 1.3 記什麼、怎麼衰減

- 一筆紀錄：（前文 key, 讀音, 詞, 權重, 日期）。
- 權重每過一天乘以 `DECAY`，半衰期 14 天（具名常數，附理由；使用者 2026-10-05 決定）。日期差 clamp 到 ≥ 0，時鐘倒退時權重不會變大。
- **改選走**：同一組（前文, 讀音）之後被改成別的詞時，舊的詞權重減半，新的詞加 1。
- **全域化**（只對 2 個字以上的詞，§12）：同一組（讀音, 詞）在 ≥ 2 種不同的**完整**前文 key（「^」算一種）都有權重 ≥ 0.5 的紀錄時，產生一筆前文為空的全域紀錄。1 字比對不會產生新的 key，所以一次教學不會全域化。單字另有兩條限制（§12 規則 5、6）：只在完整前文相同時加分、不用 1 字比對與全域；前文 key 是「^」時單字不學、不查。
- **修剪**：載入與完整重寫時（§4），刪掉衰減後權重 < `PRUNE_FLOOR`（0.05，約 60 天沒再用到）的紀錄；超過 50,000 筆時，先刪權重最低的。追加路徑不修剪，所以兩次完整重寫之間，記憶體最多多出 `JOURNAL_MAX` 筆。
- **檔案裡的殘留上限**：載入時修剪掉的紀錄，最多留在檔案裡到下一次寫入（學習的 Enter 或忘記）；在當天的完整重寫之後才跌破 `PRUNE_FLOOR` 的紀錄，最多留到隔天第一次寫入。這和修訂一之前的設計相同（那時也是存檔才動檔案）。§4 的「開啟後與每天第一次寫入一律完整重寫」保證這一點。

### 1.4 解碼時怎麼用

- 若查到權重 ≥ 0.5 的紀錄，該詞的詞庫分數改成 `max(原分數, 同讀音最高分 + ε × w／(w + 1))`，w 是衰減後的權重，ε 是 `LEARN_EPS`＝6.0（全域這一層改用 `LEARN_EPS_GLOBAL`，§12；ε 為 0 時全域這一層完全關閉，包括「不在前 `PER_KEY` 名」的列舉）。單字的紀錄只在完整前文（非「^」）相同時參加（§12 規則 5、6）。權重大的紀錄勝過權重小的（改選走時舊詞權重減半）。ε 的取法：鏡像測試上 2.0 學會 4／10、4.0 學會 8／10、6.0 與 8.0 都是 9／10，取最小的 6.0（2026-10-05，`core/src/lm.rs` 的註解）。學習只能把詞往上提，不能壓低其他詞。（原本寫的固定 ε 是實作時改的，2026-10-05 `/code-review` 指出契約沒跟上，補正。）
- 該讀音有學習紀錄的詞，**就算不在前 `PER_KEY` 名也加入列舉**。
- store 是空的時候，不加任何東西，輸出和現在逐位元組相同。

### 1.5 忘記

- 候選窗開著時按 ⌘⌫（使用者 2026-10-05 決定），刪除反白的那個詞在這個讀音下的所有紀錄：所有前文 key，含「^」與全域。
- 刪完後組字區重新解碼，回到沒學過時的輸出。候選窗本來就照詞庫排列，所以「看得到的變化」是組字區，不是候選窗。

## 2. 前文讀取（R4，Swift 殼）

- **讀一次**：每次組字開始、第一次 `setMarkedText` 之前讀。這時 client 還沒有 marked text。組字期間與送出前不再讀。
- **什麼時候算沒有前文**：`selectedRange` 是 `NSNotFound`；或 `markedRange` **不是** `NSNotFound`（client 已經有 marked text，表示上一段組字還沒結束）；或讀取回傳 nil。沒有 marked text 時 `markedRange` 本來就是 `{NSNotFound, 0}`，這是正常情況，照樣讀。
- **範圍有上限**：
  - 只請求插入點前最多 32 個 UTF-16 單位（具名常數）：`NSRange(location: max(0, ins − 32), length: ins − max(0, ins − 32))`。
  - 範圍被截過時，丟掉第一個 grapheme，避免切到代理對或 grapheme 中間。
- **最小化**：殼在最後一個換行處截斷後，只取尾端連續的漢字，最多 2 字（同 §1.1 的規則），再傳給核心。PLAN R4 的 8 個 grapheme 是給 S6 雲端用的，這片不保留。殼不另外存放，每次組字結束就丟。
- 新的 C ABI：`shanjie_engine_set_left_context(engine, const char *utf8)`。
  - 核心複製字串、不保留指標，只留最後 2 個漢字。
  - NULL 或空字串表示沒有前文。不是 UTF-8 時回 2，並清空舊的前文。
  - 前文在每次 commit、reset、錯誤碼 4 之後由核心自動清掉。殼在每次組字開始都要呼叫一次，讀不到就傳 NULL。
- `privacyGate` 擋的時候不讀前文，傳 NULL。

## 3. privacyGate（R3）

- **判斷式**：以下任一成立就**暫停**：
  - `IsSecureEventInputEnabled()`；
  - 目前 client 的 bundle ID 在學習 denylist；
  - 判斷不了，例如取不到 bundle ID。
- **學習 denylist 預設**：密碼管理器，寫死在程式裡，仿 `Shell.chatApps`。
  - 1Password（`com.1password.1password`、`com.agilebits.onepassword7`）、Bitwarden（`com.bitwarden.desktop`）、KeePassXC（`org.keepassxc.keepassxc`）、Apple 密碼（`com.apple.Passwords`）、鑰匙圈存取（`com.apple.keychainaccess`）。
  - 這些 bundle ID 沒在本機核對，§7 請使用者確認。
  - 終端機依使用者的決定**不**列入。
- **取樣時機**：殼在所有核心呼叫的必經點（`Session.send()` 與 `finish()`）都重新取樣 gate，而且**每次都**呼叫 `shanjie_engine_set_learning`，不只在值改變時。否則換排列重建引擎（預設停用）之後，學習會一直停著，直到 gate 自己翻一次。
- **核心語意**：
  - `set_learning(0)` 會丟掉尚未送出的待學段落。
  - 旗標為 0 時，`choose()` 不記錄待學段落。只學「`choose()` 當下」**和**「送出當下」旗標都是 1 的段落。
  - 只接受 0 和 1，其他值回 2。
  - 引擎建立時預設**停用**（fail-closed，排列切換重建引擎時也一樣）。殼確認 gate 不擋之後才開。
- **選單**：第一項顯示「學習已暫停（安全輸入）」或「學習已暫停（此 App）」。只用固定字串，不放 App 名稱。
- **要使用者實機確認的事**（S3b 遺留）：組字中把焦點移到密碼欄，組字送到哪個 client？依結果決定 deactivate、commitComposition 要不要丟字。在拿到結果前維持 S3b 現行行為；這兩條路徑本來就不學（§1.2）。

## 4. 儲存（R5）

- **路徑與格式**：`~/Library/Application Support/shanjie/learning.tsv`。
  - 第一行是 `#shanjie-learning v1`；每行是 `前文\t讀音\t詞\t權重\t日期`，沒有其他欄位。
  - 前文只可能是 ≤ 2 個漢字、「^」或空字串，所以不會出現 tab 或換行。
- **目錄**：
  - 建立時 0700；已存在時檢查擁有者是自己並 `chmod 0700`。
  - 清除只刪檔案、不刪目錄，排除備份的屬性設在目錄上，才不會因為刪目錄而消失。
- **寫入**（核心；修訂一，見 §11）：兩條路寫同一個 `learning.tsv`，格式不變。
  - **追加**：每次送出且學習有變動時，只把這次改到的紀錄（每個改選段落最多 3 筆：教到的詞、被改選走的詞、全域）用同樣的五欄格式加到檔尾。
    - 用 `O_WRONLY|O_APPEND|O_NOFOLLOW|O_NONBLOCK` 開**既有**的檔，不建立。
    - `fstat` 必須是一般檔案、擁有者是自己、權限沒有群組與其他人的位元，而且加上去之後不超過 16 MB。
    - 一次寫入，不做 fsync；只寫進一部分（例如磁碟滿）也算追加失敗。
    - 任何一項不成立（含檔案不存在、符號連結、FIFO）就改走完整重寫。
  - **完整重寫**：以下任一成立時，這次寫入走完整重寫，不追加：
    - ⌘⌫ 忘記：**一律**完整重寫，不論記憶體有沒有變（被載入時修剪掉的同一個詞，可能只剩在檔案裡）。沒有 store 時只改記憶體，不動旗標；
    - `must_rewrite` 旗標是 1（見下）；
    - 上次完整重寫的本地日期不是今天。這個日期在**開啟時與清除成功後設為「無」**，所以開啟後的第一次寫入、清除後的第一次寫入、每天第一次寫入都一律完整重寫：載入時修剪、去重、略過的行與截斷的檔尾都在這次整理掉，長時間不重啟的輸入法也會照 §1.3 修剪檔案；
    - 上次完整重寫後追加的行數會達到 `JOURNAL_MAX`（1,024，具名常數）；
    - 追加失敗。
  - **`must_rewrite` 旗標**（記憶體內，引擎持有）：
    - 設為 1：忘記與清除在**一開始**（改記憶體之前）；**每一次**完整重寫開始前。不必偵測 panic：中途 panic 或失敗時旗標自然留在 1。
    - 只有完整重寫的 rename 成功才清成 0；清除則在刪檔成功後清成 0（同時把上次完整重寫日期設成「無」，下一次寫入由日期規則保證完整重寫）。
  - **bit0（`shanjie_engine_learning_status`，上次寫入失敗）**：獨立定義，和 `must_rewrite` 脫鉤。完整重寫失敗（含追加失敗後改走的完整重寫）就設 1；只有成功的完整重寫或成功的清除才清成 0。bit0 是 1 時 `must_rewrite` 一定也是 1，所以不會有追加把它蓋掉。
  - **完整重寫的步驟**：先修剪（§1.3）。暫存檔固定名稱 `learning.tsv.tmp`：先 `unlink`，再用 `create_new(true)`、`O_NOFOLLOW`、`mode(0o600)` 建立；寫入、`fcntl(F_BARRIERFSYNC)`、rename。`F_BARRIERFSYNC` 失敗時改用 `F_FULLFSYNC`。兩者都失敗時：忘記照樣 rename（隱私優先於耐久）；其他情況算寫入失敗，不 rename，`must_rewrite` 留在 1、bit0 設 1。
  - **追加的額外檢查**：`st_nlink == 1`，而且檔案大小至少是標頭長度加 1（使用者手動清空的檔案不追加，避免追加的學習在下次載入時因為沒有標頭整個被改名成 `.corrupt`）。
  - 引擎記錄上次完整重寫後追加了幾行，開啟時從 0 起算（開啟後第一次寫入一定是完整重寫）。
  - **耐久性**（使用者 2026-10-05 選定）：`write` 回傳後資料已交給作業系統核心，輸入法閃退不會丟；斷電或 kernel panic 可能丟掉最近一段時間的追加（macOS 的髒頁可能數十秒才寫出，未實測）。被截斷的最後一行在載入時逐行略過，或變成同一筆的較舊版本（日期欄被截短只會更舊、更弱；依「以最後一行為準」，它會蓋掉前一行，這是資料損失，不涉及隱私）；開啟後第一次寫入一律整檔重寫，所以截斷的檔尾不會和之後的追加黏在一起。完整重寫用 barrier 讓資料先於 rename 落地，不會留下空的或半個取代檔（依 Apple 的 `fcntl` 文件推論，未實測）。rename 與刪檔本身不保證耐久：忘記或清除之後不久斷電，舊檔可能回來，修訂一之前也一樣，揭露文字要寫。
  - **檔案裡會有什麼**：每個（前文, 讀音, 詞）一定是學習模型在上次完整重寫後持有過的紀錄；被取代的舊行和新行只差權重與日期。忘記一律完整重寫、清除刪檔，`must_rewrite` 保證兩者失敗時下一次寫入不會改用追加，所以成功之後 `learning.tsv` 裡不會留下該詞（斷電的例外見上一項）。**忘記的重寫失敗時**（bit0 = 1），`must_rewrite` 只活在這個引擎裡：換排列重建引擎或輸入法重啟後，會從還沒重寫的檔案把該詞載回來；這是誠實反映「忘記沒寫進去」，選單會顯示寫入失敗（§11 收尾審查的 P4，不改）。忘記時同一段組字裡同讀音、同詞的待學選字也一併丟掉，否則下一次 Enter 會把它學回去（2026-10-05 `/code-review` 抓到並修正，§6.13 有測試）。`.corrupt` 隔離副本只有清除才會刪，忘記不碰它（它只會在外部改動造成標頭錯誤時出現，修訂一之前也一樣）。
  - 寫入失敗就放棄，不影響打字。
  - 核心沒有 logger，所以寫入失敗不記 log；殼可以用 `shanjie_engine_learning_status` 查到「上次寫入失敗」，並在選單顯示固定字串。
- **讀取**：引擎建立時由殼傳入路徑，`shanjie_engine_learning_open(engine, path)`。
  - 用 `O_NOFOLLOW|O_NONBLOCK` 開檔；`fstat` 必須是一般檔案；超過 16 MB 當作損毀。
  - 同一組（前文, 讀音, 詞）出現多行時，以最後一行為準（追加的結果）。
  - 檔案不存在：回 0，從空的開始。
  - 標頭不對：整個檔改名成 `learning.tsv.corrupt`（只保留一份、直接覆蓋），rename 後補 `chmod 0600`，從空的開始，回 0。
  - 壞行（權重是 NaN、inf 或負數；前文超過 2 字；日期不合法；欄位數不對）**逐行略過**。
- **清除**：
  - 選單「清除選字記憶…」點下去跳出系統的確認視窗（`NSAlert`）：標題「要清除選字記憶嗎？」，內文含下面的揭露文字；「取消」是預設按鈕（Return），「清除」標成破壞性動作。輸入法是 agent app，跳窗前把自己帶到前面、關掉後把焦點還給原本的 App。（使用者 2026-10-05 要求「這個應該做成提示窗通知」，取代原本在選單裡兩段式確認。）
  - 呼叫 `shanjie_engine_learning_clear(engine)`：清空記憶體，刪除 `learning.tsv`、`.tmp`、`.corrupt`。
  - 檔案本來就不存在（ENOENT）算成功；其他刪除失敗回 3，跳出「清除選字記憶失敗」的提示窗，不能假裝成功。
  - 清除也丟掉尚未送出的待學段落，避免清除前選的字在下一次 Enter 又學回來。
  - 清除一開始就設 `must_rewrite`；刪檔成功後把上次完整重寫日期設成「無」再清旗標，所以下一次學習的 Enter 一定是完整重寫，從標頭開始建新檔，只含清除後學到的紀錄；不靠「追加時找不到檔案」。
  - 沒有 store（`learning_open` 沒成功過）時清除回 3，同樣跳出失敗提示窗，不假裝成功。
  - 揭露：「清除只刪本機檔案；已經進 Time Machine 備份或本機快照的副本不受影響」。
- **Time Machine**：預設**會**備份（使用者 2026-10-05 決定，換電腦時記憶跟著走）。選單「不要備份選字記憶」可以排除，對目錄設 `isExcludedFromBackup`（目錄要先建立）；說明文字要寫明預設會備份、以及怎麼排除。
- **揭露文字**（說明與 `site/index.html` 的隱私段落；網站等使用者確認後才部署）：
  - 學習檔記錄你改選過的詞，可能包含人名，連同日期；
  - 它不受 macOS 的隱私權限保護，靠 FileVault 加密；
  - 預設會不會進 Time Machine（依 §9 的決定）。
- 不用 SQLite，所以沒有 `-wal`、`-shm`。

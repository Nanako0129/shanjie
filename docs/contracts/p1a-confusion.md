# 詞態 P1a：同音功能字的上下文分類器（離線）

PLAN「P1 詞性連接（併入 S2）」底下的第一片（編號 P1a，不和 S6 雲端、S7 自訓小模型撞號）。

使用者 2026-10-10：「想辦法從詞態解決常見錯字」（選擇題確認是「詞態」）、「繼續解決詞態問題」，之後「P1a 問一下 Fable 找到最佳解」。這一片回答：**用字位前後的字、詞與詞類當特徵，為常打錯的同音功能字各訓練一個分類器，重排 n-gram 的前幾名，能不能修掉這一類錯字？** 只做離線量測；做進核心是下一片。設計依 Fable 5.1 的分析（2026-10-10，研究紀錄同日）。

## 0. 依據（2026-10-10 量測，model-v5＋classes-v3、`--context`、不開詞包、寬鬆對照之後，只記數字）

  - cvtune 聊天（`31de456d…`，3,791 列，錯 427 列）：再＞在 11、事＞是 11、錢＞前 11、做＞作 9、作＞做 4、像＞向 3、得＞的 3。
- **Fable 5.1 的量測**（Python 參考實作；cvtune 用的是本機舊版 3,677 列 `fd632479…`，只當指標，第 0 步在 188 用釘住的 `31de456d…` 重量）：

  - **bigram 為什麼輸「再／在」**：以「再告訴他」為例，bigram 知道 P(告訴｜再) 是 P(告訴｜在) 的 50 倍，但「在」先贏三樣：句首 P(在｜<s>) 是 P(再｜<s>) 的 26 倍（每個漢字段、含逗號後都從 <s> 起算）、詞庫分數 −2.43 對 −3.34、切分（詞庫以「在」結尾的詞 570 個，例如我在、就在、不會在；以「再」結尾的 36 個）。
  - **便宜修法不夠**：只把「再」「做」的詞庫分數拉到「在」「作」：cvtune 聊天 +4／−2、書面 +2／−4，wikitune 兩種設定都 +1／−3，錯字回報 +4／0、+3／0。

## 2. 做法

### 2.1 範圍（事先寫死）

- 讀音：`ㄗㄞˋ`、`ㄗㄨㄛˋ`、`ㄕˋ`、`ㄚ`、`ㄒㄧㄤˋ`、`ㄉㄠˋ`（§0 盤點裡最多的功能字讀音）。
  - `ㄋㄚˇ` 不做：「哪＞那」是「那」掛在 ㄋㄚˇ 底下的詞庫問題，另外處理。
  - `ㄉㄜ˙` 這一片不做：詞庫給單字「得」的最高分讀音是 ㄉㄜˊ、「地」是 ㄉㄧˋ，照下面的字位讀音規則，助詞的「得」「地」（跑得快、慢慢地）永遠不會成為 ㄉㄜ˙ 的樣本，分類器反而會在助詞的位置推向「的」。要做得先有逐字的讀音標注，另開一片。
- **字位與讀音**：訓練文字切詞後，每個詞的每個字位的讀音取自詞庫給那個詞的讀音（`Lexicon.by_word` 的音節；同一個詞有多個讀音時取分數最高的那個）。只有讀音等於目標讀音的字位才是樣本。這樣「載」（載客 ㄗㄞˋ 才算）、「地」（慢慢地 ㄉㄜ˙ 才算）、「相」（照相 ㄒㄧㄤˋ 才算）這類破音字由詞庫讀音自然篩掉，不必另列不收的字。
- **類別字**：每個讀音取「字位讀音等於該讀音」的樣本裡出現 ≥ 1,000 次（加權前）的字，最多 6 個；另加一個「**其他**」類，收該讀音其餘字的樣本（同一個上限）。實際的類別表由第 0 步產生、寫進報告與 README，之後不改；不算「其他」剩不到 2 個類別的讀音整組不做。
- 不處理：「錢／前」「訂／定」這類內容詞（是詞彙與語意的問題，留給語意機率 S7a）。

### 2.2 訓練資料與特徵

- 文字和 model-v5 的 n-gram 用**同一組函式**產生：維基 `build_counts.articles(200000)` 照 `count_batch` 的順序做實體還原、`TEMPLATE`、`MARKUP`、`SENT`、每句 `convert()`（OpenCC＋TWVariants，**不用** S2w 的 MediaWiki 轉換），取 `HAN` 段、丟掉長度 < 2 的段；口語 `colloquial-train.txt`＋`synth.txt` 每行照 `build_counts_text.py` `convert()` 後取 `HAN` 段、丟掉長度 < 2 的段。權重：維基 ×1、口語 ×5。用同一個 `segment`（最高分切分）與基底＋`overlay-add.tsv` 的詞庫切詞。注意：model-v5 的計數用的是詞圖上的期望次數，這裡用的是單一最佳切分，兩者不完全相同；這一片只需要每個字位的上下文。
- 輸入雜湊（第 0 步列表，和 `experiments/model-v5/README.md` 的值比對，不符就停）：維基 dump `5db9052e…`、`colloquial-train.txt` `3e833d06…`、`synth.txt` `bec7a6a2…`、`mcbpmf-data.txt` `0deae7b7…`、`overlay-add.tsv` `348979c8…`、TWVariants `245b94eb…`、STCharacters `a0ca1601…`；model-v5 `f81a021e…`、classes-v3 `75a5efb3…`；cvtune `31de456d…`、wikitune `8dcfe40c…`（S2w 之前那一份）。
- **特徵一律遮掉被分類的字位**：特徵不能依賴那個位置填的是哪個字（不然就等於看到答案；「就在」是一個詞、「就再」會切成就／再，切詞本身也帶著答案）。所以訓練與打分都這樣算：句子在那個位置切成左段與右段，**兩段各自**用同一個 `segment` 切詞；特徵是左段的最後 2 個字、右段的前 2 個字（各自與組合）、左段的最後一個詞與右段的第一個詞、它們的詞類（classes-v3 的 Brown 詞類，用 model-v5 詞彙對應）、左段是否為空（句首）、右段是否為空（句尾）。不用「所在的詞」，也不用詞首／詞尾旗標。特徵雜湊到 2^20 維，出現 < 3 次的特徵丟掉。
- **模型**（超參數事先寫死，不調）：每個讀音一個多類別邏輯斯迴歸；Adam，學習率 0.01，批次 4,096，3 個 epoch，L2（weight decay）1e-6，隨機種子 20261010，每個類別最多取 300,000 個樣本（依出現順序取，維基與口語分開各取一半上限）。CPU 上跑、可重現：同一個種子跑兩次，權重檔的 SHA-256 相同。

### 2.3 候選、計分與重排

- **候選**：現行出貨的解碼（model-v5＋classes-v3、`--context`、不開詞包），用 Python 參考實作的 `decode` 取前 8 名，**保留詞的切分**與 n-gram 分數。聊天、書面各一份。候選的第一名必須等於 CLI 的第一名（逐列比 `top1_sha256`）。語意機率 S7a 若已產生同樣的候選檔，可以共用，但要核對雜湊。
- **前文**：該列前文經引擎的 `context_key`（最多 2 個漢字）；不是句首哨兵時，這些字接在候選前面、屬於左段（左段因此不為空），左段照上面的規則切詞；是哨兵時照句首處理。
- **計分單位是字位**：候選 c 裡每一個**字位**（含多字詞裡的字），只要使用者打的那個音節是 §2.1 的讀音（而且這一階段那個讀音的分類器是啟用的），就用遮掉該字位後的 c 與前文算特徵：`f(c) = Σ_i [ log P_char(c_i | 特徵) − max_m log P(m | 特徵) ]`，m 跑過該讀音的類別（含「其他」）。c_i 在類別表裡時 `P_char(c_i｜特徵) = P(c_i｜特徵)`；不在表裡時 `P_char(c_i｜特徵) = P(其他｜特徵) · q(c_i｜其他)`，q 是 c_i 在該讀音「其他」類訓練樣本裡的占比，平滑寫死為 `q(c) = (n(c) + 0.5) / (N + 0.5·V)`（n(c) 是 c 的樣本數，N 是「其他」類的樣本總數，V 是詞庫裡該讀音不在類別表的單字數）。每一項 ≤ 0；冷僻字只分到「其他」機率的一小部分，不會因為字不在表裡而佔便宜。
- **融合**：`s'(c) = s_ngram(c) + μ · f(c)`，只在 n-gram 第一名與第二名分差 `< τ` 時重排。
- 格點：μ ∈ {0.1, 0.2, 0.3, 0.5, 0.7, 1, 1.5, 2, 3}，τ ∈ {0.5, 1, 2, 3, 5, 不設門檻}；「不設門檻」在同分規則裡算 τ = +∞（最大）。
- **選法（事先寫死）**：每種設定（聊天、書面）各選一組 (μ, τ)，cvtune 與 wikitune 合計 top1 最高；同分取 τ 較小、再同分取 μ 較小。選好凍結，記錄集合只用凍結的值。
- **兩個對照組**（同一份候選、同一張表）：
  - **詞庫分數拉平**：把「再」的詞庫分數設成「在」的、「做」的設成「作」的（只改 ㄗㄞˋ、ㄗㄨㄛˋ 兩組；其他讀音不做），重新解碼。
  - **μ = 0**：等於 n-gram 第一名（檢查表格的基準沒有錯）。
  - 分類器要算有貢獻，discordtune 聊天的淨修好必須**多於**「詞庫分數拉平」。

### 2.4 分階段（最便宜的決定性實驗先做）

每一階段都照這個順序：(a) 這一階段啟用的分類器＝到目前為止訓練過的讀音，扣掉 §3 第 2 項沒贏過最常見字而停用的；(b) 用 cvtune＋wikitune 依 §2.3 的規則**重新**選 (μ, τ) 並凍結；(c) 照該階段的規則判斷。
1. **只訓 `ㄗㄞˋ`**。**事先寫死的停止規則**（用這一階段凍結的值）：cvtune（`31de456d…`）聊天的「再＞在」列數沒有至少減半，或「在＞再」增加超過 2 列，就停下來寫結論，不做其他讀音。
2. 過了再加 `ㄗㄨㄛˋ`，同樣的規則套在「做＞作」「作＞做」（用第 2 階段凍結的值）。
3. 兩個都過，才加其餘讀音（`ㄕˋ`、`ㄚ`、`ㄒㄧㄤˋ`、`ㄉㄠˋ`）。§4 的判斷與「+0.2 個百分點」的停止條件**只用最後一個階段**凍結的 (μ, τ) 與啟用的讀音；如果在第 1 或第 2 階段就停了，§4 不判斷，直接寫結論。

## 3. 驗收

1. **第 0 步**（188）：輸入雜湊表；建構上的不重疊（wikitune 來源條目序號 ≥ 300,000；cvtune 與 `colloquial-train.txt` 的切分對原始來源 `cv-*`、`cmn_sentences.tsv.bz2` 逐行算 `build_tune.is_tune(raw)`，為假的行數等於 `colloquial-train.txt` 的行數、真假合計等於原始總行數，不對轉換後的句子套 `is_tune`；原始來源雜湊記進報告；只有這個檢查失敗才停）；類別表與每個類別字的樣本數；候選檔的第一名等於 CLI（逐列）；用釘住的 cvtune 重量 §0 Fable 那幾個數字（只錯功能字的列數、正解在前 8 名的列數、錯在多字詞裡的列數）。
2. **分類器本身**：在 cvtune、wikitune 正解句裡各讀音的字位上，分類器的正確率對「永遠猜最常見的那個字」（依 §2.1 篩過的訓練樣本裡最多的字）與 n-gram 第一名在這些字位的正確率，三個數字並列（兩個集合分開報，也報合併）。**停用的判斷用兩個集合合併的字位**：分類器的正確率沒有**嚴格大於**最常見字的讀音，在重排裡停用，寫進報告。
3. **表格**：兩種設定 × 每個集合（cvtune、wikitune、dev302、打字測驗、錯字回報、discordtune）× 三組（分類器、詞庫分數拉平、μ = 0）各一行 `tools/evalstats.py compare`（基準是 n-gram 第一名）。另報：凍結的 (μ, τ)、門檻觸發比例、前 8 名 oracle、各讀音的字位正確率（基準／新，例如「再」）、各集合「錯字在多字詞裡」的列數與其中修好的列數、「第一名換成或換掉不在類別表的字」的列數、錯字回報與 discordtune「加不加前文 `f(c)` 有變的列數」（兩個都必須 ≥ 1，否則前文沒有接上，停下來查）。
4. **大小**：每個讀音的非零特徵數，以及 int8 稀疏格式的檔案大小（只量，不出貨）。
5. **判斷**：照 §4 寫成一行結論，寫進研究紀錄；PLAN「P1 詞性連接」那一節更新狀態。
6. **單元測試**（不需要真資料）：資料準備（一段原始維基文字與一行口語得到的漢字段，和 `build_counts` 同一組函式逐段相同）；字位讀音（「載客」的「載」是 ㄗㄞˋ 樣本、「記載」的「載」不是）；**遮掉字位**：同一句在同一個位置分別放「在」與「再」（一次「就在」成詞、一次不成詞），兩者的特徵向量完全相同；多字詞裡的字位會計分（「不要再」的「再」）；前文（`了我` 接在前面、左段不為空；哨兵時左段為空）；`f(c)` 的手算值，含不在類別表的字：照 `P(其他)·q(c｜其他)` 的手算值；同樣特徵下兩個 q 不同的表外字得到不同的項；融合在 τ 上下與同分規則；選法只讀調參集，同分案例含 τ = 5 與不設門檻同分（取 5）；分階段的啟用與重新選格點，案例含一個讀音只在其中一個調參集贏過最常見字（依合併判斷，結果唯一）；詞庫分數拉平對照組只改 ㄗㄞˋ、ㄗㄨㄛˋ 兩組。突變：只計單字詞（不計多字詞裡的字位）、拿掉字位讀音的篩選、把前文丟掉、恢復「所在的詞」特徵（遮掉的測試要失敗）、不在表裡的字改回記 0、表外字改成拿整個「其他」的機率（拿掉 q），各要讓至少一個測試失敗。

## 4. 做進核心的判斷（事先寫死）

照凍結的 (μ, τ)，**discordtune 聊天設定**：

- Δtop1 ≥ +0.5 個百分點（4,958 列裡至少 +25 列），精確 McNemar p < 0.05，Δtop1 的 bootstrap 95% 區間不含 0，ΔCER ≤ 0；
- 淨修好多於「詞庫分數拉平」對照組；
- 而且 cvtune、wikitune、dev302、打字測驗、錯字回報在兩種設定都沒有「淨值為負而且 p < 0.05」的格。

過了才開下一片（分類器權重的出貨格式、Rust 實作、保留集由 fresh verifier 跑一次、實機）。

**停止條件**：§2.4 的分階段規則沒過；§3 第 2 項有一半以上的讀音分類器沒贏過最常見字（分母是實際訓練的讀音數）；**聊天設定**的 cvtune＋wikitune 合計最佳格點比 n-gram 少於 +0.2 個百分點（書面只報告，不觸發停止）；輸入雜湊不符或建構檢查失敗；候選第一名和 CLI 對不上；前文有效的列數是 0；同一個種子兩次訓練的權重不同。都停下來寫結論。

# V3 即時預測：引擎、C ABI 與殼層

#44 的即時預測進 v0.3.0（使用者 2026-10-07）。核心函式 `predict`（`docs/contracts/v3-core-predict.md`，記為 V3 核心）回傳某個（歷史詞, 單位序列）的候選。這份契約把它接進引擎、C ABI 與殼層。

設計經 Fable 5.1 分析並在公開資料上量測（研究紀錄同日）。介面由使用者決定（2026-10-07）：

- 第一鍵就顯示。
- 預測放在現有候選窗，顯示成不帶數字、不反白的一列；零候選不顯示。
- Tab 進入預測列，之後和候選窗一樣操作；Shift+Tab 退回。
- 滑鼠點未進入的預測列，直接選。
- 進入後按 Backspace：退出，並刪掉最後一個注音、重算。
- 詞的起點用「兩種都猜，接續最多 3 個」（§1.2）。
- 縮寫設定的選單名稱是「可省略韻母」，預設關（第二片，§6）。

分兩片交付，各一個 PR：

- **第一片**：§1–§5 與 §7，只有前綴補完。
- **第二片**：§6 的縮寫組字器與設定。

**前置條件**：V3 核心已合併到 main，這個分支 rebase 到合併後的 main。

## 1. 什麼時候算、算什麼

### 1.1 顯示條件與重算時機

- 只在載入語言模型時有預測；沒有模型就沒有預測列。
- 只在游標位於組字區尾端（`cursor == syls.len()`）而且候選窗關閉時顯示。
- **重算**：只在下面這些按鍵處理完之後重算，而且處理後仍符合上一條：
  - 第 9 條（注音鍵放進未完成音節）；
  - 第 10 條（完成一個音節）；
  - 第 11 條（Backspace 刪未完成音節的符號）；
  - 第 14 條（開始新的未完成音節）。

  第 10 條遇到詞庫沒有的音節而不完成時（`engine.rs` `finish_syllable` 的提早返回），預測列不變。
- **清除**：其他所有狀態變化都清掉預測列：
  - 標點（第 2 條）與 22a（聲調符號放進組字區）；
  - 開候選窗（第 15 條）與候選窗裡的所有按鍵（第 3–8 條）；預測列在候選窗開著時不顯示，關掉後也不恢復；
  - 游標移動（第 17 條）、刪音節（第 18 條）；
  - 送出（第 19–21 條、40 音節自動送出）、Esc（第 12、20 條）；
  - `reset`、`set_profile` 的快照、`pick`、選了預測、回傳碼 4。

### 1.2 詞的起點（「兩種都猜，接續最多 3 個」）

引擎不知道使用者的詞從哪個音節開始。每次重算時，取下面這些**起點**，各查一次 `predict`：

- **游標**：有未完成音節時才有。單位序列＝未完成音節。
- **最後一個解碼詞的起點**：目前最佳路徑（`path`）裡結束在游標的那個詞的開頭。
- **前一個詞的起點**：再往前一個詞的開頭。

規則：

- 起點到游標之間不可以有標點（含 s3e 的標點固定詞）；有就略過那個起點。同一個位置只查一次。
- 每個起點的單位序列＝起點到游標的完整音節（已完成，各自帶聲調）＋未完成音節（如果有）。
- 每個起點的歷史詞 `v`：
  - 以起點前的顯示文字為準：輸入框前文（`left`）接上組字區起點之前的顯示字串。
  - 照 S4 的前文鍵規則取最後 ≤ 2 個連續漢字，再用 `lm::history` 求得。
  - 沒有漢字時是 `<s>`。
- 呼叫 `predict(lm, capped, λ, v, units, P, 9)`。
- **合併**：
  - 起點由遠到近排：越長的起點越前面。
  - 長起點的項目最多 3 個（`PREDICT_LONG_CAP = 3`），排在游標起點的項目之前；長起點剩下的項目排在游標起點的項目之後。
  - 同一個詞只留第一次出現的。
  - 和該起點到游標目前顯示字串相同的項目不列（例如已經解成「奶茶」，就不再列「奶茶」）。
  - 取前 9 個。
- 每個項目帶（詞、讀音、起點）。讀音是 `predict` 計分用的那個相容讀音，也就是達到 `lp_max` 的讀音（V3 核心 §1）。V3 核心若還沒回傳讀音，這一片加上。

Fable 在 typing76 聊天設定量到的 hit@9，限兩字以上的詞、前面已有字的樣本（n = 217）：

| | 第一鍵 | 第二音節第一鍵 | 第二音節打完 |
|---|---|---|---|
| 這個規則 | 26.7% | 82.5% | 98.2% |
| 知道正確起點與歷史詞 | 29.0% | 95.9% | 99.5% |

## 2. 選取

選了項目（詞 W、讀音 R 共 m 個音節、起點 s）：

- 丟掉未完成音節。
- 把 `syls[s..cursor]` 換成 R；R 比原本多的音節插在游標處。游標在尾端，右邊沒有固定詞。
- 移除和 `[s, cursor)` 重疊的固定詞，做法和 `choose()` 相同。
- 加固定詞 `Fixed { start: s, end: s + m, word: W, pre: None }`。`pre: None` 讓 `learn_commit` 不記錄它：預測選取不是改選，不學。之後在候選窗改選這一段，照常學。
- 游標移到 `s + m`，重算顯示，清掉預測列。
- 音節數達到 40 時照 `insert_token` 自動送出。

## 3. 按鍵規則（`docs/contracts/s3a.md` §3 新增）

**預測列已進入**（插在第 2 條之前）：

| 按鍵 | 行為 |
|---|---|
| 1–9 | 選第 n 個（超過個數就吃掉、不動作） |
| ←→、Tab | 移動選取（Tab 往後，到最後一個停住） |
| Shift+Tab | 退回未進入（預測列保留） |
| Enter | 選目前選取的 |
| Esc | 退回未進入（預測列保留） |
| Backspace | 退回未進入，然後照第 11 條刪未完成音節的最後一個符號，再重算預測列（使用者選擇；和候選窗的第 7 條不同） |
| ⌘⌫ | 吃掉、不動作（沒有學過，不能遺忘） |
| 其他鍵 | 退回未進入，再從第 2 條起處理這個鍵 |

**預測列未進入、不是空的**（插在第 9 條之前）：

- Tab（沒有修飾鍵）：進入預測列，選取第 0 個。

其他情況照舊：

- 預測列是空的：Tab 在有未完成音節時照第 13 條吃掉，沒有時照第 21 條送出並直通。
- Shift+Tab 在預測列未進入時照第 13、21 條。
- 第 15 條開候選窗時清掉預測列。

## 4. C ABI

- **重用候選欄位，不加新欄位**：`Shell.apply` → `showCandidates` → 格子 → 點擊 → `pick` 的路徑全部照舊；網格邏輯只看 `candidate_columns > 0`。
  - **預測列未進入**：`candidate_count` 1–9、`candidate_selected = -1`、`candidate_columns = 0`、`candidate_first = 0`、`candidate_total = candidate_count`。
  - **已進入**：`candidate_selected ≥ 0`，其他同上。
  - **候選窗開啟**：照舊。
- `shanjie_engine_pick(index)`：
  - 候選窗開啟時照舊。
  - 候選窗關閉但有預測列（進入或未進入）時，選預測列的第 index 個（使用者選擇：點擊就是明確的選取）。
  - 都沒有時回 2。
- `core/include/shanjie.h` 的說明改成：`candidate_selected` 為 -1 而 `candidate_count > 0` 表示未進入的預測列。

## 5. 殼層

- 數字只在 `selected ≥ 0` 時顯示。`InputController.swift` 與 `CandidateCells.swift` 各改一行；未進入時不顯示選取膠囊。
- 每一鍵都可能更新預測列，面板位置照現有的 `lineRect` 規則。殼層不另外加動畫。
- 外觀不另外設計：同一個玻璃面板、同樣的格子。

## 6. 第二片：可省略韻母（縮寫組字器）

- **設定**：
  - `shanjie_engine_set_abbreviation(engine, 0|1)`，預設 0，不是 0 或 1 回 2，不改目前顯示。
  - 殼層選單加「可省略韻母」，預設關。存法照 `LayoutStore`：UserDefaults，鍵 `abbreviation`。
- **組字器**（只在開啟時改變；關閉時照第 9 條「同一欄再按一次是取代」）：
  - 未完成音節變成有順序的未完成單位清單。
  - 注音鍵：最後一個單位的那一欄是空的就放進去；那一欄已經有符號就開新單位。
  - 聲調鍵與空白：只有一個單位時照第 10 條完成音節。有兩個以上單位時吃掉：單位只靠選取、Backspace、Esc 解決。
  - Backspace：刪最後一個單位的最後一個符號（照第 11 條的順序），空的單位拿掉。
  - Esc：全部清掉。
  - 組字區在游標處依序顯示所有單位。
- **查詢**：單位序列＝起點後的完整音節＋全部未完成單位，模式 PA。有兩個以上未完成單位時，只有縮寫解讀可能相容，所以含完整音節的起點不會有結果，可以略過。
- **已知缺口**（SP README）：沒有聲母的後續音節（例如「安」ㄢ）會接到前一個單位，不會開新單位；兩字以上的詞約 13–16% 打不出縮寫。

## 7. 驗收（第一片）

1. **引擎測試**（真實模型 `data/lm/bigram.sjlm`，`core/tests/engine_predict.rs`）：
   - 預測列等於 §1.2 的起點各自呼叫 `predict` 再合併的結果。測試自己算起點與歷史詞，不呼叫引擎內部的函式。
   - 前文「我想喝一杯」、打 ㄋ：預測列含「奶茶」。
   - 沒有相容候選時預測列是空的，輸出的候選欄位是 0／-1。
   - 進入與退出：Tab、Shift+Tab、1–9、←→、Enter、Esc、Backspace（退出並刪符號、重算）、⌘⌫ 吃掉、其他鍵退回後照常處理。
   - 選取：音節換成讀音、游標在 `s + m`、固定詞正確、重疊的固定詞移除；Enter 送出後 `learner().records()` 是空的。
   - 清除：游標左移、標點、開候選窗、Esc、送出、`reset`、`set_profile`、40 音節。
   - `pick` 在未進入的預測列選取；沒有預測列也沒有候選窗時回 2。
   - 沒有載入模型的引擎沒有預測列。
2. **既有測試**：
   - 沒有載入模型的測試、重播測試、既有 golden 一個位元組都不改。
   - 載入模型的測試若斷言「候選欄位是 0／-1」，而那個狀態現在有預測列，就改成斷言預測列（逐項列在 PR 裡）：`core/tests/engine_lm.rs`、`engine_learn.rs`、`ffi.rs` 的測試、`abi_smoke.c` 第 8、10 項一類的檢查。
3. **突變**（每一項都要讓某個測試失敗；build error 不算）：
   - 長起點不設上限（全部排在前面）；
   - 預測選取記入學習；
   - 游標不在尾端仍顯示預測列；
   - 未進入時 `pick` 回 2；
   - Backspace 只退出不刪符號。
4. **時間**（release，M 系列 Mac，機器負載低於核心數時量）：每一鍵（含最多 3 次 `predict`）的引擎處理時間 p95 < 16 ms；超過是停止條件。另報常駐記憶體增加量。
5. `cargo test`（debug、release）、`swift test`、C 冒煙測試、CI 全綠。
6. **實機**（需要使用者）：
   - 在 TextEdit、Discord、VS Code 各打一次：前文「我想喝一杯」後打 ㄋ，預測列出現「奶茶」。
   - Tab 進入、選取、送出都正常；點擊預測列能直接選。
   - 「搞完」這類一般句子打字時，預測列不干擾組字。
7. 保留集由 fresh verifier 收尾時跑一次，只回數字：選字結果應該不變，預測不影響解碼。

## 8. 停止條件、預算、限制

- **停止條件**：
  - 既有 golden 改變；
  - 解碼結果改變（預測只加輸出欄位，不改組字）；
  - 時間超過上限；
  - 需要改模型檔格式；
  - Tab 在實機上送不到輸入法。
- **預算**：每一片 executor 1 回合加 1 次修正。
- **executor 不可以做的事**：
  - 不連網。
  - 不讀 `eval/holdout/`、`~/side-project/shanjie-private/`、Discord 資料、學習檔或聊天紀錄。
  - 不安裝、不啟動 App，不執行 `.app` 裡的程式，不呼叫 TIS 或 lsregister，不碰 `~/Library` 與鑰匙圈。
  - 不 push、不開 PR、不碰其他 worktree。

## 9. 不在這一片

- 預測候選的學習與重排（S4 只能重排、不能當來源，之後另寫）。
- 敏感字排除（SW 第二片）。
- 長起點上限 3 的調整：使用者實機回饋後再量。
- 蘋果注音的 Tab／Shift+Enter 行為量測：只是參考。使用者已選 Tab；實機若發現衝突，照 §8 停止。

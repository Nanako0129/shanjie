# W0：量微軟注音（官方 Windows 版第二片）

狀態：**修訂一**（2026-11-07）：plan-verifier 第一次 REVISE 的六項照最小修改（截圖是 RGB565、顏色照這個精度報並等畫面穩定；固定 VM 解析度與切縮放的方法；App 從主控台開；記事本不是 Win32 文字框；每格之前的重設與順序；追蹤檔不寫腳本路徑與帳號）。修訂二：第二次 REVISE 的三項照最小修改（等畫面穩定先等最短時間、比對區域排除游標與時鐘；每格之前確認目標在前面且有焦點，會關掉「執行」對話框的格子只在記事本量；視窗類別名稱量不到，改記已知的控制項種類）。修訂三：收尾審查 REVISE 的兩項照最小修改（解析度在每次還原檢查點之後設、開機後核對；開 App 時先切英文、打完切回中文並截圖確認）。

## 0. 為什麼

官方 Windows 版的設計語言是 Windows 11，介面與按鍵盡量和微軟注音一致（`win-core.md` §0，維護者 2026-11-06）。Mac 版的外觀與按鍵以實測的蘋果注音為準（`s3a.md` §3 的按鍵表、組字底線、候選窗都是先量再做）。後面的最小 TIP、候選窗與預測列兩片要有同一種依據：一份實測的微軟注音參考，不靠文件或猜測。這一片只量、不寫輸入法程式。

## 1. 要做到什麼

在 188 的測試 VM `shanjie-ime`（zh-TW Windows 11 25H2 專業版，檢查點 `clean-base`）上，量系統內建的微軟注音（預設版本，不切「使用舊版」），產出一份參考文件 `docs/windows/ms-zhuyin-ref.md`，內容三部分：

1. **外觀**：淺色與深色、100% 與 150% 縮放，四種組合各量一次：
   - 候選窗：排列方向、每頁個數、編號樣式、外框圓角半徑、邊框粗細與顏色、陰影範圍、背景色、選取列的底色與形狀、文字顏色、列高、左右與上下內距、字的像素高度、翻頁或捲動的指示、和插入點的相對位置（左上角對插入點的位移）。
   - 組字區：底線的樣式（實線、虛線、點線）、粗細、顏色、和文字的距離；未完成音節與已轉換文字的樣式差別。
   - 聯想詞（打完字後出現的後接詞）：有沒有、出現在哪、外觀和候選窗的差別。
   - **顏色的精度**：截圖是 16 位元 RGB565（§2），每個顏色報成「RGB565 值與它涵蓋的 8 位元範圍」，對得上 Windows 11 主題的已知值時寫「符合 #xxxxxx」，不寫成精確的十六進位值。
  - 字型名稱只寫量得到的證據（例如和已知字型比對的結果）；比不出就寫「未確認」，不寫推測。
2. **按鍵**：照 `s3a.md` §3 的狀態分法（組字區空、有未完成音節、組字區有字、候選窗開著、聯想詞顯示中），每個狀態量這些鍵：空白、Enter、Shift+Enter、Esc、Backspace、Delete、Tab、Shift+Tab、↑↓←→、Home、End、Page Up／Down、1–9、聲調鍵、單按 Shift、Shift+字母、Caps Lock、Ctrl+Space、Win+Space、`,` `.` 與 Shift 版、Ctrl+`,` 等全形標點的快速鍵。每格寫實際看到的結果（送出什麼、窗怎麼變、游標在哪）。另外量：組字區最多幾個字、到上限時怎麼處理。
3. **設定頁**：系統設定裡「微軟注音」的每個選項與預設值（截圖讀出），以及哪些會影響上面兩部分。

## 2. 怎麼量

- **不在 VM 裡裝任何東西**。全部從 188 主機用 Hyper-V 的 WMI 做：
  - 按鍵：`Msvm_Keyboard` 的 `TypeScancodes`／`PressKey`／`ReleaseKey`（送進 VM 主控台，和實體鍵盤一樣經過輸入法）。
  - 截圖：`Msvm_VirtualSystemManagementService.GetVirtualSystemThumbnailImage`。每次取圖前從 `Msvm_VideoHead` 的 `CurrentHorizontalResolution`／`CurrentVerticalResolution` 讀解析度，用這個寬高取圖（不縮放）；回傳的原始 RGB565 像素轉成 PNG 存檔。
  - **等畫面穩定**：Windows 11 的候選窗有淡入動畫。每個鍵之後先等 800 ms，再每 200 ms 取一張，比對區域內連續 1 秒（6 張）逐像素相同才算這一格的畫面；10 秒內沒有穩定就算這一格失敗、停下。比對區域是整個畫面去掉工作列右側的時鐘區，以及目標文字框的插入點所在的那一小塊（閃爍的游標）；區域的座標在探針時量出、寫進參考文件。
  - 在 VM 裡執行命令（切主題與縮放、讀登錄的設定值、確認目前的 DPI）：PowerShell Direct（`Invoke-Command -VMName`，VM 的本機帳號，憑證用既有的 DPAPI 檔）。PowerShell Direct 是非互動的工作階段，**不用它開 App**。
  - **開 App**：用 `Msvm_Keyboard` 在主控台按 Win+R；VM 只有微軟注音一個輸入法，先單按 Shift 切到英文、取圖確認工作列指示是「英」，打指令（`notepad`、`ms-settings:…`）、Enter，再單按 Shift 切回中文、取圖確認是「中」；App 開在已登入使用者的桌面上。這次切換在每格的重設之前，重設照樣檢查「中」。送量測的鍵之前先取圖確認目標視窗在最前面，不是就停。
- **解析度與縮放**：檢查點會一併還原顯示設定，所以順序是：還原 `clean-base` → VM 關機時 `Set-VMVideo -ResolutionType Single -HorizontalResolution 1920 -VerticalResolution 1080` → 開機；每次還原之後都重做。自動登入後讀 `Msvm_VideoHead`，不是 1920×1080 就停（記進參考文件）。主題（淺色／深色）與縮放（100%／150%）用 PowerShell Direct 改目前使用者的登錄值（主題 `Personalize\AppsUseLightTheme`、`SystemUsesLightTheme`；縮放 `Control Panel\Desktop` 的 `LogPixels` 與 `Win8DpiScaling`），改完重新開機，等自動登入回到桌面，用 PowerShell Direct 讀登錄的 DPI、並在截圖上量一個已知元件（例如工作列高度）核對縮放真的生效，對不上就停。
- **打字的地方**（視窗類別名稱在這片的限制下量不到：PowerShell Direct 看不到主控台的視窗、截圖沒有類別、VM 裡不裝工具；參考文件記已知的控制項種類並標「未量測」）：
  - 「執行」對話框（Win+R）的輸入框：傳統 Win32 的 EDIT 控制項。只量外觀與組字中、候選窗開著的格子；組字區空時的 Enter、Esc、Tab、Shift+Tab 會執行、關掉對話框或移走焦點，這些格子只在記事本量。
  - 記事本：Windows 11 25H2 的記事本是新版的封裝 App，不是 Win32 EDIT；當成第二種介面量，按鍵表的全部格子都在這裡量。
  - 兩者的候選窗位置或外觀不同就兩個都記。
- **每一格之前的重設**：先取圖確認目標視窗在最前面、它的文字框有焦點（看得到插入點），不是就重開那個視窗（「執行」對話框）或停下（記事本）；接著 Esc 清掉組字與候選窗（在「執行」對話框裡只在組字區有東西時才按，免得關掉對話框）；確認 Caps Lock 是關的（取圖看工作列的輸入指示，必要時讀 VM 的鍵盤狀態）；確認輸入法在中文模式（工作列指示是「中」）。任何一項對不上就停，不猜。
- **順序**：會改變輸入法狀態或讓它學習的格子（用 1–9 或 Enter 選候選、單按 Shift、Caps Lock、Ctrl+Space、Win+Space、全形半形）排在讀候選順序的格子之後；或在它們之後還原檢查點。兩次量測用同一份順序，各自從剛還原的檢查點開始。
- 像素量測：截圖帶回 Mac，用 Python（Pillow）讀像素，單程序、秒級（`CLAUDE.md`「運算機器」的格式轉換與統計例外）。
- 還原點：每一輪量測、以及每一種主題與縮放的組合開始前，都把 VM 還原到 `clean-base`；量完關機（`Stop-VM`），不刪檢查點。
- 截圖不進 repo（`CLAUDE.md`「實機測試與虛擬機」：截圖只放 session 暫存區）；參考文件只寫數字、文字描述與量法。
- 驅動腳本：存成檔、放維護者本機（不進版控），送出前由 fresh verifier 審；`.ps1` 存成 UTF-8 加 BOM、經 ssh 從 stdin 傳（`CLAUDE.md` 的 188 規則）。
- **單程序**：這片的工作是一個程序依序送鍵、等畫面、截圖，本質上不吃 CPU；「60 秒內負載低於核心數一半就 STOP」對它不適用，要列為核准的單程序步驟（見 §5，要維護者同意）。腳本仍記每一步的秒數，並在每一步檢查 VM 還在跑、截圖檔有產生、大小不是 0，失敗就停。

## 3. 怎麼看到它有效

- 參考文件的每個數字都附：量的組合（主題、縮放、App）、截圖檔名（暫存區）、量法。
- **重量一次**：從剛還原的 `clean-base`、用同一份格子順序再做一遍，按鍵表每一格兩次相同、像素數字差 ≤ 1 px。不同的格子寫兩次的結果並標「不穩定」，不挑一個。
- 按鍵結果和善解 Mac 版（`s3a.md` §3）不同的格子，列一張「和 Mac 版不同」的表，給後面兩片決定要照哪一邊。這張表只列事實，不在這片做決定。

## 4. 驗收

- `docs/windows/ms-zhuyin-ref.md` 有 §1 的三部分，§1 列的每個項目都有值或寫明「量不到」與原因。
- 重量一次的一致性照 §3。
- fresh verifier 對照截圖（交給它暫存區的路徑）抽查至少 10 個數字與 10 格按鍵。
- 純文件 PR（參考文件、研究紀錄），審查照「改動分級」的純文件一級；驅動腳本不進 repo。

## 5. 停止條件

- **探針**（先做、只用一個組合，用 §2 的開 App 方法與前景確認）：WMI 送的注音鍵在「執行」對話框與記事本裡打得出微軟注音的組字，`GetVirtualSystemThumbnailImage` 取得的圖是 VM 的實際解析度、看得到候選窗。兩者有一個不成立就停下回報，不改用別的方法（例如在 VM 裡裝自動化工具）。
- 量到一半 VM 的系統更新、啟用、登入畫面擋住輸入：停下，不關掉 Windows Update 或改系統設定來繞過，先回報。
- 單程序步驟沒有得到維護者同意前，不送腳本。

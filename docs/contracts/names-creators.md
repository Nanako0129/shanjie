# 契約：名單層增補——實況主、YouTuber、VTuber 的名字

狀態：**過審**（2026-10-25，第二輪 READY；修訂一：只在檔尾追加、不重建既有名單；YouTube 來源移出這一片；修訂二：節目名、頻道名、系列名併進這一片，維護者選擇題）。

## 0. 起因、要做到什麼、怎麼看到

- 起因（維護者 2026-10-24／25）：「像統神等一些實況主的名字有沒有在詞庫或是候選裡」；查了，統神（PTT 201 篇）、國動（222）、鬼鬼（143）、呱吉、蔡阿嘎、愛莉莎莎、灰妲等都不在詞庫（網路用語片把人名排除在外）。選擇題：實況主、YouTuber、VTuber 的名字放**名單層（常開）**；接著維護者要更多（「有沒有更多，有關錫蘭、峰哥、多米多羅... 等 等，應該還有更多才對」）。
- 要做到什麼：用量夠的創作者名字進 `data/lexicon/names-add.tsv`（名單層，常開；通語 SJ-LM-7 計數時進計數詞表）。
- **修訂三**（維護者 2026-10-25：「人物沒有錫蘭嗎？中文圈知名的都應該要收啊」）：範圍放寬到台灣以外的中文圈名人（大陸、港澳、星馬與海外華人的網紅、藝人、歌手等），同一個來源檔、同一個標籤 `creator`、同一套用量與同讀音規則（§2）；另外照 `names-stores.md` §2 只收出貨解碼器現在打錯的。用量是子字串計數，被更長的字串（全名、地名）灌水的短稱不收（辛巴／辛巴威、力宏／王力宏、燕姿、霆鋒、秋生、奕迅、言真）；模型見過、被 `capped_score` 壓住而現在沒有效果的名字先不收，等通語 SJ-LM-7（規模待定）能量到再說。
- 怎麼看到：創作者名字檢查集在聊天設定打出收錄的寫法；出貨標準不退步；實機打「統神」「國動」「鬼鬼」。

## 1. 候選與來源

| 來源 | 內容 | 授權 |
|---|---|---|
| Muse CLI（Meta 平台，muse-spark-1.3-contributor、max；2026-10-25 兩輪） | 約 360 個名字＋83 個「待確認」，只取名字字串 | 模型建議的名稱字串，不含原文 |
| main 查到、維護者與 Discord 提的 | 統神、國動等 | CC0 |

- **節目名、頻道名、系列名**（修訂二，維護者 2026-10-25 選擇題：「是要對決」這類併進這一片）：同一個來源檔、同一個用量門檻與同讀音規則，標籤一樣是 `creator`、備註寫「節目」；中英混寫的只收中文部分（「Joe是要對決」收「是要對決」）。英文前文接中文的預測另一片（`docs/contracts/english-next.md`）。
- 名字取網友常打的中文寫法；純英文帳號不收（引擎只收漢字詞）；混字母的（如「How哥」「Andy老師」）不收。
- 不收：已在詞庫任何一層的字串（館長、放火、敬業這類一般詞，或已在疊加層、詞包的名字）。

## 2. 收錄規則與建置

- **用量**：PTT 這一輪抓取（110 看板）裡，名字字串出現的看板 ≥ 3、文章 ≥ 10（名字比網路用語少見，門檻比 net-slang 的 5／20 低；事先固定，量之前 commit）。
- **同音衝突**：任何同讀音的詞庫詞（基底、疊加層、名單、詞包、網路用語）在 PTT 的文章數 ≥ 名字，名字不收（照 `docs/contracts/net-slang.md` §2「用量多的留第一」）；同讀音的兩個名字照文章數排序、後面的扣分當候選（同 net-slang 的 `SLANG_BEHIND` 做法）。另外用出貨 CLI 解碼每個名字的讀音（聊天、書面，兩個詞包都開），收錄後第一名從既有的詞換成這個名字的，逐列列出給 main 看，照上一條判。
- **讀音**：`tools/readings.py`；CHECK 與多音字由 main 逐條看（例如「國動」的動、「峰哥」的峰沒有歧義；「樂」「行」「長」「重」這類照名單層既有的 POLY 規則人工核對）。
- **建置（只在檔尾追加，不重建既有名單）**：名單層是 2026-10-14 用當時的解碼器建的，整份重建會讓既有列的排序、分數與同音處置跟著現在的解碼器變（審查指出；先例是 10-14 接上 A3 那次的重建）。所以：
  - 新來源檔 `data/lexicon/names-creators.tsv`（欄位：詞、讀音、備註（來源與 PTT 文章數））；
  - `tools/build_names.py` 加一個 `--append-creators` 模式：讀已提交的 `names-add.tsv`，把既有列（標籤不是 `creator` 的）原樣保留，在檔尾追加 creator 列（分數＝同字數的 `scores()`＋`NAMES_BONUS`，同讀音後面的扣分），`names-sources.tsv` 與 `names.json` 也只追加；不連網、不讀快取、不重跑既有來源的處置。
  - 測試：既有列逐位元組不變（`names-add.tsv` 去掉 creator 列後等於追加前的檔，SHA-256 `77f70524…`）；沒有 creator 檔時輸出和追加前相同；creator 列不和任何一層重複。

## 3. 驗收

- **創作者名字檢查集** `eval/dev/names/creators.txt`：每個收錄的名字一列（無前文），聊天、書面各報收錄前後的第一名（只報；收錄後聊天應全部打出，打不出的列出原因）。
- **出貨標準**四條對現行出貨（兩個詞包都開）：只加詞的片，第 4 條（錯字回報）在改壞 0 時算過。
- **回歸**：dev302、打字測驗逐列；動漫五集、名單檢查集、資訊詞包檢查集、網路用語檢查集 0 改壞。
- 合併關卡：程式改動（`/code-review`＋fresh verifier＋CI）。

## 4. 順序、停止、範圍外、授權

- **順序**：網路用語（PR #281）合併之後（同讀音規則與 `SLANG_BEHIND` 做法沿用它）；合併在通語 SJ-LM-7 的階段 1 計數之前。YouTube 事件索引分流到名單層的人名，等那一片的契約合併後另開一次增補。
- **停止**：出貨標準任一條不過；回歸集合有改壞而且查不出是哪個名字造成。
- **範圍外**：創作者的台詞（迷因詞包那一片）；英文帳號名；YouTube 事件索引的人名（另一次增補）；重建既有名單；改核心或 App。
- **授權**：`LICENSES/data.md` 的 `names-add.tsv` 列加 `creator` 來源（名稱字串來自 Muse 的建議與 PTT 用量確認、Discord；只取名稱）；`names-creators.tsv` 一列，標明是建置輸入。

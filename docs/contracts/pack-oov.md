# 契約：選用詞包的詞不走通語的統計（通語計畫第一片）

## 0. 起因、要做到什麼、怎麼看到

- **起因**（2026-10-23）：動漫詞包 A4 把「麗」改讀 ㄌㄧˋ 後，伊莉絲／伊麗絲這類同音名字的順序，詞包怎麼排都蓋不過通語。量到的原因（兩份研究顧問報告在維護者本機）：
  - 動漫詞包 44,448 個詞裡有 20,393 個（46%）在通語（model-v6）的詞彙裡。
  - 詞彙內的詞，詞項是 `λ·log10 P(w|v) + (1−λ)·lp`，模型那一半（保留的二元組、承接、辨類）和詞包無關，詞包分數只進 `(1−λ)·lp`。
  - 詞彙外的詞，lp 以權重 1 進來。
  - 例：開詞包打 ㄧ ㄌㄧˋ ㄙ，詞包給伊莉絲 −7.04、伊麗絲 −10.04，解碼卻是伊麗絲 −8.40 第一、伊莉絲 −9.45；伊麗絲在通語詞彙裡（有 `(<s>, 伊麗絲)` 的保留二元組），伊莉絲不在。
- **維護者的決定**：「這個是通語的問題…通語本身詞庫其實還需要與其他詞包去重」；第一片選「所有選用詞包詞＋分級分數」：解碼時只在選用詞包裡的詞不走通語的統計，分數由詞包建置時給。model-v7 再把選用詞包的詞拿出通語的計數（另一片）。
- **要做到**：開詞包時，詞包詞彼此（與和詞庫的詞）怎麼排，由詞包的分數決定；關詞包時一切照舊。
- **怎麼看到**：開詞包打 ㄧ ㄌㄧˋ ㄙ，第一名是處置列指定的「伊莉絲」；A4 那 10 個讀音照研究的順序；關詞包時和 main 逐位元組相同。由 main 在 GCP 量、在 tart VM 實機打一次。

- **前提**：動漫詞包 A4（同步更新到最新來源，`feat/acg-refresh`）先合併；這一片的詞包重建與第 3、4 項都以 A4 之後的清單為準。

## 1. 規則

1. **哪些詞**：核心載入的選用詞包（現在只有 `--packs acg`／App 的動漫詞包開關；之後的資訊詞包同一套）裡的每個詞。詞包建置工具本來就對基底、疊加層、變調列、名單層逐字串去重，所以「詞包裡的詞」就是「只在選用詞包裡的詞」；核心照檔案判斷，不另外比對。
2. **核心**（`core/src/lm.rs`，`reference/proto/lm.py` 鏡像）：
   - `CappedLexicon::new` 收詞包詞在 `ents` 裡的位置。這些條目的分數就是詞包檔的分數：**不封頂**（不取 `min(score, log10(c/N))`）、**不扣** `UNSEEN_OVERLAY_PENALTY`。
   - 解碼（`decode_segment_learned` 與它用到的詞項、句尾項）對這些條目用 `wid = None`：沒有保留的二元組、沒有承接的接續項、沒有辨類項，lp 以權重 1 進回退項（和現在的詞彙外詞同一條路）。當前文時視為未知詞（`ctx_of(None)`）。
   - `Engine::total_score` 同一套（s3a「總分等於第一名」照舊）。
   - 候選清單、V3 預測、學習、降權表不動。
3. **詞包的分級分數**（`tools/build_acg_pack.py`）：
   - 每個詞包詞的基礎分數改成 `max(S_len, log10(c(w)/N) + B)`：`c(w)` 是**凍結的計數表** `data/packs/acg-counts.tsv` 裡這個詞的次數，`N` 是同一份表的總數，`S_len` 是現在依詞長給的分數（沒有次數的詞就用它），`B` 是加分。
   - 凍結計數表：建置工具第一次從現在的 `data/lm/bigram.sjlm`（model-v6，`fc2bddd1…`）讀出每個詞包詞的 unigram 次數與 N 寫成表（詞、次數；檔頭記模型雜湊與 N），之後建置只讀這份表，不再碰通語。這樣 model-v7 把詞包詞拿出計數後，詞包仍有自己的頻率。
   - 同讀音的處置順序（`collision_rank` 的 TIE）、`NEW_BEHIND_SHIPPED`、keep-both、kept-c、(c) 規則照舊，作用在新的基礎分數上。
   - A4 那 10 個讀音（伊莉絲等，現在在 `acg-keep-both.tsv` 的 A4 段）改回研究的順序（`acg-collisions.tsv` 的 `+` 列），keep-both 那 22 列拿掉。
4. **B 的選法**（探索，事先固定，看過數字不改格點）：B ∈ {0, 0.5, 1.0}。對每一格重建詞包，在 GCP 量：
   - 動漫五集（works 142、characters 227、character-parts 105、recent 23、interpunct 45）與名單檢查集 61，聊天與書面的 top1；
   - 一般集合（dev302、打字測驗、錯字回報）兩種設定的改壞數。
   - 選法：一般集合改壞 0 的格裡，動漫五集兩種設定的 top1 合計最大；同分取較小的 B。都不符合就停，報給維護者。

## 2. 驗收

1. **關詞包逐位元組不變**：不給 `--packs` 時，golden 全部不變；dev302、打字測驗、錯字回報、cvtune-clean、wikitune-clean 兩種設定的 `top1_sha256` 與 rowstats 和 main 相同（GCP）。
2. **開詞包的處置生效**：選定的 B，`--recheck --base <v0.5.0 的詞包>`（出貨模型）的 `first_named` 失敗清單為空，包含 A4 那 10 個讀音（例：ㄧ ㄌㄧˋ ㄙ 第一名伊莉絲）。
3. **動漫與名單**：選定的 B，動漫五集與名單檢查集兩種設定，對現行出貨（main 的詞包）報改對／改壞與淨值；淨值 < 0 的集合逐列列出、停下來問維護者。
4. **出貨標準四條**（開詞包＝出貨預設，對 main）：discordtune、打字測驗與 dev302 書面、cvtune-clean 聊天、錯字回報，照規則判。
5. **測試**（每條有會讓它失敗的突變，看結束碼與斷言數）：
   - 合成小模型＋小詞包：詞包詞的詞項等於沒有模型 id 時的值、不封頂也不扣未見罰分；非詞包詞不變；同一個詞包詞在 `total_score` 與解碼一致。突變：拿掉 `wid = None`、只在解碼套不在 `total_score` 套、詞包詞仍封頂，各至少讓一條失敗。
   - `build_acg_pack.py`：分級分數公式（有次數、沒次數、B）、凍結計數表雜湊不符時中止。
   - Rust 與 Python 參考實作在開詞包的 golden 上逐位元組相同。
6. **延遲與記憶體**（Mac、閒置窗）：`timing_typing76_keys` p95 ≤ 16 ms；開詞包的 RSS 對 main 增加 ≤ 1 MiB。
7. **實機**（繁中 tart VM，裝本分支開發版，動漫詞包開）：打 ㄧ ㄌㄧˋ ㄙ 第一名「伊莉絲」；關掉動漫詞包後同一串和 main 相同。

## 4. 停止條件、預算、範圍外

- **停止**：關詞包有任何一格不是逐位元組相同；三格 B 都讓一般集合改壞；出貨標準任一條不過；動漫或名單集淨值 < 0（問維護者）；記憶體 > 1 MiB；核心改動超出 `CappedLexicon`、解碼詞項、`total_score`、`lm.py`。
- **預算**：GCP ≤ 2 小時（三格建置與量測、關詞包對照）；executor 實作 1 次＋修正 1 次。
- **範圍外**：重建通語（model-v7）；單字與疊加層讀音修正（維護者：等 model-v7）；承接的去留（另跑關掉的對照）；資訊詞包（之後照同一套接上）；名單層（常開詞庫，留在通語）。

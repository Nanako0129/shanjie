# S7f：核心的口語語料——加真人口語與生成句，重訓小模型（研究片）

狀態：完成（2026-10-12）：§3 兩項都不過，照四格表停下來回報、不再加量（§7）。READY 的經過見 §6。

接續 S7e（PR #120，a04cefa）。S7e 的結論：照「改壞 1 句 ≈ 改對 10 句」，M、L、XL 在使用者的聊天上都沒過（改對：改壞約 5–7:1），模型變大沒有幫助；推論是訓練文字缺聊天語域。使用者 2026-10-12 決定語料分**核心**（App 內附，只收明示開放授權）與**外接**（另一個 repo，這一片不做）。

## 0. 依據

- **先例（研究紀錄 S2）**：n-gram 那條線第 2 輪加入針對混淆字的合成句（29,810 句，用同一個模型把關），調整集和 Discord 都退步；第 9 輪加大口語權重沒有幫助；第 10 輪的結論是「凡是不像真人聊天的資料都推不動聊天的分數」。第 0 輪（口語語料權重 5 倍，含合成句）讓 Discord 錯誤率從 23.3% 降到 18.9%，但那一輪沒有對照組，分不出是哪一部分的功勞。Fable 的方法審查也指出「合成句沒有對照組」。所以這一片：**真人口語先做、合成句單獨一組、訓練預算固定**，合成句沒有幫助就停。
- **核心可用的對話來源**（2026-10-12 的調查，研究紀錄同日）：唐鳳逐字稿 archive.tw（CC0）、Cofacts（CC BY-SA 4.0，HF 上要使用者同意條款）、中文維基的討論頁與互助客棧（CC BY-SA 4.0）。政府新聞稿（著作權法第 9 條＋政府資料開放授權）是書面語，不是這一片要測的聊天語域，**不放進這一片**（之後新聞語域另做）。
- **生成句**：使用者要求用多個開源模型（gpt-oss、Gemma 4 等）。只用模型卡寫 Apache-2.0 或 MIT、而且**不需要同意條款就能下載**的模型（Gemma 4 從 2026-04 起是 Apache-2.0），種子詞只用乾淨的來源，**不用使用者的私人聊天**。

## 1. 要做到什麼、怎麼看到

- 回答兩個問題：(1) 在固定的訓練預算下，把一部分訓練文字換成真人口語，能不能讓改壞變少、改對變多？(2) 在 (1) 之上再換進生成句，有沒有額外的幫助？
- **怎麼看到**：同一套選法（S7e 的 `fusegrid.py --break-weight 10`）下四組模型的表格與 §3 判斷——A0 現行 M、A0′ 同樣資料重訓一次（量訓練本身的雜訊）、A1 加真人口語、A2 再加生成句。

## 2. 做法

### 2.1 取得與清理（每個來源一個腳本，`experiments/s7f-corpus/`）

| 來源 | 取得 | 清理 |
|---|---|---|
| archive.tw | VM 或 Mac 上 `git clone https://github.com/audreyt/transcript`，記 commit SHA | 只收中文檔；用 `.alternates` 去掉英文演講的譯稿；去掉講者標記與時間戳；以句號類標點切句 |
| Cofacts | **只在 Mac 上**從 HF `Cofacts/line-msg-fact-check-tw` 下載（使用者同意條款後，read token 從鑰匙圈讀，不印、不寫檔、不上 VM），記 HF 的 revision；清理後的文字走 S4 有時效的網址給 VM | 只下載並只讀 `articles.csv.zip`（訊息內文）與 `reply_requests.csv.zip`（使用者回報理由）；**不下載** `anonymized_users`、`analytics` 等和使用者有關的檔案；去掉網址、電話、email 樣式的字串。2026-10-12 確認 token 讀得到檔案清單（revision `eda4648c69d3`，授權標籤 CC BY-SA 4.0），還沒下載 |
| 維基討論頁 | VM 從 your.org 鏡像抓 2026-10-01 的 `zhwiki pages-meta-current` dump：namespace 1、3（討論、使用者討論），以及 namespace 4 裡標題以 `Wikipedia:互助客棧` 開頭的頁面（其他方針、投票頁不收）〔修訂，2026-10-12：實際頁名是簡體的 `Wikipedia:互助客栈`，兩種寫法都收，§6〕 | 去掉簽名、模板、機器人訊息；只留整段是繁體的段落（段落裡簡體專用字的比例 = 0），不做繁簡轉換 |

- 共同：去掉含簡體專用字的句子、長度 4–60 字、整句去重；字表固定用 S7a 的 9,717 個 id（不在字表的字照舊是 UNK）。
- **量是固定的**：三個來源清理後各自用固定種子隨機抽句，每個來源最多 800 萬字，合計最多 2,000 萬字；某個來源不夠就全收，不拿別的來源補。實際字數記進研究紀錄。合計少於 500 萬字就停（§5）。
- **和評測集的重疊**：所有公開評測集（cvtune、wikitune、dev302、打字測驗、錯字回報、功能字測試句）的句子，凡是整句出現在新語料裡的，**從新語料裡拿掉**，列數記進研究紀錄。保留集不碰：由 verifier 收尾時只回報重疊列數。〔修訂，2026-10-12〕只用 **4 字以上**的評測句拿掉新語料（和新語料句的下限相同）：一到三字的評測列（例：錯字回報第 29 列「吧」、「對齊」、「試了」）出現在新句子裡不算那一句的重疊，照字面拿掉會讓聊天文字少掉所有含「吧」的句子；短於 4 字的評測列數，與每一列被多少新句子包含（只記數字），記在 manifest。
- **和 discordtune 的重疊**（Mac 上、只回數字）：數 discordtune 有幾列整句出現在 A0 的訓練文字、A1 新增的真人口語、A2 新增的生成句裡。判斷（§3）一律用**和 A1、A2 新增文字都不重疊的列**，全部列的結果另列參考。
- **來源快照**（使用者 2026-10-12 同學的建議）：`LICENSES/data.md` 新增一節「研究語料（未出貨）」，每個來源一列：名稱、網址、取用範圍、取得日期、當天授權頁或條款的原文摘錄與網址、原始檔 SHA-256（或 commit／revision）。**`tinylm` 那一列不改**（它描述的是已出貨的 `tinylm-v1`），等出貨片再改。

### 2.2 生成句（A2 才用）

- 模型：實作時在 HF 模型卡核對授權（Apache-2.0 或 MIT），記下模型名稱、版本、授權網址與日期；兩家（gpt-oss-120b 與 Gemma 4），每家生成量相同。
- **在哪裡跑**（〔修訂，2026-10-12 使用者決定〕先用 API 額度，真的不行才用 Colab）：gpt-oss-120b 走 Cerebras API；Gemma 4 走 OpenRouter 並指定 provider（關掉 fallback）。條件：provider 的條款把輸出的權利交給模型本身的授權、沒有限制用輸出訓練模型，生成當天存下條款頁的快照（網址、日期、原文摘錄）記進「研究語料（未出貨）」；送出去的提示只有公開的種子詞與固定的指示，沒有任何私人資料。金鑰從鑰匙圈讀進單一程序、不印出、不寫檔（沿用 `experiments/providers/` 的做法與花費帳本）。任一家條款不符或 API 不能用，才改在 Colab 用 vLLM 跑（權重由 VM 直接從 HF 下載，只用不需要 token 的權重）。
- 種子：維基標題與 Wikidata 的 zh-tw 標籤（遊戲、軟體、網路服務、台灣地名與食物），加上維護者自寫的台語漢字與網路用語詞表（`experiments/s7f-corpus/seeds/`，CC0，進 repo）。種子檔在生成前凍結，SHA-256 記進研究紀錄。每次提示給 3–5 個種子詞，要求寫台灣人在聊天軟體裡會打的一句話。
- 把關（全部是確定的規則，各有單元測試，§4）：
  - **和種子有關**：句子裡至少原樣出現一個這次提示的種子詞；
  - **大陸用語**：句子含 invade 大陸用語詞表（CC0，`docs/methodology.md` 已登記）裡的詞就丟掉。詞表在生成前取得、記來源網址與 commit、凍結 SHA-256；〔修訂，2026-10-12〕單字詞（宏、寄、潤）不用：它們在台灣是別的意思的日常字（例：寄信），被排除的單字詞記在 manifest，兩字以上的詞照舊；
  - 含簡體專用字的句子丟掉；長度 4–60 字；整句去重；和評測集重疊照 §2.1 拿掉。
- **量是固定的**：生成句總字數**正好 500 萬字**（兩家各 250 萬字），超過就用固定種子隨機抽句到這個數；不夠就停下來回報（§5）。

### 2.3 訓練與比較

- **訓練預算固定**：A0′、A1、A2 都是 `train.py --size M`、`--max-steps 8836`（A0 的步數）、每批 32,768 個 token；每批放 floor(32768/長度) 段，所以 token 數幾乎相同、不完全相同，差異記進研究紀錄。新增的文字放在第三個檔 `ids-chat.npy`，權重 1（`train.py` 加一個 `--extra` 選項，不給時行為不變；`--max-steps` 的說明從「只給冒煙測試」改成也用於固定預算）：
  - A0：現有的 `tinylm-M`（S7a 的 wiki ×1＋coll ×5），不重訓；
  - A0′：和 A0 同樣的資料，在 Colab 上重訓，種子 20261012（和 A1、A2 相同），不給 `--extra`。它和 A0 的差就是「換平台、換種子、換批次順序」造成的雜訊；
  - A1、A2 的種子都是 20261012；
  - A1：S7a 的文字＋`ids-chat.npy`（真人口語，權重 1）；
  - A2：A1＋生成句（併進 `ids-chat.npy`，權重 1）。
  - 一個 epoch 比 8,836 步長時，`--max-steps` 只取洗牌後的前 8,836 批；新文字因此等比例地取代一部分舊文字。A2 對 A1 只差「混合裡有沒有生成句」，訓練量相同。`train-*.json` 的 `steps` 三組都是 8,836，`tokens` 的差異記進研究紀錄。
- **int8**：A0′、A1、A2 訓完用 `int8check.py dequant` 轉成和 A0 一樣的 int8（M8）再打分。
- **打分全部在 Mac 上用 numpy**（和 A0 的分數同一個後端）：公開集合與 discordtune 都是；Colab 只用來生成與訓練。
- **資料傳輸**照 2026-10-12 定案的做法（`experiments/s7a-tinylm/README.md` 的 Colab 一節）：公開來源由 VM 自己抓，清理與轉 `ids` 也在 VM 上做、和 Mac 上同一腳本的結果核對雜湊；只在 Mac 上的檔案（Cofacts 清理後的文字）走 S4 bucket `shanjie-colab`、前綴 `s7f/`、有時效的網址；結果用 `colab download`。私人資料不上 Colab。
- **重現關卡**（任何 A1、A2 打分之前）：
  1. 重新產生的 discordtune 候選，在 M8、0.7／2／δ 0 下必須是 n 4,958、聊天 4,209 → 4,275（229／163）、書面 4,143 → 4,228（232／147）；
  2. A0（M8）在 `--break-weight 10` 下必須選回聊天 0.2／1／0.25、書面 0.7／1／2，discordtune 聊天 70／10（−30）、書面 30／1；
  3. 在 Colab 上打公開集合時用的 dump，SHA-256 必須和 S7b／S7e 的 dump 相同（`~/.cache/shanjie/s7e-public/` 有那幾份）。
  任何一項不同就停。
- 打分與選法完全照 S7e：`run_sets.py score --backend numpy`、`fusegrid.py --break-weight 10`；discordtune 只回數字。

## 3. 判斷（事先寫死）

discordtune 在 S7a、S7b、S7d、S7e 已經用了四次，這一片**只當開發集**看方向，不做出貨判斷。下面的「淨值」是 discordtune 聊天在**和新增文字不重疊的列**上的「改對 − 10 × 改壞」（相對 n-gram）；「守門」是 S7e §3 第 4 項（六個公開集合兩種設定都沒有改對 < 改壞且 p < 0.05 的格）。

- **雜訊界線**：B ＝ max(A0 的淨值, A0′ 的淨值)。只換平台與種子就能差出來的範圍，不算資料的功勞。
- **第 1 項**：A1 的淨值 > B，而且 A1 守門通過。
- **第 2 項**：A2 的淨值 > A1 的淨值，**而且 > B**，而且 A2 守門通過。

| 第 1 項 | 第 2 項 | 動作 |
|---|---|---|
| 過 | 過 | 候選是 A2：真人口語與生成句都有幫助 |
| 過 | 不過 | 候選是 A1：生成句不進核心 |
| 不過 | 過 | 候選是 A2：真人口語單獨沒有幫助，但加上生成句之後比 A0、A0′ 都好；研究紀錄寫明 |
| 不過 | 不過 | 停下來回報，不再加量 |

有候選時，出貨要另開一片：用**使用者另外提供、沒用過的新聊天資料**（例如某個日期之後的訊息，要先問使用者）判斷一次，再加保留集（fresh verifier）。

1. 單元測試（`experiments/s7f-corpus/`，用小的假資料）：簡體段落被丟掉、電話與網址被去掉、評測句被拿掉、去重；生成句的「含種子詞」與「大陸用語」兩條規則；`train.py --extra` 不給時的行為和現在逐位元相同、給了之後檔案真的進到 epoch。
2. 每個來源的列數、字數、SHA-256（或 commit／revision）、和評測集重疊被拿掉的列數、discordtune 的重疊列數，記進研究紀錄；`LICENSES/data.md` 的「研究語料（未出貨）」一節。
3. §2.3 的重現關卡結果；A0／A0′／A1／A2 的表格（S7e 同格式）、四組的淨值、雜訊界線 B 與 §3 逐項，記進研究紀錄；本契約的結果一節；PLAN 的 S7 狀態行。
4. **保留集的重疊**：verifier 回報保留集有幾列整句出現在 A1、A2 新增的文字裡（只回列數），記進研究紀錄；下一個出貨片要用這個數字判斷保留集能不能直接用。
5. `make test` 全綠。**verifier 的輸入**：main 把 A0、A0′、A1、A2 的公開集合分數與 dump 複製到 `~/.cache/shanjie/s7f-public/{a0,a0p,a1,a2}/`（檔名照 `run_sets.py` 的格式），加上 A0′、A1、A2 的 `train-*.json` 本身與 `tinylm-*.npz` 的 SHA-256，以及 A1、A2 **新增的文字**（真人口語與生成句，都是公開來源，附 SHA-256）。**順序**：discordtune 的衍生檔先刪、確認刪掉之後，verifier 才開始；verifier 只讀那個資料夾與 worktree，從公開分數重現公開集合的表格與選到的值。

## 5. 範圍外、停止條件、預算、限制、回滾

- **範圍外**：外接（NC／ND、立法院公報等）、n-gram 模型重建、核心或殼的改動、出貨、δ 進核心（S7c-2c）。
- **停止條件**：任何來源的授權頁和調查時不同；清理後三個對話來源合計少於 500 萬字；生成句不夠 500 萬字；§2.3 的重現關卡不符；§3 兩項都不過；Colab 用量到預算上限；生成模型需要同意條款或 token 才能下載。
- **預算**（使用者 2026-10-12）：API 花費上限 **US$20**（照 `experiments/providers/` 的帳本，超過就停）；Colab 上限 **10 個運算單元**（三次 M 的訓練，加上 API 不能用時的生成備案）；到上限就停下來問使用者。量都照 §2.1、§2.2 固定。
- **限制**：私人資料（discordtune、學習檔、聊天紀錄）不上 Colab、不進任何訓練文字或種子；HF token 與 S4 金鑰只從鑰匙圈讀、不離開 Mac；agent 不讀 `~/side-project/shanjie-private`、`~/.cache/shanjie/work`、`eval/holdout`。
- **回滾**：repo 的改動（`experiments/s7f-corpus/`、種子檔、`train.py --extra`、文件）revert 即可，不出貨。外部狀態：S4 bucket `shanjie-colab` 的 `s7f/` 前綴下的暫存物件，在使用者同意後刪除；每次用完就 `colab stop` 關掉 session；嵌著有時效網址的腳本用完就刪；使用者在 HF 同意的條款與 token 由使用者決定要不要撤銷。

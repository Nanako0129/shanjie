# 解碼器（n-gram 選字）

這份寫的是現在的行為。

範圍：把一串注音音節解成字串的那一層：詞庫分數、bigram／trigram 機率、讀音項、模糊輸入、降權與異體排序，以及這些資料檔的格式與建置規則。語意校正（小模型重排）、預測列、選字記憶、按鍵與組字區、英文混打、模型與詞包的建置流程各有自己的文件（`docs/spec/semantic-rerank.md`、`docs/spec/prediction.md`、`docs/spec/learning.md`、`docs/spec/keys-and-composition.md`、`docs/spec/english-mixed.md`、`docs/spec/models.md`、`docs/spec/lexicon-and-packs.md`），這裡只寫解碼器看得到的部分。實作在 `core/src/lm.rs`（解碼、機率）、`core/src/trigram.rs`、`core/src/reading.rs`、`core/src/fuzzy.rs`、`core/src/lib.rs`（詞庫）；`reference/proto/lm.py`、`reference/proto/trigram.py` 是逐位元組對照的 Python 參考實作。

## 1. 資料流與載入

### 1.1 輸入檔

解碼一段注音需要三類輸入：

| 輸入 | 檔案 | 作用 |
|---|---|---|
| 詞庫 | `mcbpmf-data.txt`（基底）、`overlay-add.tsv`、`sandhi-add.tsv`、`names-add.tsv`、選用詞包、`variant-order.tsv`、`demote.tsv`、`std-exempt.tsv`、`rerank-protect.tsv`（只進重排遮罩，不加詞） | 每個讀音下有哪些詞、各自的分數（log10） |
| 語言模型 | `bigram.sjlm` 加旁邊的 `classes.sjc`、`kn.sjkn`、`trigram.sjt3`（書面）、`trigram-chat.sjt3`（聊天） | 詞與詞的接續機率 |
| 設定 | 設定（聊天或書面）、降權開關、模糊輸入位元 | 選 λ、表與扣分 |

基底每行 `讀音 詞 分數`（空白分隔，讀音以 `-` 接音節）；`#`、`_` 開頭的行與「字數不等於音節數」的行略過。疊加層類的檔每行 `讀音<TAB>詞<TAB>分數<TAB>標籤`。

### 1.2 載入順序與失敗

- 詞庫依序讀基底、`overlay-add.tsv`、`sandhi-add.tsv`、`names-add.tsv`、選用詞包、（評測用的額外疊加層），接在基底後面，同讀音的列最後一起穩定排序（高分在前）。上述每個檔缺檔或讀不了都是載入失敗（C ABI 回傳 3）；唯一例外是選用詞包的檔缺檔時當作沒有那個詞包。
- `Engine::load_lm` 另外要求：`classes.sjc`（缺檔、魔數、模型雜湊、長度、機率範圍任一不符就失敗）、`std-exempt.tsv`、`variant-order.tsv`（再讀一次）、`mcbpmf-data.txt`（建讀音表）。`kn.sjkn`、兩張 trigram 表是選用的：路徑不存在就是關閉，路徑存在（含壞掉的符號連結）卻讀不了或和模型不符就是載入失敗，不會靜默略過。App 的載入（`Engine::load_lm`）兩張 trigram 表都讀，所以任一張壞掉都讓整個載入失敗；評測 CLI 只讀該設定自己的那張（`--no-tri` 都不讀、`--no-kn` 不讀 `kn.sjkn`、`--no-classes` 不讀 `classes.sjc`）。
- 沒有載入語言模型時，組字區走 `decode_beam`（只用詞庫分數，光束 64）；語言模型一旦載入，所有路徑都走 §4。

## 2. 詞庫分數

### 2.1 一個讀音下的排序

- 每個讀音下的詞依分數由高到低排；同分維持載入順序（基底在前、疊加層在後、疊加層依檔案順序）。
- 解碼器每個讀音只試前 `PER_KEY` = 12 個詞，另外加上選字記憶學過、排在 12 名之後的詞（只在學過它的前文脈絡下可用）。
- 詞庫有兩份：候選窗與音節判斷用的未封頂詞庫（`Lexicon`），以及解碼用的封頂詞庫（`CappedLexicon`，§2.2）。

### 2.2 封頂

- 疊加層（`overlay-add.tsv`、`names-add.tsv`、詞包）裡的詞，不論它是疊加層新增或和基底同詞，分數都封頂到語料頻率：`min(分數, log10(次數 / N))`；通語沒看過的（次數 0）扣 `UNSEEN_OVERLAY_PENALTY` = 1.0。封頂後每個讀音重新排序。
- 例外只有選用詞包，見 §2.5。`sandhi-add.tsv` 的列不在封頂清單裡（它們是基底詞的讀音變體）。
- `CappedLexicon::readings()`（預測列與數字層用）重建出和「沒有詞包例外」時相同的封頂清單，所以詞包的分數規則不影響預測與數字層。

### 2.3 異體排序表（`variant-order.tsv`）

- 格式：每行 `讀音<TAB>少用寫法<TAB>常用寫法<TAB>來源`，讀音用詞庫寫法（音節以 `-` 相接）；空行與 `#` 行略過。意思：這個讀音下，少用寫法的分數不高於常用寫法的分數減 `VARIANT_GAP` = 0.01，即 `min(原分數, 常用寫法在同一讀音下的最高分 − 0.01)`。出貨的檔有 35 組。
- 載入規則（Rust `VariantOrder::parse`、Python `load_variant_order` 一樣嚴格）：剛好 4 欄、欄位首尾沒有空白類字元、同一個（讀音, 少用寫法）只能一行、少用 ≠ 常用、某行的常用寫法不能是另一行的少用寫法（不連鎖）；兩個寫法在這個讀音下都要存在於載入後的詞庫（基底或任一疊加層），否則引擎建立失敗（回傳 3）。缺檔也是 3。不帶表的 `Lexicon::parse` 行為不變。
- 套用三次：
  1. 未封頂詞庫，各讀音排序之前（`Lexicon::parse_with_variants`），候選窗的詞庫段因此常用寫法在前。
  2. 封頂之後（`CappedLexicon::with_packs`、`readings()`、Python `cap_overlay`）再套一次：常用寫法若是疊加層的詞，封頂可能把它壓到少用寫法下面。
  3. 候選窗（`Engine::variant_move`）：預測列的項目會先排在詞庫之前，所以預測列把少用寫法排前面時，窗裡同讀音的少用寫法移到常用寫法的緊後面。少用寫法是使用者教過的預測項目（帶學習權重）時不移。移動保持 `Cands.rows` 與清單開頭一一對應：兩個都是預測項目時 `rows` 同樣重排；少用寫法是預測項目、常用寫法是詞庫項目時，只有該項目的讀音等於已打的那一段才讓它離開 `rows`，否則不動。
- 沒有開關，不受降權開關、設定、語意校正強度影響；少用寫法仍在候選窗，選了照常學習。
- 取捨：用「詞庫分數的上限」而不是改計數，因為通語兩個寫法的次數是模型的資料，詞庫順序要能獨立修正；解碼第一名是否一定是常用寫法取決於模型計數，這張表只保證候選窗與詞庫順序。

### 2.4 降權表（`demote.tsv`）

- 格式：每行 `讀音<TAB>詞<TAB>δ<TAB>類別<TAB>來源`，5 欄、欄位首尾無空白類字元；讀音以 `-` 相接，`*` 表示該詞所有讀音；δ 是只含 ASCII 數字與一個小數點的有限正數；同一個（讀音, 詞）只能一行；特定讀音優先於 `*`。出貨的檔目前有 1 行（`ㄍㄠˇ-ㄨㄢˊ 睪丸 2.0 reading`）。格式錯、重複鍵、或某行在詞庫找不到該讀音下的該詞，引擎建立失敗（回傳 3）；缺檔也是 3。Python 與 Rust 用同一套嚴格規則。
- `reading` 類的收錄條件（三個都成立）：教育部辭典有這個詞但沒有這個讀音；差別不是輕聲或變調；有使用者回報或探針證據顯示它擋到同音的一般詞。
- 效果：該（讀音, 詞）的詞項分數再減 δ（見 §4.2）；試哪些詞條仍依封頂分數，不依扣分後的值；學習加分的基準（該讀音最高分）不扣 δ，學習加分之後仍扣 δ。固定詞（使用者選定的詞）在接續項（`End::Next`）與 `Engine::total_score` 裡同樣扣它的 δ。
- 開關：`shanjie_engine_set_demote(engine, 0|1, out)`，預設 1，其他值回 2 且狀態不變；和 `set_profile` 一樣重算組字區並回傳快照。0 時所有 δ 視為 0，結果與沒有這個檔逐位元相同。App 選單的「避免把敏感字詞排在前面」接這個開關，預設開。候選窗順序不受降權影響。
- 評測：`shanjie-eval` 與 `lm_eval.py` 的 `--no-demote`；摘要行在關閉時加 `-nodemote`。
- 取捨：扣在最終詞項分數而不是詞庫分數，因為模型裡有「睪丸」的二元組而「搞完」只能回退，第一、二名分差（聊天 1.52、書面 1.39）比詞庫分數差大，只降詞庫分數壓不下去。

### 2.5 選用詞包詞

- 詞包列寫在詞包檔（目前 `acg-add.tsv`、`quotes-add.tsv`、`it-add.tsv`、`meme-add.tsv`、`beauty-add.tsv`）的第 4 欄標籤。只有動漫詞包（`PACK_OOV`）的列用到下面的強制標籤 `acg-oov`；資訊、迷因、美妝詞包等照一般疊加層封頂。
- **強制詞**（第 4 欄 `acg-oov`）：解碼時被當成通語不認得的詞，分數就是詞包檔給的值，不封頂、不扣罰分。具體地，每個要用詞 id 的地方一律改用 `CappedLexicon::model_id`（強制詞回 `None`，其他詞回 `Lm::word_id`）：解碼的詞項與句尾項、解碼狀態記下的前一詞與前前詞、段落開頭的固定詞或前文詞、右邊接續的固定詞（`End::Next`）、`Engine::total_score` 走路徑的每個詞（`word3_in`／`eos3_in`／`word_learned_by_id` 吃 `Option<u32>`）。Python `cap_overlay` 與 `decode` 對同一組字串照樣當未知詞。
- **非強制的詞包詞**（第 4 欄 `acg`）：照一般疊加層封頂，`model_id` 是 `Lm::word_id`；唯一差別是通語沒看過的（次數 0）不扣 `UNSEEN_OVERLAY_PENALTY`。
- 不受影響的地方：`history()`（左邊前文以詞包詞結尾時仍記那個字串，只有拿它算分的地方經 `model_id` 變成未知詞）、候選窗、預測列、學習、降權表、會意的輸入、常談項。
- 強制詞的集合由詞包建置工具標出，規則：
  - 處置讀音＝詞包碰撞表中有指定第一名（`first_named`）的讀音，加上讓位清單 `acg-yield.tsv` 的讀音；處置讀音上的每個詞包字串是候選強制詞，以字串封閉（同字串在別的讀音上的列也標）。
  - 排第一（`first_named`）、通語認得（凍結次數 > 0）、而且封頂分數 `log10(c/N)` ≥ `S_len − 0.5` 的字串不強制，保留通語統計；它若在別的處置讀音上排在後面，照樣強制。強制列排在「沒強制的第一名封頂後的分數」之下。
- 詞包列的分級分數（`build_acg_pack.py regrade`）：`g(w) = max(S_len, log10(c(w)/N) + B)`，`S_len` 依字數（基底同字數詞條分數的第 25 百分位；2 字 −7.17、3 字 −7.04、4 字 −6.61），`c`、`N` 取自凍結次數表 `acg-counts.tsv`（只有子命令 `freeze-counts` 會寫，檔雜湊釘在工具裡；一般建置只讀它，不看 `data/lm` 是哪一版），不在表裡的詞一律 `S_len`；`B` = 0（出貨值）。同一讀音內先依處置名次、再依原分數排，第 i 列 = `min(分級值, 第 i−1 列 − TIE)`（`TIE` = 1e-6），所以分級只會整個讀音一起抬高或壓低，不改讀音內先後。原本相對 `S_len` 的差距只可能是 0、0.5（「一」「不」變調列）、3.0（`NEW_BEHIND_SHIPPED`：新詞在已出貨詞的讀音上只當候選）、3.5；重算時變調列減 0.5，扣過 3.0 的列再扣 3.0（處置第一名不扣），讓位清單上的（讀音, 詞）再扣 3.0。`regrade` 不改任何列的讀音與詞，只換分數。
- 關閉詞包時全部行為與沒有這個機制逐位元組相同。
- 取捨：強制詞才當未知詞，因為通語認得的名字（出現上百次）當成未知會丟掉它自己的二元組與接續機率，詞包加分補不回；而同音名字的順序要由詞包的分數排定時，詞包詞不能被通語的統計蓋過。

## 3. 機率模型

### 3.1 bigram 與回退

- `bigram.sjlm`（`SJLM0001`，小端序）：魔數 `SJLM0001`、V（u32）、N（u64，總計數）、句尾計數（u64）、折扣 D（f64），接著 V 個詞（u16 長度加 UTF-8），id 0 是 `<s>`、id 1 是 `</s>`，其餘依 UTF-8 位元組序遞增；再來是每詞 unigram 計數（u64[V]）、有前文條目的詞 id、各自的前文總數、偏移、後繼 id（每個前文內遞增）與計數。載入時檢查魔數、排序、偏移範圍、id < V、尾端無多餘位元組。每個前文的回退權重 `back(v) = 1 − Σ(計數 − D) / 前文總數`（依檔案順序加總後除一次）。
- 一個詞項的機率 `P(w | v)`（`Lm::prob_c_kn`）：
  1. 回退分布 `pb` 先是詞庫分數的 `10^lp`；詞彙內的詞（id ≥ 2）且有 KN 側檔時換成 `β·N′/ΣN′ + (1−β)·pb`（§3.3）。
  2. 有保留的二元組（計數不為 0）：`(計數 − D) / 前文總數 + back(v)·pb`。
  3. 否則：`back(v)·( (1−μ)·pb + μ·Pc[c(v), c(w)]·emit(w) )`（v、w 都有類別時，§3.2），否則 `back(v)·pb`；v 沒有前文條目時 `back = 1`。
- 詞項分數 `λ·log10 P(w|v) + (1−λ)·lp`（`word_term`），`lp` 是詞庫（封頂後）分數。句尾項 `λ·log10 P(</s>|v)`，詞彙外的詞與句尾（id 1）不套 KN。
- 浮點運算順序固定（`10^lp` 用 libm `pow`，Rust 端避免編譯器改寫成 `exp10`），Python 與 Rust 逐位元相同。
- 同一個機率函式服務所有呼叫：解碼、`total_score`、句尾、預測列（`word_by_id`）、數字層（`unigram_back` 與 `prob_back`）。

### 3.2 詞類項（`classes.sjc`）

- 格式（小端序，`tools/build_classes.py` 寫、`lm.py` 與 Rust 讀同一份預先算好的數字）：魔數 `SJCL0001`、模型 SHA-256（32 bytes）、K（u32）、μ（f64）、V（u32）、`cls` u16[V]（`0xFFFF` 沒有類別；`<s>` = K+1、`</s>` = K+2）、`emit` f64[V]（`P(w|c(w))` = 該詞 unigram ÷ 其類別 unigram 總和；`<s>`、`</s>` 為 1.0；沒有類別為 0.0）、`Pc` f64[(K+3)²]（列主序，`(M[c,d]+ε)/(M[c].sum+(K+3)ε)`，M 是剪枝前加權 bigram 的類別計數，ε = 0.1）。總長 `8 + 32 + 4 + 8 + 4 + 10V + 8(K+3)²`。K = 512。
- μ 寫在檔頭、取自檔案，目前出貨值 0.2（`build_classes.py` 的 `MU`）。
- 載入檢查：魔數、模型雜湊、V、μ ∈ [0,1]、長度、類別編號 < K+3、所有機率 ∈ [0,1]；不符就是 `LmError::Format`（載入失敗）。
- 類別只依「模型詞 id」查：分群資料裡有類別、但不在模型詞彙裡的詞（模型裡計數為 0 被剪掉的罕見詞）不套類別項，只退回 `back × pb`；建置工具只記錄這類詞的數目。
- 類別項只在回退分支混入；有保留二元組的條目不變。`--no-classes`（CLI 與 `lm_eval.py`）關閉，摘要行加 `-noclasses`。
- 取捨：用非監督詞類（Brown 式分群）補 bigram 的稀疏，因為組合沒在語料出現時退回單字頻率會選出「磁態」「對其」這類不通的結構。

### 3.3 Kneser-Ney 側檔（`kn.sjkn`）

- 格式 `SJKN0002`（小端序，`tools/kn_cont.py` 寫）：魔數、V（u32）、模型 SHA-256（32 bytes）、θ（u32）、β（f64）、ΣN′（u64）、`N` u32[V]（id 0、1 為 0；異體類的非代表成員取代表成員的 N）。檔案長度 = 64 + 4V。出貨檔 θ = 1、β = 1。`SJKN0001` 只有 Python 讀得到。
- `N(w)`＝有多少種不同的前一個詞 v（`<s>` 不算、v 在模型詞彙裡、v 是它的異體類代表或不在類裡）滿足二元組計數 ≥ θ；`N′ = N + 1`。ΣN′ 是預先彙總的值（每個異體類只算一次），由工具用 `lm.kn_total` 算好寫進檔頭，Rust 只讀檔頭。
- 載入檢查（失敗都是 `LmError::KnSide`）：魔數、V、模型雜湊、β ∈ [0,1]、長度、ΣN′ > 0、且 ΣN′ 介於「最大的 N′」與「id ≥ 2 的 N′ 總和」之間。
- 作用：詞彙內的詞（id ≥ 2）的 `pb` 換成 `β·N′/ΣN′ + (1−β)·pb`，在三個分支之前做一次。β：聊天用檔頭的值，書面一律用 `FORMAL_KN_BETA` = 0.75，不論檔頭記多少。預測列與數字層用該設定的 β，但不用 trigram 表。
- 例外：解碼時被學習加分的詞條（`was_boosted`）與 `Engine::total_score` 裡同樣的詞，改走 `prob_learned`（等於沒有側檔時的公式，`pb` 是加分後的值），不做 KN 替換、也不經過 trigram（§3.4），否則加分會被縮掉。
- 摘要行標記 `+kn:<側檔 SHA-256 前 8 碼>:θ<θ>:β<該設定的 β>`；側檔本身的雜湊在第一次用到標記時才算。`--no-kn` 兩種設定都關。
- 取捨：把 ΣN′ 存進檔頭，因為 Rust 核心沒有詞庫的異體類輸入，無法重算；上游的 Python 每次評測用 `kn_classes` 重算並和檔頭比對，那才是這個預先彙總值的檢查。

### 3.4 trigram 表（`trigram.sjt3`、`trigram-chat.sjt3`）

- 格式 `SJT30001`（小端序，`tools/build_trigram.py` 寫、`reference/proto/trigram.py` 與 `core/src/trigram.rs` 讀）：魔數、V（u32）、D（f64）、模型 SHA-256（32 bytes）、C（u32，前文數）、E（u32，條目數）、`key` u64[C]（`u·V + v`，遞增）、`total` u64[C]（該前文剪枝前的總數）、`off` u32[C+1]、`next` u32[E]（前文內遞增）、`count` u32[E]。檔頭 60 bytes，`off` 有 C+1 個元素；總長 = 64 + 20C + 8E。
- 載入檢查（失敗都是 `LmError::TriTable`）：魔數、V、模型雜湊（綁定同一個 `bigram.sjlm`）、D 必須等於 0.75（其他值一律拒絕，這樣回退權重的加總是精確的）、長度、`key` 遞增且 < V²、`total` ≠ 0、`off` 單調且範圍正確、`next` < V 且遞增、每個前文保留條目的計數和 ≤ 它的 `total`（否則回退權重會變負）。
- 打分：前文是 (u, v)（前前詞、前一詞）時
  `P3(w) = max( (c − D)/total + back3·P2 [有保留條目且計數不為 0；否則只有 back3·P2], F·P2 )`，
  `back3 = 1 − Σ(c − D)/total`（依檔案順序加總），`D` = 0.75，下限 `F` = `TRI_FLOOR` = 0.5（Rust 與 Python 各一個具名常數，不在表檔裡）；`P2` 是 §3.1 的 bigram 機率（含詞類項與該設定的 KN）。前文 (u, v) 沒存、或 u 未知時，結果就是 `P2`（逐位元相同）。
- 每個設定用自己的表：書面 `trigram.sjt3`（連文 SJ-CX-2-7.7M），聊天 `trigram-chat.sjt3`；缺哪張只關哪個設定的 trigram 層。表的內容、檔雜湊與下載見 `docs/spec/models.md`。
- 摘要行標記 `+tri:<表檔 SHA-256 前 8 碼>`。`--no-tri` 兩個設定都不讀。
- 取捨：下限 `F·P2` 用來限制「有存的前文、但這個詞沒被留下」時的懲罰：不加下限時書面會出現「好」＋ㄅㄚ˙ 變「爸」、「搞完這波」變「睪丸這波」這類退步；`F` = 0.5 是照調參集挑的。

### 3.5 trigram 表的唯讀映射

- 兩張表都以唯讀、私有映射載入（`mmap(PROT_READ, MAP_PRIVATE)`；Windows 用 `CreateFileMappingW`／`MapViewOfFile`，開檔只允許共享讀取），核心不加依賴，`mmap`、`munmap` 直接宣告。檔案必須是一般檔案、長度非 0，否則 `LmError::TriTable`。測試可用 `Vec<u8>` 當位元組來源，解析與打分相同。
- 映射期間檔案不能原地截短或改寫（被截掉的頁面會 SIGBUS）；安裝流程一律先放到暫存區再 rename 換上，舊版移走。這件事寫在 `core/include/shanjie.h` 與映射型別的註解。
- 記憶體：映射的頁面是乾淨的檔案頁，系統可隨時丟掉，不計入程序的 phys_footprint（活動監視器的「記憶體」欄）；書面有表時 max RSS 仍會把讀過的頁面算進去（載入檢查會讀整個表）。看記憶體成本時以 peak memory footprint 為準。
- 取捨：用映射而不是 `std::fs::read`，因為 133 MB 的表整檔讀進匿名記憶體會讓使用者看到的記憶體多一整張表。

### 3.6 各設定的打分

| | 聊天 | 書面 |
|---|---|---|
| λ | `LAMBDA_CHAT` = 0.5 | `LAMBDA_FORMAL` = 0.7 |
| KN | 開（β 取檔頭） | 開（β = 0.75） |
| trigram | 有 `trigram-chat.sjt3` 就用 | 有 `trigram.sjt3` 就用 |
| 詞類項 | 開 | 開 |

- `Lm::scoring(profile)` 導出 `Scoring { lam, profile }`；只給 λ 的呼叫（沒有 profile）視為「bigram 加側檔」，不用任何 trigram 表。沒有 KN 側檔時兩個設定都是 KN 關。
- 沒有 trigram 表時，所有輸出與只有 bigram 時逐位元組相同。
- 設定由殼依前景 App 挑（聊天或書面）；核心不記 App 身分。`set_profile` 重算目前的組字並回傳快照。

## 4. 路徑搜尋

### 4.1 光束與合併

- 動態規劃，位置 i 的候選路徑從所有長度 l ≤ `max_len`（詞庫最長詞的音節數；有新詞學習時取 `max(詞庫最長, NEWWORD_MAX)`）的詞接過來。每個位置留分數最高的 `BEAM_S1` = 64 條路徑（數的是路徑，不是相異字串）。
- 合併鍵是（已選字串，前一詞，最後一詞）：沒有 trigram 表時前一詞欄為空（等於（字串，最後一詞））；有表時狀態是最後兩個詞，所以前一詞也是鍵的一部分。最後一詞用詞的字串當鍵（不用模型 id，詞包詞與字表外的詞沒有 id）。同鍵只留分數較高的一條，同分先放進去的留下。
- 取捨：不能只依字串合併。下一個詞的分數取決於最後一個詞，舊的「每個字串留一條」規則會在「下來分析」丟掉分數較高的 `下｜來｜分析` 路徑（`下來→分析` 的二元組遠不如 `來→分析`），留下較差的 `下來｜分析`。

### 4.2 詞項分數

一條路徑上每個詞的分數增量（`decode_segment_fuzzy`）：

`(λ·log10 P + (1−λ)·lp) − δ + 讀音項`

- `P` 依 §3：有 trigram 表時用 `P3`（前文 = 路徑最後兩詞），否則 `P(w|v)`；被學習加分的詞改用 `prob_learned`（§3.3）。
- `lp` 是該詞在這個讀音下的封頂分數；學習加分把它抬到 `該讀音最高分 + ε·w/(w+1)`（ε 與層級的細節見 `docs/spec/learning.md`），抬高後 `pb` 重算。
- `δ` = 降權表的 δ（降權開時，§2.4）＋模糊輸入的容錯扣分（§6）。δ 和學習加分都只動分數，不改「試哪些詞條」。
- 讀音項見 §5，只加在「單字詞、來自詞庫條目、沒被學習加分」的詞上。

### 4.3 段落、前文與收尾

引擎把組字區依固定詞（使用者選定的詞）與標點切成一段一段，每段各自解碼：

- **起點**：段落左邊是固定的字 → 歷史是（未知, 那個字），第一個詞只用 bigram；左邊是標點或英文段 → 歷史 `<s>`（trigram 狀態為（`<s>`, `<s>`））；左邊沒有固定詞時從輸入框前文開始（見本節末的輸入框前文）。
- **收尾**：右邊是固定的字 → 收尾項是從最後一詞到那個字的轉移（`End::Next`，含該字的降權 δ）；否則是句尾項（`End::Eos`）。有 trigram 表時收尾項也用（倒數第二詞, 最後一詞）。**單詞段落**例外：段落的起點歷史是（未知, 某詞）（不是 `<s>`）而且段內只有一個詞時，收尾項的 u 也當未知，用 bigram。
- **輸入框前文**：`lm::history(left, lm)` 取殼傳進核心、結尾至多 2 個漢字的前文（`context_key` 的結果），依序試「整段」與「最後一個字」，第一個在模型裡有 bigram 前文條目的就是歷史詞；都沒有或前文空，歷史詞是 `<s>`。前文本身不計分，只當第一個詞的條件。只用在左邊沒有固定詞的那一段。核心的 n-gram 與學習只看前文結尾至多 2 個漢字，殼傳進來更長的前文（同一則訊息最多 64 字）不改變歷史詞。
- 英文段（`run_cut`）是邊界：游標處的英文打字中，左邊那段以句尾收尾、右邊從（`<s>`, `<s>`）重新開始；只在有 trigram 表時 `total_score` 照此切（沒有表時 bigram 的總分從來沒在那裡切過）。
- 取捨：歷史詞退回 `<s>` 而不是引入第三種「沒有句首也沒有前文」狀態，因為歷史詞沒有紀錄時 `prob` 本來就直接回詞庫機率，等於不看前文；這條規則讓「好」送出後再打 ㄅㄚ˙ 得到「吧」而不是「巴」。

### 4.4 輸出

- 結束時加上收尾項、依分數排序，**同一個字串只留分數最高的一條**，所以呼叫端拿到的 n-best 是相異字串（語意校正取前 `TOPK` = 8 名、評測 CLI 的 oracle 與傾印都靠這點）。
- 每個輸出詞帶（詞、使用的 lp、δ、涵蓋的音節數、模糊音標記、句首學習標記）；沒有任何路徑覆蓋整段時回 `NoPath`，引擎重設。

### 4.5 `Engine::total_score`

組字區目前最佳路徑的總分，逐詞算 `word(λ, 前詞, 詞, lp) − δ`（trigram 表開時帶兩個歷史詞，起點與收尾照 §4.3，學習加分的詞走 `word_learned`），最後加句尾項；標點把它切成句子，標點本身不計分。沒有模型或沒有詞時回 `None`。不含讀音項：在 `set_reading_decode(false)` 或詞庫沒有讀音表時它等於單段第一名的分數，讀音項開著時差在讀音項。

## 5. 讀音項

- 作用：解碼器對每個「單字詞」的路徑加一項 `LAMBDA · max(t(讀音, 字), −CAP)`，`LAMBDA` = 2.0、`CAP` = 4.0，讓 n-gram 看得到讀音（「變快」不會被選成「便會」）。每一鍵同步算、進光束的分數，聊天與書面、三檔語意校正強度、語意校正開或關、有沒有小模型都一樣；沒有使用者開關。
- `t(讀音, 字)`（`reading.rs` 的 `logp`）≤ 0，是該字這個讀音的詞庫（未封頂、取重複列最大值）分數減去該字最好讀音的分數；修正：
  - `SANDHI` 三個讀音（`ㄧˊ` 一、`ㄧˋ` 一、`ㄅㄨˊ` 不）t = 0，不看下一個音節是不是真的需要變調。
  - 分數剛好是 `LEX_FLOOR` = −6.8（詞庫對單字次要讀音沒有計數時給的底分）的（讀音, 字），改用多字詞估：`M(r, w) = 10^s(r,w) + Σ（基底裡每個含該字且該位置讀音為 r 的多字詞的 10^分數）`，t 取 `log10 M(r, w)` 減去該字各讀音中最大的 `log10 M`（同一個（讀音, 詞）重複列取最大值，依檔案首次出現的順序加總）。
  - 讀音質量（`ReadingDecode::with_mass`，在讀完免扣清單之後建，因為資格看免扣後的 t）：單字 w 有 ≥ 2 個單字讀音、這些讀音現在的 t 全是 0、而且 w 是聲韻字（去掉 `ˊ ˇ ˋ ˙` 之後至少有兩個不同的音節；只差聲調或輕聲的字不動）時，每個讀音 r 的 `m(r)` ＝ `mcbpmf-data.txt` 原文裡至少兩字、某個位置是 w 讀 r 的詞條的 10^分數之和（同一個（讀音, 詞）重複列取最大值，依檔案首次出現的順序加總；只加多字詞，不含單字列自己的分數），`t'(r) = log10((m(r) + 1e-9) / (max m + 1e-9))`，max 取 w 的各個單字讀音。**只有 `t'(r) ≤ −MASS_MIN_DEDUCTION`（1.0，剛好 −1 也採用）的讀音改用 `t'(r)`**，其他維持 0；所有 m 都是 0 的字、`SANDHI` 三個讀音與免扣的（音節, 字）維持 0。出貨詞庫上共 132 對（`core/tests/fixtures/reading-mass-pins.tsv`，`core/tests/reading_mass.rs` 逐對斷言，其他對與不加規則時相同）。例：「莎」的 ㄕㄚ、ㄙㄨㄛ 單字同分，單打 ㄙㄨㄛ 原本第一名是「莎」，現在是「縮」（錯字回報第 184 列）。這是研究 repo `experiments/reading-counts-b3/` 變體 T3b 的規則；`λ`、`c` 不變，聲調字不動。
  - `std-exempt.tsv` 的（音節, 字）t = 0。出貨檔有 12 組（`ㄅㄛ 波`、`ㄆㄛˋ 朴`、`ㄇㄚ˙ 嗎`、`ㄌㄧ 哩`、`ㄌㄧㄣˋ 賃`、`ㄕㄨㄞˋ 率`、`ㄏㄜˊ 和`、`ㄏㄜˋ 嚇`、`ㄏㄨㄢˊ 還`、`ㄐㄧㄠˋ 教`、`ㄒㄧㄤ 相`、`ㄞˊ 癌`）：簡編本給該字的單一讀音、詞庫有這組、分數低於該字最好讀音、而且不在 `LEX_FLOOR`。`tools/std_exempt.py` 用這條規則重產它，`tools/test_std_exempt.py` 比對資料列；簡編本資料不在 repo，CI 缺資料時跳過。
  - 字或讀音在詞庫裡查不到的組合、以及字數 ≠ 1 的詞，項為 0。
- 學習加分的詞（`was_boosted`）不加讀音項：讀音項最多扣 `LAMBDA·CAP` = 8，學習加分最多 6，否則使用者教過的罕用讀音會被蓋掉。句首單字學習的「抬高」解碼同樣加讀音項（和不抬高的分數相同，抬高的增益才是兩者差）。
- 模糊音容錯讀音的字，讀音項用它的詞庫讀音算。
- 建表只有一個函式 `engine::load_reading_decode(lexicon, data_dir)`，讀 `mcbpmf-data.txt` 原文與 `std-exempt.tsv`；`Engine::load_lm`、評測 CLI、重播程式都只呼叫它。缺檔、讀不了或格式錯（不是「音節<TAB>單一字」）就是載入失敗（回傳 3），不會靜默沒有豁免。
- 開關：`Engine::set_reading_decode(false)`、CLI 與重播的 `--no-reading-decode` 只給評測用，不在 `shanjie.h`。關閉等於沒有讀音項的解碼器。
- 摘要行：每個設定的標記最後都是 `+rd+rx:<std-exempt.tsv 的 SHA-256 前 8 碼>+rm`（`+rm` 是讀音質量規則）；`--no-reading-decode` 時都沒有。標記驗證工具（`tools/kpi.py`、`tools/bench.py`，以及不在本 repo 的研究工具）依版本判定尾端是否應有它。
- 融合層沒有讀音通道項：`set_reading_channel`、`--no-reading-channel` 與標記 `+rc` 已不存在。
- 研究用的表（只有 `shanjie-eval`，不在引擎與 `shanjie.h`）：`--dump-reading-table 檔` 把內建的 t 寫成 `字\t讀音\tt`（單字讀音至少 2 個的字，每個（字, 讀音）一行，照字與讀音排序，t 是讀音項的輸入、浮點用最短可還原的寫法；已有檔案時拒寫），寫完就結束、不印任何東西；`--reading-table 檔` 用該檔的 t 取代內建值（檔裡沒有的（字, 讀音）是 0；格式錯、詞庫沒有的字或讀音、重複的對都停下並說出行號），摘要標記在 `+rd+rx:…+rm` 後加 `+rt:<該檔 SHA-256 前 8 碼>`。兩個選項都要有讀音項（不能和 `--no-reading-decode` 並用），彼此也不能並用。用 `--dump-reading-table` 寫的檔去跑 `--reading-table`，每列選字與 `top1_sha256` 和不帶選項的一跑相同（`cli/tests/reading_decode.rs` 釘住）；不帶選項時輸出不變。
- Python 參考實作不實作讀音項，所以和 Python 逐位元組比對的 golden 一律帶 `--no-reading-decode`；另有只有 Rust 的出貨預設釘值（dev302、打字測驗、錯字回報，兩個設定：摘要行與 `top1_sha256`）。
- 取捨：讀音項放在解碼器本身而不是重排前的一步，因為 n-gram 只看字不看讀音，要在每一鍵、語意校正關著時也生效，光束才會用它剪枝。

## 6. 模糊輸入

### 6.1 位元與分數

`shanjie_engine_set_fuzzy(engine, flags, out)`：位元 0–3 是四對模糊音（ㄣ/ㄥ、ㄓ/ㄗ、ㄔ/ㄘ、ㄕ/ㄙ，依此順序），位元 4 是鄰鍵打錯；其他位元非 0 回 2、狀態不變；重算組字區並回傳快照（回傳碼同 `set_english`）。預設 0，0 時一切照舊。殼把四個勾選加一個勾選存在 UserDefaults 的整數鍵 `fuzzyFlags`（沒有值＝0），每次建引擎與設定改變時各送一次；排列選倚天時鄰鍵的勾選反灰（值保留）。CLI：`--fuzzy FLAGS`（0–31），摘要行加 `+fz:FLAGS`；給了 `--fuzzy` 時解不出路徑的列算錯、繼續跑，不中止整個集合。

| 常數 | 值 | 意義 |
|---|---|---|
| `DELTA_SOUND` | 2.5 | 經一個模糊音音節讀到的詞減這麼多（log10） |
| `DELTA_ADJACENT` | 2.0 | 經鄰鍵替代讀音讀到的詞減這麼多 |

`--fuzzy-delta-sound D`（只給評測）換掉 2.5；不等於預設時摘要行標記變 `+fz:FLAGS:dD`。

### 6.2 容錯表

載入詞庫時（第一次需要時才建，只建一次）從詞庫音節集合建兩張表，定義和 `reference/proto/fuzzy_ref.py` 相同：

- **模糊音**：每種啟用組合（1–15）一張。把啟用的對合併到對裡的第一個符號（聲調符號保留）後相同的詞庫音節互為替代讀音。
- **鄰鍵**：標準排列的鍵盤列 `1234567890-=`、`qwertyuiop[]`、`asdfghjkl;'`、`zxcvbnm,./`；把音節的某一個符號鍵換成同一列左右的鄰鍵、再依組字區的欄位規則重新組合（一個鍵填它自己的欄位，同欄的第二個鍵取代第一個）後得到的「顯示讀音」，對應回可能打出它的詞庫音節。聲調鍵與非符號鍵不算。只有「有單音節詞條」的詞庫音節才算鄰鍵替代讀音（詞包的音節可能只出現在多音節詞裡，單獨一個音節就沒有路徑）。

### 6.3 解碼

- 每個區段（長度 l 的音節範圍）除了完全吻合的詞庫讀音，另外有「來源」：
  - 區段全是詞庫音節且啟用了模糊音位元：區段裡每個音節輪流換成它的模糊音替代讀音各查一次（每個詞最多一個音節用容錯），查到、且不是完全吻合讀音的詞，用該詞在各替代讀音中最好的分數，每個替代讀音最多 12 個、合計最多 12 個，減 `DELTA_SOUND`。
  - 區段含詞庫沒有的音節（恰好一個）：**一律**（不看鄰鍵位元）用它的鄰鍵替代讀音查，減 `DELTA_ADJACENT`。位元只管「收不收這個音節」，所以收下之後再關掉鄰鍵，已收下的音節照樣解得出來，不會進內部錯誤。含兩個以上詞庫沒有的音節的區段沒有容錯來源。
  - 模糊音只用在全是詞庫音節的區段。
- 挑哪些詞、各自在哪個讀音，和候選窗用同一個函式（`Lexicon::tolerant_pick`）；差別只在解碼器每個替代讀音設 `PER_KEY` 上限，窗不設上限。
- 容錯扣分放在 δ 裡（留在路徑上），所以 `Engine::total_score` 與語意校正看到的分數就是解碼器用的分數。
- 容錯來源的詞用它的詞庫讀音查學習紀錄；寫入只發生在固定的詞上，候選窗選了容錯詞時，那一段的音節已換成該詞的詞庫讀音，所以學到的記錄也是詞庫讀音。學習守門：第一名路徑含詞庫沒有的音節（鄰鍵讀音的詞）的區段不算被學習加分，不計守門跳過。

### 6.4 收下音節與候選窗

- 鄰鍵位元開著、已載入語言模型、標準排列（倚天排列下位元 4 沒有作用）、這個音節詞庫沒有、且有至少一個替代讀音時，`finish_syllable` 才收下它（存打的讀音），組字區照常顯示解出的字。沒有語言模型時照舊不收（`decode_beam` 讀不了替代讀音）。
- 候選窗：某段的清單＝完全吻合的詞條，後面接容錯得到的詞（模糊音開著時的模糊音詞、含詞庫沒有音節時的鄰鍵詞），去掉重複。選了容錯詞，就把那一段的音節換成詞庫讀音，再照一般選詞固定。

### 6.5 與語意校正的配合

- **容錯詞**＝詞條來源是「不含詞庫沒有音節的區段」的模糊音替代讀音；解碼時明確把這個標記帶在路徑上每個詞（不從 δ 或分數推斷）。鄰鍵讀音的詞、學到的新詞、打的讀音本身的詞（降權與否都一樣）都不是容錯詞；有學習加分的容錯詞仍是容錯詞。路徑含一個容錯詞就是容錯路徑。
- `lm::rerank_pool(best, topk)`（引擎的重排工作與評測 CLI 共用）：n-gram 第一名是容錯路徑（救回）→ 該段不送語意校正，組字區照 n-gram 第一名，並計入 `fuzzy_skips`；否則候選＝n-best 依原順序跳過容錯路徑後的前 `TOPK` 條，不足就全部；池子少於 2 條就不做重排工作（不計 `guard_skips`）。錨點仍是 n-gram 第一名。沒有模糊音位元時沒有任何容錯詞，等於前 `TOPK` 條。
- 取捨：重排看不到讀音，所以不讓它把容錯詞換上去（只從打的讀音解出的路徑重排）；δ 取 2.5 是用出貨設定重選的，原本的 1 是在沒有詞包、小模型與 KN 的條件下選的，會讓容錯的常用字蓋過打對的讀音（打 ㄙㄨ 的「蘇」被容錯的「書」蓋掉）。

## 7. 手動詞保護

- 手動詞＝`overlay-add.tsv` 第 4 欄標籤是 `manual` 的列（由 `tools/build_overlay.py` 從 `overlay-manual.tsv` 接在後面，分數為該字數的 `S_len + MANUAL_BONUS`，`MANUAL_BONUS` = 0.75）。`Lexicon` 讀疊加層時收成 `ManualSet`（詞的字，讀音音節序列）；字數不等於音節數的列不收；其他標籤不收。另外 `data/lexicon/rerank-protect.tsv` 的詞（`docs/spec/lexicon-and-packs.md` §2.12，基底詞也可以）在載入詞庫時併進同一份 `ManualSet`，所以保護集合 = 手動詞加上重排保護詞；它們不改分數也不加詞條。引擎與評測 CLI 共用同一份，重排工作帶它（`Arc` 共用）。
- 規則：語意校正某一段的 n-gram 第一名若在某個位置以那個手動詞的音節序列、字面上含有該手動詞，這一段就保護它；候選若沒有在同樣位置保有每一個被保護的手動詞，就在選擇時被遮掉（不能被選）。門檻（τ）與所有分數仍用完整清單算；第一名永遠保有，所以至少有一個可選。遮罩函式只有一個：`tinylm::manual_mask`（`TinyLm::rerank`、`rerank_colloquial`、`guarded_pick` 的退回路徑與評測 CLI 的 `--tinylm-scores` 都呼叫它；退回時也只能退到保有的候選）。
- 音節序列用第一名路徑實際用的讀音（`Lexicon::path_readings`）：鄰鍵輸入把詞庫沒有的音節讀成替代讀音時，用那個詞庫讀音，所以手動詞經由容錯成為第一名時也受保護。
- 沒有手動詞時完全照舊；`--tinylm-scores` 每列多一個欄位列出被遮掉的候選索引（沒有就是空）。
- 重排的其餘部分（融合、τ、δ）見 `docs/spec/semantic-rerank.md`。

## 8. 詞庫讀音規則

這些規則由 `tools/build_sandhi.py`、`tools/build_overlay.py` 與模型建置工具產生資料檔；解碼器只是照一般詞庫載入它們。規則本身是事實，不含教育部資料；依據是《國語辭典簡編本》〈單一音讀〉、《國語一字多音審訂表》（只列本調，連讀變調不在審訂範圍）與《重編國語辭典修訂本》（「一」「不」只標本調）。一個合規的詞庫對同一個詞要本調與合規的變調兩種打法都收。

### 8.1 「一」「不」「法」（`sandhi-add.tsv`，標籤 `sandhi`）

`tools/build_sandhi.py` 從基底的多字列產生，輸出每列 `讀音<TAB>詞<TAB>分數<TAB>標籤`，依（讀音, 詞）的 UTF-8 位元組序排序；`--check` 重產並逐位元組比對。分數照抄來源列；（讀音, 詞）已在基底或疊加層就不產生；同一個（讀音, 詞）由多列產生時取最高分。每條規則對一列至多產生一個變體，規則各自套在原列上：

| 規則 | 條件 | 產生 |
|---|---|---|
| R1 | 「一」讀 ㄧ、不在排除範圍、下一音節聲調可判 | 去聲前 ㄧˊ；陰平／陽平／上聲前 ㄧˋ；其他不改 |
| R2 | 「一」讀 ㄧˊ 或 ㄧˋ，或「不」讀 ㄅㄨˊ | 這一列所有的「一」改 ㄧ、所有的「不」改 ㄅㄨˋ（兩個都在變調時產生全部本調的那一列） |
| R3 | 「不」讀 ㄅㄨˋ 且下一音節是去聲 | 改 ㄅㄨˊ |
| R5 | 「法」讀 ㄈㄚˋ（審訂表沒有這個音） | 改 ㄈㄚˇ |
| R6 | 「紮」讀 ㄓㄚˊ 或 ㄗㄚ（見 §8.2） | 改 ㄓㄚ |

- R1–R3、R5 只處理多字列（單字的變調讀音本來就在基底）；R6 也處理單字列。
- 下一音節的聲調看讀音最後的聲調符號（無符號＝陰平）；下一個字是「不」時視為去聲，是「一」時視為陰平，是「個」而讀輕聲時視為去聲（審訂表「個」不取輕聲）；詞尾沒有下一音節。
- R1 的排除（「一」只用本調）：前一字是「第」或數字字（零〇一二三四五六七八九十百千萬億兆兩廿卅佰仟）；後一字是數字字或「月」；詞尾；前一字等於後一字（疊字動詞中間，問一問）；詞中的詞尾（基底裡以「一」結尾、每個讀音都讀 ㄧ、且基底沒有任何一列在它後面接字時把這個「一」變調的詞，如統一、唯一、國一）；以及 `LISTED` 清單上的序詞與專名子字串（校名、年級、編號、路線、審級、世代，以及教育部沒有規則的人名品牌，如一女中、核一廠、同一性、弘一大師）。
- 自我檢查（`--check` 會先跑）：「真不一般」的「不」不變調、「一不做二不休」第一個「一」是 ㄧˊ、「不一會」的「不」不變 ㄅㄨˊ、R6 兩例；拿掉 `next_tone` 的「一→陰平」會讓它失敗。
- 評測用的讀音翻轉探針（`tools/build_probe.py`）把句中「一」「不」換成另一種合規讀音；探針與基底讀音比較用同一個 `other_reading`。
- 出貨的 `sandhi-add.tsv` 有 1,331 列 `sandhi`（R1 284、R2 976、R3 14、R5 28、R6 29，每列歸給第一個產生它的規則）和 1,501 列 `neutral`（§8.3）；生成器在標準錯誤印出每條規則的列數。
- 載入：`sandhi-add.tsv` 在每個載入點（引擎、評測 CLI、Python `ime.Lexicon`）都接在 `overlay-add.tsv` 之後；缺檔載入失敗。`tools/readings.py` 只載入基底，不要讓它載入這個檔，否則它對「一」「不」選本調的規則會改掉評測集的讀音。

### 8.2 「紮」的口語讀音 ㄓㄚ（R6）

- 規則：基底每一列，詞含「紮」且那個位置讀 ㄓㄚˊ 或 ㄗㄚ，就把那些位置改成 ㄓㄚ 產生一列，單字列也處理（單字「紮」沒有 ㄓㄚ）。新增 29 列（28 個多字詞、1 個單字）。疊加層裡含「紮」的詞不處理。
- 這是口語通行讀音，不是審訂音：只收「不收就打不出那個字、選字記憶也學不到」的口語讀音，且逐字確認；目前只有「紮」。
- 副作用：同讀音有「扎」「紮」兩種寫法的詞會改成「紮」（扎實→紮實、包扎→包紮），往台灣標準寫法。

### 8.3 輕聲的本調（`neutral`）

- 起因：引擎不把本調當輕聲比對，「桌子」的「子」打 ㄗˇ 得到「捉子」，打 ㄗ˙ 才是「桌子」。
- 規則：`build_sandhi.py` 對基底（只有基底；疊加層、名單、詞包不在這裡）兩字以上、讀音含輕聲（`˙`）的列，產生把每個輕聲位置換成該字「本調」的列，標籤 `neutral`。本調＝該字當單字詞的非輕聲讀音裡，韻（去掉聲調符號後）相同、分數最高的那個；同分的每個都寫（多個輕聲位置時展開成組合）；沒有同韻的非輕聲讀音的位置保留輕聲（核心不收沒有聲調符號的 ㄉㄜ、ㄌㄜ，寫了也打不到）；整個詞沒有任何位置能換就不寫。例：子（ㄗˇ、ㄗ˙、ㄗㄜˇ）→ ㄗˇ；頭 → ㄊㄡˊ；們 → ㄇㄣˊ；的、了、著沒有同韻的非輕聲讀音所以保留輕聲（「白色的」不寫，「桌子的」寫 ㄓㄨㄛ ㄗˇ ㄉㄜ˙）。
- 分數：原列分數減 `NEUTRAL_PENALTY` = 2.0（`--neutral-penalty` 可蓋過，量格點用）；已存在（任何一層或 `sandhi` 列）的（讀音, 詞）不寫。不補單字、不改輕聲列本身、不從 `sandhi` 變調列再產生「變調加本調」的組合。
- `neutral` 列不增加任何新的詞字串，所以不改模型的計數詞表；疊加層的輕聲詞也有同一條規則（`build_overlay.py` 的 `tone_row`），本調列隨疊加層寫進 `overlay-add.tsv`（簡編本給了該詞的本調時直接用簡編本的）。
- 驗證：`tools/test_build_sandhi.py`（韻相同的最高分本調、同分每個都寫、無同韻保留輕聲、多個輕聲位置一起換、已存在不寫、單字不補、只在疊加層的輕聲詞不產生、δ 照常數扣）；`tools/test_build_overlay.py` 對疊加層的同一條規則。
- 取捨：δ = 2.0 是調參集上唯一讓兩個調參集都不退步的格（候選 {0.5, 1.0, 2.0}）；用資料列解決而不是讓核心把輕聲當萬用聲調，核心比對規則不動。

### 8.4 疊加層的讀音（`overlay-add.tsv`）

疊加層的讀音是用 `ime.Lexicon.to_syllables`（把詞切成基底詞、每段取分數最高的讀音）推出來的，破音字只能猜，所以 `tools/build_overlay.py` 對推出的讀音做後處理：

1. **正規化**（`normalize`）：「一」的變調改回 ㄧ；「不」的 ㄅㄨˊ 改回 ㄅㄨˋ；「法」的 ㄈㄚˋ 改 ㄈㄚˇ；「和」的 ㄏㄢˋ：後面接 麵、麪、泥 時讀 ㄏㄨㄛˊ，前一字是 唱、倡、附、應、酬、賡（或「和」之前任何位置有 唱、倡）時讀 ㄏㄜˋ，其餘讀 ㄏㄜˊ（疊加層是詞條標題，多為人名地名）。正規化後的讀音是主要列。
2. **變調列**：主要列裡每個「一」「不」照 `build_sandhi.other_reading`（含 §8.1 的全部排除條件）換成變調，有任何位置換了就多輸出一列，緊接在主要列後；分數＝主要列 − `VARIANT_PENALTY`（0.5）。原因：變調列常和別的詞共用讀音，同分時由檔案順序排誰第一；降分後「已經有這個讀音的詞」贏，變調列只在沒有競爭者時才排第一。一個詞最多兩列（全本調、全變調）。疊加層的「一」變調列全部保留，包括人名、序詞、品牌。
3. 變調列是疊加層的衍生，授權跟疊加層走，留在 `overlay-add.tsv`，不放進 `sandhi-add.tsv`。
4. 讀音來源（`--moedict-readings`）：簡編本、再萌典第一讀音；字典有收且合條件就用字典，其餘用 `readings.py` 的規則；規則改音時 `為 町 蛤 吧 萎 凊` 這幾個字保留原讀音；日文新字體字（字不在簡編本與萌典任何詞條）的詞不寫。
5. 核心與 Python 不需要特別處理：`CappedLexicon` 依詞（第 2 欄）封頂，變調列是同一個詞，照樣封頂；`Lexicon::parse_with` 允許同詞多個讀音；變調列的封頂後分數不高於主要列、差距不超過 0.5。

### 8.5 簡體殘留與字形異體

這一節是詞庫與模型建置共用的字形規則；轉換表是 `data/lexicon/tw-conv.tsv`（由台灣用量建出）加雜湊核對過的 OpenCC 對照表（STCharacters、STPhrases、TWVariants、TWPhrases）。

- **來源種類**：建置時呼叫端必須宣告每份輸入是 `native`（台灣原生文字，從不轉換）或 `mixed`（簡繁混合，如維基），沒有預設。
- **句子的簡繁判斷**（`build_counts.sentence_kind`）：集合 S＝真簡體字（STCharacters 的鍵，值不含自己，且沒有被基底詞庫任何兩字以上的詞用到）、M＝標記字（STCharacters 第一個對照不是自己的鍵，含 后、于、里、台、干 這類本身也是正確繁體的字）、T＝繁體證據字（對照表的值不是鍵的字、摺疊目標、TWVariants 目標，扣掉 M）。令 R、M、T 為句中屬於各集合的字數：R ≥ 1 且 R ≥ T → 簡體句（simp）；R = 0、M ≥ 1、T = 0 → 標記句（只有標記字，轉換較保守）；其餘為繁體句。
- **`mixed` 的轉換**（`convert`）：
  - 簡體句：STPhrases 最長優先（取 tw-conv 選定的值）→ 其餘字用字表第一個對照（同樣取選定的值）→ 台灣用詞子集（tw-conv 的 `term` 列）最長優先 → 摺疊（`FOLD`）。「里」由 `li_decide` 依前後文與計數判成裡或里。
  - 標記句：先詞組，再只轉「台灣幾乎不寫」的集合 N（装、痒、苹、价 之類）的字，再用詞、摺疊。
  - 繁體句含 S 字：只套保留詞（原樣）與含 S 字或 R2 字的詞組，再轉 S、N、R2 的字，最後摺疊；沒轉到的「咸」原樣保留、沒轉到的「涌」只在特定後字前轉成「湧」。
  - 繁體句不含 S 字：只轉 N 的字、再摺疊。
- **疊加層拿掉簡體寫法**（`build_overlay.py`）：疊加層候選詞 w 同時滿足 (i) `is_simplified(w)`、w 不在基底詞庫也不是萌典詞目、轉換後變成另一個寫法 w′，(ii) w′ 有落點（本身在基底，或有讀音），就拿掉 w（之后、最后、由于）；「台灣」「里長」「干涉」這類本身在詞庫或萌典的詞保留。被拿掉的清單輸出到建置目錄。
- **異體寫法併類**（`MERGE`）：爲→為 衆→眾 綫→線 麪→麵 僞→偽 裏→裡 峯→峰 羣→群 啓→啟 敎→教 着→著 説→說 佔→占 佈→布 祕→秘 臺→台 牀→床 汙→污，套到兩邊後字串相同、而且在詞庫裡的讀音集合完全相同的詞併成一類（占 另有 ㄓㄢ，就不和 佔 併）；週／周、唸／念、嚐／嘗、它／牠、妳 台灣用法有分工，不併。類的代表成員依序取：詞庫最高分最大、是 `MERGE` 正規形、字串 code point 最小（`build_lm.variant_classes`）。
- **計數時的併類**（`build_lm.merge_variants`）：各語料加權相加、四捨五入、去 0 之後、算總數與剪枝之前做：unigram 以類加總後寫回每個成員（每個寫法都要在詞彙表裡才能當前文）；二元組以（類, 類）加總，「後一個詞」的次數只放在代表成員上，前文則寫給類裡每個成員（條目相同），這樣每個前文的總數 t 只算類一次；N 與 `</s>` 計數每類也只算一次。結果：同讀音兩種寫法在模型裡次數相同，預設由詞庫分數排定，使用者改選一次由選字記憶記住。
- **疊加層的異體拿掉**：疊加層詞 w 若 `fold(w) ≠ w`（`fold` ＝ `MERGE` 加 tw-conv 的摺疊列），而且 `fold(w)` 在同一個讀音下出現在基底或留下的疊加層裡，就拿掉 w；被拿掉的每個詞都要有一個在基底或留下的疊加層裡的替代寫法（落點），拿掉簡體寫法與拿掉異體寫法兩條規則的落點互相指向時分兩階段判定，不繞圈。
- 取捨：併類時「後一個詞」只放代表成員，因為把類的總數寫回每個成員會讓一個前文的總數把 k 成員的類算 k 次，壓低同前文其他詞的機率（曾使回退權重變負）。

## 11. 已知限制

- 光束固定 64，沒有自適應；更長的組字區靠 `MAX_SYLLABLES` 與前段凍結切開，不靠加寬光束。
- 解碼第一名是否為異體的常用寫法取決於模型計數；異體排序表只保證詞庫與候選窗的順序，模型計數把少用寫法抬得太高時第一名仍可能是少用寫法。
- 降權表目前只有 1 行；粗話與歧視用語類、解剖與醫學詞的降權不做（δ ≥ 1.5 會把「左側睪丸」打成「左側高玩」）。
- 模糊音：換出詞庫沒有的音節（例如 ㄓㄨㄚ 打成 ㄗㄨㄚ）時，只有鄰鍵開著才可能收下，而且只走鄰鍵；多於一個音節用容錯的詞不支援；鄰鍵只限標準排列，只容錯詞庫沒有的音節（打錯成另一個合法音節不救）。
- 讀音項的 `SANDHI` 免扣不檢查下一個音節是否真的需要變調；讀音項不納入 `total_score`。
- 強制詞（`acg-oov`）不經通語統計：當成未知詞，所以它們不會從通語的二元組得到上下文加分，也不會被當成下一個詞的上下文。
- trigram 表的 D 固定 0.75、下限 F 固定 0.5；映射期間表檔不可原地改寫。
- 輸入框前文只有結尾至多 2 個漢字進 n-gram；英文段只在有 trigram 表時當總分的邊界。
- 學習加分的詞不經過 KN、trigram 與讀音項：使用者教過的選擇優先於模型統計。

# 微軟注音參考（W0 量測）

狀態：2026-11-07～08 量完（按鍵表、外觀、設定頁）；2026-11-10 補量並更正兩格、2026-11-11 補量組字中按 ↑（見最後「補量」）。Windows 版的現行規格在 `docs/spec/windows-tip.md`。

## 量的環境

- Windows 11 25H2 專業版（zh-TW），乾淨的測試 VM（Hyper-V Gen2），每一輪從同一個檢查點還原。
- 系統內建的微軟注音，預設版本（沒有切「使用舊版」），VM 上只有這一個輸入法。
- 解析度 1920×1080，每次還原檢查點之後從主機設定、開機後讀回核對。
- 截圖來自 Hyper-V 的 VM 縮圖介面，是 16 位元 RGB565：顏色只能精確到這個精度，報成「RGB565 值與它涵蓋的範圍」或「符合 Windows 11 主題的某個已知值」，不寫成精確的十六進位值。
- 按鍵從主機送進 VM 主控台（和實體鍵盤一樣經過輸入法），VM 裡沒有安裝任何工具。截圖不進 repo。

## 探針已經確認的事（淺色、100%）

- 「執行」對話框（Win32 文字框）開起來是**英文模式**，新開的記事本（Windows 11 的新版記事本）是**中文模式**：微軟注音的中英模式是**每個視窗各自記**的。
- 單按 Shift 切換中英；在組字中按，組字**留著**、只切到英文（探針第一次看成「先送出」，按鍵表兩輪量到的是留在組字裡，見按鍵表「單按 Shift」那一列）。
- 組字中按 ↓ 叫出候選窗：
  - 直排，編號 1–9。
  - 選取的那一列左側有一條藍色選取條。
  - 右側有捲動點，底部有 ▲▼ 兩個翻頁鈕和兩個圖示。
  - 窗出現在插入點正下方，左緣和組字的字對齊。
- 「ㄋㄧˇ」的第一頁候選：你、妳、擬、（第 4 個是左邊有「阝」的字，150% 截圖看得出偏旁，像「隬」）、旎、（第 6 個「昵」或「眤」，截圖解析度分不出）、伱、伲、儗（乾淨的檢查點，沒有學習過）。

## 按鍵表

記事本，淺色、100%。兩輪（2026-11-07、11-08）各自從乾淨的檢查點、用同一個順序量，**175 格兩輪在記事本範圍內（x < 1520、y < 1040）有 173 格逐像素相同，另外 2 格只差插入點的幾個像素**（全螢幕比會因工作列的天氣、圖示、時鐘與一次系統通知而不同），下面每一格都量到兩次。狀態：S0 組字區空；S1 有未完成音節（ㄋ）；S2 組字中（ㄋㄧˇ＝「你」）；S3 候選窗開著（S2 再按 ↓）；S4 剛送出（S2 再按 Enter）。「組字」＝還在輸入法裡、有底線；「送出」＝進了記事本。

**輸入法會學最近選的字**：在候選窗選了某個字，下次同一個讀音它就排第一（第一輪選了「妳」「擬」…之後，它們依序跑到第一）。所以 S3、S4 選字那幾格之後看到的第一個候選不一定是「你」。

**S4 沒有聯想詞**：送出之後沒有出現後接詞的清單（預設設定）。

**組字區上限**：連打 ㄋㄧˇ（第二輪 28～42 每個音節一張），狀態列到第 31 個音節都停在第 1 欄，第 32 個第一次改成第 33 欄，第 40 個再改成第 41 欄；到第 80 個時是第 77 欄、80 個字元。補量直接讀回已送出的字：31 個音節都還在組字裡，第 32 個起把前段送出（見「補量」）。畫面上輸入法用藍底標示目前的詞段。

## 外觀

2026-11-08 一輪量完四種組合（淺色／深色 × 100%／150%）。每種組合都從乾淨的檢查點開始；淺色 100% 就是檢查點本身的設定，其他三種改登錄後在 VM 裡重新開機，讀回登錄值核對：深色是 0,0,96、淺色 150% 是 1,1,144、深色 150% 是 0,0,144。另外在畫面上核對：150% 時工作列變高，深色時工作列的平均綠色通道是 7.0 和 8.9，淺色 100% 是 59.0。每種組合在記事本與「執行」對話框各拍四張：組字、候選窗、展開（Tab）、清掉。下面的數字是像素，顏色是 RGB565 截圖的讀值（見「量的環境」），只能當近似值。

位置：

- 記事本：窗的左緣和組字的字對齊，上緣在組字那一行的正下方。四種組合的相對位置都相同（記事本視窗本身的位置每次開不一樣，所以絕對座標不同）。

## 和善解 Mac 版不同的地方

只列事實：左欄是上面量到的微軟注音，右欄是善解 Mac 版現行的按鍵規則（`docs/spec/keys-and-composition.md` §4.1 的規則表，條號附在後面）與設定預設值。要照哪一邊，在之後的 Windows 片裡定。兩邊相同的格不列（例如 S2 的 Enter、Esc、Backspace，S3 的 Esc、數字鍵，S0 的聲調鍵）。

| 情境 | 微軟注音 | 善解 Mac 版 |
|---|---|---|
| 候選窗預設 | 直排、每頁 9 個 | 橫排（設定「直排」預設關） |
| S1 Enter | 不動作，ㄋ 留著 | 送出畫面上的整串，含未完成的符號（12a） |
| S1 Shift＋字母 | 丟掉 ㄋ、送出那個字母 | 忽略（13；中英混打關著時） |
| S2 空白 | 在組字裡接一個空白 | 開候選窗（15） |
| S2 Shift+Enter | 照原樣送出組字，不換行（W0 寫成送出「妳」是錯的，見「補量」） | 送出組字，再把換行交給 App（19a） |
| S2 ↑ | 換游標前那個字：第一次換成單字清單的第 3 項、第二次換成第 2 項，第三次開窗（目前的字排第一）；見「補量」的「組字中按 ↑」 | 忽略（16） |

### 組字中按 ↑（2026-11-11 補量）

上面「S2 ↑」那兩列看不出換成哪一個候選，這次另外補量幾個讀音的單字清單和連按的順序。

- 量法同上：同一台 VM、乾淨檢查點、只有微軟注音；兩輪，每輪 4 組候選頁在同一次開機截圖（不選字，讀回都是空的），其他 17 格每格開始前從開機後的執行中檢查點還原。21 格兩輪逐格相同（共 42 筆讀回），0 格量不到。隔離核對：照上面那格的做法（先 ↓、Esc 再 ↑）兩輪都送出「擬」。

### 更正 W0 的兩個結論

- **S2 的 Shift+Enter**：W0 寫「送出『妳』（第二個候選；兩輪相同）」，是錯的。實際是照原樣送出組字、不換行（上表，「你」「我們」「去」三組各兩輪）。
- **S4 的空白與 Tab**：W0 寫「前一個送出的字顯示成『妳』，原因還不知道」，也是錯的。實際前一個字仍是「你」（上表）。
- 原因：微軟注音預設會把最近選過的字排到第一（「根據我輸入的字調整第一個候選字」預設開）。W0 兩輪都從乾淨的檢查點開始，但兩輪的格子順序相同；前面的格子兩輪都選過「妳」，所以兩輪都被同一個學習狀態影響。「兩輪相同」只證明同一個順序重來會一樣，不能排除照順序累積的狀態。這次改成每格還原檢查點再量。

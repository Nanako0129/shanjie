# 模型檔怎麼產生、怎麼重建或換掉

善解出貨七個模型檔（清單、版本、大小與雜湊見 `docs/spec/models.md` §1、§11）：通語 `bigram.sjlm`、辨類 `classes.sjc`、承接 `kn.sjkn`、連文 `trigram.sjt3` 與 `trigram-chat.sjt3`、會意 `tinylm.sjtl`、常談 `colloquial.sjlm`。這份文件把從語料到發佈的流程照順序排在一起，每一步標出規則寫在哪份規格。

這份文件**不取代**規格：格式、公式、數字與判斷規則以 `docs/spec/` 為準，這裡只彙整並指路。

- **〔推論〕** 是整理者從規格推出、規格沒有明說的話。
- **沒有紀錄** 是查遍手上的資料也找不到的事，不猜。
- **之後加回** 是訓練與分群的程式：它們不在這棵樹裡，之後加回；repo 裡有的是格式、綁定、載入與改綁的程式和測試。

## 1. 總覽

### 1.1 七個檔案怎麼互相綁定

```
語料計數 ──build_lm──> 通語（加來源辨識條目後，SHA-256 = H）
                          │
  分群結果 ──build_classes（讀 H 的檔）──> 辨類（檔內記 H）
  接續次數 ──kn_cont（讀 H 的檔）────────> 承接（檔內記 H）
  三元組計數 ──build_trigram（改綁到 H）──> 連文兩張（檔內記 H）
  小模型權重 ──export_sjtl（--ngram-model 讀 H 的檔、--kn-side 讀承接）──> 會意（檔內記 H 與承接的雜湊）
                          α、τ、δ 在「通語＋辨類＋承接＋連文」之上調
  口語計數 ──build_lm --corpora──> 常談（不綁 H；只在會意檔等於核心常數時生效）
```

| 綁定 | 內容 | 後果 |
|---|---|---|
| 辨類、承接、連文 → 通語 | 檔頭記通語的 SHA-256；缺檔、配到別的通語、內容不對，載入都回 3 | 重建通語就要重建這三種檔（`docs/spec/models.md` §2.1） |
| 會意 → 通語、承接 | 檔頭記調參時用的通語與承接的 SHA-256；不符時核心拒絕載入、只用 n-gram | 重建通語就要重新匯出、重新調參 |
| 會意 → 辨類、連文 | **沒有檢查**，只在 α、τ、δ 的調法上依賴 | 重新分群或換連文表也要重量或重調，雜湊攔不住這種錯配，只能靠 `docs/spec/models.md` §12 的版本表 |
| 常談 → 會意 | 核心常數 `PAIRED_TINYLM_SHA256` 等於載入的會意檔的雜湊時常談才生效 | 換會意檔會讓常談悄悄關掉，要重量常談的參數（§8） |

## 3. 通語 `bigram.sjlm`

規格：`docs/spec/models.md` §3.1、§4。

### 3.1 配方的由來

| 項目 | 做了什麼 |
|---|---|
| 簡繁判斷與轉換 | 先逐句判斷簡體句或繁體句再轉換（維基是簡繁混合），繁體句不套 `TWPhrases`（`docs/spec/models.md` §9） |
| 期望次數 | 計數用詞圖上的**期望次數**：每種切法依機率計入（`--expected`），單條邊期望次數 < 0.01 不記 |
| 台灣字形與異體合併 | 台灣字形表（OpenCC `TWVariants.txt`）；讀音集合完全相同的異體寫法在 `build_lm.py` 合併計數 |
| 詞包詞進斷詞詞彙 | 詞包與名單的詞進斷詞詞彙，用加法計數；有同音衝突的詞與片段不進計數（`docs/spec/models.md` §4.2、§4.3） |
| 口語補次數 | 合成口語句補沒見過接續的口語詞（`docs/spec/models.md` §4.5） |
| 不用 MediaWiki 的台灣正體轉換 | 試過，沒有出貨；重建時**不要加 `--mw`** |

疊加層與讀音修正是詞庫端的改動，已經包含在 `overlay-add.tsv`、`sandhi-add.tsv` 裡，重建通語時用 repo 裡現有的檔案。

### 3.2 步驟

下面是做法的順序；計數程式的參數寫在 `tools/lib/build_counts.py`、`tools/lib/build_counts_text.py` 的檔頭，批次腳本之後加回。慣例：絕對路徑、`PYTHONUTF8=1`、工作資料夾指到新目錄（已有 `counts-200000.pkl` 就停，免得混到舊檔）。

1. **固定輸入並記雜湊**：把 §2.2 那幾個輸入與維基 dump、口語訓練檔、合成句的雜湊寫進工作資料夾的 `inputs.sha256`。除了詞包，雜湊要和上一版相同。
2. **算計數詞表**：把詞包與名單的詞篩過同音衝突（衝突讀音裡連續兩個以上音節的詞整個不進計數），輸出計數詞表（`docs/spec/models.md` §4.3；篩選程式之後加回）。
3. **口語計數**（單一程序）：`build_counts_text.py --expected --extra-lexicon <計數詞表> <輸出.pkl> --native … --mixed …`。`--extra-lexicon` 只能和 `--expected` 一起用。
4. **維基計數**：`build_counts.py --articles 200000 --procs N --expected --extra-lexicon <計數詞表>`。`--articles` 的預設是 50,000，出貨用 200,000，要自己給。多程序合併讓**輸出檔的位元組每次不同**，只能比內容（§3.4）。
5. **建模型**：`tools/build_lm.py --prune 6 --corpora FILE:WEIGHT … --out <不含條目的檔>`（工具預設的剪枝是 2，出貨用 6，見 `docs/spec/models.md` §4.4）。步驟：計數乘權重相加 → 四捨五入去 0 → 異體合併 → 丟兩端有一端不在詞彙的二元組 → 剪枝（前文總數用剪枝前）→ 寫出 `SJLM0001`。Python 參考實作是 `reference/proto/lm.py`，Rust 讀同一份檔。
6. **加來源辨識條目**（§3.3），**對加過條目的檔算雜湊**，並用它建辨類、承接與連文。

### 3.3 來源辨識條目

發佈的通語含少量用來辨識來源的條目，只公開「含有這種條目」，不公開是哪些、怎麼放。條目由不在 repo 的工具加入，且要在算雜湊、建辨類、產生承接、匯出會意**之前**加。所以：

- 用 `tools/build_lm.py` 自己重建，得到的是**不含條目**的檔，雜湊和發佈版不同；
- `cli/tests/golden.rs` 的 `lm_file_is_the_released_model` 會因此失敗，開發一律下載發佈版。

驗收：同一個模型加不加條目，受影響的打字情境裡解碼與預測完全相同；清單與情境不公開，只報「N 條；解碼 n 列、相同 n；預測 q 筆、相同 q」。

### 3.4 重現核對（改了計數程式之後先跑）

先不加 `--extra-lexicon`、用和上一版相同的輸入重算一次，確認之後的比較只反映新東西。任何一項不成立就停（模型檔的位元組不算在內）：

| 項目 | 標準 |
|---|---|
| 口語計數 | 輸出 pickle 的 SHA-256 等於上一版的 |
| 維基計數 | 比內容：鍵集合、`runs`、`articles` 相同，每個值相對誤差 ≤ 1e-9 |
| 重建的模型 | 用 `tools/build_lm.py` 建出來；同一個 CLI 執行檔、兩邊都加 `--no-classes`、都不加 `--packs`、加 `--context`，解碼重建的模型與上一版（兩邊都不含條目），dev302、打字測驗、錯字回報，聊天與書面的第一名逐列相同（`top1_sha256` 相同）。模型檔位元組不同時記下差了幾個條目，不是停止條件 |

`tools/build_lm.py --check` 重建後和 `--out` 指的檔比 SHA-256、不寫檔；`--out` 預設是 `data/lm/bigram.sjlm`（加過條目的發佈檔），自己重建的一定不同，所以要比時另外給 `--out <不含條目的檔>`。不帶 `--check` 也不帶 `--out` 執行會直接覆寫 `data/lm/bigram.sjlm`。

### 3.5 `UNSEEN_OVERLAY_PENALTY` 與模型檔的關係

語料沒出現過的疊加詞與詞包詞，分數是「同長度基底詞的第 25 百分位減 `UNSEEN_OVERLAY_PENALTY`」。這個常數在核心（`core/src/lm.rs`、`reference/proto/lm.py`），**不在模型檔裡**，現行值 1.0。重建模型時若要動它，是核心與 golden 的改動，不是重建檔案的一部分。

## 4. 辨類 `classes.sjc`

規格：`docs/spec/models.md` §3.2、§5。由兩段做成：先分群，再把分群結果與模型一起寫成檔。

1. **分群**（程式之後加回）：Brown 式 exchange 演算法，目標是類別 bigram 的互資訊。前 N = 40,000 個高頻詞：前 K 個各自成類，其餘貪婪貼進最佳類別，再依詞頻順序 exchange；N 之外的詞用和已分類詞的 bigram 貼進最佳類別。K = 512。輸入是和 `build_lm.py` 同一份加權計數；第一次執行把計數轉成邊檔（詞彙、unigram、二元組邊）。分群只有一個確定性的演算法，沒有隨機種子。
2. **沿用舊分群**：舊詞彙裡的詞沿用上一版的類別（不跑交換），前 N 詞裡的新詞依頻率貼進最佳類別，其餘新詞照罕見詞的方式貼。理由：用新計數重新分群，一般詞的詞類整體漂移，若干探針句退步；沿用舊分群後回到原水準。所以**自己從頭分群會得到不同的檔**，沿用的舊分群資料不在 repo。
3. **寫成檔**：`tools/build_classes.py --edges <邊檔> --cls <分群檔> --lm <加過條目的模型> --out classes.sjc`。這一步用邊與分群重算類別 bigram 表 `Pc`（平滑 ε = 0.1）與每個詞的發射機率，依**模型**的詞 id 存（`<s>` 是類別 K+1、`</s>` 是 K+2）；模型裡計數為 0 而被剪掉、卻有類別的詞不套類別項；**檔頭寫入模型檔的 SHA-256**，這就是綁定，所以一定要對加過條目的模型建。
4. **量詞**：分群之後、`build_classes.py` 之前，把罕見量詞搬進「個」的類別（`docs/spec/models.md` §5.4）。
5. **μ**：檔頭的類別項權重，現行 0.2（`tools/build_classes.py` 的常數 `MU`，`docs/spec/models.md` §5.2）；只改 μ 而且開著出貨的會意量過，可以沿用原來的會意。

## 5. 承接 `kn.sjkn`

規格：`docs/spec/models.md` §3.3、§6。`tools/kn_cont.py` 對加過條目的通語產生（θ = 1、β = 1），用和通語同一套加權、四捨五入、去 0、異體合併的整數二元組，並丟掉前文不在詞彙裡的詞對（與模型的建置一致）；側檔綁通語的雜湊。測試：`tools/test_kn_cont.py`。

## 6. 連文 `trigram.sjt3`、`trigram-chat.sjt3`

規格：`docs/spec/models.md` §3.4、§7。三元組的計數與剪枝用的研究工具之後加回；repo 裡有 `tools/build_trigram.py`，把一張表改綁到另一個通語（詞用字串對應、前文重新排序、次數與剪枝前總數照抄）。換通語時兩張表一定同時重新對應，否則每個設定的載入都失敗。

## 7. 會意 `tinylm.sjtl`

規格：`docs/spec/models.md` §3.5、§8；用法見 `docs/spec/semantic-rerank.md`。小模型的工作：n-gram 解碼出前 8 名候選後，用字元語言模型替每個候選打分（`LL`），照 `s'(c) = s_ngram(c) + α·LL(c)` 重排；只在 n-gram 第一、二名的分差小於 τ 時重排，而且融合最高分的候選要比第一名高出 δ 以上才換。它只能從這 8 個候選裡挑，不產生新文字。

### 7.1 訓練文字與字表

訓練程式之後加回。它做的事：

1. **產生訓練文字**：用和通語計數**同一組函式**（條目處理、語料轉換、取漢字段），維基前 20 萬篇加口語類來源，每個連續漢字段（≥ 2 字）一個序列；核對輸入雜湊，不符就停。不用 MediaWiki 的轉換，也不用詞包。
2. **建構檢查**：口語那一半對原始來源逐行重算切分，核對留作訓練的行數等於訓練檔的行數；維基那一半核對條目數與調參集起點。它核對的是切分，不是「沒有整句重疊」。
3. **字表與編碼**：字表取訓練文字（各來源算一次，不乘權重）出現 ≥ 5 次的字，次數多的在前、同次數依碼位，其餘 UNK；id 0／1／2 是 PAD／UNK／BOS。
4. **記錄用的整句重疊比例**：調參集正解句整句出現在訓練文字裡的比例。只記錄，不是停止條件。

### 7.2 序列、批次與模型

| 項目 | 值 |
|---|---|
| 序列 | 每段 `BOS` ＋ 漢字，不把多段接在一起；超過 65 個 token 的段切成重疊 1 個 token 的片 |
| 批次 | 同批只放同長度序列，每批約 32,768 token；一個 epoch，各來源依權重重複、打散 |
| 架構 | pre-LN decoder，tied embedding，可學習位置（前文 64），GELU tanh 形式，MLP 4d，無 dropout |
| 大小 | 6 層、寬 384、6 頭；字表 10,351 個 id，約 1,465 萬個參數，int8 |
| 從頭訓練的設定（初版） | AdamW（β 0.9／0.95，權重衰減 0.1 只給矩陣）、峰值學習率 1e-3、前 200 步線性暖機再 cosine 到 0、梯度裁切 1.0、bf16 autocast，8,836 步、約 2.55 億 token，批次順序固定種子 |
| 現行權重 | 從上一版的權重接續訓練：3,000 步、峰值學習率 1e-4、暖身 100 步、weight decay 0、沿用上一版字表（`docs/spec/models.md` §8.2） |

試過的其他大小：4 層寬 256 沒過；8 層寬 512 在調參集比 6 層好、在私人聊天集合比 6 層差，沒過；12 層寬 640 在聊天集合上沒有比較好，模型變大沒有幫助。加真人口語與生成句重訓的版本也沒有贏過只換平台與種子的雜訊界線，核心的小模型沒有換；那些研究語料沒有進任何已發佈的檔案。

### 7.3 匯出成 `tinylm.sjtl`（int8）

```sh
python3 tools/lib/export_sjtl.py --npz <權重.npz> --out <輸出>.sjtl --type int8 \
  --ngram-model data/lm/bigram.sjlm --kn-side data/lm/kn.sjkn \
  --chat α τ δ --formal α τ δ --levels <聊天保守 α τ δ> <聊天積極 α τ δ> <書面保守 α τ δ> <書面積極 α τ δ>
```

- 格式與版本見 `docs/spec/models.md` §3.5。二維權重每列對稱 int8 加一個 float32 縮放，載入時還原成 float32；一維向量是 float32。
- `--ngram-model` 讀的是**加過條目的發佈版模型**，它的雜湊被寫進檔頭，這就是和 n-gram 的綁定；`--kn-side` 同理。
- 重現同一個檔：用上一版的權重與上一版檔頭的全部值重匯出，結果必須與上一版出貨檔逐位元組相同。
- int8 夠用：6 層寬 384 的權重 int8 對 float32，在所有量過的格都沒有「淨值為負而且 p < 0.05」。Rust 的 int8 路徑與 numpy 逐列相同（最大 |ΔLL| 約 1.6e-5，門檻 1e-4）。

### 7.4 融合參數 α、τ、δ

現行值與三檔的規則見 `docs/spec/semantic-rerank.md` §3.5、§4.4。選法：

- **格點**：α ∈ {0.1, 0.2, 0.3, 0.5, 0.7, 1, 1.5, 2}；τ ∈ {0.5, 1, 2, 3, 5, 不設門檻}；δ ∈ {0, 0.25, 0.5, 1, 1.5, 2, 3, 4}。
- **打分流程**：(1) 用出貨的 n-gram（`--context`、不開詞包）對每個集合各產生一份前 8 名候選；(2) 用小模型替每個候選算 `LL`（torch 或 numpy 後端）；(3) 掃格點、選值、做表（`tools/evalstats.py compare`）；(4) 一致性關卡：numpy 對 torch，最大 |ΔLL| < 1e-4 才往下。
- **選值**：聊天的值在私人的聊天調參期上，以 1:1 的「改對 − 改壞」加改壞率上限（≤ 0.5%）選；書面的值在書面調參集上選，篩選後在沒看過的集合確認一發。選好就凍結；判讀期用過就退役。
- 三檔（保守、標準、積極）只換這一組值，不換模型；積極等於標準是選定的值，不是漏寫。
- **換融合參數不需要重新訓練**，只要重新匯出。
- 融合參數是在出貨的 n-gram 組合上調的；換通語、辨類、承接或連文表就要重量或重調。
- 聊天的值是在私人的評測集上選的，repo 裡只有選出的值、判斷用的程式與數字，沒有那份評測集，所以別人無法用 repo 重選聊天的三個數字。

## 8. 常談 `colloquial.sjlm`

規格：`docs/spec/models.md` §3.1、§8.3；融合見 `docs/spec/semantic-rerank.md` §4。一般的二元詞頻表（`SJLM0001`，不用詞類與 KN，剪枝門檻 2）：用通語的計數詞表重算口語計數，加公開口語池的計數，繁體句不套 `TWPhrases`；不含 g0v 與論壇語料（含了之後記憶體超過預算，保守檔在私人的聊天集合上顯著變差）。署名清單 `colloquial-attribution.tsv` 由 `tools/build_attribution.py` 與常談表同一次建置，每列有來源與句數，不含句子文字。常談的參數是跟著會意檔與通語底層量的，換了其中一個要重量（`docs/spec/models.md` §8.3）。

## 9. 出貨前的評測關卡

標準與規則寫在 `docs/spec/evaluation.md` §11.4（出貨標準）、第 5 節（保留集）。順序：

1. 改到選字結果的改動，dev302、打字測驗、錯字回報，聊天與書面各報一行同一張表（`docs/spec/evaluation.md` §2.6）。
2. 固定探針不退步（「大概十分鐘後到」、竈門、好吧、讀音變體探針）。
3. 詞包在新模型上重驗同音處置（`tools/build_acg_pack.py --recheck`），沒處置的衝突讀音要停下來。
4. 規模：模型檔 < 100 MB 為目標；每鍵延遲 p95 < 16 ms（`docs/spec/evaluation.md` §7.5）。
5. 所有依模型的 golden 用 Python 參考實作重產，Rust 逐位元組相同。
6. 來源辨識條目的核對（§3.3）。
7. 保留集只在推 `v*` tag 前由沒參與實作的審查者量一次，只回數字。
8. 跨版本基準只在輸入法版本（`v*`）發版前跑，不是模型檔發佈前（`docs/spec/evaluation.md` §7.11）。

## 10. 建 Release 與切換

1. **PR 1（不換檔）**：說明檔 `docs/releases/<tag>.md`、規格；本地驗收（§9）通過、審查與 CI 全綠後合併。保留集在這個階段、建 Release 之前量。
2. **建 Release**（對外動作，每次先確認）：指令、核對步驟與規則（資料類 Release 不標 Latest、上傳前後用說明檔的雜湊核對、說明檔不能留草稿標記）寫在 `docs/releases/README.md`。
3. **PR 2（換引用）**：同一個 PR 更新 `docs/spec/models.md` §12 列的那一串（雜湊檔、`data/models.tsv`、CI 與 `release.yml` 的下載、`cli/tests/golden.rs`、各測試的缺檔訊息、`scripts/build-app.sh`、網站的「已合併、還沒發版」、CONTRIBUTING、`LICENSES/data.md`）；依模型的 golden 重產。
4. 舊 Release 保留，可以回到那一版。
5. 換檔順序：先把新雜湊合進 main 會讓 CI 拿舊檔對新雜湊而失敗，所以雜湊檔和 CI 下載在同一個切換的 PR 裡改；第一次加的新檔沒有人讀，雜湊檔可以和說明檔一起先進 main。

輸入法版本（`v*`）的推 tag、簽章與公證是另一套流程（`docs/spec/release-and-ci.md` §5、`docs/releases/README.md`）。

## 11. 在哪裡訓練

- **模型訓練**跑在 Google Colab：A100 80GB，一次訓練約 10 分鐘（8,836 步、每批 32,768 token）；工具是 Google 官方的 `google-colab-cli`（`colab new --gpu A100 --high-mem`）。計數、建模型、分群與評測跑在一般的 CPU 機器上。
- 送上 Colab 的只有公開的程式與資料。私人評測集可以上 Colab 算評測、不進訓練；學習檔與原始聊天紀錄不上。
- 資料怎麼傳：
  - 公開資料讓 VM 自己抓：維基 dump 走鏡像站、8 路平行分段，約 39.5 MiB/s（官方站單線約 4.8 MiB/s）；Hugging Face 約 54.5 MiB/s、GitHub 約 12.5 MiB/s。
  - 只在本機的檔案：用有時效的下載網址交給 VM，網址在本機產生、不印出、用完刪掉嵌著網址的腳本。
  - 結果用 `colab download` 取回，約 3.2 MiB/s，適合幾百 MB 以內。
  - `colab upload` 約 2.2 MiB/s，不用；Google Drive 每個 session 都要授權一次，不用。
- **在不同平台重訓同一份資料，得到的是不同的權重**：同資料、固定訓練預算、不同種子的重訓，權重雜湊與出貨的不同。來源沒有把「換平台」和「換種子」分開；這個差距當成「只換平台與種子」的雜訊界線。同種子、同資料在不同平台的權重是否位元組相同：沒有紀錄。

## 12. 這份文件沒辦法重現的部分

| 項目 | 原因 |
|---|---|
| 發佈的 `bigram.sjlm` 雜湊 | 來源辨識條目由不在 repo 的工具加入，自己重建得到的是不含條目的檔，雜湊不同 |
| `classes.sjc` | 沿用舊分群，那份資料不在 repo；自己從頭分群的結果不同。另外詞類表綁加過條目的模型 |
| 維基計數的位元組 | 多程序合併讓鍵順序與浮點加總順序每次不同，只能比內容（誤差 ≤ 1e-9） |
| 輸入資料本身 | 維基 dump、公開口語句、合成句都在 repo 外；合成句是模型輸出，重新生成不會得到同一份，只能核對雜湊；Wikimedia 會下架舊 dump，所以來源檔雜湊要記下來 |
| 疊加層與詞包 | `overlay-add.tsv` 與詞包在 repo；重建它們要讀維基，且詞包的 (c) 規則會用 `data/lm` 的模型解碼，換新模型前要先改 `tools/build_acg_pack.py` 的 (c) 規則或加例外，否則會丟掉人工決定保留的名字 |
| 小模型權重 | 初版是在一張 8 GB 的消費級 GPU 上訓練的；換平台重訓得到不同的權重（§11）；是否能在同一台機器上位元組重現：沒有紀錄 |
| 口語權重 ×5、聊天的融合值 | ×5 是看評測數字挑的；聊天的融合值是用私人的評測集選的；這些私人資料不在 repo，只有數字 |
| 私人口語資料 | 發佈的檔都**沒有**用私人訊息訓練；但私人訊息影響了出貨的選擇（上一列、調參集的守門、聊天融合值的選擇）。研究用的真人口語與生成句沒有進任何已發佈的檔案 |

沒有紀錄的事：Common Voice、Tatoeba 原始檔的雜湊與取得日期；`sandhi-add.tsv` 的雜湊；疊加層重產與加來源辨識條目花多久；計數的記憶體用量；不含條目的通語的位元組數；條目核對最終的 N／n／q；初版訓練指令的完整參數（只有 `--size M` 與預設值）；同種子在不同平台的權重是否相同。

# 持續改進計畫（2026-10-18 起）

由來：維護者 2026-10-17 晚要求深度檢視實驗方法、理論、方向、語料與評測。三位審閱者各自獨立讀 repo（Fable、Gemini 4 Argon、Opus 5.5），另用網路搜尋整理既有的論文、開源輸入法與實務文章；main 逐條對 repo 核對，和 Fable 討論三輪後定稿，維護者 2026-10-18 用選擇題決定。經過與核對細節在 `docs/research-log.md` 2026-10-18 一節；可直接套用的規則在 `docs/methodology.md`「2026-10-18：研究流程改版」。

## 1. 檢視的結論

- **聊天設定沒有在進步。** v0.4.1（2026-10-13）之後，聊天設定在使用者端集合幾乎不動：discordtune 聊天 4,299 → 4,304、保留集 191 → 191（舊份）與 234 → 234（新份，`docs/benchmark.md`）。進步的都是書面（三元表、書面強度重選），而維護者平常用「一律聊天」。
- **原因是訓練文字，不是模型大小。** 小模型的訓練文字約 94% 是維基，口語（朗讀句、翻譯句、合成句）×5 後約 6%（研究紀錄 2026-10-11 S7a：維基 240,750,484 字，加權後共 255,373,634 個 token）；n-gram 用同樣的來源與 ×5 加權（`docs/training.md` §2.1）。把小模型放大到 L、XL，維基上單獨的鑑別力變好，維護者的聊天幾乎不變（研究紀錄 2026-10-17 rerank-size 的診斷）。
- **重排的目標與輸入不對題。** 小模型學的是「這串字像不像訓練文字」，不是「這 8 個候選選哪個」；只看 2 個漢字前文（`core/src/learn.rs` 的 `context_key`），看不到注音；靠三個手調門檻融合。chatjudge 上正解在前 8 名但不在第一的有 12.8%（評測的寬鬆比對），出貨的重排只淨拿回約 1.2 個百分點。吃注音、看 64 字前文、為候選排序訓練的 0c 公開模型，在 v0.4.1 的候選上和當時的 tinylm-v3 比（`docs/benchmark.md`「外部模型對照」）：維護者的聊天（discordtune、E2 判斷期，私人）對 n-gram 的淨改對是 tinylm-v3 的 2.3–2.4 倍；公開集合反而較差或打平（wikitune、lytune 顯著較差，cvtune 不顯著）。這說明為使用者語域排序有空間，不是 0c 全面較好；chatjudge 與出貨的 M 沒有和 0c 比過。
- **評測看不到一部分實際的錯。** 錯字回報有 29% 在離線評測裡是對的（`docs/triage.md`）；離線評測給的前文比 App 實際看到的多（App 在標點後與新訊息開頭都從句首算；Phase 0 量過，在現在只用 2 個字前文的設計下影響很小，研究紀錄 2026-10-18 的 E-1）；沒有「每 100 字要改幾次」這類按鍵層級的量。
- **一個沒重判的結果。** 用開放授權真人口語重訓的小模型（S7f 的 A1、A2）是在當時「改壞 1 句＝改對 10 句」的計分下被否決的；同日稍晚計分改成 1:1，它沒有被重判過，權重還在。
- **流程本身可信，但成本與方向有問題。** 選值與判讀分離、預先寫死的判讀、精確 McNemar 加 bootstrap 讓「X 在集合 S 上贏不贏 Y」可信；問題是決策集多半不是使用者的語域、0.5% 上限用點估計執行（選值集壓線 0.50%、到新資料 1.72%）、確認前沒先估檢定力、看過結果後放寬過統計門檻。

## 2. 維護者的決定（2026-10-18 選擇題）

| 題目 | 決定 |
|---|---|
| 研究方向 | 聊天優先；書面只守門 |
| 私人聊天判讀集 | 每月最多一份 6,000 列；只從調參池月份（2015-07～2026-07）抽，2026-09 永遠排除；2026-10 以後用善解打的文字不當正解；校對改抽樣 10%＋CHECK 率與改正率控管 |
| 私人聊天的其他用途 | 在 Windows 機器上當「挑像聊天的公開句子」的語域分數（不出貨）；做本機自學（從使用者送出的句子學，預設開、可關、一鍵清除；要重做隱私設計並過安全審查） |
| 0c 公開模型當教師 | 可以；探索期和自產標籤版並行，挑一版進確認 |
| 重排模型記憶體 | 載入增量上限 250 MiB |
| 改壞率 | 0.5% 上限不變，改用改壞數的 95% 單尾上界判；「改壞」＝最後送出的錯，另報「顯示後被改掉」 |
| App 量測 | 加只記數字的本機計數器（預設開、可關、設定頁揭露）、「回報這句」、維護者照打約 200 句公開句子的真實按鍵集 |
| 真人口語進出貨 | S7f 重判為正就進下一版 n-gram 與小模型（model-v7） |
| 產品車道順序 | 沙盒 → 模糊音開關（預設關）→ 資訊＋AI 詞包 → 句首單字學習 → demo |
| 書面判讀 | 只用維基判讀集與保留集新聞半邊；立法院發言（lytune）退回單獨警示；未知 App 的預設等計數器有數字再問 |
| 流程 | 探索／確認兩軌；保留集只在推 `v*` tag 前用；小集合退出關卡；確認前先算最小可偵測效果；比較模型每臂 ≥ 3 個種子；重排只在校準後信心夠時才改 n-gram 第一名 |

## 4. Phase 1（第 1–2 週，探索為主）

- **E-A S7f 重判**：探索＝Phase 0 第 2 項（現有的單一種子）；診斷估值 ≥ MDE 才往下：每臂在 Colab 補到 3 個種子（方法 #10），調參期挑一個，再開確認（chatjudge-2 一發；書面在開發層——退役的 wikijudge1–3——非劣性）。過了就匯出新的語意校正檔，並依決定把口語語料排進 model-v7。（2026-10-18：每臂 3 個種子做完，估值仍低於 MDE，不開確認，研究紀錄同日。）
- **E-B 讀音前綴的小模型**：序列用保留符號分段，`[CTX] 前文 [RD] 注音串（含聲調）[OUT] 字串`（azooKey Zenzai 的格式）；損失只算輸出段，分母只留同讀音的字（PinyinGPT 的同音約束）；M 規模、3 個種子；並行一臂用 0c 公開模型的分數當軟標籤（蒸餾）。研究紀錄 2026-10-17「derisk-1015 E2 修訂七」的讀音臂用的是逐位置對齊的分數，公式本身有偏，所以「讀音沒有用」沒有被證明。（2026-10-18：試點一個種子，讀音前綴臂在調參層淨值 +32、對照臂 +91，照登記停在試點；蒸餾那一臂沒做，研究紀錄同日。）
- **E-C 權重聯合調**（探索）：(λ, μ, β, 三元下限, α, τ, δ) 一起調，聊天目標＝chatclause 調參期淨值（上界約束）、書面＝clean 集；探索的搜尋不受 24 格限制（方法 #4 的上限管確認片），要進確認時從探索結果事先固定 ≤ 24 格並先 commit。多一個候選特徵：口語另建一張表當獨立的 log-linear 項（不再 ×k 混進維基計數）。（2026-10-18：λ、β、三元下限與 α／τ／δ 一起調，聊天最好的格只比出貨點多 5 列、書面最好的就是出貨點，兩邊結案；μ 與口語另建一張表沒做，研究紀錄同日。）
- **E-D 候選覆蓋探針**：`PER_KEY`（每個讀音只取詞庫前 12 名）放寬與前一詞後繼詞，量 oracle@64 的增幅；聊天 64 名外只有 1%，增幅 < 0.5 個百分點就結案。（2026-10-18：`PER_KEY` 放寬到 24／48／1000，聊天兩個集合（chatclause、discordtune）增幅 ≤ 0.03 個百分點，結案；後繼詞那一半沒做，研究紀錄同日。）
- **E-E 真引擎重播評測**（2026-10-18：做成獨立的 `shanjie-replay`，契約 `docs/contracts/engine-replay.md`，PR #210）：擴充 `core/tests/engine_rerank.rs` 的重播：逐鍵、學習開關、串流修正模式（模擬改選、記「本來對、學了之後錯」）、重排兩種時序；輸出 rowstats 與注音版按鍵分數（KySS 的做法：理想按鍵數 ÷ 實際按鍵數）；拆開錯字回報離線是對的那一桶。
- **E-F 學習式閘門**：用現有分數檔訓練代價敏感的選擇性分類器取代 α／τ／δ（特徵：n-gram 分差、小模型分差、名次、差異字的類別、是否句首；溫度縮放後以信心門檻決策，門檻由改壞率上界定），報 error ratio（新造的錯 ÷ 修好的舊錯）。另做一條消融：「第一名是高次數的詞庫多字詞就不改」。它同時是主線重排的下限估計。（2026-10-18 第一輪只用數字特徵：比同規則多淨值 13，但贏不過出貨值、開發層上界超過 0.5%；字串特徵要分數檔先帶候選字串，研究紀錄同日。）
- **輕聲降權表**（reading-aware-0 的 A1 臂，44 字；和 S7f 的 A1 模型無關）：照原排程出貨。

- 確認片以 M 出貨值當基準，0.5% 上界（改壞數 95% 上界 ÷ n）只用來管候選。

## 5. Phase 2（第 3–6 週）

- **主線：判別式 listwise 重排。** 輸入照 E-B 的格式（前文跨標點、最多 64 字），n-gram 分數與名次當特徵；主損失是 8 個候選上的 listwise 交叉熵，多一個「維持第一」的選項一起學，對改掉 n-gram 對的第一名加代價；輔助損失是同音約束；從 E-B 的權重起始。風險閘門：溫度縮放 → 信心門檻，門檻用聊天調參期的改壞率上界定。延遲：前文與注音的前綴狀態在 8 個候選之間共用、跨按鍵沿用（水杉 pinyin-ime-reranker-4M 的量測：p95 從 20.64 ms 降到 8.61 ms），權重保持 int8 常駐。資料全部公開，挑像聊天的句子（Moore–Lewis 交叉熵差），約 30 萬列，3 個種子；主判讀是聊天在新的 chatjudge 一發顯著好，書面在開發層非劣性守門（方法 #5）。書面要不要也改用新模型的值是另一個決定，另用 wikijudge4 一發判。
- **本機自學**：候選窗改選照現行一次到頂；從送出的句子學的用快取模型逐次累加、天級衰減、一鍵清除；隱私設計先過審查。
- **App 計數器與「回報這句」**：只記數字的計數（送出數、每百字改選與退格、顯示後被改掉、預測列接受、送出時重排還沒回來），可關；「回報這句」把實際按鍵與送出文字寫到本機檔，維護者自己貼進錯字回報。
- **model-v7**（E-A 或 E-C 為正才做）：口語另建一張表；計數的轉換不再對繁體句套 OpenCC `TWPhrases`（現在會把「插件」改成「外掛」，`experiments/s2/build_counts.py` 的 `convert`）；合成句做一次有／無對照。
- **蘋果注音的乾淨量尺**：每個 minor 版在虛擬機乾淨帳號用 `tools/imetype.swift` 重量一次。
